# Rules by change class

Imperative rules per change class: tool registration, skill payloads, live E2E, light mode/deliverables, retention, delegated subagents, cancellation, onboarding/settings, transport and late-result custody, LLM calls, timeout/wait control, and loop/result-review state machines. Each section follows DEVELOPMENT "Documentation contract" (invariant home or review-only, mechanism cited). `docs/CHECKLISTS.md` stays sole reviewer scorer (`development_compliance` cites this handbook).

### Tool registration and guard surfaces

- New tools export a `ToolEntry` from `get_tools()` with one safety policy (`safety_policy` or outranking `ouroboros/safety.py::TOOL_POLICY`: `skip` trusted built-ins, `check` opaque/outward-facing), declare capability class in `ouroboros/tool_capabilities.py`, and join child profiles only if that narrower principal needs them.
- Repo working-tree writers join `_ROOT_ARG_REPO_WRITE_TOOLS` and `_PATH_NORMALIZED_TOOLS`, with `_payload_write_paths` returning all targets (omitted-root inference uses it; `protected_repo_write_paths` tests each bound target for body membership, falling back to payload paths on unbound repo writes). Visibility passes without the write guard, so test through the real guard chain (ARCHITECTURE §6 "Tool capability and execution").
- Forwarding wrappers take own args positional-only and never rename or denylist public keywords (`tests/test_pause_forwarding_names.py`).
- Read-only producers return typed misses for admitted absent targets only after query, confinement, runtime and protected-artifact checks; denials and bad content stay errors (`tests/test_discovery_miss_warnings.py`).
- New memory/data files decide in the same change whether they enter LLM context (`context.py`); a change that adds or grows a request-resident part names who digests it and when (ARCHITECTURE §6 "Durable memory and project focus"; review-only).
- Single owners: `ToolRegistry._builtin_hidden` for built-in visibility (regenerate `test_tool_visibility_golden.py` only for intended PR-named changes); `workspace_copies.protected_write_admitted` for protected body paths at dispatch/apply (`test_isolated_copy_corrections.py`).

Enforcement: CHECKLISTS items 11(g), 13 (`tool_registration`), 22 (`context_building`); `ouroboros/tools/registry.py` (public schema), `tests/test_safety_policy.py` (one policy/tool).

### Skill repair and payload lanes

- Repair is ordinary managed development carrying selected skill, source request and admitted revision; Repair-and-run is a real owner message on the ordinary task path. Model enabling resolves that source, never a client `allow_enable` flag; a later direct owner disable wins (load-error reverts do not). `skill_repair` records select without narrowing tool profiles.
- Installed payloads are ordinary directories (Git copy optional): check known revision before acting and record observed revision after opaque work without claiming authorship; no long shell lock or auto-rollback. Every path form binds through payload owners: valid `TaskConstraint` supplies omitted skill-name/bucket selectors; explicit ones must match physical payloads.
- Review, grants, package readiness, enablement and execution stay independent: packages ready by what admits bytes (`skill_dependencies.py`); dependency/load failures never rewrite verdicts; `review_round`/`snapshot_attempt` are display ordinals.
- UI, CLI and tools call shared operation owners. Actor identity is host-derived: owner-only actions need a real member chat/quiz/mailbox source naming exact skill, revision and items; synthetic refs grant nothing, and Repair implies no grant-all, attestation or deletion.
- Test real installed scripts/tools/HTTP/widgets/companions after review, prerequisites and every correction (inspect widget screenshots); execution receipts name the dispatched revision and are not PASS.
- Bundled payload edits bump manifest version; changed seed reconciliation semantics invalidate `native_seed.json` receipt schema (ARCHITECTURE §2), and receipts never replace review/grant binding to installed bytes (`tests/test_builtin_skill_platforms.py`).

Mechanism: ARCHITECTURE §13 and §6 "Skills and extensions". Enforcement: `tests/test_skill_payload_binding.py`, `tests/test_skill_lifecycle_actions.py`, `tests/test_review_skill.py`.

### Capability placement

Skills survive core updates untouched; private core edits need re-merging. For any new capability, whoever asks (owner, user or myself):

- Offer the lowest sufficient rung first, even if the request names core: setting → arrangement of existing pieces → declarative contribution (`contributes`) → skill code (routes, tools, providers, page modules) → core seam. Build higher only if the informed requester keeps it.
- Core is open for extension, closed for features: keep seams and shared floors (draft, Send/authorship, device leases and native permissions, host-owned sessions/cognition, service sign-in custody, Panic/recovery). Vendor- or feature-specific core code is a defect unless the plan names the floor it implements.
- Ship new seams with their first real consumer in one change (no consumer-shaped seam); core consumes contracts, never skill names. Mint shared provider contracts (speech, realtime …) only when multiple providers are plausible, consumers need not care which runs and core owns selection; fallbacks are never silent.
- Self-evolving installs turn wishes into skills and upstream missing seams as PRs rather than private core patches.

Judgment, not a gate. Review: CHECKLISTS Plan row 6, `capability_placement` (advisory). Mechanisms: CREATING_SKILLS "Contributing controls and speech engines" / "Declaring a place, tool effects and an icon"; CLIENT_CONTRACT §11.

### Extension dispatch and isolated dependencies

- Any `type: extension` skill with a reviewed isolated dependency env or payload-native marker (`.so`, `.dylib`, `.dll`, `.pyd`)—even if seemingly pure-Python—never imports `plugin.py` or runs handlers in `server.py`; `extension_process_runner` runs short-lived children. Only dependency-free pure-Python extensions use `extension_loader`'s in-process PluginAPI. Containment is not admission: native payloads still face skill review.
- Child crashes, invalid JSON, timeouts or aborts (`SIGABRT` included) return normal tool errors, HTTP 502 or WS log messages, never crashing the server; never fall back to importing native-risk modules in-process.
- Only workers reuse a catalog run, keyed by source identity (never time); failures never cache (ARCHITECTURE §13).

Enforcement: `tests/test_extension_boot_cache.py` (second birth makes no copies/catalog children; changed inputs invalidate only affected extensions), `tests/test_extension_process_runner.py`.

### Declared skill resources and builds

- Exact downloads and literal build/check argv reuse the isolated dependency owner: new declarations need fresh executable review and hash-covered specs, with pinned payloads revalidated before launch.
- Only an explicitly declared check—never package-manager exit—proves function. Log versions, hashes and diagnostics in existing dependency records; keep verified caches outside replaceable payload/env.
- Keep wheel-only and npm ignore-scripts unless an entry opts into build; put large resources in isolated deps, not giant source patches. Deno flags reflect current script effects and task network constraints, not new grants or stronger claimed sandboxes.

Mechanism: ARCHITECTURE §13. Enforcement: `tests/test_skill_install_resources.py`.

### Skill-defined Presence

- Places belong to the owner: connector manifests declare `provides: place` and per-tool `effect`/`target`; owner choices live in host `places.py` (never payloads), untouched by connector updates. Wake matching and identities read typed provider facts, never message text.
- Foci carry consciousness authority (autonomy level, allowance, Safety at that level), not per-place ceilings: Silent/Paused and Advises refuse at the single dispatch guard over declared tool effects (`place_guard.py`); automatic replies pass `place_reply` (old ceilings stay decodable only for retained work).
- Admission is host-owned: transport tokens reach only their exact connector's places matching provider/account/conversation/thread (ARCHITECTURE §12). Each admitted event runs a fresh agent under a deterministic binding+source-event task id, state-root-wide turn cap and per-conversation serialization; transport durable custody owns arrival FIFO—no transport-specific scheduler, memory silo, core outbox or resident cross-room agent.
- Descendants (`start_task`, `schedule_followup`) copy Presence carrier, workspace and ceiling or refuse (`destination="owner"` copies none). Presence callers reach only their binding's roots (read/steer/cancel) and follow-ups (read/withdraw: `queue_schedules.presence_promise`).
- Knowledge-topic and scratchpad mutations serialize on one stable lock each so concurrent turns never overwrite newer projections with older renders.

Enforcement: `tests/test_presence_admission.py`; provider-adapter E2E is separate evidence.

### Light mode and external deliverables

- Light refuses repo/control-plane mutation while building deliverables (`ouroboros/config.py`; ARCHITECTURE §6 "Safety and runtime mode"). Canonical runtime READ aliases keep fork-relative bytes, explicit roots, task/Presence limits and write ceilings; test context readers via real dispatch (`tests/test_canonical_runtime_reads.py`, `tests/test_authored_memory.py`), not duplicate permission predictors.
- Storage tiers (`task_drive` scratch, `artifact_store` canonical result, `user_files` visible copy; ARCHITECTURE §6 "Tool capability and execution"): `user_files` writes and declared `outputs` register captures; replacement keeps recovery history; changed directory members keep distinct ledger/ZIP pairs; `root=deliverables` is read-only for all actors. Stream task files (`artifacts.stream_artifact_file`, atomic `copy_artifact_file`), never buffering whole datasets; changed files or missing members fail capture explicitly. Run blocking HTTP admission/materialization off the event loop (`gateway._helpers.run_sync_to_completion`); cancelled HTTP waiters never cancel tasks. `send_file` uses immutable captured names so old URLs never alias rewrites. Inputs stay outside deliverable inventories; previews never replace `attachment_manifest_ref` (ARCHITECTURE §1).
- `scratch=[...]` is ephemeral in-cwd verification distinct from `outputs=[...]`: exempt from undeclared-output audit, never an artifact or patch content, adopted only with declaration-time sha (`artifacts.record_task_scratch`); audit stats candidates post-exec. cwd defaults to `active_workspace`; light scratch/services need explicit task/artifact/external cwd honored by scripts. Stop and completion export declared `outputs`; kept/unconfirmed services and Panic skip export. Test Docker addresses and native ZIP names through consumers.
- Outside Cyber Pro, shell uses target-aware git policy (`git_shell_policy.py`): `commit_reviewed` handles self-repo edits; `git init`/`commit`/`push` in external trees is ordinary work.
- Renamed tools stay callable but hidden (`ToolEntry.alias_for`) or retire into `TOOL_NAME_ALIASES` (saved names resolve, uncallable); `registry_guards._disabled_tools` pairs aliases and splits narrow forms; Presence grants of consolidated names never migrate (`tests/test_tool_facade_boundaries.py`). Payloads use `root="skill_payload"`, `bucket`, `skill_name`; `_RETIRED_GITHUB_TOOLS` maps disabled GitHub names to successor restrictions; `run_ci_tests` has no alias. Golden tests prove supported targets by final outcome (tombstones prove removal only); dropping a class needs owner acceptance naming the lost outcome. Uploads, skill payloads and owner state are not artifact transport.

Enforcement: `ouroboros/tools/shell.py` (cwd, light refusals), `tests/test_tool_api_v2_public_surface.py`, `tests/test_deliverables_layout.py`, `tests/test_git_shell_policy.py`; successor parity and artifact transport review-only.

#### Subscription transport

- Claudexor preserves model content and continuation bytes without credential injection, tools, compaction or silent regeneration.
