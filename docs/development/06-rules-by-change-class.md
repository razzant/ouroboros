# Rules by change class

Imperative rules per change class: tool registration, skill payloads, live E2E, light mode/deliverables, retention, delegated subagents, cancellation, onboarding/settings, transport and late-result custody, LLM calls, timeout/wait control, and loop/result-review state machines. Each section names its enforcing test or marks the rule review-only, citing ARCHITECTURE for mechanism instead of restating it. `docs/CHECKLISTS.md` remains the only reviewer scorer; its `development_compliance` item points at this handbook as a whole.

### Tool registration and guard surfaces

- A new Tool: export it from `get_tools()` as a `ToolEntry` with one explicit safety policy, its `safety_policy` or an `ouroboros/safety.py::TOOL_POLICY` entry (which outranks it): `skip` for trusted built-ins, `check` for opaque/outward-facing ones. Declare its capability class in `ouroboros/tool_capabilities.py`. Without one it falls through to `DEFAULT_POLICY = POLICY_CHECK`: a light-model call per invocation. A child profile gets it only when that narrower principal should.
- A tool writing the repo working tree also joins `_ROOT_ARG_REPO_WRITE_TOOLS` and canonicalizes its target paths (`_PATH_NORMALIZED_TOOLS` for a top-level `path`; `_payload_write_paths` plus `protected_repo_write_paths` for payload-borne ones): visibility checks pass without the write guard, so tests exercise the real guard chain (ARCHITECTURE §6 "Tool capability and execution").
- Forwarding host wrappers take their own arguments positional-only; never rename or denylist a public tool keyword to avoid collision (`tests/test_pause_forwarding_names.py`).
- Read-only producers report admitted absent targets as typed misses only after query, confinement, runtime and protected-artifact checks; denials and bad content remain errors (`tests/test_discovery_miss_warnings.py`).
- New memory/data files: decide in the same change whether they enter LLM context (`context.py`).

Enforcement: CHECKLISTS items 11(g) and 13 (`tool_registration`); `tests/test_tool_api_v2_public_surface.py` pins the public schema/registry contract and `tests/test_safety_policy.py::test_tool_policy_covers_all_builtin_tools` one policy per tool; CHECKLISTS item 22 (`context_building`) backstops the context decision.

### Skill repair and payload lanes

- Repair is ordinary managed development carrying the selected skill, source request and admitted revision; Repair-and-run is a real owner message on the ordinary task path. The model enabling the repaired skill resolves that source, never a client `allow_enable` flag; a later direct owner disable wins; a load-error revert is not one. `skill_repair` records are selectors, not a reduced tool profile.
- Installed payloads are ordinary directories; a delegated Git copy is optional. Check the known revision before an operation and record the observed revision after opaque process work without claiming authorship; no long shell lock, no automatic rollback.
- Every path form uses the existing payload binding owners: a valid `TaskConstraint` supplies omitted skill-name/bucket selectors, and explicit selectors must match the physical payload.
- Review, grants, package readiness, enablement and execution are independent facts: one seam readies packages by what admits the bytes (`skill_dependencies.py`); a dependency or load failure never rewrites the verdict. `review_round`/`snapshot_attempt` are display ordinals.
- UI, CLI and task tools call the shared operation owners. Actor identity is host-derived: an owner-only action needs a real member chat/quiz/mailbox source naming the exact skill, revision and items; a synthetic reference creates no permission, and Repair implies neither grant-all, attestation nor deletion.
- Test the real installed script/tool/HTTP/widget/companion after review and prerequisites, repeat after corrections, inspect a widget screenshot. Execution receipts name the dispatched revision and are not PASS.
- A bundled payload change bumps that skill's manifest version; a change to seed reconciliation semantics invalidates the `native_seed.json` receipt's schema (ARCHITECTURE §2), and the receipt never replaces review/grant binding to installed bytes (`tests/test_builtin_skill_platforms.py`: unchanged boot without payload work, new versions, dirty source, failed phases).

Mechanism: ARCHITECTURE §13; §6 "Skills and extensions". Enforcement: `tests/test_skill_payload_binding.py`, `tests/test_skill_lifecycle_actions.py`; `tests/test_review_skill.py` pins the $0 reuse and both cycle lanes; UI lane `tests/test_ui_smoke_skill_lifecycle.py`.

### Capability placement

Skills survive core updates untouched; private core edits need re-merging. For any new capability, whether requested by the owner, a user or myself:

- Name the lowest rung that delivers it and offer it first: a setting; an arrangement of what exists; a declarative contribution (`contributes`); skill code (routes, tools, providers, page modules); a core seam. Offer the lower rung even when the request names core; build the higher one when the requester, informed, keeps it.
- The core is open for extension and closed for features: it keeps the seams and the floors every rung relies on (the draft, Send and message authorship, device leases and native permissions, host-owned sessions and cognition, Panic and recovery). Vendor- or feature-specific code in core is a defect unless the plan names the floor it implements.
- A new seam ships with its first real consumer in the same change; no seam without a consumer, no consumer-shaped seam. Core consumes the contract, never a skill's name. A shared provider contract (speech, realtime …) is minted only when more than one provider is plausible, consumers must not care which runs, and core owns selection; a fallback is never silent.
- On an installation that evolves itself the wish becomes a skill, and a missing seam is offered upstream as a pull request instead of living on as a private core patch.

Judgment, not a gate. Review: CHECKLISTS Plan row 6 and `capability_placement` (advisory). Mechanisms: CREATING_SKILLS "Contributing controls and speech engines" or "Declaring a place, tool effects and an icon"; CLIENT_CONTRACT §11.

### Extension dispatch and isolated dependencies

- A `type: extension` skill with a reviewed isolated dependency env or a payload-native marker (`.so`, `.dylib`, `.dll`, `.pyd`) never imports `plugin.py` or runs handlers inside `server.py`, even when the dependency tree looks pure-Python: `extension_process_runner` dispatches it in short-lived child processes; only no-dependency pure-Python extensions use `extension_loader`'s in-process PluginAPI. Containment, not admission: a native payload still faces skill review.
- A child crash, invalid JSON, timeout or abort answers as a normal tool error, HTTP 502 or WS log message; a child `SIGABRT` is a handled extension failure, not a server crash. Add no host-process fallback importing native-risk modules.

A cached catalog needs an exhaustive `catalog_inputs` declaration; anything else keeps the child run (ARCHITECTURE §13). `tests/test_extension_boot_cache.py`: a repeated boot makes zero copies and catalog children, changed inputs invalidate only the affected extensions; isolation: `tests/test_extension_process_runner.py`.

### Declared skill resources and builds

- Exact downloads and literal build/check argv reuse the isolated dependency owner: a new declaration needs a fresh executable review and hash-covered specs; the pinned payload is revalidated before its processes launch.
- Only an explicitly declared check, not package-manager success, proves the requested function. Resolved versions, hashes and diagnostics go into the existing dependency records; verified caches stay outside the replaceable payload/env.
- Keep wheel-only and npm ignore-scripts unless the entry opts into the build action. Large downloaded or built resources belong to the isolated dependency path, not a giant source patch.
- Deno flags express the script's current effects and the task's network constraints, not new grants or a stronger claimed OS sandbox.

Mechanism: ARCHITECTURE §13. Enforcement: `tests/test_skill_install_resources.py`.

### Task contract resource policy

- Outside Cyber Pro, `resource_policy.protected_artifacts` is execute-only: the declared path may run as a black box; byte reads, copy/hash/static introspection, tracing and debugging of it are refused (ARCHITECTURE §6 "Safety and runtime mode").
- Acceptance claims (`acceptance_claims`, the task-success claim grammar) are bounded advice, never gates or taxonomies; `success_criteria` is an input alias; children receive only claims explicitly passed via `schedule_subagent`. The result review's ask lists the effective claims as text; a reviewer's finding names the concrete gap and its place, and no host path parses a claim id out of it or re-executes anything to grade it (ARCHITECTURE §6 "Result review", §11.1).

Enforcement: `tests/test_acceptance_claims_wiring.py`, `tests/test_protected_artifacts_policy.py`.

### Skill-defined Presence

- A place is the owner's: a connector declares `provides: place` and per-tool `effect`/`target` in its manifest; the owner's choices live in the host place record (`places.py`), never in the payload, and a connector update never overwrites them. Wake matching reads typed provider facts, never message text.
- A focus has consciousness authority (autonomy level, allowance, Safety at the consciousness level), not a per-place ceiling: Silent/Paused and Advises are refusals at the one dispatch guard from declared tool effects (`place_guard.py`), and the automatic reply passes the `place_reply` check. Old ceilings stay decodable only for retained work.
- Admission is host-owned: a transport token reaches only places of its exact connector, whose provider/account/conversation/thread must match; identities are never recovered from message text (turn flow: ARCHITECTURE §12).
- Each admitted event runs a fresh agent under a deterministic binding-plus-source-event task id, a cross-process state-root-wide turn cap and per-conversation serialization; the transport's durable custody owns arrival FIFO. Add no transport-specific scheduler, memory silo, core outbox or resident cross-room agent.
- Every descendant producer (promotion, `schedule_followup`) copies the Presence carrier, admitted workspace and capability ceiling by value or refuses. A Presence caller reads, steers and cancels only roots of its own binding and reads or withdraws only its follow-ups (`queue_schedules.presence_promise`).
- Knowledge-topic and scratchpad mutation each serialize on one stable lock: concurrent owner and Presence turns never overwrite a newer projection with an older render.

Enforcement: `tests/test_presence_admission.py` (parsing, admission, schema and execution filtering, binding/token/origin checks, idempotency, ordering, inheritance), `tests/test_presence_promises.py`; provider-adapter E2E is separate evidence.

### Devtools isolation

`devtools/` is tracked operator code outside runtime package discovery and the import graph: runtime modules, `server.py`, web modules and build scripts never import it; generated outputs live in an explicit external root, never in `repo/` or live `data/`; domain methodology lives beside the devtool, not in core governance docs. Review-only (ARCHITECTURE §1 "Devtools boundary").

### Live E2E stand (`devtools/e2e_live/`)

`python -m devtools.e2e_live.run_live_lanes` runs owner-shaped SM1/SW1/SK1 on isolated real servers; `stub_lane.py` uses `tests/system_e2e/harness.py`'s loopback model/review answers for `--stub`. The rule binding runtime changes: keep this opt-in stand outside runtime imports and default local evolution. Operator manual: `devtools/e2e_live/README.md`.

#### Scenario acceptance

Judge durable artifacts and real consumer observations, never model prose or an HTTP 200 alone (`devtools/e2e_live/README.md#scenario-acceptance`).

#### Seed and settings

One admitted, clean, detached seed; settings from the tree's defaults plus explicit stand knobs, never the owner's live settings; the provider key by environment name only (`devtools/e2e_live/README.md#seed-and-settings`).

#### Budget admission and ordering

Admit an attempt only while settled spend, in-flight reservations and its own reservation fit the run cap, FIFO by dispatch index; `run_live_lanes.lane_spend` reads `state/usage.sqlite` (the journal only for an older seed) (`devtools/e2e_live/README.md#budget-admission-and-ordering`).

#### Self-modification and browser lifetime

`--self-mod` is opt-in; only SM1 owes the real re-exec/absorb proof, which liveness alone never passes; the browser client reopens across a restart on the lane thread (`devtools/e2e_live/README.md#self-modification-and-browser-lifetime`).

#### Reports, focused verification and CI

Run roots are append-only outside `repo/` and live `data/`; the focused contracts are `tests/test_e2e_live_*` plus `tests/test_server_runner_absorb_wait.py`; the `e2e-live` CI job runs only on an explicit `e2e_live=true` dispatch (`devtools/e2e_live/README.md#reports-focused-verification-and-ci`).

### Light mode and external deliverables

- Light refuses repo/control-plane mutation while building external deliverables; Pro permits protected rewrites; Cyber follows effective Access (`ouroboros/config.py`; ARCHITECTURE §6 "Safety and runtime mode"). Canonical runtime READ aliases must preserve fork-relative bytes, explicit roots, task/Presence restrictions and write ceilings. Verify emitted context readers through real dispatch (`tests/test_canonical_runtime_reads.py`, `tests/test_authored_memory.py`), not a duplicate permission predictor.
- Flow: `task_drive` for scratch, `artifact_store` for the canonical deliverable, `user_files` for the owner's visible copy (ARCHITECTURE §6 "Tool capability and execution"). `user_files` writes and declared process `outputs` register the canonical artifact; a rewrite keeps the previous copy as recovery history, never a second deliverable list; `root=deliverables` is read/list/search-only for every actor.
- Task files stream (`artifacts.stream_artifact_file`, atomic `copy_artifact_file`), never a whole dataset in a bytes object; a changed file or missing member is an explicit capture failure. Blocking HTTP admission and materialization run off the event loop (`gateway._helpers.run_sync_to_completion`); cancelling an HTTP waiter never cancels the admitted task. `send_file` uses immutable captured names, so an earlier delivery URL never aliases a later rewrite. Inputs stay outside deliverable inventories; the inline preview never replaces the full `attachment_manifest_ref` (ARCHITECTURE §1).
- `scratch=[...]` and `outputs=[...]` are distinct channels: scratch is ephemeral in-cwd verification, exempt from the undeclared-output guard, never an artifact, adopted only with a declaration-time sha via `artifacts.record_task_scratch` and excluded from the workspace patch; the guard verifies candidates post-exec by stat, so a path mention is not a write (ARCHITECTURE §6 "Safety and runtime mode").
- cwd defaults to `active_workspace`; light scratch/services need explicit task/artifact/external cwd. Scripts honor it (`tools/shell.py`). Explicit stop and normal completion export declared `outputs`; kept/unconfirmed services and Panic bypass export. Test original Docker addresses and native ZIP names through consumers (policy: ARCHITECTURE §6 "Tool capability and execution").
- Outside Cyber Pro the default shell lane carries target-aware git policy (`git_shell_policy.py`): `commit_reviewed` remedies self-repo changes; `git init`/`commit`/`push` in an external project tree is legitimate task work.
- Renames stay callable but hidden (`ToolEntry.alias_for`) or retire into `TOOL_NAME_ALIASES` (saved names resolve, uncallable). `registry_guards._disabled_tools` pairs aliases and splits narrow forms; Presence grants of consolidated names never migrate (`tests/test_tool_facade_boundaries.py`). `claude_code_edit` disables `delegate_start` one-way; payloads use `root="skill_payload"`, `bucket`, `skill_name`. `_RETIRED_GITHUB_TOOLS` preserves disabled GitHub names as method restrictions: PR create/update/draft in `github_write`; run logs/artifacts in `github_read`; api too. No old handler remains; `run_ci_tests` has no alias. Golden tests must prove each supported target through final outcome; tombstones prove removal only. Dropping a class needs owner acceptance naming the lost outcome. Uploads, skill payloads and owner state are not artifact transport.

Enforcement: `tests/test_v674_light_mode_cwd.py` (cwd selection and what light refuses), `tests/test_deliverables_layout.py` (placement and output manifest), `tests/test_git_shell_policy.py`; successor parity and artifact transport are review-only.

### Own-body candidates and adoption

Mechanism: ARCHITECTURE §6 "Own-body candidates" and §2. Rules a change keeps:

- One identity. A consumer of the body root reads `ctx.repo_dir` / `system_repo_dir_for` (the candidate when bound); only what must describe the running body (review governance, the restart marker, rollback) reads `body_candidate.serving_repo_dir_for`. Never rebind `Env`; never give a candidate workspace-mode authority.
- Prepare before effects, by seam: a new body-writing tool joins `body_candidate.authoring_seam`. Never classify command text or infer a candidate from a room, name, date or PID; ownership moves only from a terminal task record whose ledgered processes are dead (`live_lineage_processes`).
- Attribution is the lineage's own baseline (`mutation_attribution.capture_mutation_baseline`); the commit gate resolves attributed paths on `ctx.repo_dir` with no candidate bypass. A process inside the candidate or an admitted own-body child copy gets its isolated environment or a typed refusal.
- Retention never deletes unique work on age: extend `unique_work` / `_preserve` together, an incomplete capture retains the directory, and a GC verdict computed outside the record lock applies only while `verdict_holds` under it.
- The old generation never writes the serving tree for an adoption: arm only from the existing stop owners' outcomes (PID census, `stop_owned_work`'s ownership set, reaped children); add no wait, drain or PID probe, nothing on the Panic path. Boot settles `adopted` only for a process that attested the switched tree before its imports (`sys._ouroboros_body_generation`).
- The hook in `ouroboros/__init__.py` and `body_switch.py` stay stdlib-only and compatible with the helper an older body captured; a body without the hook receives it via an ordinary release, never by adoption.
- No generic adoption reset (`holds_checkout` covers landed, returned and open transitions); returning files never claims restored dependencies. Preserve the loaded-generation handoff contract in ARCHITECTURE §2.
- Candidates are not auto-pushed. Permitted serving/adoption pushes send only the operation-created tag, never backfill; selected adoption withholds branch and tag (§14). The gate reads `numbered`/`neutral` from the diff (`neutral_allowed` for prepared index and bound candidates); partial carrier moves are findings. Recovery grants no adoption authority.

Enforcement: `tests/test_body_adoption.py` with `tests/test_body_candidate.py`. Not exercised there: Windows handover, the packaged launcher's frozen code, a native Android host, an end-to-end `commit_reviewed` with live reviewers on a candidate.

### Runtime cleanup and retention

- Age-based GC of disposable runtime artifacts shares one owner knob, `OUROBOROS_GC_RETENTION_DAYS` (default and clamp: ARCHITECTURE §7), and the `ouroboros/retention.py` helpers (`age_cutoff`, `clamp_retention_days`, `get_gc_retention_days`); no hand-rolled cutoff math. Prune functions keep an explicit `retention_days=` parameter whose default alone reads the knob; `server_maintenance.py` schedules them.
- A subsystem needing its own lifetime passes explicit `retention_days=`; an owner-settable one is an ordinary `OUROBOROS_<SUBSYSTEM>_RETENTION_DAYS` in `SETTINGS_DEFAULTS` clamped by `clamp_retention_days`. Never restore the consolidated keys or keep a knob that deletes nothing.
- Durable artifacts are not age-pruned: genesis projects (`OUROBOROS_SUBAGENT_PROJECTS_ROOT`) and forensic observability blobs (packed, never deleted or counted).
- Review continuations are recovery state, not disposable GC: archive a record (collision-safe move, never delete) only when its owner task is settled, it stayed un-resumed past `task_continuation.RETIRE_SETTLED_CONTINUATION_AFTER_DAYS` and no recorded obligation is open; any uncertainty or move error keeps the live record.

Enforcement: `tests/test_phase3c_observability_gc.py` (knob and cutoff math), `tests/test_observability_retention.py` (preserve indefinitely); the continuation archive rule is review-only.

### Live subagents

Mechanism is ARCHITECTURE §6 "Delegated subagents (Claudexor transport + the nanny)" and the module docstrings it names. Review gate: CHECKLISTS items 16 (`subagent_isolation`), 19 (`delegated_transport`). Imperatives:

- Only `schedule_subagent` schedules; schema/handler share `control.schedule_subagent_properties()`. Child needs use the capability enum, not contract fields/prose. `subagent_id` selects a full `OUROBOROS_SUBAGENTS` row admitted by both enabled axes; dispatch uses its scheduling snapshot. No second selector, host ranking or substitution. Redelivery of an exact task id with live/durable custody is an idempotent no-op.
- The parent's substrate binds. Auto-start fresh work only; saved supervision restores before leaf admission, without probing or replaying a pending POST. Keep local handoff authority checks; unobserved liveness is not readiness or loss. Stage shown wake exposure before saving; ACK externally only after incorporation. Add to `_DEFINITE_UNRUN_REASONS` only proof of no run. Zero-run receipts remain `incomplete | unknown`; no silent substrate fallback.
- Work orders carry the full assignment and host authority, without size cutoffs, forced question/file transport or duplicated objectives; redacted reviews never replace original requirements. `delegate_start_instructions.access_instruction` states typed native access once; per-call access may only narrow it, never derive it from prose. `delegate_message` uses the operation catalog and route `liveInput`, not a harness name; its host-minted `message_id` is the Idempotency-Key, reused only after `delivery_unknown`, without retry/stall machinery.
- `subagents.route_health` is every consumer's route reader; quota readers project one `ClaudexorGateway.quota_state()` envelope, and a fully-used ratio without a valid future reset neither refuses dispatch nor certifies quota, because final admission is the engine's. Lifecycle facts are visibility only (the result review judges quality, never the route); an unreadable custody log reads `evidence_read_failed`, never proven-empty. The coordination poll only reads task state and writes nothing beyond the canonical usage-ledger reader's bounded maintenance; every ledger state, absence included, goes through that reader (`usage_attempts.lock` recovery: ARCHITECTURE §1 "Platform substrate"; pre-send policy: `_usage_wait.py`).
- `task_constraint` booleans parse strictly (`"false"` is false); deadlines only narrow, delegation budgets only reduce, and persisted depth facts are never recomputed from current Settings. `active_tool_profile` fails closed to read-only, never to `self_modification`/`operator_control`; an explicit read-only assignment stays read-only. Only `schedule_subagent` creates subagents (`delegation_role=subagent` is refused at the gateway task route and the CLI); live `memory_mode=shared` stays disabled. The Cyber acting-tool catalog and the subagent browser boundary: CHECKLISTS item 16 and ARCHITECTURE §6 "Tool capability and execution".
- Acting children may ask `review_change` about assigned work, not approve/commit/integrate (`test_review_change_child`). The immediate parent stages via `integrate_subagent_patch`, land body commits via `commit_reviewed`. Native succession grants no child control; test its entry (`test_continue_successor_integration`; ARCHITECTURE §6). Capture bases prove no authorship (`vcs_read diff`). One reducer owns canonical/replica terminal fields; test stale replicas at both seams. Custody consumers name covered owner kinds: `RunCustody.review_owned` stays panel-owned and alive through author finish. Git/payload edits stay private until `integrate_delegated_patch` (not an explicit `in_place` writer's). Separate orphan geometry/current rights: `copy_apply_refusal` checks the recorded target, not caller's folder (`test_orphan_apply_authority`). Each copy mechanism names its job, the fault it prevents, its size on a small install and its remover; a new kind gets plan review.
- `continue_from` enforces the four floors of `delegate_continuation` (recorded task line, observed terminal, no ambiguous apply, access not wider) plus its typed snapshot and engine refusals (ARCHITECTURE §6 "Nanny verbs and continuation"). Other facts are advice in the child's prompt, never gates or `instructions`.
- Outcome honesty: a delegating parent never produces a clean no-tool final answer while direct children run undecided; reminder counts never terminate the task. `wait_tasks` stays batch-compact; `control_task_results._wait_for_tasks` owns its projection (ARCHITECTURE §6 "Child reads and waits"); full handoff belongs to `get_task_result` and a settled `wait_task`. Push/live events are wakeups, not terminal authority: a lifecycle change exercises lost/reordered terminal frames.
- Ordinary-directory sessions use the engine-owned file work product: keep the parent-selected direct/copy strategy, never initialize Git or change run mode as a workaround, carry full file artifacts beside source patches (deletion included: an empty text diff cannot certify no work), apply via the engine CAS, retain unselected results, and never relabel direct effects or a discard as an undo.

- Vendor maintenance shares engine-owned capability/request identity across UI and tools, never a harness-specific installer or task replay (ARCHITECTURE §6 Vendor program maintenance). Preserve selected/baseline, rejoin and partial/cancel facts; verify both authority directions and desktop/mobile rejoin (`test_harness_maintenance_host`, `test_harness_maintenance_transport`, `test_harness_maintenance_browser`).
- Writable access without product-write authority means private, evidence-only investigation. Integration/debt use `delegate_registration_policy.candidate_apply_possible`; Continue uses `independent_review_without_apply`, not path/label guesses (`tests/test_investigation_custody.py`).

Enforcement: `tests/test_acting_subagents.py` (profiles and creation), `tests/test_delegate_continuation.py` (`continue_from`), `tests/test_custody_owner_kinds.py`, `tests/test_delegated_directory.py`; `tests/test_tool_api_v2_public_surface.py` pins the schema/handler derivation.

### Cancellation and effective status

Mechanism: ARCHITECTURE §5 (`supervisor/queue_transitions.py`, `supervisor/cancel_publication.py`, `supervisor/owner_stop.py`); ARCHITECTURE §10 invariants 14-15. The imperatives:

- Effective task status belongs in `ouroboros/task_status.py`; never duplicate child-drive merge or terminality logic in gateways or tools. Waits use `SETTLED_STATUSES` and structured facts plus queue-heartbeat freshness, never keyword matching.
- `wait_task`, `wait_tasks` and `await_messages` peek the waiting actor's own mailbox via the transport-wait reader: early return for pending mail is disclosed without ACK or stopping children; the round-top drain delivers and ACKs. Only a proved-empty mailbox is retained; a read failure or torn data is neither proof nor cached.
- Terminal quiz reconciliation closes the paired wait even when the answer arrived before worker capacity. A failed loop without captured evidence reports unknown counts, never zero work or an unverified checkpoint.
- `task_status.observe_cancellation_target` precedes intent writes and reports physical target, result/queue freshness and delegated custody separately. Caller reason and request origin differ: HTTP ingress proves no personal owner intent. Preserve `cancel_origin` through publication, history, cards and conditional result reads; unknown actors stay unknown; keep the whole reason, labelling a shortened form a preview. Unconfirmed terminal sends are disclosed as "not confirmed", saved copies named as copies; only a same-delivery receipt for the recorded destination retires the notice.
- Cancel intent is never a status value: every cancel ingress writes a durable intent via `ouroboros/cancel_intents.request_cancel`, fails closed if that write fails, checks live physical ownership (a settled result does not mean a dead worker) and keeps the recorded scope widen-only. Natural completion wins a late cancel (discarding is the parent's separate `discard_child_result`); timeout reaping is not a cancel ingress. The intent and delivery registries read strict to rows and `task_done` always validates via the durable result; only `interrupted` keeps its restore-path exemption.
- `stop_policy` is an axis on the durable intent; owner hurry is a typed task-local owner-mailbox control, never a chat message, settings mutation or review-gate weakening. Every same-id requeue producer calls the one shared `owner_hurry.retry_reset`; the hurry projection writes only via `update_json_locked` on `owner_hurry` keys, never `write_task_result`; UI surfaces share `web/modules/task_control_menu.js`; terminal rows win.
- Keep cancellation, terminal-delivery, pause-notice and usage recovery off supervisor drain with independent single-flight duties. Test their interleavings through existing claims/receipts and generation checks; local keys deduplicate dispatch, never own durable effects. Do not serialize unrelated Stop/delivery behind history work (ARCHITECTURE §5).

Enforcement: `tests/test_cancel_intents_phase_a.py`, `tests/test_cancel_cascade_v664.py`, `tests/test_cancel_origin.py`.

### Onboarding and Settings surfaces

ARCHITECTURE §2 owns wizard steps, completion and install-time proofs; §3 owns Settings, accounts and shared controls. Copy and wizard shape are review-only. The imperatives:

- Keep entry models, keys, Supervisor, Review and room cognition private; never publish project overrides to process env. New participants resolve their current room; running actors retain their choice through Resume (`test_project_cognition_runtime`). Writers, grants and skill settings read current disk. Cyber configures under effective Access; permission is not a verdict.
- One wizard host, the `GET /onboarding` page, serves subscriptions, API keys and mixed installs; its frame keeps the `allow-popups allow-popups-to-escape-sandbox` sandbox tokens, without which the sign-in click is blocked silently. Completion is one transaction, `GET /api/onboarding` and its `/bootstrap` JSON never persist, and the client completes only on the exact success envelope (`ok`/`runtime_mode`/`restart_required`), because a silent success discards the restart receipt. Only declared raw-model sources supply Main, never agent-only connections; "Without an API key" never means free.
- Settings validates the complete draft before any Save: never drop an invalid custom-key row and save the remainder; a failed save/refresh preserves edits; leaving a dirty draft asks first. Saved intent, generated drafts and live status are different axes: a status/catalog failure annotates, never erases, a loaded row; only an Agents edit, the wizard or Colab authors a generated or factory catalog; a late preview never absorbs owner edits.
- Model-role and actor/reviewer adapters use `model_chooser.js`, owning only suggestions/keyboard/position, never route identity or entitlement. ### Android platform development

Android keeps the common source, update and review authority. Its runtime layout, launcher/seed distinction, native artifact receipt and lifecycle owners are ARCHITECTURE §1 "Android host (experimental)"; the user procedure is `docs/ANDROID_INSTALL.md`; the CI lanes are ARCHITECTURE §8. Rules:

- Describe experiments as rooted ARM64 Android, physically tested on Pixel 10a only. Never turn that tested model into a runtime allowlist or the manifest's minimum SDK into a proven support matrix.
- Native changes use ordinary Android source, reviewed commits and the persistent per-install signing identity. Never copy the publisher private key, runtime credentials, memory or a live rootfs into release assets. Verify official bytes before trusting their source, and record a publisher-signed reference APK and the locally built installed APK as distinct artifacts. Restore the original personal key after loss; never silently generate another identity for an installed package.
- Dependency changes reach the same source-selected `ensure_platform` hook serving first installation and later updates, with tracked recipes and patches; a group stays `platform_preparing` until completion so an interruption or a Git rollback cannot reuse a partially changed SDK as current. Use the existing verified download cache, Node manager and Playwright installer; start no second daemon. Preparation completion is not HTTP or native-success evidence, and the contained preparation's `EXTERNAL_PLATFORM_UPDATE_TIMEOUT_SEC` bound is neither an environment setting nor a harness deadline.
- Before claiming native adoption, exercise source → dependency preparation → build → install → readback → restart, and cover a failed native build beside a still-usable core, an older immutable seed with newer source, a local APK modification followed by an upstream source merge, bootstrap-only changes, rollback to older native source with a newer versionCode, bridge loss and recovery, and Panic versus automatic entry. Core HTTP health is separate from native artifact and bridge readiness; checks use their existing owners and preserve incomplete outcomes.
- Delegated access keeps the common actor/delegation owners (ARCHITECTURE §6 "Delegated subagents (Claudexor transport + the nanny)"); Android acquires no second access default, trust policy or retry implementation, and a sandbox failure is not a successful run or permission to disguise a retry.
- `enter-linux` sets this entry's defaults for the existing `OUROBOROS_PREFLIGHT_TEST_WORKERS` and `OUROBOROS_PREFLIGHT_TIMEOUT_SEC` levers and preserves explicit overrides; they change test concurrency and time, not test content, review models or context. Measure memory and swap and confirm process cleanup before running full preflight on a phone; do not deliberately reproduce a kernel panic; keep reusable large downloads in the installer's durable cache.
- `android-test` explicitly collects `android/tests`, which ordinary `pytest tests/` does not cover. Portable fixtures and host compilation are separate from physical root, boot, permissions, hardware and battery evidence, and the emulator job certifies neither the phone bootstrap nor the owner consent UI. Release SBOMs describe shipped source/APK bytes; installed pins describe the provisioned phone; neither invents the other. Only the tag-only `android-build` job reads the publisher signing secrets (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`); branch and PR Android jobs sign with a disposable key they never publish, so a PR is source/build evidence, not a publisher-signed release claim.
