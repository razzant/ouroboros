# Design System

This chapter owns the engineering rules that keep the visual and interaction semantics of `docs/DESIGN.md` true in code: where a value may live, which module is the one source of a control, what counts as review debt, how history and the chat viewport mutate, and how a visible change is verified. The failures it prevents are silent ones (a size token without a colour token, a control that widens its column, a dialog that bypasses the design system), so every rule names the test or review item that keeps its class closed.

`web/ui.css` owns shared values and the field, button, status and popup recipes, and both `web/index.html` and `web/onboarding_template.html` load it before their page styles; `web/style.css` and the page sheets keep shell and page composition (the primitive registry: ARCHITECTURE §3 "Navigation and shared UI contracts"). Documentation keeps semantic roles and failure-prevention rules, never a copied colour, radius or dimension inventory.

### Tokens and primitives

- **Shared control classes** (`.ui-control`, `.ui-checkbox`, `.ui-field`, `.ui-field-help`) are selected on the controls themselves, never through a growing list of page ancestors. A family migration removes the replaced chrome in the same change; domain drafts, validation and serializers stay with their owners. Review-only under CHECKLISTS item 30 (`web_design_system`); migrated consumers are pinned individually (`web/tests/ui_primitives.test.js`). DESIGN §8 lists the migrated families.
- **`web/modules/ui_primitives.js`** is the one safe-field renderer, collector, attribute escaper and tone/status source; `ui_helpers.js` and `utils.js` keep the re-exports. Keep the leaf free of shell, network and document-global initialization, so first-party and author consumers share one implementation (`web/tests/ui_primitives.test.js`).
- **Typography on a migrated surface** names a `--type-*` size token and a named foreground token in every text declaration: a size with no colour is the defect that made secondary text inherit near-white primary ink. `tests/test_web_typography_static.py` keeps the class closed on the migrated families; extending that guard and migrating its subject are one commit (DESIGN §8 names the boundary).
- **The variable contract** is checked in both directions by the same test file: every `var(--x)` must resolve, because an undeclared one silently renders its fallback and becomes the real value nobody can find; every `:root` token must have a reader, because a token that resolves nowhere makes surfaces reach for literals. Each document resolves against the sheets it loads, and neither page may shadow a shared palette name. Fix a dangling name by pointing it at an existing token, not by declaring a new one.
- **Appearance is client-local.** The choice and its radiogroup live in `web/theme.js`, outside Settings' `s-` input collector; theme-dependent images and selected warning controls use semantic tokens, never a raw hue. Every theme subscription has an owner and a disposer; `onTheme` is opt-in and resolved-only (storage, charts, Mermaid and iframe mechanics: ARCHITECTURE §3 "Navigation and shared UI contracts"). Request persistent desktop storage at every `webview.start`, and verify a rebuilt launcher through quit and relaunch, not a server restart. The Windows caption tint is the top-level page calling its own window's bridge, applied by `launcher_appearance.py`: no second theme store, frameless frame or page-colour caption. Regressions: `web/tests/theme.test.js`, `tests/test_appearance_static.py`, `tests/test_launcher_appearance.py`, `tests/test_theme_browser.py`.
- **One semantic button variant expresses one action role**: neutral Settings and onboarding controls use `.btn.btn-default`; a one-action result row uses the `.settings-action-row` contract (status first, action docked right); notifications use the shared toast host. Working, warning, error and destructive states keep one meaning across Chat, Logs, Settings and Skills. Enforced by `web/tests/settings_action_row.test.js`; the toast-host and cross-page meaning clauses are review-only (CHECKLISTS item 30).

### Layout and containment

- **Layout and controls.** Top-level pages use a fixed `renderPageHeader` outside an independently scrolling body; primary actions, Refresh included, live in its `actionsHtml` slot. A tab strip is one design-system control (`renderTabStrip` + `bindTabStrip` in `page_header.js`): the binder owns selection, ARIA and focus, callbacks own loading and panels, and the binder is disposed with its page. Segmented single-selects are one generator too (`renderSegmentedField`): their columns come from the count it writes, never a per-control column override, and focus is the one ring apart from hover (`web/tests/segmented_field.test.js`; every group on the real page in Chromium and WebKit: `tests/test_segmented_layout_browser.py`). The navigation column's height never grows with a collection inside it; a variable-length collection owns a bounded window with its own scroll (`--nav-projects-list-max-height`). Scroll bodies share `.scroll-fade-y`, except a dense list whose rows are shorter than the fade edge (`--scroll-fade-edge`), where the fade would cover a whole row. Masonry packs through `web/modules/masonry.js::applyMasonry`, which writes only `--masonry-*` custom properties, because CSS Grid row packing leaves gaps under shorter cards; never move `<article>` nodes to reorder or resize, because a moved `<iframe>` reloads (persistence: ARCHITECTURE §3 "Widgets page"). A new visual dimension becomes a CSS variable consumed by shared classes; new inline `style=""` markup and `.style.<property>` assignments are review debt, except a measured value, or a renderer's count of what it rendered (`renderSegmentedField` writes `--segment-count`), updating a narrowly named custom property when that is the real runtime data flow.
- **Containment.** A control never widens its column. Horizontal overflow lives in the wrapper that owns the wide content and declares `overflow-x: auto` (code block, `.md-table-wrap`, tab strip, Costs table cells), never in a page scroll body, whose `overflow-y: auto` alone makes `overflow-x` compute to `auto`. The shared `select.ui-control` recipe clips its own value (`overflow: hidden`): WebKit computes `overflow: visible` on a native select, so an unclipped option label becomes scrollable overflow of the page scroller. A grid track holding controls takes a minimum that yields to its container (`minmax(0, …)` or `repeat(auto-fit, minmax(min(100%, Npx), 1fr))`); a fixed px minimum rescued only by a viewport media query is review debt, because the viewport does not know how wide the content column is. The global webkit scrollbar recipe sizes both axes. Enforced by `tests/test_web_typography_static.py` (`test_select_control_clips_its_value`, `test_webkit_scrollbar_recipe_covers_both_axes`) and the `ui_browser` modules `tests/test_ui_settings_overflow_browser.py` (WebKit) and `tests/test_ui_settings_grid_tracks_browser.py` (Chromium).

### Chat surfaces

- **One owner intent has one control, built in one module** (DESIGN "References and actions"). `project_reference.js` builds the Project reference and alone raises `ouro:open-project`; callers choose a layout, never labels/classes. System/routing action rows use `ui_helpers.createSystemMessageActions`; Project entries own their shell in `project_handoff.js`, shared by conversion and replay. Each composition owns spacing and focus clearance. Primitive reuse alone does not prove intent parity: after changing control text run `python scripts/regenerate_inventories.py` and read neighbouring `docs/inventories/UI_CONTROL_TEXT_INVENTORY.md` rows; repeated intents get one door. Enforced by `web/tests/project_reference.test.js`, `tests/test_project_work_card_browser.py` and inventory byte identity; intent judgement is review-only (CHECKLISTS item 30).
- **Question lifecycle words live once** in `question_presentation.js` and their Python twin `project_dialogue.QUESTION_STATUS`; a new state lands on both sides in one commit with a row in `question_presentation_parity.json`. A Project question in Main is the Project's own form (`chat_decision.buildQuizCard`) plus the Project reference, never a second reduced form; a field the Project form gains reaches Main on the `project_question_pointer` row. The settle-then-remove countdown leaves through chat.js's one `releaseMessageNode` path inside the stable-viewport transaction (mechanism: ARCHITECTURE §3 "Main rows and host-stamped card rows"; semantics: DESIGN "Project question mirror"). Tests: `web/tests/question_mirrors.test.js`, `tests/test_ui_coherence_browser.py`.
- **The delivered-document reader** (`document_reader.js`; semantics: DESIGN "Document reading") reads only the delivered copy and answers a refused one with its cause, never from another address; Markdown goes through `mountChatMarkdown(…, { softBreaks: true })`, so sanitizing stays one implementation. Every close path aborts the read and a late answer paints nothing; its name, size line and text carry `data-i18n-authored`, so the language overlay leaves them alone. Enforced by `web/tests/document_reader.test.js` and `tests/test_ui_document_reader_browser.py`.
- **The Project completion mirror is an ordinary message, not a second renderer**: a `completion_answer` on the row goes through `addMessage` as an assistant message, and only `project_answer.js::decorateProjectRow` adds the fold class and the Project reference; the fold is CSS over the complete text. `tests/test_project_completion_mirror.py` pins the producer gate and live = durable = replay; `web/tests/chat_plain_system_rows.test.js` pins both renderings.
- **A list editor** reveals the entry it just added through `ui_helpers.revealNewRow(row, field)`, the one seam for "scrolled into view, caret in the first field", and a freshly added entry shows no error before the owner tries to save. A mark or switch patches its entry in place; open disclosures, keyed by the entry's stable UI key, survive repaint and reload (DESIGN §6). `tests/test_available_subagents_ui_static.py` pins the seam; `tests/test_ui_smoke_agents_panel.py` and `tests/test_subagent_card_quiet_browser.py` (pointer and keyboard apart: a WebKit click need not focus) pin behaviour.
- **Authorship:** follow DESIGN's chat-voice rule on backend and frontend alike (CHECKLISTS item 30). `tests/test_host_message_voice.py` pins the AST boundary; `tests/test_progress_narration_voice.py` pins live/history parity.
- **A host fact about a task is a row of that task's card**, never a standalone bubble beside it: the producer stamps the placement (`card_row` with `card_row_id`) and the browser attaches the row through one helper shared by live delivery and replay, falling back to a standalone System row only when the task has no card in the page (mechanism: ARCHITECTURE §3 "Main rows and host-stamped card rows"). A host fact that belongs in the card but carries no placement fact is review debt (CHECKLISTS item 30). A client-side list of row types is not the rule (DEVELOPMENT "Anti-pattern: an open default behind a closed exception list").
- **Task outcome truth** stays in `log_events.js::taskOutcomeSeverity` and `taskTerminalPhase`; `taskPresentation` is the one compact projection for chips, live completion, replay and child cards. Its host mirror is `project_dialogue.outcome_phase`, pinned to the browser by the shared fixture `web/tests/fixtures/outcome_phase_parity.json`: a new axis, reason or acceptance status lands on both sides in one commit, with a row there. The detail line comes from `taskReasonDetail` alone (precedence: ARCHITECTURE §3 "Task cards, errors and reason lines"). A non-terminal diagnostic never promotes the whole task, and an unknown event name never acquires Chat severity from keyword matching (BIBLE P5). Header liveness comes only from the `/api/state` census, never from a WS frame, because a typing frame is a submission receipt; a failed task status synthesizes no header attention, toast or unread state (ARCHITECTURE §3 "Liveness census and the chat header"; `web/tests/chat_header_census.test.js`).
- **Narration leads; routine execution evidence stays compact; exceptions keep their explanation and controls** (semantics: DESIGN "Conversation activity block"; mechanism: ARCHITECTURE §3 "Direct turns and the activity block"). A note is promoted on the typed `narration` fact its producer stamps, never on a client reading of its text; execution evidence is one bounded row per block, never a row per event; host snapshots of the same turn merge field-wise, because an absent field is unknown rather than zero. A change to the block is shown at a realistic multi-call burst, collapsed and expanded, before it is accepted. Enforced by `web/tests/chat_activity_block.test.js` and `tests/test_progress_narration_voice.py`.
- **Executor presentation and model-call provenance** consume the existing task and run-attempt facts (shape and producer: ARCHITECTURE §3 "Child cards and executor presentation"). Keep `executor_observation` event-local and never fill an absent live observation from a final-attempt model or progress prose; keep `execution_evidence` and `actual_substrate` terminal-only, with no new poller or execution-state store; `harness_presentation.js::executorIdentityMarkup` is the one label builder. The task's last usable solve response is shown separately from initial routing, executor observations and final-answer authorship, survives result storage, copy-back and history rendering, and no post-task or cost-only update erases it; fan-out counters describe emissions and wall-clock intervals, never inferred execution waves. Tests: `tests/test_executor_observation.py`, `tests/test_task_model_execution.py`, `web/tests/task_result_reconciliation.test.js`.
- **Chat viewport invariant.** Sample live-edge intent before an ordinary transcript mutation; native scroll anchoring is not proof that the owner's visible message stays stable, so focused regressions disable it. The stable-viewport seam (ARCHITECTURE §3 "Timeline ownership and ordering") decides when the transcript follows the bottom; otherwise preserve the visible keyed message, nested card or Reviews anchor, and route late DOM writes through that seam. Main and Project transcripts reserve their overlaid composer with one non-shrinking flex spacer, because bottom padding can fall outside native WKWebView's scrollable overflow; the keyboard-in-flow layout removes that item.
- **History pages and reconnect** merge into the existing keyed card and row owners (mechanism: ARCHITECTURE §3 "Timeline ownership and ordering" and "History reads and the SSE v2 transport"). Preserve the actual selected, focused and expanded nodes: rebuilding an equivalent node is not preservation. A historical frame never grants current activity or replaces newer terminal evidence. Pages count the room's own rows; `has_more` follows the conversation, and completeness follows delivered physical spans, never dates, shared IDs or EOF. Keep one wrapping Main/Project header note for uncertainty, errors and approximate positioning; navigation clears approximation. Initial loading and the beginning marker stay in the feed, without a duplicate header loading note. Tests: `web/tests/chat_history_integration.test.js`, `tests/test_history_room_pages.py`, `web/tests/chat_history_loading.test.js`.
- **The Project work pointer** (`project_work_pointer.js`; selection and label rules: ARCHITECTURE §3 "Project rooms") is a navigation component over the existing Chat card registry: its click changes only scroll position and reading intent, never message routing; without a represented root card it is hidden, not disabled; a represented unfinished card is not proof of current execution. Add no second card tree, poller or task-state store for it.

### Responsive and accessible behavior

Navigation, headers, controls and dialogs stay operable by pointer and keyboard, preserve focus order, and fit the relevant narrow viewport without stealing usable text space; use the shared responsive component before adding a page-specific layout. Vision evidence follows CHECKLISTS item 11(i); engines and viewports follow risk. Containment is the WebKit-sensitive exception (a native select is not clipped there), so a change to a control recipe or a page scroll body is verified on the engine that shows the class: Playwright WebKit for native-control clipping, Chromium for engine-independent track geometry, measuring overflow on the scroll body's `scrollWidth` rather than on `documentElement`. Review-only: scored by CHECKLISTS items 11(i) and 30 (`web_design_system`).

### Browser dialogs

`window.prompt`, `window.confirm` and `window.alert` are forbidden in `web/modules`; use `confirm_dialog.js::openConfirmDialog` (why, and its mode contract: ARCHITECTURE §3 "Navigation and shared UI contracts"). A critical action tests the exact confirmed result and keeps the confirmation plus its side effect in one injectable flow. `tests/test_web_dialogs_static.py` keeps the native-dialog class closed.

`ui_interactions.js` owns focus, menus, popup geometry and message-field keys. Callers mount `.ui-popup` outside clipping, keep domain result/cancel contracts, dispose before removal and close menus before opening dialogs. Message fields bind `bindEnterSubmit` to their Send button: no second submit path or global textarea handler, and field-local listeners die with their nodes (DESIGN §3). `web/tests/ui_interactions.test.js` pins keys, focus, geometry and cleanup; `tests/test_ui_quiz_comment_only_browser.py` drives the real fields.

### Declarative widgets

A module handler that calls `OuroborosWidget.openExternal(url)` or `window.open(url)` from an anchor click also calls `event.preventDefault()`, invoking the helper during the gesture, before awaiting other work; automatic relaying respects an already-handled click.

`web/modules/widgets.js` is the host for reviewed widget declarations — forms/actions, text/data/media, tabs/charts, async jobs, files, map/calendar/kanban, and composition through `group`, `metric` and `callout` (author schema and limits: `docs/CREATING_SKILLS.md`; render modes, frame CSP and bridge: ARCHITECTURE §3 "Widgets page", "Declarative widgets" and "Module widget bridge"). The rules a host editor must keep: nested interactive components use stable identity and one disposer, and `subscription.render` is transitively passive; data updates patch the existing nodes at the mount's identity seam, and passwords stay only in their mounted control, never in the retained form-value snapshot; forms, actions and jobs own their pending/result/error feedback by component id; text and attributes are escaped for their actual sink, media is constrained to extension routes or safe data URLs, and charts stay readable through a semantic table; `kind: "module"` UI runs only in the sandboxed opaque-origin iframe, never in the SPA origin; a failed list read exposes a contextual Retry through the keyed list reconciliation, never a global refresh or remount; every timer, listener, observer, stream, chart and mounted widget has a paired disposer.

Enforcement: `tests/test_widgets_ui_static.py` at commit tier; in the release-tier `ui_browser` lane `tests/test_widgets_ui_browser.py`, `tests/test_widgets_ui_browser_lifecycle.py`, `tests/test_widgets_ui_browser_patch.py`, `tests/test_widgets_ui_browser_widths.py` and `tests/test_widgets_ui_browser_capabilities.py`, all five before a release that touched Widgets; `tests/test_widgets_ui_browser_identity.py` additionally pins retained interactive nodes, password lifetime, local action feedback and non-destructive list Retry through real declarative consumers.

### Optional author controls

`ouroboros.server_web.read_author_kit_assets(request.app.state.repo_dir)` reads the fixed installed `web/ui.css` and `web/modules/ui_primitives.js` for an author-owned page (what the kit is and is not: ARCHITECTURE §3 "Author UI kit"). Resolve at the page or kit GET that serves a new mount, not at extension registration; the helper gets no bundle cache, new endpoint or auth exception. `docs/examples/author_ui_kit/` holds the two ordinary extension recipes; the kit stays optional and author-overridable, with no theme poller or forced remount. `tests/test_author_ui_kit.py` and `tests/test_author_ui_kit_browser.py` cover source-root delivery and real framed consumers, not an arbitrary author's CSP or application.
