# Design System

This chapter keeps `docs/DESIGN.md` semantics in code; each rule names its test or review item.

`web/index.html` and `web/onboarding_template.html` load `web/ui.css` before page sheets (ARCHITECTURE §3 "Navigation and shared UI contracts"); docs keep roles and guardrails, not values.

### Tokens and primitives

- **Compose from shared parts; change the part, not the screen.** `web/ui.css` (listing every part in its register, tested both ways) and `ui_primitives.js` own shared decisions; page sheets compose them. A look two screens need changes once, in its part; shared-part edits or replies to owner remarks name every consumer that composes it (frames under CHECKLISTS 11(i)); screen-local copies or page-ancestor overrides of shared classes are review debt (CHECKLISTS item 26). Under `.ouro-ui` the control box is locked (`!important`), so pages size controls only via a `--control-*` token on a scope (listed in the lock's comment), never by writing box or text size.
- **`ui_primitives.js`** is the leaf safe-field, tone/status and result source (no shell, network or document-global init, so first-party and author consumers share it); `ui_helpers.js` and `utils.js` re-export it (`web/tests/ui_primitives.test.js`).
- **Typography** pairs a `--type-*` size with a named foreground token so text never inherits near-white primary ink (`tests/test_web_typography_static.py` reads every first-party sheet: no raw size under 12 px, no all-caps label).
- **Variable contract** (same test): every `var(--x)` resolves in its document's sheets and every `:root` token has a reader, else literals and silent fallbacks replace shared values; never shadow shared palette names; fix a dangling name with an existing token.
- **Appearance is client-local.** `web/theme.js` owns the choice and radiogroup outside the settings writer; theme-sensitive images, warning selections and host charts use semantic tokens, never raw hues, and theme subscriptions have owners and disposers (ARCHITECTURE §3 "Navigation and shared UI contracts"). Every `webview.start` requests persistent storage (verify rebuilt launchers by quit/relaunch). Native chrome follows page declarations (`launcher_appearance.py`, `launcher_window_chrome.py`: no second store, frameless window, page-colour caption or unmeasured spacer); pre-asset pages inline `theme.js`/`ui.css` (`standalone_page.py`). Tests: `theme.test.js`, `test_appearance_scope.py`, `test_appearance_static.py`, `test_launcher_appearance.py`, `test_theme_browser.py`, `test_theme_before_interface_browser.py`, `window_chrome` tests.
- **One button, three tones; one result slot.** Neutral controls use `.btn.btn-default`. Place action results in `.ui-result` after their control in `.ui-action-row` (`setResult` writes/ends per DESIGN §4; `clearResultOnEdit` clears on subject edits; `errorWords` formats typed failures with raw text under Details; else shared toast host), keeping working/warning/error/destructive meanings consistent across surfaces (`web/tests/ui_primitives.test.js`; toast/meaning parity is review-only: CHECKLISTS 26).

### Layout and containment

- **Layout and controls.** `renderPageHeader` draws top-layer Back (jumps batch returns after leave guards); bodies scroll and actions (Refresh included) use `actionsHtml`. Shared tabs (`renderTabStrip` + `bindTabStrip`, `page_header.js`) own selection, ARIA and focus (dispose with page) while callbacks own loading/panels. Segmented single-selects (`renderSegmentedField`, row `strip`) are markup-only, word-wide, with focus as the only non-hover ring (`web/tests/segmented_field.test.js`, `tests/test_segmented_layout_browser.py` in Chromium/WebKit). Navigation scrollers follow DESIGN §10; bodies fade, not shells, and folds use `data-fold-clipped` (DESIGN principle 9). Pack masonry via `masonry.js::applyMasonry` writing only `--masonry-*` custom properties (avoiding grid row gaps) without moving `<article>` nodes, because moving reloads `<iframe>` (ARCHITECTURE §3 "Widgets page"). New visual dimensions use CSS variables consumed by shared classes; new `style=""` or `.style.<property>` writes are review debt except a measured value in a narrowly named custom property.
- **Containment.** Controls never widen columns; wide content (code, tables, tabs) scrolls in its own `overflow-x: auto` wrapper, never the page body (because `overflow-y: auto` alone computes `overflow-x` to `auto`). Shared `select.ui-control` clips values to prevent WebKit overflow. Tracks yield to containers (`minmax(0, …)` or `repeat(auto-fit, minmax(min(100%, Npx), 1fr))`); viewport-rescued minima or action tracks squeezing primary text are review debt — wrap by container width and inspect long content at intermediate widths, since zero overflow does not prove readability. Global webkit scrollbars size both axes (`tests/test_web_typography_static.py`, `tests/test_ui_settings_overflow_browser.py`, `tests/test_ui_settings_grid_tracks_browser.py`; reading quality remains visual judgment).
- **`:has()` stays in the subject compound**, with no combinator inside its `:is()`/`:where()`/`:not()` arguments and no `:empty`, `:focus` or `:focus-within`, because other forms trigger full-document WebKit re-checks or miss dynamic updates (`tests/test_design_system_css_static.py`).

### Chat surfaces

- **One owner intent, one control, one module** (DESIGN "References and actions"). Only `project_reference.js` builds Project references and raises `ouro:open-project` (callers set layout, never label/class). The reference sits under System rows and mirrored answers (`ui_helpers.createSystemMessageActions`), ends the owner's receipt line (`routing_receipt.js`) and leads a portal's action row (`work_portal.js`); each composition owns spacing/focus clearance without global button margins. After control-text edits, run `scripts/regenerate_inventories.py` and read adjacent `UI_CONTROL_TEXT_INVENTORY.md` rows: reused primitives prove no agreement, so a repeated intent gets one door first (`web/tests/project_reference.test.js`, inventory byte identity; "same intent" is review-only: CHECKLISTS item 26).
- **Main decisions** (DESIGN "Project question mirror"): each `project_question_pointer` mounts one `chat_decision.buildQuizCard` copy plus Project reference at ask time (never a reduced form); `current_questions` census only confirms/settles copies, and `main_waiting.js` owns the amber pill and owner-wait System rows. Answer, close and dismiss share one ingress; lifecycle words live once in `question_presentation.js` and `project_dialogue.QUESTION_STATUS`, landing together with `question_presentation_parity.json` in one commit. Settled cards leave via `releaseMessageNode` in the stable-viewport transaction (ARCHITECTURE §3 "Main rows and host-stamped card rows"). Waits follow owner-stamped `requires_owner_action`, Resume reads `work_stop.current_stop/stop_presentation`, technical refusals stay on `continuation_refusal`, and automatic waits stay quiet (`test_main_decisions`, `test_main_question_lifecycle`, `web/tests/main_decisions.test.js`, `web/tests/question_mirrors.test.js`, Chromium/WebKit journeys).
- **Chat reader** (`document_reader.js`; DESIGN "Document reading") uses inline/artifact bytes, current owner-upload bytes (no rehash) or tile image sources. Text errors explain known refusals; URL image errors offer Retry even on 404 (hiding HTTP reasons). Render Markdown via `mountChatMarkdown(…, { softBreaks: true })`; Close aborts reads/loads against late paint; name/size/text carry `data-i18n-authored` (`web/tests/document_reader.test.js`, `tests/test_ui_document_reader_browser.py`).
- **Project outcomes** keep managed/transferred-direct mirror eligibility while Project-native replies and quiet runs stay local. `completion_answer` is an assistant `addMessage`; only `project_answer.js::decorateProjectRow` adds the CSS fold, Project reference and nonclean `completion_reason`. Full answers/documents open in Project, not Main expansion/Files (task-card Files and quiz readers stay; availability never claims delivery). Publication addresses precede exposure and survive conversion; strict append precedes ACK; canonical receipts outlive bounded retry caches (`tests/test_project_completion_mirror.py`, `tests/test_quiz_delivery_recovery.py`, `tests/test_main_terminal_delivery.py`, `web/tests/chat_plain_system_rows.test.js`, Main→Project journeys).
- **List editors** reveal new entries or Remove's successor via `ui_helpers.revealNewRow(row, field)` (caret in first field), defer errors to Save, and patch marks/switches/disclosures in place. Settings redraws saved rosters without moving focus or reading place, and keyed disclosures survive repaint/reload (DESIGN §§6, 10; `test_available_subagents_ui_static`, `test_ui_smoke_agents_panel`, `test_subagent_card_quiet_browser`, `test_account_resources_browser` — measure before and after a deep press held through a poll, no hover or auto-scroll; WebKit clicks need not focus).
- **Authorship:** enforce DESIGN's chat-voice rule on backend and frontend (CHECKLISTS item 26; AST boundary `tests/test_host_message_voice.py`, live/history parity `tests/test_progress_narration_voice.py`).
- **Host task facts belong inside that task's card**, never as standalone bubbles: producers stamp `card_row` / `card_row_id` and one shared live/replay helper attaches them, falling back to a standalone System row only when no card exists. Unplaced host facts are review debt (CHECKLISTS item 26); never use client row-type lists (DEVELOPMENT "Anti-pattern: an open default behind a closed exception list").
- **Task outcome truth** lives in `log_events.js::taskOutcomeSeverity` and `taskTerminalPhase`, with `taskPresentation` projecting chips/completion/replay/child cards and `project_dialogue.outcome_phase` pinned via `web/tests/fixtures/outcome_phase_parity.json` (new axes/reasons/statuses land on both sides with a parity row in one commit). Detail lines come only from `taskReasonDetail` (ARCHITECTURE §3 "Task cards, errors and reason lines"); non-terminal diagnostics never promote tasks and unknown events never infer Chat severity by keywords (BIBLE P5). Header liveness reads only `/api/state`'s work projection, never a WS frame (a typing frame is a submission receipt), and failed tasks synthesize no header attention, toast or unread state (ARCHITECTURE §3 "Liveness census and the chat header"; `web/tests/chat_header_census.test.js`).
- **Narration leads; routine evidence stays compact; exceptions keep explanations and controls** (DESIGN "Conversation activity block"; ARCHITECTURE §3 "Direct turns and the activity block"). Promote notes only on producer-stamped `narration` (never text heuristics), keep one bounded evidence row per block, merge turn snapshots field-wise (absent = unknown, not zero), and show multi-call bursts collapsed/expanded before acceptance (`web/tests/chat_activity_block.test.js`, `tests/test_progress_narration_voice.py`).
- **Executor presentation and model-call provenance** consume existing task/attempt facts (ARCHITECTURE §3 "Child cards and executor presentation"): keep `executor_observation` event-local (never backfilled from final models or prose), `execution_evidence`/`actual_substrate` terminal-only with no new poller/store, and `harness_presentation.js::executorIdentityMarkup` as the sole label builder. Separate the last usable solve response from routing, observations and final authorship across result storage, copy-back, history rendering and every post-task or cost-only update; fan-out counters measure emissions/intervals, never inferred waves (`tests/test_executor_observation.py`, `tests/test_task_model_execution.py`, `web/tests/task_result_reconciliation.test.js`).
- **Chat viewport invariant.** Sample live-edge intent before transcript mutations (disable native scroll anchoring in regressions, since it proves nothing about the visible message). The stable-viewport seam (ARCHITECTURE §3 "Timeline ownership and ordering") governs bottom-following vs. preserving the visible keyed message/card/Reviews anchor and owns late DOM writes; read layout only before the first write or via `layout_batch.measure` afterward, never between rows, skipping irrelevant reads (`tests/test_chat_history_paging_browser.py`). Main and Project transcripts reserve the overlaid composer with one non-shrinking flex spacer (WKWebView can drop bottom padding from scrollable overflow); keyboard-in-flow removes it.
- **History pages and reconnect** merge into existing keyed card/row owners (ARCHITECTURE §3 "History reads and the SSE v2 transport"), preserving actual selected, focused and expanded nodes (never rebuilding equivalents); history frames never grant activity or overwrite newer terminals. Pages count the room's own rows, `has_more` follows the conversation, completeness follows delivered physical spans (never dates/IDs/EOF), and edges follow DESIGN "History edges" (`web/tests/chat_history_integration.test.js`, `tests/test_history_room_pages.py`, `web/tests/chat_history_loading.test.js`).
- **Room work status** (`room_work.js`, `work_status.js`; DESIGN "Room work status") paints the server room's word/mark, one row per work, pending sends and unconfirmed cards using `task_phase_chip.js`, `work_status.openWorkControls`, `chat_decision.revealQuestion` and the reading owner — deriving no status/control/routing, adding no card tree/poller/store/ranking, and borrowing no bar or room-ink paint (`tests/test_floating_material_static.py`, `tests/test_work_list_panel_browser.py`).

### Responsive and accessible behavior

Keep navigation, headers, controls and dialogs pointer/keyboard operable with preserved focus order, fitting the relevant narrow viewport without stealing usable text space, preferring shared responsive components. Verify on the risk-matching engine — Playwright WebKit for native-control clipping, Chromium for track geometry (both checking scroll-body `scrollWidth`, not `documentElement`), system WKWebView for style cost; vision review follows CHECKLISTS items 11(i) and 26 (`web_design_system`).

### Browser dialogs

Forbid `window.prompt`, `window.confirm` and `window.alert` in `web/modules` (`tests/test_web_dialogs_static.py`); use `confirm_dialog.js::openConfirmDialog` (why/contract: ARCHITECTURE §3 "Navigation and shared UI contracts"), critical actions testing the exact confirmed result, with confirmation and side effect in one injectable flow.

`ui_interactions.js` owns focus, menus, popup geometry and message-field keys: mount `.ui-popup` outside clipping, preserve result/cancel contracts, dispose before removal and close menus before opening dialogs. Bind message fields via `bindEnterSubmit` to their Send button with no second submit path or global textarea handler, so field-local listeners die with their nodes (DESIGN §3; keys, focus, geometry and cleanup: `web/tests/ui_interactions.test.js`; real fields: `tests/test_ui_quiz_comment_only_browser.py`).

### Declarative widgets

Anchor-click handlers calling `OuroborosWidget.openExternal(url)` or `window.open(url)` must also call `event.preventDefault()`, invoking the helper during the gesture before awaiting other work; auto-relay respects handled clicks.

`widgets.js` hosts CREATING_SKILLS declarations (render modes/CSP/bridge: ARCHITECTURE §3). Keep stable identity, one disposer per nested interactive component (and every timer/listener/observer/stream/chart/mount), passive `subscription.render`, in-place data updates, passwords inside mounted controls, and component-owned pending/result/error states. Escape text/attributes for sinks, restrict media to own extension routes, safe data URLs or own leased files, give charts semantic tables, and preserve failed-read cards with contextual Retry (no global remount).

Keep module frames opaque and classic unless `entry_type: module` opts in. Native ESM/resources use declared, captured, review-bound files with lease controls outside bridge reach, preserve publication identity through board/chat reconciliation, bounded expiry and ordered disposal, and verify relative imports/resources over a password-gated non-loopback path (bundled/loopback fixtures cannot prove it).

Enforcement: `tests/test_widgets_ui_static.py`; full browser lane `tests/test_widgets_ui_browser*.py` before releases touching Widgets.

### Optional author controls

Read installed `web/ui.css` and `web/modules/ui_primitives.js` via `ouroboros.server_web.read_author_kit_assets(request.app.state.repo_dir)` per page/kit GET (never at registration), with no bundle cache, new endpoint or auth exception. Keep the kit optional and author-overridable without theme polling or forced remount (recipes: `docs/examples/author_ui_kit/`; ARCHITECTURE §3 "Author UI kit"; `tests/test_author_ui_kit.py` and `tests/test_author_ui_kit_browser.py` cover source-root delivery and real framed consumers, not an arbitrary author's CSP or application).
