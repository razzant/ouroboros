# MCP Client Integration

MCP is a client boundary: remote data is not policy; only the owner selects Settings references. Referenced values reach process environments with their secret classification preserved in diagnostics.

The optional client serves trusted HTTP/SSE and local stdio servers (structure, transport validation, the stdio `command`/`args`/`cwd`/`env`/`env_from_settings` contract, identity, catalog lookup, the capability envelope and its visible omissions, and masking: ARCHITECTURE §6 "MCP and browser-facing external tools"; `ouroboros/mcp_client.py`). Its tools keep Safety and caller ceilings; grants authorize no new Settings references. Task-browser changes retain protocol, ready-skill, invocation and teardown consumers in `docs/browser-task-bridge.md`. Executable schema properties, required fields, enums, defaults and wire tool names stay unchanged; resources, prompts and MCP server behaviour are separate architecture changes. Header values are masked Settings literals sent only to their origin, not text filters: an echo stays visible, unlike the legacy token's; import is one-way and draft-only: no connection, OAuth, helper or sync. Prove headers, redirects and logs through real SDK transports against synthetic loopback servers. Enforcement: `tests/test_mcp_*.py`, `web/tests/mcp_header_fields.test.js`.

`start_service` overlays literal `env` on its minimal host baseline; commands, scripts and run-kind verification keep their inherited environment. Resolve Settings references (`env_from_settings`) once after admission through `workspace_executor.resolve_process_env` (mechanism: ARCHITECTURE §6 "Safety and runtime mode"), behind the host-owned `ouroboros/tools/process_facts.py::settings_environment_allowed` authority, which admits root and Cyber acting tasks, not Presence; configured MCP access and skill grants neither expand it nor authorize an unrelated service. A referenced field keeps its secret or ordinary classification: a secret is masked in service diagnostics and finalized log blobs and never enters host argv, generated shell source or the durable process ledger; Docker forwards it through inert CLI environment aliases. Enforcement: `tests/test_process_environment.py`, `tests/test_workspace_executor_services.py`.
