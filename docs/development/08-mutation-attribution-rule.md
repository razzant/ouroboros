# Mutation Attribution Rule

Attribution is evidence, not exclusive ownership or proof of individual authorship. Ambiguity stops automatic staging; a body candidate's explicit selection may carry it into review. Known foreign work stays excluded.

- `mutation_attribution.py` records root-start baselines (empty tree for unborn Git repos) and terminal changes in task results; pre-existing dirt, missing/stale baselines, and failed scans are evidence, not vetoes. Add no second ledger, ownership service, or command-word scanner.
- Result review reads mutation evidence from the canonical results root (`budget_drive_root` first) shared by writer and outcome consumer.
- Automatic staging takes clean-at-baseline and explicitly adopted paths; explicit literal selection may include disclosed uncertainty (empty never means `git add -A`). Refuse already-staged paths outside the selection without mutation, and on exit unstage only this call's paths; whole-tree staging is restricted to typed managed update/release, external capture, or baseline-free omitted paths.
- In-place predecessor adoption requires validated admission, terminal quiescence, same repo, exact bytes/mode, and unchanged per-path base, keeping original dirt (size-only/unknown fingerprints prove no transfer) and granting no review approval, task reset, or wallet reset.
- A candidate carries its original basis/exclusions, the previous owner's established basis or genuine clean creation—never today's files—preserving superseded late captures while other dirt stays uncertain. Explicit selection may include uncertainty or an overlapping moved base without re-anchoring, carried through review, handback, and baseline history (`test_candidate_attribution_continuity.py`).
- Process tools (including run-kind verification) resolve bare Python pre-guard and bare Node post-dispatch—so refused calls never probe PATH shims—leaving explicit/versioned, shell, and remote argv unchanged; `process_interpreters.py` never installs on import failure and runs unusable Node unchanged to fail honestly (docstring).
- Freshness is checkout-scoped: `invalidate_advisory_after_mutation(mutating_task_id=…)` records the editor in that checkout's own marker, disclosed to all task readers (missing identity stays unknown).
- Skill Review provenance stays in `review_job.json`/skill ledger (briefs carry job/group ids); allocate ordinals under the lifecycle lock, consume only at actual start, and derive historical ones from retained ledger/legacy rows without rewriting them.

Enforcement: `tests/test_mutation_attribution.py`.
