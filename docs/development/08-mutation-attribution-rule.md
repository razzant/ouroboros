# Mutation Attribution Rule

Attribution is evidence, not exclusive ownership or proof of individual authorship. Ambiguity stops automatic staging; a body candidate's explicit selection may carry it into review. Known foreign work stays excluded.

- `mutation_attribution.py` records root-start baselines (an unborn Git folder's at the empty tree) and terminal changes in task results. Pre-existing dirt, missing/stale baselines and failed scans are evidence, not outcome vetoes. Add no second ledger, ownership service or command-word scanner.
- The result review reads mutation evidence from the canonical results root (`budget_drive_root` first), the same root the writer and the outcome consumer use.
- Automatic staging selects clean-at-baseline and explicitly adopted paths; explicit selection may also name a candidate's disclosed uncertainty. Names are literal and empty never means `git add -A`. Refuse already-staged paths outside the selection without mutation; exits unstage only the call's composition. Whole-tree staging is for typed managed update/release, external capture or baseline-free omitted paths.
- In-place predecessor adoption needs validated admission, terminal quiescence, the same repository, exact bytes/mode and unchanged per-path base. Keep original dirt; size-only/unknown fingerprints prove no transfer. Adoption grants no review approval, task or wallet reset.
- A candidate carries its original basis/exclusions, the previous owner's established basis or genuine clean creation, never today's files. Preserve superseded late captures; other observed dirt remains uncertain. Explicit selection can include uncertainty or an overlapping moved base without re-anchoring. Carry those facts through review, author handback and baseline history. Tests: `test_candidate_attribution_continuity.py`.
- Process tools, including run-kind verification, resolve bare Python before the shell guard and bare Node after dispatch, so refused calls cannot probe PATH shims. Explicit/versioned, shell and remote argv stay unchanged. `process_interpreters.py` never installs on import failure; unusable Node runs the original argv and fails honestly.
- Freshness is checkout-scoped: `invalidate_advisory_after_mutation(mutating_task_id=…)` records the editor in that checkout's own marker; readers of any task disclose it, and a missing identity stays unknown.
- Skill Review provenance stays in `review_job.json`/the skill ledger; briefs keep job/group ids. Allocate ordinals under the lifecycle lock, consume only at actual start, derive historical ordinals from retained ledger/legacy rows without rewriting them.

Enforcement: `tests/test_mutation_attribution.py`.
