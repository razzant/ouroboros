# Process Custody Rule

Every long-lived child process passes one spawn chokepoint and carries a custody scope; one seam kills a worker tree; the daemon stop and the failed-start latch keep the rules below. An unledgered process survives the death of its owner invisibly, and a command-line-class match would let one instance reap another's children, so custody is by ledger identity, never by what a command line looks like.

**Spawn chokepoint.** Long-lived OS processes (a `Popen` or `mp.Process` without a bounded wait in the same call) are spawned through `ouroboros.process_custody.spawn_supervised(cmd, drive_root=..., purpose=..., scope=...)` or, when an existing manager owns the Popen call, registered with `record_process(...)` write-through immediately after spawn. Scopes are `task`, `session` and `daemon`; an installation-owned daemon uses `daemon` scope and is never killed by a server-generation change alone. Never add command-line-class matching to the reaper. A worker's process tree is killed only through `supervisor.worker_pool_lifecycle.kill_worker_tree`, which spares the ledger's live `daemon`-scope roots (`process_custody.live_daemon_root_pids`) and, for one task's cancel or timeout only, the kept services; a direct `kill_pid_tree` on a worker elsewhere in `supervisor/` is a defect. Ledger, reaper fingerprint and the skill-companion exception: ARCHITECTURE §1 "Runtime topology". Enforcement: `tests/test_process_custody.py` (the chokepoint, with an explicit allowlist for bounded synchronous helpers).

**Daemon stop.** `OwnedClaudexorDaemon.stop_outcome` (Panic and Restart) separates authenticated cooperative shutdown from forced signalling; protocol: ARCHITECTURE §9. A change keeps these rules: read-only resolution never ensures or installs a runtime, starts a daemon, probes accounts or inherits another home's socket override; operator commands select the existing exact Node with `resolve_cli_command(require_npm=False)`, so an ordinary stop works on Windows and on bundled-only installs; an RPC acknowledgement or a lease release alone never proves physical exit; a matching error-code string alone gives no right to signal; the manager lock stays bounded, with preparation, network and exit waits outside it; the bounds are `config.CLAUDEXOR_OPERATOR_STOP_TIMEOUT_SEC` and `config.CLAUDEXOR_STOP_EXIT_WAIT_SEC`, defined once in `runtime_limits`.

**Failed start.** A failed owned-daemon start latches on the typed exit fact only (`ExitFact.failed_without_control`); `claudexor_startup_failure.py` classifies the child's own log interval for the diagnostic label and the one supervisor row, never for behaviour (BIBLE P5). Harvest the exit fact at every spawn decision, at attach and at stop (`_settle_exited_child`), never only on a caller's wait expiry, and take the latch under the same lock as the reap. Do not add a backoff machine, retry counter, cooldown constant, host-side heap sizing, writer-lease handling or a third retrier: the periodic sweep, the owner's explicit Refresh, a live attach or a new manager are the only releases, and `NODE_OPTIONS` passthrough is the operator escape hatch. Settling a non-review run leaves registration custody to the sweep, which retains it while the owner line is open or any root of the recorded Continue chain still has an offer, and when liveness or the result is unknown (`delegate_continuation.still_continuable`); review settlement and persistent projects keep their own lifetime. The sweep's project retirement (`delegate_custody._retire_project_locked`) discharges a `PROJECT_RETIRE_FAILED` refusal as `PROJECT_RETIRED {project_kept: true}` only on the typed code `project_has_threads`, never its prose, and only after a second complete replay under the retirement lock shows no unsettled run of the project; anything else stays retryable, with no counter, backoff, new store or second lock. Classes, rows and releases: ARCHITECTURE §9.

**Lifetime across platforms.** Ordinary close preserves the shared daemon on every platform, forced worker/server/stray cleanup included; exclusions protect the whole subtree, not merely a ledger row. Do not extend this lifetime to all skill companions or broaden reserved-port/service ancestry rules. Windows birth, command, Job and prior-generation stop claims require native Windows evidence (psutil is a Windows-only main dependency; embedded and frozen imports need packaging proof); a portable fixture does not establish them. Platform-lock, ABI and fingerprint rationale: ARCHITECTURE §1 "Platform substrate".

**Restart.** Explicit stop and next-start selection are separate: a new engine pin is never hot-swapped. A planned restart ends the serving daemon only for a changed engine pin, through `server_restart._stop_owned_daemon_for_new_pin` after worker custody and before optional cleanup, never as a veto (`tests/test_planned_restart_engine_pin.py`); service quiescence checks every member before releasing a writer fence (`tests/test_process_custody_liveness.py`). The owner's manual Restart keeps its checkout-first order: the update gate and `safe_restart` refuse before anything stops, and `server_restart._stop_owned_work` runs only after the durable no-resume flags; reuse `request_cancel`, `kill_workers(reconcile_delegate_custody=False)`, `reconcile_orphaned_runs` over `read_owned_gateway` and `OwnedClaudexorDaemon.stop_outcome`; never call `ensure_owned_gateway` between the cancel intents and the daemon stop, and never read the manager's private error state to tell "nothing to stop" from "unconfirmed". Past the gate an unconfirmed step is a critical diagnostic with custody retained, never a deferral or a veto — no new state, drain, lease or event kind for it; the next generation's startup sweep is the recovery (`tests/test_manual_restart_execution.py`).

Out-of-process extension HTTP responses run in the child: the runner owns staging, Popen registration and cleanup, `extension_route_stream` owns pipe frames and ASGI delivery; spawn, registration, pipe shutdown and termination stay off the ASGI event loop, cancellation binds to the loaded bundle before spawn, and no total or pre-header response deadline applies (ARCHITECTURE §3 "Out-of-process extension responses", `ouroboros/extension_route_stream.py`).
