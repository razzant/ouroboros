# Process Custody Rule

Every process has an owner (task, generation, delegated run, test or installation). End it or transfer custody. Identity: ledger, `OURO_{INSTALL,TASK,LAUNCH}_SCOPE_<hex>=1`, recorded group or measured parent chain, never command line. Terminal paths settle, never provision/spawn/admit. Failed reads/signals mean unverified; retire only on recorded settled/no-census outcomes (`test_task_scope_lifetime.py`, `test_exit_does_not_admit.py`, `test_launch_stop.py`).

**Delegated invocation order** uses durable append ordinals, never clocks or run IDs (ARCHITECTURE §6 "Nanny, transport and custody"). Unprovable legacy facts stay `legacy_gap`; bookkeeping never replays events, rebuilds require a quiescent root, and `invocation_record(rows=...)` is the independent oracle (`test_custody_invocation_record.py`, `test_custody_fold_equivalence.py`).

**Owned stop** retires stale identity as `not_ours` only on measured birth/command mismatch, never on an unavailable measurement, EPERM or deadlines alone (ARCHITECTURE §9). `test_owned_stop_identity.py` covers a foreign leader without signal/wait, live matches, unreadable identity, failed evidence writes and racing PID re-registration; leaderless group evidence and Panic census stay.

**Spawn chokepoint.** Unbounded `Popen`/`mp.Process` use `process_custody.spawn_supervised`; managers call `record_process` immediately. Spawners overlay `lifeline_parent_env()` last onto child env so `start_parent_lifeline` excludes grandparent identity (`test_pid1_parent_lifeline.py`). Conversation carriers spawn as workers; pid-less inline slots are never ledgered/respawned. Worker kills use `worker_pool_lifecycle.kill_worker_tree`, sparing `live_daemon_root_pids`; cancel/timeout and idle retirement also keep retained services; other supervisor `kill_pid_tree` calls are defects (exceptions: ARCHITECTURE §1). `test_process_custody.py` flags raw/contained births lacking a stopper per door (blind to sibling starts, callers, library children). Tracked producers use `tracked_start` → `contained_popen` → `retire_tracked` (`test_tracked_command_publication.py`), keeping live/unknown trees after root exit; root receipts settle separately and task-group records transfer no OS handle.

**Daemon stop.** `OwnedClaudexorDaemon.stop_outcome` (Quit, Panic, Restart Claudexor, pin changes) separates authenticated cooperative shutdown from forced signals. Read-only resolution never provisions daemons, probes accounts or inherits another home's socket override; stop uses existing Node (`resolve_cli_command(require_npm=False)`, Windows/bundled too). Neither RPC ack nor lease release proves exit, and error codes grant no signal. Keep preparation, network and exit waits outside the manager lock (bounds: `CLAUDEXOR_OPERATOR_STOP_TIMEOUT_SEC`, `CLAUDEXOR_STOP_EXIT_WAIT_SEC` in `runtime_limits`).

**Failed start.** Only `ExitFact.failed_without_control` latches daemon spawning; `claudexor_startup_failure.py` diagnoses logs without setting policy. Harvest under reap lock at spawn/attach/stop (`_settle_exited_child`); sweep, Refresh, Restart Claudexor, live attach or a new manager releases the latch (no backoff/counter/cooldown, host heap sizing, writer-lease policy or third retrier; keep `NODE_OPTIONS`). Serialize legacy lookup/create; confirm raced ids. Order preparation holds, `START_REQUESTED` and creator `START_FAILED` by address (workspace holds per engine route), not imports. Persist exact ownership separately from workspace use (ARCHITECTURE §10.18). Settled `project_has_threads` discharges as kept; other outcomes stay retryable. Review and persistent lifetimes stay separate. Body collection owns jobs through exit without delaying Panic (ARCHITECTURE §6/§9).

**Platforms.** Forced worker/server/stray cleanup spares the shared daemon subtree; skill-companion reserved-port/service ancestry stays scoped (another port grants no kill authority) and recorded servers re-prove birth/command before signalling. Windows birth, command, Job, restart-handle and prior-generation stops require native evidence, not portable fixtures (psutil: Windows-only; frozen imports: packaging proof; ARCHITECTURE §1 "Platform substrate").

**Restart and Panic.** Separate stop from next-start; never hot-swap pins. `_stop_owned_daemon_for_new_pin` stops off-pin daemons unless newer, after worker custody and before optional cleanup, without veto (`test_planned_restart_engine_pin.py`); verify all members before releasing writer fences (`test_process_custody_liveness.py`). Manual Restart runs update/`safe_restart` before transaction/`_stop_owned_work`, reusing `request_cancel`, `kill_workers(reconcile_delegate_custody=False)` and `reconcile_orphaned_runs` over `read_owned_gateway` without ensuring gateways, inferring outcomes from private manager errors or adding state/drain/lease/event kinds; unknown cleanup keeps custody/critical diagnostics for the startup sweep, never defers/vetoes Restart (`test_manual_restart_execution.py`). Panic is irrevocable: failed ingress spawning runs its executor synchronously, manager/diagnostic faults spare other requests, and bounded writes precede exit (`test_server_control_panic_daemon.py`). `test_planned_delegate_assignment.py` covers all four continuations, saved-work/queue successor binding, and undispatched owner-wait/planned carriers keeping gates without interprocess once claims.

Agent Restart holds independent starts (not owner turns), requires ACK, saves drain input or refuses, lets work/control/committed handoffs continue, starts drain at finalization, and releases only known failures/refusals while retrying unknown preparation (`test_agent_restart_intent.py`).

Extension HTTP runs out-of-process: the runner owns staging/registration/cleanup, `extension_route_stream` owns pipe frames and ASGI delivery while spawn, registration, pipe shutdown and termination stay off the ASGI loop, cancellation binds to the loaded bundle before spawn, and no total/pre-header deadline applies (ARCHITECTURE §3).

**Tests.** Use `ProcessContainer(lifeline=True, overload=True)` (POSIX pipe guardian survives owner death; Windows kill-on-close Job), releasing only on a clean first `reap` including guardian. `config.TEST_*`/`test_parallelism.py` own budgets (nested runs default to 1 slot; shared memory reader/reserve: ARCHITECTURE §5/§7). `overload_stop` names its largest member and fails past the floor under reserve/macOS pressure, disclosing unreadable samples; without an OS quota it sums RSS and polls detached tokens every 5 s (token-dropping children and simultaneous guardian death remain gaps; `test_process_owner.py`).
