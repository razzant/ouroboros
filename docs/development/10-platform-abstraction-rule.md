# Platform Abstraction Rule

Platform-specific code lives behind `ouroboros/platform_layer.py` (private Win32 ABI: `platform_win32_abi.py`), with documented function-local exceptions, and durable state files go through the shared atomic helpers, whose byte-exactness keeps a manifest or a hashed receipt identical across operating systems.

Platform modules (`fcntl`, `resource`, `grp`, `pwd`, `msvcrt`, `winreg`, `ctypes.windll`), direct `os.kill`/`os.killpg`/`os.setsid`/`os.getpgid`, `signal.SIGKILL`/`signal.SIGTERM` and platform-conditional subprocess flags (`subprocess_new_group_kwargs()` / `subprocess_hidden_kwargs()`) go through the layer; paths use `pathlib.Path`, never hardcoded separators. The exceptions are function-local platform imports under an explicit `sys.platform` guard: `resource` in `ouroboros/extension_process_runner.py`, `winreg` in `ouroboros/windows_autostart.py`, `msvcrt`/kernel32 in `ouroboros/confined_files.py`, `fcntl`/`msvcrt`/`_winapi`/kernel32 in `ouroboros/body_switch.py` (stdlib-only; it cannot import the layer), and the typed `ctypes` caption calls in `ouroboros/launcher_appearance.py`, which belong to one window's lifecycle (its `before_show` handle, UI-thread `BeginInvoke` and close) that no generic layer wrapper owns.

Enforcement: `tests/test_platform_guard.py` scans `ouroboros/`, `supervisor/` and `server.py` for top-level platform imports, the four `os` calls and the two signals; function-local imports, `launcher.py` and subprocess flag patterns are deliberately not scanned (code review and the `cross_platform` checklist item cover them); CI runs the tests on Ubuntu, Windows and macOS.

### Shared state-file helpers

Durable state files use the SSOT helpers in `ouroboros/utils.py`: `atomic_write_json` / `read_json_dict` and `write_text_atomic` / `write_bytes_atomic`, one atomic full-overwrite seam, so a reader sees either the complete old file or the complete new one across a crash; `fsync` is opt-in, and appends are a separate, non-atomic contract. Both are byte-exact on every platform: the caller's newlines are the newlines on disk. Prefer them over bare `Path.write_text`/`write_bytes` for full-file overwrites; lockfiles go through `platform_layer.acquire_exclusive_file_lock` / `release_exclusive_file_lock`, except never-unlinked lifetime holds (the PID lock, `server_entrypoint.admit_data_root`). Narrow exceptions: `supervisor/state.py` keeps `atomic_write_text` for its mirrored state writes, and `ouroboros/config.py` keeps its own settings-file lock, because settings are bootstrapped before the shared helpers may depend on them. Enforcement: `tests/test_atomic_write_v639.py`; the prefer-the-helper rule is review-only.
