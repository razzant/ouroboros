# 6. Agent Core

Lifecycle, tools, route evidence, authored context/source recovery, review authority, delegated custody, planning, common story and budgets. `loop.py` runs tasks, direct turns and wakes; reviews/post-task work settle separately.

### Task lifecycle

Workers run `OuroborosAgent` (§5); direct chat owns an agent and `DirectActivityRegistry` (§3). `agent_task_pipeline.py` freezes contract/context, runs the loop, stores results/artifacts (the store row is the lifecycle authority, read by `get_task_result` / `query_data`; `task_results/<id>.json` is import input and export output), runs root post-work (`post_task_synthesis.py`, `post_task_checkpoint.py`) and publishes. Admission, completion, satisfaction, verification, review and artifact finality stay separate. `task_result_schema.py` admits rows (§11); usage owns money/tokens. A crash is `failure.kind="runtime"`; lost capture is unknown. `finalization_timing.py` times delivery, sharing child projections per pass until a model wait; lookups use task/root/queue-seed lineage (`task_store`). Test spies count reads. `supervisor/cognitive_operations.py` keeps typed operations off the idle rail; deadlines, budgets and cancellation stay active.

The loop transcript is append-only: OpenAI-family caching requires the previous request as a byte-prefix (§6 Prompt caching). `transcript_prefix.py` records breaks without blocking sends and identifies deliberate compaction. `model_execution` records the last accepted ordinary solve response, keeping requested, routed and provider-reported models distinct; empty, forced, review and post-task responses cannot replace it. After a host model change following tool work, the successor gets one recovery round to resume authorship; a second tool-less response degrades as `authoring_handover_incomplete`.

`loop_delivery.py` retains the complete `DeliveryCandidate` before verification or review; later failures cannot erase useful work. `outcomes.py` combines execution, objective, review, artifact, child-absorption and custody facts, substituting none for another. Host receipts and exact artifact references prove effects; declarations do not. Failed tools alone do not degrade an answer; an unevaluated objective retains `residual_tool_errors_without_review`. The unconditional `FINAL ANSWER:` latch survives review, nudges and forced finalization though only `task_contract.answer_protocol="final_answer_line"` prompts the marker. A best-effort result may have lifecycle `completed` with an unaccepted objective. Stored reason codes stay unchanged; current owner wording is projected at read time (§3 Task cards, errors and reason lines).

Host disclosures stay beside the answer: `terminal_host_notice` carries plan/orphan limits; the owner's typed `terminal_custody_notice` row omits empty categories. CLI labels these as host status; Presence speech excludes them. A notice changes neither answer bytes/hash nor verdict; identical text never revives superseded approval. Child-result and plan-evidence hashes include notices: a changed limitation voids an old parent disposition. Host salvage is visibly labelled `Preserved intermediate output (not a final answer):`; the durable preview is bounded; `get_task_result` and stop receipts keep the whole copy.

A first reply without a selection episode is a plain final. After substantive host continuation, Main selects complete retained bytes with `finish_task(action="finish"|"stop", answer=...|answer_sha256=...)`; compaction withdraws unavailable selectors. Finish checks children, skills/handover, owner sources, material, services, configured review and admission. Stop retains the selected unfinished work without buying criticism or another answer, cancelling descendants or claiming approval; evidence-only changes cannot undo it. Undispositioned direct children hold finish, while reminders and custody disclosures never decide it. Presence completes a send only with host-confirmed delivery. Acceptance keeps reviewed and delivered identities distinct.

Provider death salvages text but ends `failed`/`infra_failed` with `provider_unavailable` (or `resource_refusal_no_resend`) and an immediate not-completed owner notice. One forced model call runs only while a call can land; wait expiry and `loop_llm_call.provider_no_call_source` forbid another paid window. `terminal_provider_notice` quotes the provider's own words beside the result, never recommends blind replay. The finalization sink stamps `model_final`, `host_notice` (host words) or `host_salvage` (model output kept after provider death); a forced reply still requesting tools is incomplete. Finalization controls are typed mailbox entries. Descendant activity is not the task's own progress, and an unkillable process remains visibly running: even a zero, final cost cannot settle `delegated_runs_unreconciled` custody.

#### Task acceptance

Task acceptance advises work; commit review is separate. Auto needs root nomination (`deferred_to_host_acceptance`, `authoritative=false`); Required also admits observed effects or retained produced material. Requirements, inputs, checkpoints and queue status prove no production. `acceptance_material.py` retains selected `final_answer_line` bytes, verified outputs, baseline-attributed changes and OSWorld GUI-input receipts before eligibility; packet and subject reuse them. Empty/stale/failed sources grant nothing; GUI execution proves no goal success. Neither prose/tool counts nor automatic child panels qualify (`skipped_child_advisory`).

`task_acceptance_review` nominates work; Main authors criteria. Off forbids new root panels, manual/historical included, never paid/unknown collection, cap-only amendment, code or child critics. A child picks one configured `reviewer_slot_id`. Historical requests need new owner chat/quiz/mail: `amend_cap` changes only the original-root cap; `review` judges frozen terminal work. `acceptance_history.py` retains skipped roots/retries, gaps and separate `historical_author_inputs`; old premises direct nothing; host-authored terminals mint no debt (`emitted_delivery_authorship`). Spend, Stop/Panic, prohibitions and deadlines bind; Hurry/Wrapup stop unstarted automatic work, never paid collection. Partial delivery leaves the goal open; sufficient work needs no embellishment.

`queue_transitions.py` proves subtree quiescence and fences child admission before payment; unanswered fences buy no round. Delivery seals again. Pooled fences bind attempt/PID: unanswered begins release, ended owners retire at handoff; consumed Resume rebinds direct/pooled park fences. The canonical `budget_drive_root` packet retains verbatim owner directives, criteria, deliverables, terminal children, verification receipts, service teardown (shown to the author; whole logs as `read_file` text, not tails), artifact references and an `omissions_manifest`. `repo_diff_capture.capture_repo_diff` produces preview and exact source from one read: failed, cut or undecodable capture is a gap, never a clean tree. Exact bytes stay private in observability CAS; public sections are redacted before cutting, withholding unsafe partial diagnostics. Shedding preserves `repo_diff_source_ref`; immutable-core overflow is explicit. `review_source_closure` retains named sources and host-attested refs under `source_handles/review_inputs/<request>/` before paid binding. Missing/corrupt sources refuse unpaid; oversized first sends use an exact-source work order; changed session bytes degrade. Packet, session and native rows keep their own delivery contracts (§6 Review delivery).

`acceptance_preparation.py` binds a local preparation incident to material and criteria, not exception wording. Unchanged material needs an exposed failure and explicit source-bound `acceptance_retry` (`material_change|repair_evidence|owner_retry`) for one more try. Unknown evidence revokes approval, keeping the answer as unverified, and invents no reviewer or finding. An unresolved preparation terminal is unfinished in Blocking, best-effort in Advisory.

`acceptance_paid_identity` binds the semantic subject and substantive obligation dispositions. Narration, forensic hashes and ingress counters alone buy no panel; an identical paid identity replays free with its actual verdict. `task_pacing.review_launch_allowed` requires cycle capacity, money admission and more than `OUROBOROS_ACCEPTANCE_REVIEW_EST_SEC` above the finalization reserve before evidence building; that floor predicts no duration and gates no author improvement. The first physical send claims `task_results.task_acceptance_review_accounting`; an unrecoverable claim remains unknown, never resend authority (§6 Paid stamp and owner custody). A launched review cut by its deadline is DEGRADED, not a free skip.

`review_operation.ReviewOperation` owns the immutable request, paid roster, waits and controls past the author turn. Recovery verifies stored ownership/binding; `collect_recorded_acceptance_run` parses locally at $0 with no model. Worker death is unknown. `announce_acceptance_settlement` mails each reviewer's verdict at quorum and final settlement; only typed owner/control input grants an owner revision. Its sole publisher, `settle_acceptance_operation`, owes one System `card_row="reviews"` via the durable outbox and a host mark in its room only the mind releases (`late_review_marks.py`, also a late plan reply or a left change wave), reporting time and reviewed identity, authorizing no continuation; an unplaced notice or mark stays owed. Cold execution facts come from `final_attempt_facts` (§6 Session identity).

Adaptive quorum is two of N for N≥3, both for N=2, and one disclosed `single_reviewer_no_diversity` for N=1. Failed or malformed rows are infrastructure evidence, never negative judgments; pre-send refusal is `not_dispatched`. `PASS`/`FAIL`/`DEGRADED` belong to reviewers; only `loop_acceptance._set_acceptance_decision` writes `accepted`, `revision_requested` or `finalized_unaccepted`. A clean criterion needs exact full-packet `evidence_refs`; claim support resolves through `acceptance_support_refs` to passing host receipts. Unresolved refs keep the audit but lose their clean contribution, preventing self-certification by repeating the expected outcome. Minority findings remain feedback without quorum.

Stable obligations retain both author and critic positions through repair, rebuttal and declared disagreement. A valid rebuttal retires its finding; an invalid one reopens it. The bounded `acceptance_dialogue_history` is outside hashed material, so reading it buys nothing. Every outcome permits inspection, correction or rebuttal. An informed Advisory `author_action=finish` must bind to feedback exposed in Main's request and keeps author and critic hashes separate; Blocking requires fresh approval for disputed advancement. Cyber retains BIBLE P0/P3 authority without rewriting verdict, money or custody; `dialogue_status` never chooses the author's stop.

Default `pending_review=wait` keeps the same operation in every mode through mail, rewrites and partial settlement without empty author polls; settled feedback, PASS included, precedes the next author decision; finish prose never waives it. Nonblocking modes allow explicit `pending_review=finish`, apart from criticism, with no Cyber improvement-counter veto. Once that feedback reached Main, a text-only rewrite with matching premises/material is accepted as `previous_revision_accepted` (fork 1=B; a rewrite Main nominated gets its own panel), granting no candidate, commit, plan or skill PASS. Forced finalization keeps the tool envelope but runs no tool or extra round. A dangling revision becomes `finalized_unaccepted` with `revision_unavailable_on_forced_rail`, preserving terminal decisions; deadlines or unread mail certify no subject.

#### Headless finalization and workspace patch capture

A workspace task's completion diffs against the captured preflight base (`task_constraint.base_sha`; task-local commits stay in the delta, not `git diff HEAD`); a moved HEAD fails closed only for `self_worktree` (a shared tree relies on reverse-patch verification); an unborn repository diffs against the canonical empty tree. `workspace_patch_capture.py` streams the tracked binary diff plus admitted untracked files under `workspace_patch_rules.py`'s pure rules, each vetoed entry excluded with its reason; oversized or binary untracked outputs ride a manifest+zip artifact, not a patch. Generated output follows the project's `.gitignore`, not a host directory-name veto, so build deliverables are kept; a sensitive-looking untracked credential is excluded per file (`sensitive_blocked`). `workspace_patch.json` is written for every workspace finalization, no-change and failed included; `workspace.patch` only for `ready_with_changes`; the CLI strict-patch contract reads them (§1). Forked/empty execution drives live at `data/state/headless_tasks/<task_id>/data`; results return to the canonical root, artifacts to `data/task_results/artifacts/<task_id>/`. Late copy-back preserves terminal results; terminal file adoption drops child `state/code_intel`. `task_custody.settle_child_drive` decides every child-drive deletion: the drive goes only when the supervisor's probe proves no live owner for every occupant, the durable row is settled and the canonical row holds every recorded obligation; missing or mismatched material keeps it until a restore converges.

`control_routing._routing_issuer` stamps who speaks, never the model. An owner turn relays exact ingress words with owner provenance until a later drained owner message or landed routing receipt. Task-issued `steer_task` uses `independent_task` provenance through `supervisor/steering.py`; `forward_to_worker` in `tools/core.py` uses `peer_task` for same-tree peers, without owner-corpus authority or attachments. Promotion reports the admitted destination: implicit scope re-resolves under the origin claim lock. `supervisor/plan_obligation.py` transfers an unmet Swarm planning obligation with admission.

Routing context offers registry folders and bounded typed recent/live root facts, never raw answers; predecessor eligibility comes from the result's §10 predicate. A helper predecessor or a different Project is disclosed, not forbidden. `list_projects`, `route_to_project` and receipts read canonical `state/projects.json`: a forked execution drive does not own it. Binding and concurrency: §6 Project binding by task and by origin.

### Safety and runtime mode

#### Safety Supervisor outcomes

The first line of a Supervisor result is the typed outcome. SAFE passes silently; SUSPICIOUS allows the call with `SAFETY_WARNING`; DANGEROUS or an answer still unusable after one repair retry blocks with `SAFETY_VIOLATION`. A provider 429 is an infrastructure fact about the Supervisor, not a verdict about the call: after one retry the typed non-verdict `SAFETY_UNAVAILABLE` blocks the call, telling the agent to retry the same call, not reword it; a confirmed storm arms a process-local latch (`safety.py`) that answers in-window checks without a provider call, since re-probing from the highest-frequency light-model consumer would amplify the storm it reports. #### Delegated spend and token reads

**What a delegated run costs.** Claudexor reports cash per attempt (`attemptExecution[].usageCost.cashUsd` with `cashKnowledge` exact|estimated) and in `summary.spendUsd`/`summary.spendEstimated`; `delegate_custody.disclosed_spend` is the single reader, preferring the per-attempt figures, so the ledger row and the payload the nanny relays cannot tell different stories. Runs ask `authPreference: subscription` explicitly: the engine default falls back to a paid key invisibly. Four cases:

| disclosure | ledger | finality |
|---|---|---|
| disclosed settled zero | `0.0` (`subscription_session` row) | `cost_final=true` — the proven free session |
| disclosed settled charge | the amount | final |
| estimated amount | the amount | `cost_final=false` — an estimated zero is not a proven free session |
| undisclosed | `cost_usd: null`, increments `unknown_unmetered` | drops `cost_final` for the projection |

An undisclosed spend contributes `0.0` to known `settled_usd` and `accounted_usd`: a conservative bound would fabricate a number the harness never gave (BIBLE P1), so a `TOTAL_BUDGET` fence cannot stop spend it was never told about; the honest consequence is lost finality, not a guessed charge.

**What a delegated run reads.** Harnesses count input tokens with incompatible conventions, so `settle_run` copies the engine's normalized `summary.inputTokenUsage` onto the `subscription_session` row as the optional `input_token_usage` object; `record_subscription_session` is the one validator, and a partial object is unknown as a whole: a repaired counter reads exactly like a measured one. The object stays outside the idempotent row identity, so an engine that starts reporting never rewrites a session already settled without it.

**The nanny model.** An `agent_session` child is an ordinary recursive nanny task supervising at most one active bounded external leaf. Containment incidents remain recorded.

### Own-body candidates

Ordinary body authors — a queued root, a direct turn, an evolution cycle — write a task-owned linked worktree of the serving repository, never the serving checkout, so unfinished self-change never enters serving imports. The candidate starts at the serving HEAD on branch `candidate/<task>` under the isolated worktree root, as a `kind=body_candidate` row of the worktree registry, which restores the binding across a retry, a Resume or a new worker. `prepare_self_change` prepares it explicitly; body writes, PR-integration verbs (`git_pr.BODY_WORKTREE_TOOLS`) and an acting `self_worktree` child reach the same preparation through `body_candidate.authoring_seam` before resolving any target; reads before preparation stay on the serving tree. Light mode, capped trees, subagents and the managed-update resolver get none; Cyber Pro may choose `in_place`; a body with no Git tree keeps in-place authoring.

Binding rewrites one fact — `repo_dir`, `system_repo_dir` and `branch_dev` of the tool context name the candidate — so every consumer, the review subject and `commit_reviewed` included, shares one identity under own-body policy; a candidate is never an external workspace, and `serving_repo_dir` keeps the running checkout for review governance, the restart marker and rollback. A process whose cwd is inside the candidate or its admitted own-body child copy runs in an isolated environment beside it (`<candidate>.env`, `test_environment.isolated_environment`: its own HOME and data root, no credentials or global Git config, pip only inside a venv), so a push, a provider call or a pip install outside a venv runs from a cwd outside the candidate; when it cannot be prepared the process is refused (`CANDIDATE_ENVIRONMENT_UNAVAILABLE`), not started with the serving one.

Ownership is the root task: a host-validated continuation inherits its predecessor's candidate, `prepare_self_change(resume=…)` selects one exact retained candidate, and either moves ownership only from a terminal owner whose ledgered processes are settled; nothing is inherited by room, name or date. Binding appends the candidate to the lineage's mutation baseline, so `commit_reviewed` stages what the task's own baseline attributes to it exactly as on the serving checkout; the commit is never auto-pushed. A candidate commit is version-neutral (every carrier span byte-identical to HEAD, no tag) or a numbered release (VERSION and every carrier in one diff, tagged); the release gate names the form from the diff, a partial carrier move is neither. Retention counts from last use: a candidate with no unique work expires; otherwise its files are captured on `refs/ouroboros/candidates/<id>` and the checkout is removed only when the capture is complete and the verdict still holds (`body_candidate.verdict_holds`); a nested `OUROBOROS_RETAINED.txt` marker keeps the process environment and source checkout.

Adoption is deliberate and restart-bound (`body_adoption.py`): `request_restart(adopt_commit=<sha>)`, or an evolution cycle's own restart, authorizes one exact commit that builds on the serving HEAD, came through the commit gate (Cyber Pro records the exception), keeps the entry files and the package-init hook and changes no path where the serving checkout holds uncommitted work; a constitutional change needs a numbered release outside Cyber Pro. The old generation never writes the tree: the carrying restart re-verifies under the update lock, and its exit tail arms only on the stop owners' own evidence that the old readers are gone, reading the engine pin the next generation selects from the candidate's file (`bound_candidate_file`) before the owned daemon's fate is decided (§9). The owner's Restart and Panic never arm or wait: a stuck stop must not hold the owner hostage; evolution cleanup abandons only its own authorization, and crash recovery retains a reviewed candidate without authorizing adoption. The switch and its recovery are §2; `settle_on_boot` records `adopted` only for a generation that attested the switched tree before its imports, bootstrapped and is supervisor-ready.

### Git and commit review

`pr_merge(number, expected_head_sha, method)` merges through the selected repository's `gh` identity at the exact head, never with force, admin or auto-merge; `merge_receipts.py` records intent before effect and keeps reviewed, current and merged apart (a committed `base..head` record named by `review_record_id`; a `declared_only` declaration never reads green). An unknown or queued outcome is observation-only — exit status alone, transport loss or 5xx proves no rejection — a missing review is loud, never a veto, and shell or web merges leave no receipt. Only proven pre-effect failures release intent, including the exact full `gh pr merge` stderr matching its `canMerge` refusal (before the display cut); recorded unknowns are never reclassified. `list_github_prs` preserves its bound `gh pr list` selection and reads exact counts in one node-ID GraphQL query on the returned URLs’ host; unavailable counts withhold the list, never invent zero.

`mutation_attribution.py` captures the root-task baseline and projects the clean-at-baseline delta plus an adopted predecessor's exact retained changes; a changed pre-existing dirty path, a stale baseline or a failed scan blocks automatic staging for the panel to weigh. `commit_reviewed(paths=None)` stages only that attributed candidate, explicit paths must be a subset, and an empty candidate is `GIT_NO_ATTRIBUTED_CHANGES`; managed update transactions keep their separate whole-tree authority, and `predecessor_adoption` grants no review approval.

Commit, tag, post-commit tests and push each pass `owner_pause.run_operation`: Pause after review refuses an unsubmitted commit; an ordinary one handed off stays a success whose later steps report not started, and nothing resumes them: after Resume they are its author's explicit work, never a new commit. A managed merge keeps `postcommit_resume`; `commit_reviewed` rechecks its HEAD and a clean tree, then finishes its tests and smoke with no new commit or rollback (`git_managed_postcommit.py`).

A reviewed commit is bound to one staged fingerprint — the `git write-tree` SHA, ordered `HEAD` and `MERGE_HEAD` parents, indexed VERSION, expected `v{VERSION}` tag, any existing tag target and the binary staged-diff hash — re-read after the commit before success or push is recorded; an existing release tag is never silently accepted or retargeted. Every seat of the one wave inspects the same staged snapshot, any mutation stales the binding, and the author's early look (§6 Commit preflight) changes neither tests, wave nor binding. A managed-update resolution commit reviews the declared M0→S subject (`tools/review_subject.py`) while the gate binds S to the exact index write-tree. `release_sync.sync_release_metadata` projects version carriers during commit preparation; `VERSION_CARRIER_SPANS` / `substitute_carrier_spans` is the one span primitive the managed-update resolver and the packet's carrier cut share. BIBLE supplies review authority, CHECKLISTS the criteria and DEVELOPMENT the procedure; snapshot identity, the preflight fact, deterministic results, actor evidence and final Git identity describe one material.

Every Advisory or Cyber Pro outcome returns its complete result and exact `review_reference` before commit, tag or push. Continuation through `commit_reviewed` / `vcs_commit_reviewed` with that reference and `author_disposition` binds the current attributed candidate, reruns the independent preflight, tests and Git checks and dispatches no critic; a settled handback is `reviewed/review_only`, pending custody stays `reviewing/late_wait` and collectible, and Blocking gets no author override. Evolution receipts record the wave's actual aggregate (`triad_scope_status`), never a PASS inferred from a successful commit.

#### Commit preflight

`preflight_review(commit_message="...", deterministic_only=True, source="worktree" | "index")` returns free diagnostics before sync, staging, review-state access, provider checks, tests or fingerprints. `commit_admission.release_metadata_diagnostics` evaluates the selected source's current VERSION, carriers and P9 limits. The release report identifies its source, status (`clean`, `blocked`, `unavailable`, `not_applicable`) and findings; it grants no review freshness and writes no history. A separate `book_balance` field labels its bytes as worktree (`reference_books.py`). Book growth never changes the release status or blocks a local commit; syntax and critic review do not run here.

The author's preflight is one look, not a pipeline: `commit_reviewed(preflight_reviewer="<row>")` names one enabled catalog row by id or handle, pool member or not (an unknown or disabled row is a `TOOL_ARG_ERROR` before staging, `commit_gate.preflight_reviewer_error`), and after the free checks and the tests the gate runs `review_change(subject=worktree, surface=preflight, reviewers=[row])` on the system repository (`commit_gate.run_commit_preflight`), before the wave. The look informs and never gates: its record carries `surface=preflight` in its reuse key, so it never answers the commit panel, and the commit record's `preflight` fact names it — `performed` with record, row and aggregate, `not_performed` without the argument (a plain fact, not an audited bypass), `skipped` under `skip_advisory_review=True`; a row named beside the skip or an author continuation is a `TOOL_ARG_ERROR`. The look counts against `review_change`'s paid-cycle cap and holds no commit custody; `review_status` reports the checkout's newest look (`review_ledger.latest_preflight_record`) and whether a later worktree edit staled it (`stale_from_edit`). `preflight_review(reviewer=…)` (`tools/preflight_review.py`, `advisory_review` alias) is the same look standalone, without tests or release-metadata sync.

The free checks (`commit_gate.deterministic_preflight`) run on every commit, a skip included: size headroom, the diff pulse and worktree readiness as information and warnings, then release metadata of the staged index and the syntax of staged `.py` files. Only release and syntax findings block; readiness lines go to the owner's progress and the events log. The diff pulse (`review.diff_pulse`: files, lines and new files since `reference_books.contribution_base`, touched modules against the 1000/1600 limits, the books' balance and one question; no threshold) ends every system-repository edit result and heads each non-managed body subject's brief. Tests run unless `skip_tests` (documentation has tests too), and always for a managed resolution. The reviewed-commit cycle (`git_review_cycle`) checks authorization and unresolved prior work before staging, binds the exact candidate before free-cycle and budget admission, and revalidates the index and worktree snapshot before the wave. `review_status` reports open debt from `state/advisory_review.json` (`review_state.py`) as a retry anchor, never an admission gate, and no surface projects a `repo_commit_ready` verdict from it.

### Review stack

#### Physical custody

`review_custody.py` owns `review_substrate.py` workers, operation ids and the live map, without another scheduler or timing ledger. Deadline, budget, cancellation and ceiling still bind. API/thread calls disclose `in_flight`; late answers and settled terminal errors remain collectible, never erased or resent by siblings (§6 Late completion and typed refusals). Capture state, not a synthetic id, proves custody: `dispatched|unresolved` without terminal HTTP status is custody-lost/no-resend (`usage_accounting`). Recorded commit/preflight/`review_change` calls join a live original operation's drain and remaining window (`review_live_join`), keeping unsent preparation and Pause/Stop controls; cold and acceptance collection stay nonblocking.

#### Paid stamp and owner custody

The `paid` fact behind the ceiling is recorded write-ahead at physical dispatch (`review_dispatch.py`): a gate installs one once-only `ReviewPaidStamp` for its wave and each delivery stamps at its own boundary: a packet row, a native episode's paid send, a session's replayable `START_REQUESTED` row. Assembly-only refusals exit before that seam, so a $0 attempt stays outside every ceiling; neither a worker outliving its caller nor a crash after dispatch loses the fact. The stamp is idempotent across the wave's concurrent deliveries, so each seat waits for the write's result before starting its transport; commit review, `review_change` and task acceptance treat a failed write as fail-closed, skill review only when resuming a wave, and other callers keep fail-open accounting. Task acceptance binds one exact-hash tree-wallet claim per panel to the same stamp (the paid identity is material, not route); a wallet or cancellation veto at the claim releases the reservation and no row's transport proceeds (the launch floor: §6 Task lifecycle). Residual: a compatibility transport that raises with positive physical capture before entering the canonical marker is stamped after the send, and when the tree's last paid cycle is consumed concurrently at that late stamp the wallet refusal replaces the captured exception and the substrate may resend.

Before the wave starts, one locked write records `paid=True` with the reserved seat roster and operation ids in the commit-attempt row; a delegated seat patches `pending_invocation_id` before the provider POST, and a missing or mismatched operation on resume is `custody_lost` under every enforcement mode. The stamp records the server session and pid owning the reviewer threads (`review_owner_custody.py`): owner loss is proven by pid death, never by elapsed time: a TTL would convert waiting into resend authority.

Delivery is a catalog-row property read by `reviewer_slot_config.review_pool_slots` (§7 Review pool). The one shared session target is `OUROBOROS_REVIEW_SESSION_ROUTE` (`review_execution.REVIEW_SESSION_ROUTE_ENV`), an opaque `harness[=model][:effort]` spec that falls back to `OUROBOROS_SUBAGENT_HARNESS` when unset, so one delegated route is configured once; a set but unparseable value turns review sessions off with a warning, never silently re-routing them.

#### Surfaces and money admission

The review surfaces:

- Change review (`tools/review.py`) — the pool's seats cover the layered Change Review Checklist (the Ouroboros Body Layer joins the universal core on the body; `review_helpers.load_checklist_layers`) with JSON findings under `config.adaptive_quorum`. A packet seat answers contract A (`triad_review.REVIEW_JSON_ARRAY_CONTRACT`, the findings array); a retrieving seat answers contract B (`REVIEW_TWO_PART_OBJECT_CONTRACT`: `{change, change_clean, coupling}`): one wave, two questions, one quorum over the seats that answered (`review_ledger.reduce_verdict`, shared by the gate and the record).
- The coupling question (`tools/review_brief_coupling.py`, Part 2 of the retrieving seat's brief) — intent, scope and coupling across the whole repository, asked of every retrieving seat of the same wave; there is no separate scope role (§6 The coupling question).
- Parallel orchestration (`tools/parallel_review.py`) — two-phase admission: the packet is fit-checked and every brief built before any reviewer dispatches, so a deterministic assembly block anywhere spends $0 (a seat paid while its sibling was doomed is real money for a half-verdict). Money admission (`tools/review_admission.py`: `admit_commit_gate_wave`) prices every paid seat, as disclosure, under its substrate's usage scope and admits the wave through `review_wave_budget_gate(surface="commit_gate")` while known spend is below the global `TOTAL_BUDGET`, the root and the billing-group fences; a refused wave records `$0 not_dispatched` on every seat plus one `review_wave_budget_insufficient` event naming the `binding_axis`. Admission is a read-only pre-check — per-seat reservation stays the enforcement, so a fence reached mid-wave refuses the remaining seats with truthful custody — and an admission that raises is fail-open but loud (`review_wave_admission_unavailable`). An agent-session row rides the owner's subscription and is neither priced nor waited for.

A free refusal never wears the form of a verdict: a $0 exit is a typed `not_dispatched` fact with its reason, never a DEGRADED panel or a synthetic actor, and a request never sent is one seat with `operation_state='not_dispatched'` that stays in the denominator. Part 1 catches line errors; Part 2 catches cross-module contracts, from the same seat over the same staged snapshot (managed updates: M0→S), so one answer cannot hide the other. Task acceptance (§6 Task acceptance) shares quorum and transports, asks no coupling question and stores its verdict apart from the terminal result.

| subject | caller | questions |

#### Subject operation

The review wave is parametric in its subject (`tools/review_subject.py`). A `ReviewSubjectSpec` names the root (`system_repo` or `active_workspace`), the kind (`index`, `worktree`, or `base..head` with base an ancestor of head), the surface and the checklist layer; `freeze_subject` pins it once as a `FrozenSubject` (the diff, its `diff_sha`, both trees). Governance is always the installed body's (`governance_root`: the serving checkout; a bound body candidate is a subject, never the source of its own rules), while the reading root is the subject's.

Only a synchronous wait reads a live root: the gate's own (`is_gate_subject`: the system repository's `index` against HEAD with no explicit base), through the gate's own capture (`capture_staged_diff`), so its packet, brief, seats and decision are byte-identical to the gate's. Every other subject, and a receptive wave (`review_pause`), is materialized by `isolated_checkout`: a detached worktree at the parent with the frozen patch applied to its index, under the install's data root (`state/review_checkouts/<token>/repo`) at the path of the task's round (`checkout_token`), so a rerun of the round reads the checkout an earlier wave's open custody retained; it is removed on exit unless custody stays open. Every delivery — packet, brief, the `-U0` fit rung, the required-source manifest, the retrieving seats' checkout — reads the frozen subject, never a recapture of a live index. A frozen subject that is not the body's own index skips the body's release preflight: the core layer is a foreign root under the body's rules, not the body's release contract.

Three identities derive from the frozen subject, never from the live index of the running process. (a) The reuse key (`review_reuse_key`, `review_ledger.reuse_key_digest`) covers surface, subject, rules, layer, composition, enforcement, contract and the logical round; a settled, dispatched record with that key is returned at $0 (`review_ledger.find_reusable`; `reused=true`) unless this task's own operation of the round is still open, which is collected first; pending and `NOT_DISPATCHED` records are never reused. (b) The logical round (`review_round_sha` → `review_ledger.round_sha_of`) is what the author asked of these bytes — rebuttal, questions, goal, scope, base and head — so a new rebuttal or brief buys one more paid review; the identical-diff refusal (`commit_gate.check_identical_verdict_refusal`) lets a new rebuttal through once; the paid-cycle ceiling (`check_review_cycles_ceiling`) is common to the root task per `(repo, tool)`, so a second subject under an exhausted root is refused, not reset. (c) The retry key (`review_retry_key`; the gate's has no round suffix) identifies the physical operation custody keys attempts by (`review_custody._attempt_key`), set before dispatch: a retry rejoins or replays it and never pays twice; a new round never receives the previous round's answers. The rejoin is durable (`tools/review_change_custody.py`): a rerun finds the write-ahead attempt row by retry key (`pending_round_attempt`) before the current pool, any reuse lookup, ceiling check or payment, restores its recorded panel and dispute input, and runs the gate's reconcile-only path (`arm_rejoin`: settled seats replay, the pending seat rejoins by its exact invocation, nothing new is sent, the record is revised), in this process or after a restart. A parametric wave's record names the frozen subject and carries `fingerprints.reuse_key` / `fingerprints.retry_key`.
