# 6. Agent Core

Agent lifecycle, tools, route evidence, context, reviews, delegation, memory, skills and budgets. `OuroborosAgent`'s `loop.py` runs tasks, direct turns and wakes; review and post-task executors settle separately. Admission, execution, objective, review, artifact and custody stay distinct: code records gaps and boundaries; the model judges.

### Task lifecycle

Queued tasks reach `OuroborosAgent` via the supervisor queue (§5); direct chat owns an in-process agent and `DirectActivityRegistry` entry, no queue row (§3). `agent_task_pipeline.py` freezes the task contract and context core, runs the loop, stores `task_results/<id>.json` and artifacts, then runs root-only post-work (`post_task_synthesis.py`, `post_task_checkpoint.py`) and publishes the outcome. Durable admission, lifecycle completion, objective satisfaction, verification, review and artifact finality are separate facts. `task_result_schema.py` admits result shape (§11); the usage ledger supplies money and tokens. A crash is `failure.kind="runtime"`; lost capture is unknown, never zero. `finalization_timing.py` reports timing, granting no authority; `supervisor/cognitive_operations.py` keeps typed in-flight operations off the idle rail without suspending deadlines, budgets or cancellation.

The loop transcript is append-only because OpenAI-family caching requires the previous request as a byte-prefix (§6 Prompt caching). `transcript_prefix.py` records breaks without blocking sends and identifies deliberate compaction. `model_execution` records the last accepted ordinary solve response, keeping requested, routed and provider-reported models distinct; empty, forced, review and post-task responses cannot replace it. After a host model change following tool work, the successor gets one recovery round to resume authorship; a second tool-less response degrades as `authoring_handover_incomplete`.

`loop_delivery.py` retains the complete `DeliveryCandidate` before verification or review, so later failures cannot erase useful work. `outcomes.py` combines execution, objective, review, artifact, child-absorption and custody facts without substituting one for another. Host receipts and exact artifact references prove effects; declarations do not. Failed tools alone do not degrade an answer, but an unevaluated objective retains `residual_tool_errors_without_review`. The unconditional `FINAL ANSWER:` latch survives review, nudges and forced finalization even though only `task_contract.answer_protocol="final_answer_line"` prompts the marker. A best-effort result may have lifecycle `completed` with an unaccepted objective. Stored reason codes stay unchanged; current owner wording is projected at read time (§3 Task cards, errors and reason lines).

Host disclosures stay beside the answer: `terminal_host_notice` carries plan/orphan limits, and `terminal_custody_notice` publishes a typed custody row. CLI labels these as host status; Presence speech excludes them. A notice changes neither answer bytes/hash nor their verdict, and identical text never revives superseded approval. Child-result and plan-evidence hashes include notices, because a changed limitation invalidates an old parent disposition. Host salvage is visibly labelled `Preserved intermediate output (not a final answer):`; the durable preview is bounded, `get_task_result` and stop receipts retain the whole copy.

A first reply without a selection episode is a plain final. After substantive host continuation, Main selects complete retained bytes with `finish_task(action="finish"|"stop", answer=...|answer_sha256=...)`; compaction withdraws unavailable selectors. Finish checks children, skills/handover, owner sources, material, services, configured review and admission. Stop retains the selected unfinished work without buying criticism or another answer, cancelling descendants or claiming approval; evidence-only changes cannot undo it. Undispositioned direct children hold finish, while reminders and custody disclosures never decide it. Presence completes a send only with host-confirmed delivery. Acceptance keeps reviewed and delivered identities distinct.

Provider death salvages text but ends `failed`/`infra_failed` with `provider_unavailable` (or `resource_refusal_no_resend`) and an immediate owner notice that work was not completed. The single forced model call is allowed only while a call can land: wait expiry and `loop_llm_call.provider_no_call_source` forbid another paid retry window. `terminal_provider_notice` quotes the provider's own words beside the result, never recommends blind replay. The finalization sink stamps `model_final`, `host_notice` or provider-death-only `host_salvage`; a forced reply still requesting tools is incomplete. Finalization controls are typed mailbox entries. Descendant activity is not the task's own progress, and an unkillable process remains visibly running: even a zero, final cost cannot settle `delegated_runs_unreconciled` custody.

#### Task acceptance

Task acceptance judges evidence and advises authorized work, separately from the P3 commit gate (`triad_review.TIER_CLASSIFICATION_RULES`). In `auto`/`required`, observable effects, typed deliverables/criteria and explicit root nominations qualify, research included. Queue membership alone qualifies only in `required`; conversation, exploration or memory updates alone do not qualify in `auto`, and children receive no automatic panel (`skipped_child_advisory`). No prose or tool-count classifier decides. `acceptance_history.py` freezes skipped roots/retries and a separate `historical_author_inputs` exhibit for later review, preserving capture gaps; historical premises never become owner directives. Partial delivery does not close the goal; a sufficient result needs no embellishment.

`task_acceptance_review` nominates work but is not the acceptance authority; Main authors criteria. Root `off` disables automatic review, while an explicit root call uses the full advisory pool. A child call chooses at most one configured `reviewer_slot_id`. `task_acceptance_review(late_review=...)` requires a new owner chat, quiz or mailbox source: `amend_cap` changes only the original-root cap; `review` buys an `acceptance_late` wave over frozen terminal work even with review off. Known root/group spend, Stop/Panic, prohibitions and calendar bounds still bind. Hurry/Wrapup stop unstarted automatic work, not collection of paid or unknown operations.

Before payment, `queue_transitions.py` closes child admission and proves subtree quiescence; an unanswered fence buys no model round, and delivery seals again. The canonical `budget_drive_root` packet retains verbatim owner directives, criteria, deliverables, terminal children, verification receipts, artifact references and an `omissions_manifest`. `repo_diff_capture.capture_repo_diff` produces preview and exact source from one read: failed, cut or undecodable capture is a gap, never a clean tree. Exact bytes remain private in observability CAS; public sections are redacted before cutting, with unsafe partial diagnostics withheld. Shedding preserves `repo_diff_source_ref`; immutable-core overflow is explicit. `review_source_closure` retains all named sources under `source_handles/review_inputs/<request>/` before paid binding. Missing/corrupt sources refuse unpaid, oversized first sends use an exact-source work order, and changed session bytes degrade. Packet, session and native rows preserve their respective delivery contracts (§6 Review delivery).

`acceptance_preparation.py` binds a local preparation incident to material and criteria, not exception wording. Unchanged material needs an exposed failure and explicit source-bound `acceptance_retry` (`material_change|repair_evidence|owner_retry`) for one more try. Unknown evidence revokes approval while retaining the answer as unverified; it invents neither a reviewer nor a finding. An unresolved preparation terminal is unfinished in Blocking, best-effort in Advisory.

`acceptance_paid_identity` binds the semantic subject and substantive obligation dispositions. Narration, forensic hashes and ingress counters alone buy no panel; an identical paid identity replays free, retaining its actual verdict. `task_pacing.review_launch_allowed` requires cycle capacity, money admission and more than `OUROBOROS_ACCEPTANCE_REVIEW_EST_SEC` above the finalization reserve before evidence building; that admission floor predicts no duration and does not gate author improvement. The first physical send claims `task_results.task_acceptance_review_accounting`; an unrecoverable claim remains unknown, never resend authority (§6 Paid stamp and owner custody). A launched review cut by its deadline is DEGRADED, not a free skip.

`review_operation.ReviewOperation` owns the immutable request, paid roster, waits and controls beyond the author turn's lifetime. Recovery verifies stored ownership and binding; `collect_recorded_acceptance_run` parses locally at $0 and never calls a model. Worker death is unknown. `acceptance_settlement.announce_acceptance_settlement` mails each reviewer's own verdict at quorum and final settlement; only typed owner/control input grants an owner revision. Its sole publisher, `settle_acceptance_operation`, owes one System `card_row="reviews"` through the durable outbox; failed publication retains that duty. Late settlement reports its time and reviewed identity without authorizing continuation. Cold execution facts come from `final_attempt_facts` (§6 Session identity).

Adaptive quorum is two of N for N≥3, both for N=2, and one disclosed `single_reviewer_no_diversity` for N=1. Failed or malformed rows are infrastructure evidence, never negative judgments; pre-send refusal is `not_dispatched`. `PASS`/`FAIL`/`DEGRADED` belong to reviewers; only `loop_acceptance._set_acceptance_decision` writes `accepted`, `revision_requested` or `finalized_unaccepted`. A clean criterion needs exact full-packet `evidence_refs`; claim support resolves through `acceptance_support_refs` to passing host receipts. Unresolved refs keep the audit but lose their clean contribution, preventing self-certification by repeating the expected outcome. Minority findings remain feedback without quorum.

Stable obligations retain both author and critic positions through repair, rebuttal and declared disagreement. A valid rebuttal retires its finding; an invalid one reopens it. The bounded `acceptance_dialogue_history` is outside hashed material, so reading it buys nothing. Every outcome permits inspection, correction or rebuttal. An informed Advisory `author_action=finish` must bind to feedback exposed in Main's request and keeps author and critic hashes separate; Blocking requires fresh approval for disputed advancement. Cyber retains BIBLE P0/P3 authority without rewriting verdict, money or custody; `dialogue_status` never chooses the author's stop.

Pending final delivery waits in Blocking; Cyber Pro lets Main decide, and Advisory may finish as `pending_review`. A text-only rewrite can reuse a ready/pending PASS only while owner source, criteria and material evidence match, disclosed as `previous_revision_accepted`; it grants no commit, plan or skill authority. Forced finalization keeps the exact tool envelope for cache continuity but executes no tool and buys no further round. A dangling revision becomes `finalized_unaccepted` with `revision_unavailable_on_forced_rail`, preserving already terminal decisions. A deadline or unread late message never certifies a new subject.

#### Headless finalization and workspace patch capture

A workspace task's completion diffs against the captured preflight base (`task_constraint.base_sha`; task-local commits stay in the delta, not `git diff HEAD`); a moved HEAD fails closed only for `self_worktree`, since a shared tree relies on reverse-patch verification, and an unborn repository diffs against the canonical empty tree. `workspace_patch_capture.py` streams the tracked binary diff plus admitted untracked files under `workspace_patch_rules.py`'s pure rules, excluding each vetoed entry with a per-file reason; oversized or binary untracked outputs ride a complete manifest+zip artifact, not a giant patch. Generated output follows the project's `.gitignore`, not a host directory-name veto, so build deliverables are not silently discarded; a sensitive-looking untracked credential is excluded per file as `sensitive_blocked`. `workspace_patch.json` is written for every workspace finalization, no-change and failed included, and `workspace.patch` only for `ready_with_changes`; the CLI strict-patch contract reads them (§1 CLI / Headless Boundary). A forked or empty child drive under `data/state/headless_tasks/<task_id>/data` is execution state: the result copies back to the canonical root, declared artifacts rebase to `data/task_results/artifacts/<task_id>/`, and a late copy-back never overwrites a terminal canonical result. `task_custody.settle_child_drive` decides every child-drive deletion: the drive goes only when the supervisor's probe proves no live owner for every occupant, the durable row is settled and the canonical row holds every recorded obligation; missing or mismatched material keeps the drive until a restore converges.

#### Owner routing verbs

`promote_chat_to_task`, `route_to_project`, `steer_task` and `ensure_project_scope` share one durable, token-matched receipt rail. Admission is not completion. The LLM chooses among possible tasks; code auto-delivers only an unambiguous single target. Rejection retains its typed reason; `UNCONFIRMED` means no matching receipt, never permission to launch a duplicate. A receipt on the same owner message does not prohibit a deliberate second root.

`control_routing._routing_issuer` stamps who speaks; the model cannot supply it. An owner turn relays exact ingress words with owner provenance while that origin is current; a later drained owner message or landed routing receipt closes that window. Main can reach host-listed roots, a Project room its own roots. Task-issued `steer_task` uses `independent_task` provenance through `supervisor/steering.py`; `forward_to_worker` in `tools/core.py` uses `peer_task` for same-tree peers, without owner-corpus authority or attachments. Sender and receiver retain `task_message_routed` and `task_message_injected` receipts. `peer_roster.py` supplies a bounded, disclosed `[INDEPENDENT_ROOTS]` roster; `forward_to_worker` also reaches inline Presence (§12).

`update_focus(text, source_ref)` publishes a root's judgment, not owner authority. Peers read its retained source through `get_task_result(include_focus_source=True, focus_source_sha256=…)`; an unavailable or changed source refuses `FOCUS_SOURCE_UNRESOLVED`. Focus has separate authored/observed times and no TTL, timer or project-wide focus authority.

Routing failures use `project_dialogue.ROUTING_REFUSAL_CAUSES` and one durable refusal writer. Tool-issued acts return facts for the model to narrate; host-issued acts publish a System `task_not_started` or `task_start_unconfirmed`, and an undelivered owner steer is `steer_not_delivered`. Failed genesis provisioning never falls back to the system repo. An exact system-repo `workspace_root` becomes the disclosed `workspace="none"` sentinel; its subfolders and the data drive refuse. Successful promotion reports the admitted destination, because implicit scope re-resolves under the origin claim lock. `supervisor/plan_obligation.py` transfers an unmet Swarm planning obligation with admission.

Routing context offers registry folders and bounded typed recent/live root facts, never raw answers; predecessor eligibility still comes from the result's §10 predicate. Choosing a helper predecessor or a different Project is disclosed, not forbidden. `list_projects`, `route_to_project` and receipts read canonical `state/projects.json`: a forked execution drive does not own that registry. Binding and concurrency: §6 Project binding by task and by origin.

#### Explicit starting effort of a root

A root's first round uses `agent_dispatch._initial_effort_for`: the stored `reasoning_effort` when it names an `EFFORT_SCALE` tier, otherwise the configured effort of its role or task type (`OUROBOROS_EFFORT_TASK` for ordinary work: §7). Explicit root inputs are `promote_chat_to_task`/`route_to_project`, `POST /api/tasks` (`TaskCreateRequest.reasoning_effort`), `ouroboros run --reasoning-effort`, schedule templates (owner API, `ouroboros schedule add --reasoning-effort`, `schedule_followup`) and Continue; `settings_scales.requested_effort` validates a supplied tier before any effect, omission keeps the configured default, and a blank or unknown value is a typed refusal on its own surface. The explicit value rides the queue and durable admission rows, so a root interrupted before its first worker write retains it; Continue reads the predecessor root's explicit choice from its result row; dispatch stamps children alone, and `switch_model` changes only the live round. The choice is a request: requested, submitted/clamped and provider-reported facts stay distinct in `request_wire_attempt`. Configured subagent profiles and role-owned efforts (evolution, review, consciousness) are separate axes; effort is no subagent axis but derives from the owner's configured effort for the task type (`LEGACY_SUBAGENT_FIELDS`).

### Tool capability and execution

`tool_capabilities.py` is the SSOT for the tool classes and the child allowlists (independent mutation and command ceilings); `tool_policy.py` chooses the initial capability set, `ToolRegistry` is the execution authority, and `loop_tool_execution.py` owns timeouts, concurrency, live evidence, result handling and mutative ceilings. Top-level presets share one built-in name surface: project focus changes the default target, while root policy, runtime mode, task-contract disables, credentials, resources, selected-resource bindings and delegated-child profiles narrow independently, so a registered or discoverable tool is not thereby callable for a particular target. Nothing disappears silently: lazy discovery returns an explicit omission or `CAPABILITY_UNAVAILABLE`, a policy-filtered registered tool is "hidden by policy: <reason>" (`ToolRegistry.policy_hidden_reason`), never "Not found", and a name dispatch cannot run gets one typed answer scoped to the namespace it addresses (`ToolRegistry._name_miss_result`). `list_available_tools` (`tools/tool_discovery.py`) reads `schemas()` in every mode; `loaded` is residency, not availability. The route's physical ceiling on schemas per request (`provider_models.tool_schema_limit`) is held at the Main round seam (`loop_model_call._fit_route_tool_ceiling`): core, meta and actor-loaded schemas take priority, the overflow tail is left out under a notice naming it and stays callable through `enable_tools`.

Outcome classification keeps policy refusal separate from execution failure, so an expected authority boundary never becomes the task's headline failure: `user_files_path_blocked`, `cwd_blocked` and `artifact_output_undeclared` are typed non-failure surfaces, while a declared output that cannot be registered is the genuine `artifact_output_error`. The identifier register (`tool_result._EXACT_IDENTIFIER_CODES`) applies the same rule to the whole routing and scope refusal family: a typed refusal is recorded as a refusal, never as `ok`, visible to the agent (`is_error`) without degrading the execution axis. Admitted absent targets are typed misses (`LIST_FILES_NOT_FOUND`, `SEARCH_NOT_FOUND`, image `FILE_NOT_FOUND`) only after query, confinement, runtime and protected-artifact checks; denials and bad content remain errors. The delegate tools reach the same register from the producer side (`delegate_shared._fail`): a substrate refusal is `delegate_shared.SUBSTRATE_REFUSAL_CODE` (never degrading), a malformed call `AGENT_FAULT_CODE` (degrades, feeds reflection), and a terminal run in state `failed` or `cancelled` is a successful observation of an unsuccessful leaf. The registry pairs a published typed result with the handler's return only when their texts are identical (`tool_result._publish_tool_result`), so a producer publishes after its last decoration, and a supervising wake is acknowledged on the `supervision_wake_id` that result carries, never on the tool's name.

Tool API v2 exposes only the canonical names from `get_tools()`. The file tools share a path-based public ABI; payload-borne paths (`edit_batch` entries, `apply_patch` targets) miss the dispatch seam that rewrites a `path` argument, so both ends canonicalize through `tool_access.canonical_repo_relative_path` and no guard judges `repo/BIBLE.md` while the write lands on `BIBLE.md`; `_ROOT_ARG_REPO_WRITE_TOOLS` is the single set every repo-write fence keys on. `verify_and_record` (`tools/verify.py`) runs the declared check through the same pre-execution guards as process tools, because a post-execution check cannot gate a receipt already written, and appends a host-attested receipt under `task_results/artifacts/<task_id>/verification_receipts.jsonl`. Process tools report settings changes without auto-reverting, because a revert cannot prove causation (§6 Safety and runtime mode).

#### Resource roots and physical file identity

Filesystem results identify their canonical `root:path`; `run_command`/`run_script` echo the resolved `cwd`. A direct Project room selects one folder for file reads/edits, process cwd, VCS and delegation; governance stays at `system_repo`; a missing folder keeps its address and availability note, never falling back to Ouroboros source, and a folderless task uses its own `task_drive` scratch without workspace or write authority. Resolution preserves physical identity: absolute paths inside a selected base normalize to it, rootless absolute paths bind to their permitted base, outside paths refuse before `safe_relpath` can turn them into similarly named files, and every redirect uses the same resolver as guards and handlers (`ToolContext.repo_path`/`drive_path`); a Docker backend address (`workspace_executor.map_backend_path`) is accepted only inside `active_workspace`.

Roots: `user_files` for user-visible files under the owner's home (the Ouroboros repo and runtime control plane are refused); `task_drive`, task-scoped scratch; `artifact_store`, task-scoped under `data/task_results/artifacts/<task_id>/`, created lazily, where deliverables written through `user_files` or declared process `outputs` are copied for audit (§1 tree); `subagent_projects` and `deliverables`, `read`/`list`/`search` only. The operation matrix (`tool_access_types._POLICY`) is closed under read⇒list,search and write⇒edit, adding no write-like operation to a read-only row. Helpers inherit their parent's physical read reach in every runtime mode, including canonical runtime data and recorded ancestor workspaces, while their write/command ceilings stay independent; a continuation also reads the `task_drive`/`artifact_store` of the one predecessor its contract names (one hop, read-only). Process admission: §6 Safety and runtime mode. The post-execution shell audit (`tools/shell_audit.py`) is observational; a failed audit adds a bounded diagnostic (`output_audit_unavailable`) without losing the exit, signal, timeout and runtime facts.

#### Credential mutation and diagnostic redaction

Credential, Bible and identity mutation fences use physical owner locations (`credential_shapes.owner_credential_locations`), source operands and actual VCS metadata; ordinary project names (`tokens.json`, `credentials.json`, `.well-known`) identify no host store, so attachment ingest, export/Deliverables, `user_files` mutations and Git never reject a word or suffix beyond the exact-name/dotenv rules, and Git capture checks content through `workspace_patch_capture.pem_private_key_reason`. Unlisted stores keep ordinary root access. Read, search, query and media results preserve source content for every mode and actor, without token/PEM replacement, and keep `source_masked=false` so exact-source review receipts stay verifiable; command, diagnostic/log, Settings-placeholder, capture and skill-publication redaction are independent of that read path. Runtime-data reads are gated by `core_file_tools._runtime_data_read_check` over `core_secret_paths.runtime_data_roots`.

#### Web access mechanisms (three distinct paths — do not conflate)

`search_routes.py` resolves built-in Source/Model (Auto or a strict source), separate from skills, MCP and browser. With Anthropic pinned, native per-call ids apply; only saved bare ids retain legacy defaults. Settings encodes edited Anthropic ids as `anthropic::model`, preserving untouched values. The three paths differ in reasoning, fetch authority and evidence:

| path | reasoning model | fetch authority | evidence |
|---|---|---|---|
| Main-loop native search (provider server tool, attached only if the main-loop setting allows) | the solve model decides whether to search; no second model enters the scaffold | provider-side | citations and request counts fold into `llm_usage` and the task's host-attested retrieval fact (acceptance context, never a criterion alone); the host never sees the provider-side query |
| `web_search` function tool | a provider-backed call may add a second model and its own cost | the built-in Source/Model (`search_routes.py`), run by `ToolRegistry` | arguments, tried legs and bounded results in `tools.jsonl`; never native-search usage on the answering call |
| Browser tools (`browse_page`, `browser_action`) | the main loop | a local stateful Playwright session that can fetch or act on arbitrary pages | arguments and result previews as tool evidence; browser state equals neither retrieval path |

Ordinary delegated profiles, local-readonly and acting alike, keep the URL, route, private-range and control-plane guards (`browser_policy.py`, §6 MCP and browser-facing external tools); a Cyber-effective acting child inherits the selected access minus explicit task restrictions. Their non-loopback private origins need host-established `resource_policy.allowed_origins`, named by Main/root scheduling in `schedule_subagent` and only inherited or narrowed by delegated and external Presence callers (`tools/control_subagent_spec.py`); among delegated profiles only a valid acting child may run JavaScript `evaluate`, on its current page. The separation is methodological authority: an evaluation or acceptance claim must name the path used.

#### Context fitting, retry, and compaction

`config.get_context_mode()` sizes Main; `get_owner_context_mode()` keeps owner intent and P3 applicability through the auto-Low compatibility window (`context_mode_compat.py`). `prompts/SYSTEM.md` and `BIBLE.md` stay full tier-0. Max keeps Architecture (`docs/ARCHITECTURE.md`) complete for every Main task as the capability/access map; Development (`docs/DEVELOPMENT.md`) is resident for body work, a visible pointer for external work, and explicit `context_requires_development`/`context_requires_self_body_docs` override that binding. Low/Nano use `context_layout.book_navigation`: chapter introductions and heading indexes addressing physical files, which composed-prompt offsets cannot. Live limitations: all subagent modes get book navigation contrary to BIBLE P1 (issue #1026); Low/Nano ignore the per-task self-body-docs flag (issue #1019).

`llm_local.py` trusts confirmed `serving_context_evidence` (`--n_ctx`), not model metadata, for capacity. Unknown capacity skips compaction without implying failed health or cloud fallback. Its tier-0 compactor can still cut BIBLE's principle bodies (issue #1018) and raises `LocalContextTooLargeError` for a request still too large.

`context_fit.py` measures immutable Max/Low/Nano projections using `estimate_context_prompt_tokens`. `context_budget.py` economy targets are not gates; money conservatively counts raw characters. Pressure reclaims mutable history to a low-water margin. Provider overflow may select task-local Low; a known window unable to hold minimum memory, books, tools and reply selects `memory_floor.physical_mode`. Route changes preserve owner mode and P3; `context_health.build_health_invariants` is a task-start snapshot.

`llm_attempt.bound_reply_allowance` caps sends at the fresh route maximum (`response_limits.py`), apart from the window; unknown or stale never caps. Low/Max ceilings and Nano capacity/targets still apply; fit, memory and compaction reserve that cap; summaries cut by it keep raw sources. In `capability_evidence.json`, `response_limit_refresh_failures` holds exact-route failed-refresh timestamps for the negative TTL without changing expired positive records; owner acknowledgements win.

`local_model.local_artifact_key` binds local maxima to the expanded file path or `hf:<repo>:<full repo-relative path>`, shared by settings and serving cache paths. Basenames use the downloader's `_resolve_hf_path` metadata resolver, never a download or dropped subfolders. The serving artifact outranks pending settings.

`context_compaction.py` materializes the fit's request and owns no other threshold or retry: it summarizes only units a usable response exposed, checkpoints exact originals first and keeps owner words verbatim; no positive reclaim means no checkpoint, paid summary or transcript mutation. `compact_context` uses the same materializer; its successful-response view is published before returned tools execute. Exposure survives through `owner_wait.continuation_state`. `send_clock` stamps new physical candidates before measurement, pricing and sealing; same-operation rejoins keep the original bytes.

Canonical history is provider-neutral and function-shaped; send copies adapt at the exact route: direct-OpenAI Chat's custom/function/none ladder (`openai_chat_custom.py`) never changes API surface; `anthropic_native_custody.py` retains native assistant replay only for its route; `llm_openai_compatible.py` sends OpenRouter `strict: false` and omits neutral `tool_choice`. `request_wire_recovery.py` repairs shape on the same credential-free route/profile and never chooses a provider or model; only normalized success bound to the settled physical capture teaches `state/request_wire_compatibility.json`, and error prose cannot reroute. `usage.request_wire` describes compatibility, `usage_store.py` / `state/usage.sqlite` owns money.

Retry classes stay distinct: transient 429/5xx and empty/incomplete replies may retry within deadline; auth, quota, permanent bad requests, confirmed oversize and output exhaustion never do. Compatibility exhaustion returns to configured fallback. `LLMClient` keeps leading system messages authoritative, later ones becoming user notices. A proven remote pre-dispatch failure releases at $0; configured alternatives run before `loop_transport.py` opens an interruptible network wait. Its `network_wait` facts spare the idle rail without cancelling cognition in flight; expiry never resends. Silence after kill, Panic, crash or hard Stop proves no terminal outcome.

`provider_outcome_unknown` keeps unresolved money and forbids resending the request. `loop_transport.new_generation_after_unknown` needs ended receiving, no viable same-operation rejoin and host input binding the new attempt to the old identity, route and unknown charge. Only the current accepted answer executes tools; a live delegated leaf instead parks its nanny in `delegate_hold.py` until meaningful new leaf input. Inline Presence alone opts into bounded typed transport-death repeats as separate unresolved attempts; every other caller keeps no-resend.

Retry rails nest, each with its own owner and bound; the table shows their multiplication in one place (every physical send is its own `execute_physical_attempt` lifecycle, whichever rail asked):

| Rail | Owner | Bound | What it repeats |
|---|---|---|---|
| SDK `max_retries` | client construction (`net_transport.py`, `llm.py`) | 0 everywhere | nothing: the ledger sees every physical send |
| request-wire recovery ladder | `request_wire_recovery.py` inside one `LLMClient.chat` | `_MAX_COMPOSED_ACTIONS` per call | a rejected request in a corrected wire shape |
| transport-death repeat | `call_llm_with_retry`, inline Presence primary round only | `loop_llm_call._TRANSPORT_DEATH_RETRIES` per round, deadline-aware backoff | a dispatched request killed by a typed transport death, as a new attempt |
| configured-route walk | `loop_model_call._run_cross_model_fallback_chain` | bounded attempts per binding per walk | the round on each other configured binding, the primary first when a fallback acts |
| transient burst | `call_llm_with_retry` | `OUROBOROS_TRANSIENT_RETRY_MAX` attempts per call | typed 408/429/5xx and empty/incomplete responses other than output exhaustion |
| round redial | `loop_transport.py` wait episode | managed task: owner deadline, budget, Stop, absolute ceiling; direct-chat turn: `OUROBOROS_TASK_IDLE_TIMEOUT_SEC` from episode entry or a shorter explicit deadline | the same round: released ($0), eligible unknown (new attempt), or chosen primary refusal (ordinary burst) |

#### Safety Supervisor outcomes

The first line of a Supervisor result is the typed outcome. SAFE passes silently; SUSPICIOUS allows the call with `SAFETY_WARNING`; DANGEROUS or an answer still unusable after one repair retry blocks with `SAFETY_VIOLATION`. Cyber records a negative or unavailable assessment as advice (`SAFETY_ADVICE`, durable `safety_advisory` event) without manufacturing SAFE. A provider 429 is an infrastructure fact about the Supervisor, not a verdict about the call: after one retry the typed non-verdict `SAFETY_UNAVAILABLE` blocks the call, telling the agent to retry the same call, not reword it, and a confirmed storm arms a process-local latch (`safety.py`) that answers in-window checks without a provider call, because re-probing from the highest-frequency light-model consumer would amplify the storm it reports. The no-backend cases alone fail open with `SAFETY_WARNING`, so a misconfigured runtime does not hard-block every unknown tool: no provider key and no local lane; a remote key not covering the light model's provider, with no local lane; a local runtime chosen as fallback that fails or is rate-limited. `review_evidence.historical_author_inputs` is a sibling of owner directives and terminal inputs, changing neither criteria, acknowledgement nor paid semantic identity. Reflection and native/session readers use existing source readers; packet-only evaluators receive labelled incomplete previews. Size/hash travel independently of reader placement. Anchors survive continuation and terminal recovery; missing original pins or changed bytes stay unavailable. Publication follows source storage in canonical and execution roots, and retention follows only anchor refs, never arbitrary event dictionaries.

#### Child handoffs and task waits

**Waiting on children.** Omitted-timeout `wait_task`/`wait_tasks` reuse the existing warm continuation owner, without periodic empty wakes. `wait_tasks` selects exact IDs; `wait_task` captures the named child plus this parent's other LIVE direct children at entry and returns every captured member on each exit. `wait_tasks([id])` is the exact-dependency escape. Standalone callers without a continuation owner hold a finite operation window minus `NESTED_SETTLEMENT_MARGIN_SEC`, disclosed separately from task lifetime; explicit timeouts remain bounded and zero requests one snapshot. Neither path changes deadline, money, cancellation, lease or Panic ownership.

All waits publish compact JSON outcomes, hashes, verification summaries, capability/custody facts and complete-source references. The whole response, including metadata, is bounded to 15,000 characters (`control_task_results.bounded_wait_response`); an oversized observation is retained byte-exact through existing actor-source custody before previews, never declared a complete semantic summary. Metadata overflow publishes a source index; failed retention stays explicitly unavailable. `get_task_result` remains the explicit full terminal reader (red/masked-first receipts); its nonterminal default is compact, with full authority/source requests explicit. `known_result_sha256[_by_task]` omits only matching result/trace text, never current facts. `peek_task` stays a bounded diagnostic snapshot, not the normal completion waiter.

`owner_mailbox.wait_message_requires_attention` is the single wait-mail predicate: owner words/controls, typed review feedback, selected senders and the existing actionable kind vocabulary wake. Routine ancestor/peer/descendant/system facts stay unread; milestone/partial beacons cannot force a wake. `forward_to_worker(attention_kind=...)` marks a decision or changed contract without changing sender authority. Wait exhibits carry quiet-mail identity/provenance/size, never duplicate text or ACK; the ordinary round-top drain delivers originals in the SAME resumed model request, and working-checkpoint persistence precedes content ACK. Delegate transport renewals already stay outside model rounds; their content wake ACK now uses that same checkpoint owner. Simultaneous terminals, retry hashes and source failures remain observable rather than hidden behind a second delivered cursor.

#### Delegated spend and token reads

**What a delegated run costs.** Claudexor reports cash per attempt (`attemptExecution[].usageCost.cashUsd` with `cashKnowledge` exact|estimated) and in `summary.spendUsd`/`summary.spendEstimated`; `delegate_custody.disclosed_spend` is the single reader, preferring the per-attempt figures, so the ledger row and the payload the nanny relays cannot tell different stories. Runs ask `authPreference: subscription` explicitly, because the engine default falls back to a paid key invisibly. Four cases:

| disclosure | ledger | finality |
|---|---|---|
| disclosed settled zero | `0.0` (`subscription_session` row) | `cost_final=true` — the proven free session |
| disclosed settled charge | the amount | final |
| estimated amount | the amount | `cost_final=false` — an estimated zero is not a proven free session |
| undisclosed | `cost_usd: null`, increments `unknown_unmetered` | drops `cost_final` for the projection |

An undisclosed spend contributes `0.0` to known `settled_usd` and `accounted_usd`, because inventing a conservative bound would fabricate a number the harness never gave (BIBLE P1), so a `TOTAL_BUDGET` fence cannot stop spend it was never told about; the honest consequence is loss of finality, not a guessed charge.

**What a delegated run reads.** Harnesses count input tokens with incompatible conventions, so `settle_run` copies the engine's normalized `summary.inputTokenUsage` onto the `subscription_session` row as the optional `input_token_usage` object; `record_subscription_session` is the one validator, and a partial object is unknown as a whole, because a repaired counter reads exactly like a measured one. The object stays outside the idempotent row identity, so an engine that starts reporting never rewrites a session already settled without it.

#### Nanny, transport and custody

**The nanny model.** An `agent_session` child is an ordinary recursive nanny task supervising at most one active bounded external leaf. Task lineage, authority, deadline, money, acceptance, cancellation and descendants stay with the task; the harness is a nonrecursive tool leaf, and host-authored verification checks its claims. `requested_depth` is absolute root-depth telemetry, `depth_remaining` the narrowing cap. Targets and access profiles are opaque to core: no harness-name capability or fallback branch; login asymmetries stay in `gateway/claudexor_accounts.py`.

**Transport.** `gateways/claudexor.py` owns the descriptor, the /v2 handshake and the `config.CLAUDEXOR_MIN_VERSION` floor; the client runs with `trust_env=False` so a shell proxy cannot intercept the bearer token, which grants all of /v2. Production uses `claudexor_daemon.ensure_owned_gateway` and the reviewed engine/Node pins in `claudexor_runtime.py`, never PATH. `OUROBOROS_CLAUDEXOR_BIN` is the explicit operator override; `OUROBOROS_CLAUDEXOR_ATTACH_HOME` (isolated contributor review only) attaches to that home's running engine and never spawns or falls back to the operator home. Stop, latch and failure: §9.

**Durable custody.** Runs may outlive workers. The canonical and budget-root `delegate_run_*` rows (`delegate_custody.py`) are the authority, read through the `delegate_custody_memo.py` process memo (refold and unreadable-chain bypass: its docstring). Ownership is OWNED/FOREIGN/UNKNOWN: absent custody is clean, unreadable custody is `delegated_run_state_unknown:custody_log_unreadable`. `logs/containment_faults.jsonl` keeps unresolved incidents beyond event-log tails. Every intended start mints an invocation UUID and `Idempotency-Key`; content hashes locate work, never identify deliberate reruns, and only `pending_invocation_id`/`retry_of` replays the canonical body and key; before `delegate_run_start_requested` a private CAS retains the full unredacted envelope, and a missing or corrupt body keeps the pending identity unknown, without a POST (`delegate_pending.py`).

`reconcile_orphaned_runs` settles terminal runs outside the live owner set; cancelling a live run requires a readable, truly terminal owner-authored finish. A `RunCustody.review_owned` run belongs to its panel, kept `left_live` unless the owner cancels and never reposted by generic recovery. Provider or transport death, a worker crash or an unreadable result spare runs as `left_live`: `maxSeconds` bounds damage, not custody. After ledger persistence, SETTLED is published before registration retirement: a failed retirement replays, a failed ledger write cannot settle. Registration lifetime follows continuation authority (`delegate_registration_policy`): review registrations retire at once, while `delegate_continuation.still_continuable` retains any project whose line can still continue or whose authority is missing or unreadable. An unrecorded start stays `started_uncustodied` until positive absent/terminal proof.

**No terminal/cancel claim without a verified receipt.** `delegate_cancel` returns `confirmed` (terminal readback), `requested`, `failed` or `containment_fault_run_may_still_be_live`; the last two keep a durable critical incident until a receipt or settlement, and a refused control never proves run state. `daemon_says_absent` accepts only an answering daemon's scoped 404, never a failed observation; `delegate_run_closed_absent` means unreachable, not settled, with no invented terminal, usage or spend.

#### Nanny verbs and continuation

**Five nanny verbs** (`tools/delegate.py`): `delegate_start`, `delegate_wait`, `delegate_cancel`, `delegate_answer`, `delegate_message`; no fake hurry. Start needs an exact session `subagent_id` or recovery-only `retry_of`; `subagent_bootstrap` starts the snapshotted leaf before the first model round, and the model decides when to wait. `delegate_message` (`delegate_interactions.py`) requires the engine's `/v2/operations` catalog to advertise `POST /v2/runs/:id/messages` and a route `liveInput` other than `none`; the gate uses no harness-name branch. Outcomes mirror the engine's `LiveMessageOutcome`, where `delivered` proves consumption, not obedience, and steering is attempt-local, never re-injected by the host. An unreadable capability is `capability_read_failed`, not proof that live input is unsupported; a `not_active` refusal with `interaction_pending` may carry a fresh question observation and exact pending-interaction ids through the ordinary complete/preview artifact path, the refusal is preserved, and nothing is auto-answered. A definite refusal needs a typed cause, no custody handle and either producer `definitely_unrun` or `_DEFINITE_UNRUN_REASONS`; it ends UNRUN at $0. Ambiguity wakes the model: uncertain live work cannot become a zero-spend terminal. Actor-replacement and zero-run fences exclude `review_owned` runs, which belong to review custody, while settlement, money, containment and registration see all runs.

**Continuation** (`delegate_continuation.py`): `continue_from=<run_id>` starts a new run, cap and key bound to a settled run. After unsupported live input, wait for settlement or cancel and verify settlement before continuing useful retained work; cancellation preserves partial artifacts, not a finished verdict, and continuation may repeat work. How the new run remembers the old one is the engine's choice (`continueFrom`; `continue_carrier=packet` forces the re-brief), reported back as `continuity`; an engine without `continueFrom` refuses `continuation_engine_unsupported`. Four floors refuse typed from durable custody: own task line through recorded relations (never room or folder equality; a review panel's run is no task's), settled and not already continued, no pending-ambiguous apply, access not wider and a writer's target unchanged; same-tree custody also refuses `continuation_snapshot_missing`, `continuation_snapshot_released` or `continuation_handover_busy`. Continuation facts (cause, an unread result, another route, a changed work order) travel in the started payload and the child's `prompt`, never `instructions`, which a resumed session may keep from its first request. A continuation is the mind's own start, not recovery.

**Execution evidence.** `delegate_evidence.task_execution_evidence` projects the custody rows read-side (envelope: §11.1). `delegate_start_attempted` counts blocked and uncustodied attempts too, so a refused-but-obedient nanny is never disclosed as nudge-ignoring; `applied_access_profiles` is read off SETTLED rows only, an absent `acceptance_patch_dispositions` section means no disposition was recorded, never "reviewed clean", and an unreadable custody log is the typed `evidence_read_failed` marker.

**Work orders.** The compiler (`subagent_work_order.py`) sends the entire chosen assignment with no host-size cutoff: the normalized host contract once in `instructions` (`delegate_start_instructions.py`), the assignment in `prompt`, and a real native or HTTP limit returns its actual failure. Incomplete source coverage never authorizes a terminal PASS or an apply (`delegate_source_coverage.py`).

#### Supervision, activity and recovery

**Supervision.** `delegate_supervision.supervised_wait` renews bounded transport windows without LLM calls; a meaningful event creates a coalesced durable wake replayed until ACK, while deadline, ceiling, budget and cancel remain outer rails. Read-only `coordination_context` supplies intent, time, spend, descendants and acceptance capacity for the model's judgment, never thresholds (BIBLE P5). Polls are read-only of task state (the usage reader's bounded maintenance: §1 Platform substrate); `observation_read_timeout` means our bound expired against a live daemon, `daemon_unreachable` that no socket answered. Wakes retain full tools; `leaf_live_input` is route capability, never liveness; only `nanny_pacing.BASELINE_RESET_TOOLS` reset burn, so coordination buys no metered silence.

**Delegated activity.** `delegate_activity.py` keeps the executor's message, thinking and problem parts typed in additive `progress_meta.delegated_activity`; host observation (`narration=False`) proves neither nanny authorship nor execution. `gateways/claudexor_run_events.py` reads `GET /v2/runs/:id/events` as bounded SSE keyed by run_id/seq, without a poll or retry loop. Each record's redacted range is retained under `source_handles/delegated_activity/` bound by size and digest, with truncation disclosed (`cuts_truncated`, `seqs_truncated`); identity, cursor commit and gap rules are the module docstring's. Task-file `?source=` reads: §4; UI and replay: §3.

**A run's question belongs to its nanny.** A new `pendingInteractions` entry wakes supervision as `waiting_on_user`; `delegate_answer` echoes the custody keys, and a question beyond the nanny's authority escalates to the nearest live ancestor. `continuation:same_session` is paid per turn. A route without mid-run questions ends `input_required`; the answer is `delegate_start(continue_from=<run_id>, prompt=<answers>)`, never an engine rerun outside task custody.

**Recovery is exact and cause-specific, not generic task resurrection.** A proven non-signal worker crash or a planned self-restart's typed handoff lets a successor adopt the exact run or pending invocation before any model call or new start; anything ambiguous returns typed recovery-required, never a duplicate mutator; owner restart, panic, signals, deadlines and cancellation are explicit no-resume causes (`delegate_recovery.py`). When no physical run exists and none can be started, the model may finish only with a typed zero-run receipt (`verify_and_record`) after custody proves nothing is open; a session actor's clean terminal requires its own physical leaf or that receipt, and a completed host child cannot substitute. An unknown-provider hold (`delegate_hold.py`) parks the nanny in the supervised wait and never resends.

#### Dispatch, route health and history

**Configured dispatch is exact.** `subagent_runtime.resolve_configured_actor_dispatch` checks live availability at dispatch; a bad choice returns a typed cause, alternatives, reset time and `host_fallback:false`, never host ranking, first-healthy selection or session→API conversion. Selecting `agent_session` is the parent's LLM choice of harness execution: the host sets the truth, money and authorship floor, the model owns topology, decomposition and supervision (BIBLE P13/P5). For a configured subagent every fallback is an explicit LLM-selected start; a pinned selection whose delegate tools are invisible is blocked, not substituted.

**Route health.** `subagents.route_health` is the one health reader for dispatcher, nanny and review slots, and it does not guess admission: the doctor `status` describes only the default credential store while the real accounts live in the engine's credential-profile pool, so admission is the engine's, whose start POST answers an empty pool with a typed `credential_pool_exhausted` at $0; only a disclosed `resetsAt` makes that refusal a timer-healing window. `enabled` is honored as `route_disabled` (the owner's switch, not an observation); the other structural refusals are the capability catalog, an access-profile mismatch, the delegated marker floor and positively proven quota exhaustion. Review slots inherit "the engine decides", never a silent fallback onto metered API spend. The model sees a facts-only catalog (`model_visible_subagent_catalog`). Helper observations are history, not routing: `state/subagent_last_delegation.json` (`subagent_history.py`) feeds runtime context and the UI, never admission; a fallback's success never certifies the failed route, nor does a code or test failure condemn a provider.

#### Run shape and mutation authority

**Read-only and mutating session rows share one nanny transport.** `subagents.delegated_run_shape` alone derives the acting-child run shape for `tools/delegate._derive_authority` and `resolve_configured_actor_dispatch`, so authority derivation cannot diverge.

| task authority | access | mode | isolation | `execution.delegated` |
|---|---|---|---|---|
| acting subagent (valid write surface) | captured `full` or `workspace_write` | `agent` | `live` | `true` |
| Ordinary root with a validated external workspace or a selected Project room | captured `full` or `workspace_write` | `agent` | `live` | `true` |
| top-level task selecting an exact skill payload (`root="skill_payload"`) | captured `full` or `workspace_write` | `agent` | `live` | `true` |
| anything else, including a fail-closed subagent or an invocation lowered to readonly | `readonly` | `ask` | envelope (default) | not sent |

Where a mutating run's changes are destined is the second, separate record, the host-derived **mutation authority** (`tools/delegate_integration._mutation_authority` / `_payload_mutation_authority`), never model-supplied:

| source | `target_root` derivation | `capture_mode` |
|---|---|---|
| `acting_constraint` | the child's own `task_constraint.write_root`, required to equal the active workspace root | `delegated_snapshot` |

| `readonly` | ordinary active root (nothing to write) | `none` |

Payload targets use standalone private Git snapshots (`subagent_worktrees.provision_payload_snapshot`); live payloads gain no Git. `integrate_payload_patch` applies under whole-payload hash CAS: drift conflicts, identical content is an idempotent apply, reserved paths refuse the whole apply as `blocked_reserved_paths`, a baseline-equal hash proves no write (`apply_no_op`) and any other hash is an ambiguous pending intent, because a mutation occurred. Success queues `request_extension_reconcile` and stales the skill review; a mode-only change is refused as `unreviewable_metadata_change`.

#### Snapshots, capture and disposition

**Private execution snapshots.** Native/API `external_workspace` children share the target; for them `integrate_subagent_patch` only verifies and records a verdict at the child's own target under the caller's current read, Presence and task policies, with no tree or index write (`applied=false`). `self_worktree` children get a private `workspace_copy` of the selected Git source's eligible files, uncommitted inputs included, with a task-owned branch and retention; parents change only on explicit `integrate_subagent_patch` under their current write/Presence authority. Delegated Git runs use separate detached snapshots pinned by `refs/ouroboros/delegated/` and registered in `state/subagent_worktrees.json`; explicit disposition or custody-checked startup GC removes them, unreadable custody blocks GC, and a collected snapshot refuses `execution_snapshot_missing` (registration and retention: [PERSISTENCE](../PERSISTENCE.md)). Nested Git directories are excluded and disclosed; baseline construction vetoes credential-shaped files before hashing (`workspace_patch_capture.py`). `scope.root` is read-only authority; `execution.workspaceRoot` plus the typed binding, persisted before POST, names execution writes.

At terminal, `delegate_wait` durably captures the diff against the recorded baseline into task artifacts (committed bytes carry a disclosed `head_moved`); only explicit `integrate_delegated_patch` apply/reject disposes it, or a continuation that takes the snapshot over. A Git apply proves every touched path still matches `baseline_sha`, then applies and stages without committing; a SKILL-PAYLOAD target captures through the payload adapter and the parent-owned trusted index, applies live and queues the extension reconcile request. Protected-path gates cover only the Ouroboros body. Proven drift is the running nanny's conflict. A durable `delegate_run_patch_apply_started` precedes mutation; an unfinished intent yields `INTEGRATE_DELEGATED_APPLY_AMBIGUOUS`, requiring explicit `acknowledge_ambiguous=true`. `patch_verdict.py` alone writes both pipelines' `run_<rid>` verdict subjects (§1).

**Terminal products and their reader.** Reconciliation calls `delegate_integration.capture_terminal_patch_for_drive` for settled mutating runs and never applies; only a ready manifest earns `patch_captured`, and missing run evidence keeps the snapshot because writers may live. `delegate_custody.undisposed_patches` belongs to run and target beyond the creator's lifetime until a durable `PATCH_DISPOSED` names `disposed_by_task_id`. The starter retains live control: `delegate_shared._confirmed_retry_chain` grants settled-product access only to the current automatic retry leaf (shared roots, predecessor prose, stale evidence, review-owned runs, `CLOSED_ABSENT` and manual Continue grant none), and a successor's `delegate_wait` uses `retry_terminal_result`, never live supervision, cancel, answer or message. A writing continuation runs in its predecessor's undisposed snapshot: its STARTED row replays the predecessor as `superseded`, and the one cumulative patch is integrated once under the snapshot's single disposition lock. The unrelated live top-level orphan path opens only after proven owner terminality: apply requires exact active Git root/fresh payload binding or host-minted project containment (`<project>/contributions/<track>`); reject needs no fresh target grant. Missing, unreadable or unreaped owner facts retain custody without expiry.

**Custody disclosures heal from the write side.** Custody debt is a warning beside the earned rail, never a replacement of it: `delegated_custody_unreconciled` covers the task's own undisposed runs and `outcomes.custody_debt_axes` adds the warning without replacing earned axes. Readers never replay custody: the audit writers in `delegate_terminal.py` refresh the stored facts, unknown clears nothing, and frozen `delegated_runs_*` counters stay while `actual_substrate` follows live custody. Provider death plus debt stays Failed with the custody reason; clean plus debt does not increment `evolution_consecutive_failures`.

Disclosed delegated-isolation residuals: an orphan disposed by a non-owner writes its verdict under the disposer's task while the capture directory and the `PATCH_DISPOSED` row keep the owner's id, so the owner's acceptance packet will not list that verdict; the Git lock is task-drive scoped, so two nannies integrating into the same external tree can interleave, and the drift check turns the loser's apply into a typed conflict; a credential-shaped file the child creates fails the whole patch rather than shipping a partial diff.

### Own-body candidates

Ordinary body authors — a queued root, a direct turn, an evolution cycle — write a task-owned linked worktree of the serving repository, never the serving checkout, so unfinished self-change never enters serving imports. The candidate starts at the serving HEAD on branch `candidate/<task>` under the isolated worktree root, as a `kind=body_candidate` row of the worktree registry, which restores the binding across a retry, a Resume or a new worker. `prepare_self_change` prepares it explicitly; body writes, PR-integration verbs (`git_pr.BODY_WORKTREE_TOOLS`) and an acting `self_worktree` child reach the same preparation through `body_candidate.authoring_seam` before resolving any target; reads before preparation stay on the serving tree. Light mode, capped trees, subagents and the managed-update resolver get none; Cyber Pro may choose `in_place`; a body with no Git tree keeps in-place authoring.

Binding rewrites one fact — `repo_dir`, `system_repo_dir` and `branch_dev` of the tool context name the candidate — so every consumer, the review subject and `commit_reviewed` included, shares one identity under own-body policy; a candidate is never an external workspace, and `serving_repo_dir` keeps the running checkout for review governance, the restart marker and rollback. A process whose cwd is inside the candidate or its admitted own-body child copy runs in an isolated environment beside it (`<candidate>.env`, `test_environment.isolated_environment`: its own HOME and data root, no credentials or global Git config, pip only inside a venv), so a push, a provider call or a pip install outside a venv runs from a cwd outside the candidate; when it cannot be prepared the process is refused (`CANDIDATE_ENVIRONMENT_UNAVAILABLE`), not started with the serving one.

Ownership is the root task: a host-validated continuation inherits its predecessor's candidate, `prepare_self_change(resume=…)` selects one exact retained candidate, and either moves ownership only from a terminal owner whose ledgered processes are settled; nothing is inherited by room, name or date. Binding appends the candidate to the lineage's mutation baseline, so `commit_reviewed` stages what the task's own baseline attributes to it exactly as on the serving checkout; the commit is never auto-pushed. A candidate commit is version-neutral (every carrier span byte-identical to HEAD, no tag) or a numbered release (VERSION and every carrier in one diff, tagged); the release gate names the form from the diff, a partial carrier move is neither. Retention counts from last use: a candidate with no unique work expires; otherwise its files are captured on `refs/ouroboros/candidates/<id>` and the checkout is removed only when the capture is complete and the verdict still holds (`body_candidate.verdict_holds`); a nested `OUROBOROS_RETAINED.txt` marker keeps the process environment and source checkout.

Adoption is deliberate and restart-bound (`body_adoption.py`): `request_restart(adopt_commit=<sha>)`, or an evolution cycle's own restart, authorizes one exact commit that builds on the serving HEAD, came through the commit gate (Cyber Pro records the exception), keeps the entry files and the package-init hook and changes no path where the serving checkout holds uncommitted work; a constitutional change needs a numbered release outside Cyber Pro. The old generation never writes the tree: the carrying restart re-verifies under the update lock, and its exit tail arms only on the stop owners' own evidence that the old readers are gone, reading the engine pin the next generation selects from the candidate's file (`bound_candidate_file`) before the owned daemon's fate is decided (§9). The owner's Restart and Panic never arm or wait, because a stuck stop must not hold the owner hostage; evolution cleanup abandons only its own authorization, and crash recovery retains a reviewed candidate without authorizing adoption. The switch and its recovery are §2; `settle_on_boot` records `adopted` only for a generation that attested the switched tree before its imports, bootstrapped and is supervisor-ready.

The wait projection owner is `control_task_results._compact_child_projection`: status, nullable `accounted_upper_bound_usd`, `cost_final`, `capability_delta`, execution evidence and semantic result hash survive compact rendering. Oversized whole envelopes retain exact `wait-handoff` sources; explicit authority reads also merge execution and canonical verification receipts. A preview never certifies the unseen answer or host notice.

### Git and commit review

`pr_merge(number, expected_head_sha, method)` merges through the selected repository's `gh` identity at the exact head, never with force, admin or auto-merge; `merge_receipts.py` records intent before effect and keeps reviewed, current and merged as separate facts (a committed `base..head` ledger record named by `review_record_id`, else a `declared_only` declaration). An unknown or queued outcome is observation-only — exit status alone, transport loss or 5xx proves no rejection — a missing review is loud, never a veto, and shell or web merges leave no receipt. Only proven pre-effect failures release intent, including the exact full `gh pr merge` stderr matching its `canMerge` refusal (before the display cut); recorded unknowns are never reclassified. `list_github_prs` preserves its bound `gh pr list` selection and reads exact counts in one node-ID GraphQL query on the returned URLs’ host; unavailable counts withhold the list, never invent zero.

`mutation_attribution.py` captures the root-task baseline and projects the clean-at-baseline delta plus an adopted predecessor's exact retained changes; a changed pre-existing dirty path, a stale baseline or a failed scan blocks automatic staging for the panel to weigh. `commit_reviewed(paths=None)` stages only that attributed candidate, explicit paths must be a subset, and an empty candidate is `GIT_NO_ATTRIBUTED_CHANGES`; managed update transactions keep their separate whole-tree authority, and `predecessor_adoption` grants no review approval.

Commit, tag, post-commit tests and push each pass `owner_pause.run_operation`: Pause after review refuses an unsubmitted commit; an ordinary one handed off stays a success whose later steps report not started, and nothing resumes them: after Resume they are its author's explicit work, never a new commit. A managed merge keeps `postcommit_resume`; `commit_reviewed` rechecks its HEAD and a clean tree, then finishes its tests and smoke with no new commit or rollback (`git_managed_postcommit.py`).

A reviewed commit is bound to one staged fingerprint — the `git write-tree` SHA, ordered `HEAD` and `MERGE_HEAD` parents, indexed VERSION, expected `v{VERSION}` tag, any existing tag target and the binary staged-diff hash — re-read after the commit before success or push is recorded; an existing release tag is never silently accepted or retargeted. Every seat of the one wave inspects the same staged snapshot, any mutation stales the binding, and the author's early look (§6 Commit preflight) changes neither tests, wave nor binding. A managed-update resolution commit reviews the declared M0→S subject (`tools/review_subject.py`) while the gate binds S to the exact index write-tree. `release_sync.sync_release_metadata` projects version carriers during commit preparation; `VERSION_CARRIER_SPANS` / `substitute_carrier_spans` is the one span primitive the managed-update resolver and the packet's carrier cut share. BIBLE supplies review authority, CHECKLISTS the criteria and DEVELOPMENT the procedure; snapshot identity, the preflight fact, deterministic results, actor evidence and final Git identity describe one material.

A material ordinary Advisory outcome returns the complete result and the exact `review_reference` before commit, tag or push. Continuation through `commit_reviewed` / `vcs_commit_reviewed` with that reference and `author_disposition` binds the current attributed candidate, reruns the independent preflight, tests and Git checks and dispatches no critic; a settled handback is `reviewed/review_only`, pending custody stays `reviewing/late_wait` and collectible, and Blocking gets no author override. Evolution receipts record the wave's actual aggregate (`triad_scope_status`), never a PASS inferred from a successful commit.

#### Commit review evidence

`review_evidence.capture_commit_review_evidence` freezes the selected browser and vision calls and same-round image attachments, unavailable-image gaps included, once per attempt — after free admission, before the look and the wave — as one canonical task source handle: native reviewers read its ranges under the canonical root, sessions receive byte-identical bytes in an ignored `.review-drive/<task>/<sha>.txt`, packet-only reviewers a bounded, disclosed partial view. The trace keeps exact redacted arguments and the next visible response of the same execution; adjacency never attests visual inspection. A pending rejoin restores the same source from the frozen request, and cleanup waits for physical custody.

#### Hermetic preflight proof

Only the hermetic runner (`preflight_runner.py`) mints `ctx._preflight_test_proof`, after green lanes and containment; the proof binds the assembled tree and index, the pass specs, the isolated environment and the interpreter and Node identity. The candidate is one raw-bytes `git diff --binary … HEAD` capture; a capture or apply failure is the typed `PREFLIGHT_CANDIDATE_ASSEMBLY` block, never a test verdict. The node lane runs first (`preflight_node.py`: a missing or too-old node is `PREFLIGHT_NODE_MISSING` / `PREFLIGHT_NODE_TOO_OLD`, a red suite `NODE_TESTS_FAILED`, never a silent skip, because a gate quietly dropping a suite is indistinguishable from a green one), then the parallel and serial pytest passes under one budget (marker lanes: `LANE_EXCLUSION_EXPR`); a dead xdist worker or a missing plugin is its own named block, never a silent serial fallback. Every workload binds HEAD, since even a default-lane test may inspect committed history: an unchanged subject reuses the proof, a new commit needs a new run, a skip or a no-suite `None` is not green, and a restart loses the proof. An unproven lane's teardown retains the temp tree and its Git registration, because deleting inputs under surviving processes would destroy custody.

#### Commit preflight

`preflight_review(commit_message="...", deterministic_only=True, source="worktree" | "index")` returns free diagnostics before sync, staging, review-state access, provider checks, tests or fingerprints. `commit_admission.release_metadata_diagnostics` evaluates the selected source's current VERSION, carriers and P9 limits. The release report identifies its source, status (`clean`, `blocked`, `unavailable`, `not_applicable`) and findings; it grants no review freshness and writes no history. A separate `book_balance` field labels its bytes as worktree and uses `reference_books.py` to show the cached official development merge-base or unknown contribution. Book growth never changes the release status or blocks a local commit; syntax and critic review do not run here.

The author's preflight is one look, not a pipeline: `commit_reviewed(preflight_reviewer="<row>")` names one enabled catalog row by id or handle, pool member or not (an unknown or disabled row is a `TOOL_ARG_ERROR` before staging, `commit_gate.preflight_reviewer_error`), and after the free checks and the tests the gate runs `review_change(subject=worktree, surface=preflight, reviewers=[row])` on the system repository (`commit_gate.run_commit_preflight`), before the wave. The look informs and never gates: its record carries `surface=preflight` in its reuse key, so it never answers the commit panel, and the commit record's `preflight` fact names it — `performed` with record, row and aggregate, `not_performed` without the argument (a plain fact, not an audited bypass), `skipped` under `skip_advisory_review=True`; a row named beside the skip or an author continuation is a `TOOL_ARG_ERROR`. The look counts against `review_change`'s paid-cycle cap and holds no commit custody; `review_status` reports the checkout's newest look (`review_ledger.latest_preflight_record`) and whether a later worktree edit staled it (`stale_from_edit`). `preflight_review(reviewer=…)` (`tools/preflight_review.py`, `advisory_review` alias) is the same look standalone, without tests or release-metadata sync.

The free checks (`commit_gate.deterministic_preflight`) run on every commit, a skip included: size headroom and worktree readiness as information and warnings — the touched books' balance among them — then release metadata of the staged index and the syntax of staged `.py` files. Only release and syntax findings block; readiness lines go to the owner's progress and the events log. Edit/plan results also expose the book balance before a paid call. The test preflight runs unless `skip_tests` — a documentation-only diff included, because documentation has tests too — while a managed resolution always pays it. The reviewed-commit cycle (`git_review_cycle`) checks authorization and unresolved prior work before staging, binds the exact candidate before free-cycle and budget admission, and revalidates the index and worktree snapshot before the wave. `review_status` reports open debt from `state/advisory_review.json` (`review_state.py`) as a retry anchor, never an admission gate, and no surface projects a `repo_commit_ready` verdict from it.

### Review stack

`review_cycles.py` owns the shared paid-cycle ceiling `OUROBOROS_REVIEW_MAX_CYCLES` (a positive integer or `unlimited`; anything else fails closed to the shipped default; §7). One number, four gate meanings: paid reviewer-panel cycles per task for plan review; paid panel runs per task for acceptance, independently of author responses; paid review waves per root task for the commit gate, counted from the attempt ledger at dispatch, so the ceiling counts money and only undispatched attempts stay outside it; paid panel dispatches for skill review. Byte-identical material replays each gate's recorded verdict for free; a dispatched technical failure consumes capacity, an undispatched refusal or a collection does not. The last allowed panel still permits an author reaction; an explicit task-local `max_improvement_passes=p` keeps its p author responses and p+1 paid ceiling, and `unlimited` removes only the paid count, not the ordinary task rails (§10 invariant 17).

#### Physical custody

`review_custody.py` owns the physical workers under `review_substrate.py`, with no task scheduler and no second timing ledger: operation ids and the live map keep in-flight work from reading as idle while deadline, budget, cancellation and ceiling still bind. API and thread calls disclose `in_flight` and collect a late answer before any retry; a settled terminal API error stays replayable, so siblings cannot erase it or dispatch twice (late results: §6 Late completion and typed refusals). Capture state proves custody, never a synthetic id: `dispatched|unresolved` without a terminal HTTP status is custody-lost and no-resend (`usage_accounting`), and only an explicit `__cause__` or typed transport metadata proves pre-dispatch, not an inherited `__context__`. Provider transport defaults are not review-reasoning limits; timeouts narrow to the owner deadline and the finalization reserve. A returned response or typed terminal error settles even when empty; post-dispatch socket death is `provider_outcome_unknown`, never another paid route; a spent owner window refuses at $0 before fan-out; a reviewed commit has no outer tool cutoff, so foreground custody lasts to settlement.

#### Paid stamp and owner custody

The `paid` fact behind the ceiling is recorded write-ahead at physical dispatch (`review_dispatch.py`): a gate installs one once-only `ReviewPaidStamp` for its wave and each delivery stamps at its own boundary — a packet row, a native episode's paid send, a session's replayable `START_REQUESTED` row. Assembly-only refusals exit before that seam, so a $0 attempt stays outside every ceiling, and neither a worker outliving its caller nor a crash after dispatch loses the fact. The stamp is idempotent across the wave's concurrent deliveries, so each seat waits for the write's result before starting its transport; commit review, `review_change` and task acceptance treat a failed write as fail-closed, skill review only when resuming a wave, and other callers keep fail-open accounting. Task acceptance binds one exact-hash tree-wallet claim per panel to the same stamp, because the paid identity is material, not route; a wallet or cancellation veto at the claim releases the reservation and no row's transport proceeds (the launch floor: §6 Task lifecycle). Residual: a compatibility transport that raises with positive physical capture before entering the canonical marker is stamped after the send, and when the tree's last paid cycle is consumed concurrently at that late stamp the wallet refusal replaces the captured exception and the substrate may resend.

Before the wave starts, one locked write records `paid=True` with the reserved seat roster and operation ids in the commit-attempt row; a delegated seat patches `pending_invocation_id` before the provider POST, and a missing or mismatched operation on resume is `custody_lost` under every enforcement mode. The stamp records the server session and pid owning the reviewer threads (`review_owner_custody.py`): owner loss is proven by pid death, never by elapsed time, because a TTL would convert waiting into resend authority.

Delivery is a property of the catalog row — `delivery: native | packet` on an API row, while a session row always retrieves — read by `reviewer_slot_config.review_pool_slots` (§7 Review pool). The one shared session target is `OUROBOROS_REVIEW_SESSION_ROUTE` (`review_execution.REVIEW_SESSION_ROUTE_ENV`), an opaque `harness[=model][:effort]` spec that falls back to `OUROBOROS_SUBAGENT_HARNESS` when unset, so one delegated route is configured once; a set but unparseable value turns review sessions off with a warning rather than silently re-routing them.

#### Surfaces and money admission

The review surfaces:

- Preflight (`review_change(surface=preflight)`) — the author's optional one-row look before the panel (§6 Commit preflight); it informs, never gates and never answers the commit panel.
- Change review (`tools/review.py`) — the pool's seats cover the layered Change Review Checklist (the Ouroboros Body Layer joins the universal core on the body; `review_helpers.load_checklist_layers`) with JSON findings under `config.adaptive_quorum`. A packet seat answers contract A (`triad_review.REVIEW_JSON_ARRAY_CONTRACT`, the findings array); a retrieving seat answers contract B (`REVIEW_TWO_PART_OBJECT_CONTRACT`: `{change, change_clean, coupling}`): one wave, two questions, one quorum over the seats that answered (`review_ledger.reduce_verdict`, shared by the gate and the record).
- The coupling question (`tools/review_brief_coupling.py`, Part 2 of the retrieving seat's brief) — intent, scope and coupling across the whole repository, asked of every retrieving seat of the same wave; there is no separate scope role (§6 The coupling question).
- Parallel orchestration (`tools/parallel_review.py`) — two-phase admission: the packet is fit-checked and every brief built before any reviewer dispatches, so a deterministic assembly block anywhere spends $0 (a seat paid while its sibling was doomed is real money for a half-verdict). Money admission (`tools/review_admission.py`: `admit_commit_gate_wave`) prices every paid seat, as disclosure, under its substrate's usage scope and admits the wave through `review_wave_budget_gate(surface="commit_gate")` while known spend is below the global `TOTAL_BUDGET`, the root and the billing-group fences; a refused wave records `$0 not_dispatched` on every seat plus one `review_wave_budget_insufficient` event naming the `binding_axis`. Admission is a read-only pre-check — per-seat reservation stays the enforcement, so a fence reached mid-wave refuses the remaining seats with truthful custody — and an admission that raises is fail-open but loud (`review_wave_admission_unavailable`). An agent-session row rides the owner's subscription and is neither priced nor waited for.
- Shared helpers (`review_helpers.py`, `triad_review.py`) — packet and brief building, checklist loading, JSON extraction, usage events and reviewer actor records.

A free refusal never wears the form of a verdict: a $0 exit is a typed `not_dispatched` fact with its reason, never a DEGRADED panel or a synthetic actor, and a request never sent is one seat with `operation_state='not_dispatched'` that stays in the denominator. Part 1 catches line errors; Part 2 catches cross-module contracts, from the same seat over the same staged snapshot (managed updates: M0→S), so one answer cannot hide the other. Task acceptance (§6 Task acceptance) shares quorum and transports, asks no coupling question and stores its verdict apart from the terminal result.

One pool, many subjects — who calls the wave and what each seat is asked:

| subject | caller | questions |
|---|---|---|
| the body's staged index (a commit) | `commit_reviewed` — the gate | every pool seat: the change part, the coupling part on every retrieving seat; Cyber Pro composes from the pool and records the reason |
| the body's live worktree before a commit | `commit_reviewed(preflight_reviewer=…)` / `preflight_review(reviewer=…)` — the author | one named enabled catalog row, the same two parts by its delivery; informs, never gates |
| any root's `index` / `worktree` / `base..head` | `review_change` — the mind, by judgment | the same two parts under the root's layer; `reviewers` adds seats on the body outside Cyber Pro and composes the panel elsewhere; `coupling_only` critics answer `[coupling]` outside the quorum |
| an intention | `plan_task` — plan review | the Plan Review Checklist, every pool row |
| a skill payload | `skill_review` | the Skill Review Checklist, every pool row |
| a task result | `task_acceptance_review` and loop acceptance | the acceptance question only — a root: every pool row; a child: at most one (`reviewer_slot_config.child_acceptance_slots`) |
| the running system | `/review` — `review_change(subject=system, surface=system)` | the deep self-review report from one enabled catalog row (default Main); no verdict question |

**Council and review are two mechanisms.** A council is children the mind schedules (`schedule_subagent`, `forward_to_worker`) to argue what should be done, before a review; a review is the pool's independent voices asked whether it was done right, on one exact frozen subject, recorded in the ledger. Both may serve one commit: a council's outcome is attached to the subject as evidence and never becomes a verdict, no finding is erased by a vote, and a scheduled helper never wears a seat's name. There is no consensus round and no third organ; the question reopens only on recorded evidence — the action over the subject having landed, blocking records in which one seat's critical FAIL against a passing rest spent the cycles and the owner decided (with frequency and cost), councils convened unasked on intentions that then go to the panel, defects found only in reviewer dialogue, or a false-critical share that dominates review cost — and then as an optional blind-first cross-check round of the same panel after `review_change` lands, where only the raising seat may withdraw its finding and nobody votes.

**`## Review`.** The mind sees the review pool its task's settings snapshot serves as one semi-stable block after `## Available subagents` (`subagent_runtime.review_facts_block`), read through `reviewer_slot_config.review_pool_slots` in the task's settings scope, never the last execution. It states the `source` (`structured`; `empty` — a readable catalog with no marked row, `pool_empty: true`, never a default panel; `error` — a malformed catalog or the refused migration of this document), `enforcement`, `enforcement_blocks`, the runtime `mode`, one `rule` sentence, per seat its `seat_id` (the stored row id the records carry), `subagent_id` (the catalog handle), `model`, `effort`, `delivery` and `cost_hint`, and `surfaces`, who reviews where. `coupling_unanswerable: true` (no seat reads the repository, so every commit-gate review ends `NOT_PERFORMED`) is a block fact kept through any shrink; `pool_without_credentials` / `no_pool_row_has_credentials` carry the facts `GET /api/review-pool` and Settings → Agents show; `migration_snapshot` names the migration receipt that decided this document. `## Review records`, the task's newest ledger records, rides in the changing part with a bounded `omitted.records`.

#### Subject operation

The review wave is parametric in its subject (`tools/review_subject.py`). A `ReviewSubjectSpec` names the root (`system_repo` or `active_workspace`), the kind (`index`, `worktree`, or `base..head` with base an ancestor of head), the surface and the checklist layer; `freeze_subject` pins it once as a `FrozenSubject` (the diff, its `diff_sha`, both trees). Governance is always the installed body's (`governance_root`: the serving checkout; a bound body candidate is a subject, never the source of its own rules), while the reading root is the subject's.

Exactly one subject is read on its live root: the gate's own (`is_gate_subject`: the system repository's `index` against HEAD with no explicit base), through the gate's own capture (`capture_staged_diff`), so its packet, brief, seats and decision are byte-identical to the gate's. Every other subject is materialized by `isolated_checkout`: a detached worktree at the parent with the frozen patch applied to its index, under the install's data root (`state/review_checkouts/<token>/repo`) at the path of the task's round (`checkout_token`), so a rerun of the round reads the checkout an earlier wave's open custody retained; it is removed on exit unless custody stays open. Every delivery — packet, brief, the `-U0` fit rung, the required-source manifest, the retrieving seats' checkout — reads the frozen subject, never a recapture of a live index. A frozen subject that is not the body's own index skips the body's release preflight: the core layer is a foreign root under the body's rules, not the body's release contract.

Three identities derive from the frozen subject, never from the live index of whatever repository the process runs in. (a) The reuse key (`review_reuse_key` → `review_ledger.reuse_key_digest`): surface, subject, rules, layer, composition, enforcement, contract and the logical round; a settled, dispatched record with the same key is returned instead of a wave (`review_ledger.find_reusable`, `reuse_or_none`: `reused=true`, $0) unless this task's own operation of the round is still open, which is collected first; a pending or `NOT_DISPATCHED` record is never reused. (b) The logical round (`review_round_sha` → `review_ledger.round_sha_of`): what the author asked this time of these bytes — rebuttal, questions, goal, scope, base and head — so a new rebuttal or a changed brief is one more paid review while the identical request is the settled record; the identical-diff refusal (`commit_gate.check_identical_verdict_refusal`) lets a new rebuttal through exactly once, and the paid-cycle ceiling (`check_review_cycles_ceiling`) stays common to the root task per `(repo, tool)`, so a second subject under an exhausted root is refused, not reset. (c) The retry key (`review_retry_key`; the gate's key has no round suffix) is the identity of the physical operation custody keys attempts by (`review_custody._attempt_key`), set before any dispatch: a retry of the same round rejoins or replays the same physical review and never pays twice; a new round is a new operation that never receives the previous round's answers. The rejoin is durable (`tools/review_change_custody.py`): a rerun finds the write-ahead attempt row by retry key (`pending_round_attempt`) before any reuse lookup, ceiling check or payment and runs the gate's reconcile-only path (`arm_rejoin`: settled seats replay, the pending seat is rejoined by its exact invocation, nothing new is sent, the same record is revised), in this process or after a restart. The record of a parametric wave names the frozen subject and carries `fingerprints.reuse_key` / `fingerprints.retry_key`. Same head with a different base is a different subject (§10 invariant 30).

#### Change review on any root

`review_change` (`tools/review_change.py`) is the commit gate's reviewer wave without the landing: one subject, at most one paid wave, one ledger record (`surface="change"`), nothing committed and no test run (`tests.policy=NOT_RUN`; the author attaches test results separately). The mind calls it by judgment; nothing starts it. It reviews the active workspace (default), the system repository or a `workspace_root` admitted by the `schedule_subagent` folder policy, frozen once and read in an isolated checkout unless it is the body's own staged index (§6 Subject operation); a deterministic call error (an incomplete `base..head`, an unregistered folder, an empty change) is a `TOOL_ARG_ERROR` before any reviewer is paid. The checklist layer follows the root's `body_fact` (`layer_for`), and `treat_as_body` raises only an `unknown` root. Composition follows the same fact: on the body outside Cyber Pro the owner's saved rows stand and `reviewers` only adds seats (a named subset is recorded `reviewers_subset_ignored`); on the body in Cyber Pro and on every other subject `reviewers` is the panel (`composition=composed`; omitted = `full_pool`), `reason` is recorded, and a narrowed panel without one records `reason_missing=true` rather than failing. The counted seats of a composed panel are marked pool rows, the owner's menu; an enabled catalog row outside the pool is seated as an added critic (`additional`, outside the quorum), and a composition naming no pool seat is a `TOOL_ARG_ERROR`. `commit_reviewed(reviewers=…, reason=…)` composes the commit panel through the same composer (`commit_gate.compose_commit_panel`), refused before anything is staged; the composed seats reach every pool reader of that wave as a context-local override (`reviewer_slot_config.composed_review_pool`) rather than an argument, because the gate's slot readers have no argument path — the one disclosed contextvar seam the plan-review rule excepts (DEVELOPMENT "Loop / State-Machine Changes") — and a concurrent wave keeps the configured pool. `coupling_only` critics answer only the coupling question (`review_ledger.seat_parts`), outside the quorum; `reviewer_effort` orders this wave's strength; `author_questions` reach the brief and the record verbatim. The identical request returns the settled record at $0, a `review_rebuttal` buys a new wave, and an undecided record is collected, never reused. Paid waves count against the shared cap per root task and (reviewed repository, `review_change`), apart from the commit gate's count; exhaustion is the typed `review_cycles_exhausted` with a `NOT_DISPATCHED` record and meets only a new paid wave, never an open operation's answer. Enforcement is recorded on every root; only the body under Blocking records `enforcement_blocks=true`, so another root's FAIL is information, never a lock. `commit_reviewed` / `vcs_commit_reviewed` stay the only landing in the system repository: their `root` accepts only `system_repo`, and any other root is a `TOOL_ARG_ERROR` pointing at `review_change` and ordinary git.

#### Review ledger record

Every commit-gate and `review_change` wave (surfaces `change`, `preflight`, `system`) leaves one durable record (`review_ledger.py`; `state/review_ledger/<record_id>.json`) stating what was reviewed (`subject`: root kind, tree, diff and parent binding, candidate branch), what the panel was asked (`brief`: goal, scope, the two parts, the author's questions, the checklist layer with its `body_fact` / `how`), who was asked (`panel`: `seats` — the assigned seats, the quorum's denominator — and `additional_seats` for added critics; `distinct_models` over normalized observed models, where an unobserved seat is `unknown` and never a distinct model; `composition` ∈ `full_pool` | `composed`, `chosen_by` ∈ `owner` | `author`, `reason`, `reason_missing`), what each seat was asked and observed to run (`rows[]`: requested, effective and observed model kept separate, `parts`, status, coverage, cost, `source_refs` to the retained brief and raw answer), and how the gate read it (`verdict`: one of `PASS | FAIL | NOT_PERFORMED | QUORUM_FAILED | NOT_DISPATCHED` from `review_ledger.reduce_verdict`, with `per_question.change` and `per_question.coupling`), beside `author_decision`, `tests`, `preflight`, `dispatch_refusal`, `cost` and the contract and binding fingerprints. `review_wave_id` (`review_records.resolve_review_wave`) makes the record, the usage ledger and the reviewer actor rows name one wave.

Honesty rules: `pending` keeps `NOT_PERFORMED` until the same attempt settles and raises `revision`; stale snapshots cannot overwrite newer ones. Pre-dispatch refusals are `NOT_DISPATCHED` with `dispatch_refusal`; author continuation buys no record. The canonical-root record follows the typed result and aggregation, never feeds gate authority. Before indexing (`state/review_ledger/index.jsonl`), `artifacts.store_actor_source_bytes` retains each brief/answer; only rows with resolvable records and sources lose heavy fields, segments rotate at `INDEX_MAX_BYTES`, unresolved rows stay whole (§10.1). `review_record_id` links attempt, `review_reference`, tool result and same-wave slot history; `review_ledger.load_record` reads it. Ledger → `review_projection` → task/UI preserves typed primary and cleanup causes: local authority failure stays local beside withheld rows. Reported seat `usd`, zero included, survives pending/failure; absent/estimated spend stays null. Wave cost sums known amounts and flags missing amounts `unknown`, never billing finality or a verdict.

#### The coupling question (Part 2 of the brief)

The commit gate runs one wave with one role, the seat, and one quorum. Every assigned seat receives one brief by its `parts` (`review_ledger.seat_parts`): a packet seat `[change]` (contract A); a retrieving seat — native API or delegated session, in every context mode — `[change, coupling]` (contract B, one object `{change, change_clean, coupling}`); a `coupling_only` critic of `review_change` `[coupling]`, outside the quorum. `config.adaptive_quorum(len(assigned))` counts the seats that answered at least one asked part once, and `review_ledger.reduce_verdict` decides the aggregate for the gate and the record alike (`per_question.change` / `per_question.coupling`); an unperformed coupling question never permits aggregate `PASS`. A native API seat keeps its configured identity, route, account pin and effort while the surface selects inspection delivery.

`review_admission.build_two_part_brief` is the pure builder, callable outside the gate; for the same frozen subject and intent it renders byte for byte the text a wave's seat is sent. `scope_required_sources.py` declares the change-relative reading minimum: touched protected runtime, prompts and frozen contracts, protection-owned families (`GIT_OPS_FAMILY_PATHS` and tool-dispatch leaves) and declared Python/browser contract twins. An ordinary touched file needs no whole-body obligation, because the diff carries its complete change. Each row binds the exact identity a read receipt stamps (`source_revision`, `complete_sha256` / `complete_chars`). `required_sources_ref` and `SCOPE_REQUIRED_SOURCES_POLICY` bind the manifest into the review-contract fingerprint (`commit_gate.commit_review_contract_fingerprint`), so replay authority cannot survive a changed contract. The minimum never restricts further reading.

Coverage records what could be observed — native receipts match source identity and delivered ranges, sessions fold weaker journal evidence over the same rows — as `complete`, `incomplete`, `declared_empty` or `unobserved`; a changed source is a `source_gap`, and inline delivery never proves understanding. `review_context_atlas.repository_index` supplies orientation only: no bodies, no spend, no limit on what the reviewer may open. The reducer keeps received findings and counts responding seats through `config.adaptive_quorum` independently of coverage: reading gaps stay diagnostics that change no status, block no commit and buy no paid review, and the agent judges whether a gap needs more reading. Critical findings follow `OUROBOROS_REVIEW_ENFORCEMENT`; a defective `coupling` block is recorded against that question alone while the seat's `change` answer still counts, and oversize requests, route and candidate-binding failures never become PASS. Retrieval keeps the reading obligation proportional to the change instead of letting repository size decide whether review can occur; if the change cannot fit a reviewer, split the change rather than weaken the reviewer.

#### Governance delivery

`tools/governance_context.py` owns the shared tiers for every change-review seat (both parts, on every surface a pool seat serves) and for deep review, switched by one fact, the checklist `layer` (`review_body_fact.layer_for`); the governance root is always the installed system repository, because a proposal cannot replace the rules it is judged by. In the body layer tier 1 inlines BIBLE.md, CHECKLISTS_ARCHIVE.md and the executing code's CHECKLISTS sections (the surface's own and `Shared Contract Ownership`); tier 2 selects the review-protocol chapter, DESIGN for `web/` changes and the DEVELOPMENT chapters naming touched files, within `runtime_limits.REVIEW_GOVERNANCE_INLINE_SHARE` of the usable window; tier 3 gives book navigation for ARCHITECTURE, and packet rows may inline relevant sections within the same share. In the core layer (the subject is another repository) tier 1 is the surface's universal section alone, the body's books are recorded `not_applicable` and never delivered, and the navigation indexes the subject's own documents (`subject_root`) plus its required-source manifest, empty by rule because every rule of it names a body file. Each non-inlined document has a manifest disposition and a navigation pointer; retrieving rows follow them, and tool-less packet rows receive an index of undelivered material, never an instruction to call unavailable tools.

**The body predicate.** `ouroboros/review_body_fact.py` answers one question for a change review: is this root Ouroboros's body? `body_fact` returns `BodyFact(body ∈ {true, false, unknown}, how, detail)`, and `layer_for` maps `true` to the body layer and everything else to the core. `how` records the git fact that settled it (recognition order and the `false` and `unknown` cases: the module docstring); the branch never takes part, and no directory, branch or remote name is matched by pattern (P5). The mind may raise a recorded `unknown` to `true` with `treat_as_body` (recorded in `detail`; nothing lowers a recognized body). The plan-review `constitutional` fact is the same predicate asked of a declared `affected_paths` locator (§6 Plan construction and review). `review_checklist.checklist_fingerprint(layer)` records which rules ran: the sha256 of the layered text and `rules_source` = `docs/CHECKLISTS.md` at the install's blob, because the installed body's rules execute.

### Planning, deep review, reflection, memory

Plan review, task acceptance, commit review and deep self-review answer different questions and never inherit one another's authority: they respectively judge a proposed approach before implementation, the delivered objective, a staged self-change and the whole system. Post-task reflection and memory persistence learn from execution but approve none of those boundaries.

#### Plan construction and review

`plan_task` reviews intentions for code, research, deliverables and actions (BIBLE P3). Subject paths resolve against `active_repo_dir_for`; governance comes from the system repository.

A plan is `constitutional` only when declared changed paths resolve inside the system repository outside recognized skill payloads, including files yet to be created. Reading a file or mentioning it in `affected_resources` grants no such status. Constitutional plans carry full BIBLE and Architecture, inline for packet delivery and as mandatory reads for retrieving sessions; missing either is a typed assembly failure. Other plans carry heading-derived navigation and resolvable pointers (§6 Governance delivery).

Optional `reviewer_effort` orders this panel above row pins through `plan_review_slots`; other surfaces keep their rows. With no order, row effort or `REVIEW_POOL_DEFAULT_EFFORT` applies. `ouroboros/tools/plan_evidence.py` resolves bounded evidence against the active workspace and system repo. Reviewer `need_evidence` locators follow that same path next cycle, with omissions still sent to reviewers. Manifest hash, full spec and constitutional status bind the wave; exploration logs do not. Continuation uses each reviewer's exact recorded artifact or sticky session. A packet that no longer fits can be freshly delivered with `capability_delta`; a changed roster or absent exact reference needs a fresh panel, but an unreadable recorded reference refuses `plan_review_exact_artifact_unavailable`.

Own-room evidence (`ouroboros/dialogue_evidence.py`, `ouroboros/tools/plan_dialogue.py`) captures retained dialogue, progress and addressed owner mail, with gaps explicit, as a redacted immutable `task_source` bound to the author request. Dialogue bypasses ordinary evidence bounds but may yield rows when the window cannot hold it; the immutable core refuses rather than truncates. Its snapshot is an observed source, not a required-source manifest.

The pool's reviewers return `blocking` findings tied to `breaks`, `note`, or `need_evidence` locators/spec questions. The host validates membership and discloses demotions; failed seats remain in the adaptive quorum denominator. `plan_spec.py` computes DEGRADED below quorum, REVISE_PLAN at a blocking quorum, REVIEW_REQUIRED while any blocking finding or undispositioned evidence request stays open, and GREEN only with quorum and an empty open set. Notes do not alter verdicts. Each reviewer adjudicates its own findings; unverifiable claims are questions/notes, and premise criticism or simpler alternatives are suggestions for the author.

`plan_review_state` is a bounded result index; `plan_review_artifacts.py` retains full waves, specs and manifests. Missing recorded authority is infrastructure failure, never empty claims. An author-selected revised subject stays separate from its historical critic wave and inherits no verdict. `closed_plan_review_wave` means critic closure. The paid roster, policy and prepared inputs freeze at dispatch, so collection never substitutes current Settings.

The dispatch barrier (`ReviewRequest.drain_deadline`) returns an open wave while workers keep custody. Any paid in-flight seat keeps DEGRADED with `review_late_result_pending`, even if settled seats meet quorum: a late blocker must not arrive after false GREEN. Last settlement wakes the task through its mailbox. `plan_review_collect` is the sole wave writer and collects existing results at $0. It records the packet actually dispatched; later directives reach reviewers only on a new send. Same-spec cycles retain still-open findings of terminal absent seats (`carried_absent_answer`), so silence cannot manufacture GREEN. The finalization gate makes one free collection in every enforcement mode; context health discloses an open wave without collecting it.

`plan_spec.closure_after_disposition` owns closure. GREEN closes in either mode, and evidence requests can close by a disposition-only call. A below-quorum blocker closes under Advisory only by a reasoned rejection: accepting it would acknowledge a broken plan. Blocking instead needs a reviewed changed spec or that reviewer's later retirement. Hurry changes none of this. An emptied REVIEW_REQUIRED becomes GREEN with `closed_by_disposition`; REVISE_PLAN never closes by disposition.

`OUROBOROS_REVIEW_MAX_CYCLES` counts physically dispatched waves, not $0 `not_dispatched` attempts. Before superseding, collection visits pending waves; committed custody with no cycle room holds as `PLAN_REVIEW_IN_FLIGHT`. One dispatch health snapshot skips only positively spent lanes at $0, keeping them in the denominator; unknown health dispatches. Unavailability, invalid state, money and deadline refusals never substitute for GREEN.

The retained report (`memory/deep_review.md`) is historical evidence, not a current-tree verdict: its provenance header records `generated_at`, and `source_revision=unknown` is explicit because a delivery captures no frozen Git revision; context quotes a disclosed excerpt and leaves the stored report intact.

### MCP and browser-facing external tools

`mcp_client.py` owns configured HTTP/SSE and local stdio MCP discovery and invocation (HTTP surface `gateway/mcp.py`; tool names `mcp_<server>__<tool>`). HTTP/SSE entries validate URLs and auth headers, URL userinfo is masked through the shared secret projection (`secret_masking.py` owns the MCP token placeholder shapes), and nested MCP secret values never migrate silently. Stdio entries pass one executable `command` and an exact string `args` list to the MCP SDK without a shell; optional `cwd`, literal `env` and `env_from_settings` (environment name → existing setting key) resolve from the same saved configuration for discovery and calls. Unknown fields are retained with a visible not-applied warning while a valid server stays usable; invalid known fields produce `MCP_CONFIG_ERROR`. Discovered tools join the selected initial capability envelope beside enabled, granted extension tools, behind the same `network` resource gate as on a managed task, and a discovery failure is an explicit capability omission through `list_available_tools`. The catalog lookup (`MCPManager.resolve_tool_name`) precedes the paid safety check: an unlisted, disabled or, outside Cyber Pro, allowlisted-out tool is refused typed (`UNKNOWN_TOOL`, `MCP_UNAVAILABLE`, `ACCESS_BLOCKED`) without safety, transport or a refresh, and a hit rechecks settings before Safety to honor revocation. Descriptions and results remain untrusted data; every call still crosses registry, resource, safety, timeout and result-handling policy. `web=false` alone does not disable configured MCP or extensions; explicit `network=false` and tool disables are enforced at discovery and dispatch.

Browser tools use thread-sticky Playwright/greenlet sessions. `browser_call_scope` binds the invocation’s generation before safety checks; only its own replacements advance it. Timeout retires that generation, whose owning thread closes it after settlement; late calls cannot adopt or close a newer session. Retired sessions are capped, refusing overflow as `BROWSER_BACKLOG_RETIRED_SESSIONS`. Synchronous hangs still need the outer timeout; process-isolated workers remain future work. Setup disables the `iframe.contentWindow` stealth evasion because it broke srcdoc widgets. Successful page, screenshot and evaluate results disclose their generation’s actual engine/version/stealth as a host note beside clean `producer_text`; anti-bot effectiveness is unmeasured. Chromium is the default; WebKit and device descriptors are targeted tools for a real Safari/iOS risk, not a universal acceptance matrix.

Browser target policy is `browser_policy.py`: owner-control admission uses the actual HTTP request and three-valued service identity, never JavaScript substring guesses, a per-request LLM or a second policy engine. Cyber root/acting requests retain target and control reach; explicit read-only assignments keep their restricted contract. A live binding in `state/server_port.bindings.json` proves an endpoint ours; recorded expectations (`state/server_port`, `state/server_process.json`, the Host Service configuration, the local model's custody row) name what is expected, and a matching expected endpoint whose process cannot be verified is refused as unknown, never treated as foreign (`server_process.runtime_service_identity`). Every other port is an ordinary target; a restricted target that DNS cannot classify is a typed `BROWSER_POLICY_UNAVAILABLE` refusal before navigation. Browsers follow HTTP redirects natively and route callbacks see only the first URL of a chain, so `tools/browser.py` re-checks each document's `redirected_from` chain with the same target predicate before any page result: an allowed→blocked→allowed redirect withholds its content and refuses actions on that document, while the forbidden hop's request has already been dispatched, a disclosed residual, not a pre-request or DNS-rebinding guarantee. Cookies, POST semantics, service workers and native redirects are untouched: no proxy, CDP fork, pre-probe or refetch.

`usage_accounting.py` owns monetary policy over physical attempts: `reserved → dispatched → settled | unresolved`, or pre-dispatch `reserved → released`. Final prices and releases are immutable; an exact-attempt receipt may refine a nonfinal price. A price or retained bound evidences zero; empty or unpriced rows do not; unknown never becomes sticky-final. Summary, reflection and consolidation share a frozen ledger snapshot; the final terminal checkpoint alone owns final cost, and a read failure is unavailable/null, never zero. `terminal_cost_reconciliation` settles open attempts after the task from receipts first, then owned-engine HTTP, keeping late-receipt rights; `root_phase_checkpoint.accounting` retains the cumulative ledger observation, explicitly null on failure; neither proves an invoice. Unknown spend remains the `unknown_unmetered` field, not a third accounting status. The pacing checkpoints carry `resource_facts` (tool counts, producer-reported durations, ledger buckets, the unreserved global remainder); prompt and checkpoint show the same facts, and no argv, stdout or sleep/poll classification selects behavior. `swarm_efficiency.fanout_count` and `fanout_interval_sec_total` count observed fan-out emissions and the gaps between them; neither infers work waves or child-wait time.

**Planning threshold** (`task_pacing.py`). One unreserved `CostCeiling` (`disabled`, `active`, `exhausted_soft_land`, `unknown`) supplies loop checks and `in_task_cost_ceiling`. Ordinary tasks have `no_default_cost_stop`; explicit `cost_hard_stop_pct` selects the lesser of a global-remainder share and root-cap margin. A producer allowance, such as a wake's remainder, stops at its actual value. Descendants inherit the root's authority; cold restores re-read it and retain an unreadable policy as `legacy_policy_unverified`, never widen it. Monetary admission is separate.

`loop_budget._check_budget_limits` runs after unfinished spending rounds, with or without tools, but never adds a paid final after READY. Eligible tasks pause. Other actors use a priced terminal rail only when an explicit profile permits and money admission fits (`budget_wrapup_unaffordable` otherwise); producer or unverified limits end with an unpaid host notice. Unknown price fails open, unknown spend is not zero, and an affordability probe reserves nothing. `_usage_cache_splits.py` reuses settled exact-route cache observations for estimates. `task_pacing.main_loop_wire_options` owns the complete outgoing shape; pre-send identity drift refuses `forced_candidate_drift`, with one ledger-priced unpredicated terminal retry so the answer is not lost.

#### Exact budget pause and Resume

`budget_pause.py` parks pooled and direct work under the same task id on monetary rails without buying a final answer. Raising a budget wakes nobody. Missing durable task/root/continuation ownership retains terminal behavior as `exact_pause_unavailable`. The module owns the ordered protocol: close and persist the dispatch fence before waiting; retain the nonterminal worker until already-sent reviews and late tool futures settle; capture exact cognition through `owner_wait.continuation_state`; then `events_budget.install_exact_budget_pause` durably parks the queue row. A root fence covers the tree. Failed publication holds rather than claiming a pause, and only Stop/Panic/deadline/cancel may abandon it. Delegated runs require `cancel_and_verify` because pre-terminal subscription coverage is unproven; unknown stop grants no second writer. Resume retains unanswered-call evidence as execution-UNKNOWN rather than replaying effects.

The canonical live-pause row outranks replicas and the queue mirror. After death or restart, `worker_health`, `queue_snapshot._park_pausing_running_rows` and `workers.kill_workers` finish or re-park saved pauses; an unrestorable one remains `_budget_pause_hold`, never a dropped task or crash retry.

`POST /api/tasks/{id}/resume` reaches `budget_resume.grant_exact_budget_resume` through `queue_transitions.resume_budget_paused_task`. A fresh strict ledger/tree read must prove global/root headroom; unreadable, cached or degraded authority refuses. Stop/Panic/restart, calendar/lifetime and ancestor holds still bind. A single-use grant names the pause and resume generations, and lost money or restart revokes it. Original start time, money, round and review wallets survive; execution time excludes quota unions and cumulative pauses.

A root Resume makes descendants eligible, never automatically runnable. `resume_child_task` explicitly selects within lineage; `budget_pause.budget_fence_selected` binds selection to the root-fence generation through launch and reservation. Another pause invalidates pending grants; foreign roots and terminal members cannot revive. `resume_paused_loop` refuses spent, revoked or foreign grants, discloses drift/custody before effects, and holds if consumption cannot be published. Graceful Resume may admit one fitting reservation for an explicit profile; producer allowances, unverified limits and disabled ceilings never expand, and hard exhaustion needs an owner increase. Browser, services, hidden state and crash recovery are not restored.

#### The model's own sleep

`await_messages` defaults to warm event sleep; `in_slot` and `cold` remain explicit choices. Selectors name exact senders, task or delegated-run terminals, the exit of the task's own `services` (warm only) and optional `wake_at`/`wake_after_sec`; without an explicit source/time it captures live direct children. A childless selector-free sleep refuses with guidance to select a reply sender; a missing continuation owner refuses warm sleep. Owner/control and typed actionable input always wake, routine mail waits for the resumed request. No quiet-duration or semantic-stall timer creates a model round. Canonical read → install wait → recheck prevents lost wakes; a terminal wake means settled, never success. A `services` selector pins each name to the start it has now (`service_id`, `started_at`, `backend_pid`) and reads execution facts only (`tools/services.service_execution_facts`): an exit wakes `service:<name>:exited:<code>` (`unknown` for Docker), and a lost start, an unreadable record or an inconclusive probe wakes `service:<name>:unknown` for the model to judge; cold sleep refuses the selector, because its process holds the services.

Warm sleep parks the same stack through the owner wait (`wait_after_tools`, `reason=sleep`): pooled work lends capacity but retains the project lane, direct work retains its actor, a queued root needing that lane cannot be its wake source, and Resume reacquires capacity and rechecks controls and writer admission. Cold sleep requires no `cold_blockers` (root and tree claims, runs, services, processes, running children; only the current sleep-tool invocation is exempt), seeds the exact pause (rail `model_sleep`, reason `sleep`) to close subtree launch admission before the final census, and abandons only that seed when a dependency appears after it (`cold_sleep_dependency_blocked`); `sleep_wake.py` observes readiness off-lock, records `sleep_ready`, then `grant_exact_sleep_resume` validates identity and every hold, owner Pause, money, deadline, lifetime and custody veto, and general Resume cannot impersonate `sleep_wake`. Sleep time is excluded from execution time (warm live via `TaskModelWait.sleep_started_monotonic`, cold via `sleep_exclusion_since` at grant); hard `deadline_at` never moves. Manual Restart retains a current-attempt, hash-validated warm sleep by transferring it into the exact pause; a retained sleep always needs explicit Resume before automatic wake.

#### Monetary authority and projections

**Live global limit.** One agent resolver reads saved settings, reparsed on change; a failure falls back to the environment without caching the failure. Workers refresh the environment at task start, and live file reads keep reservation/wallet `TOTAL_BUDGET` current; planning thresholds stay separate. Absent means the shipped default; non-positive means unbounded, silencing the loop's global axis. A run cap set by a launcher before settings load (`OUROBOROS_REVIEW_RUN_CAP_USD`, the isolated contributor review only) replaces the saved budget for that process tree, whose ledger starts empty; an unreadable cap is a zero allowance.

`pricing.py` uses bounded best-effort exact normalized-route catalog lookup, never manual tables, prefix/fallback prices or admission allowlists. Every limit refuses once known (settled) spend reaches it, at reserve and again at dispatch; holds and unresolved bounds are exposure, never spending, so concurrent or late charges can overshoot. Unknown price: reserve None, settle the reported cost or a later exact price, otherwise None/non-final. `usage_admission.review_wave_admission` admits a skill, plan, task or commit wave while known spend is below every global/root/group limit; the shared estimator's wave total is disclosure, and a managed update only records it (`managed_update_wave_estimate`); unpayable slots bypass without substitution, and unknown prices stay disclosed without disabling priced siblings.

**Whole-work billing group.** `usage_admission.py` keeps task/root/parent ids distinct from `billing_group_id`/`billing_group_limit_usd`; one store transaction checks global, root and group, successors and original-root late work included. Reservations retain the applied `global_limit_usd`, explicit unbounded state and `global_limit_source`/`global_limit_revision` through transitions.

For roots, `GET /api/tasks/{id}` derives `cost_breakdown` from the store (own/child/unattributed/delegated costs, subscription sessions, unknowns, finality, authority); it is never persisted and never a third sum, and an unreadable or unattributable ledger omits it rather than asserting zero. Review emits one `llm_usage` per physical send with wave/slot attribution (`review_records.resolve_review_wave`); `skill_review_usage.py` projects `(review_skill, review_wave_id)` without another ledger; delegated rows report their own route provider and resolved model, never inferred values. `state.json`, task results, `llm_usage`, `/api/state` and `/api/cost-breakdown` are compatibility projections.
