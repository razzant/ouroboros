# 6. Agent Core

Tasks/tools, routes, context/source recovery, reviews, delegated custody, plans, story and budgets. `loop.py` runs tasks/direct turns/wakes; review/post-task settlement is separate.

### Task lifecycle

`OuroborosAgent` serves pooled (§5) and direct work (`DirectActivityRegistry`, §3). `agent_task_pipeline.py` freezes contract/context, runs the loop, stores results/artifacts and root post-work (`post_task_synthesis.py`, `post_task_checkpoint.py`), then publishes. Store rows govern lifecycle (`get_task_result`, `query_data`); result JSON is import/export. `task_result_schema.py` admits rows (§11); usage owns money/tokens. Admission, completion, satisfaction, verification, review and artifact finality differ. Crash: `failure.kind="runtime"`; lost capture unknown. `finalization_timing.py` times delivery, sharing child projections until model wait by task/root/queue lineage. `supervisor/cognitive_operations.py` excludes typed operations from idle inference; deadlines/budgets/cancellation stay.

`task_store` reads the stable terminal page plus uncertain rows; the gateway applies effective global top N. `task_status` derives stability per body write; `store_hot_facts` backfills legacy NULLs by CAS. GET keeps envelopes without writes.

The loop transcript is append-only for OpenAI-family byte-prefix caching (§6 Prompt caching); `transcript_prefix.py` counts every break by origin (round facts, Health) without blocking sends. Before preparation/pricing it retires signed reasoning from the first change, or all for system/tools changes or no baseline. `model_execution` keeps the last accepted ordinary solve's requested, routed and provider-reported models distinct; empty/forced/review/post-task replies cannot replace it. A host model switch after tool work grants the successor one authorship recovery round; another tool-less reply degrades as `authoring_handover_incomplete`.

`loop_delivery.py` keeps exact `DeliveryCandidate` bytes before verification/review, even on failure. `outcomes.py` separates execution/objective/review/artifacts/child-absorption/custody. Receipts/exact references prove effects; tool errors alone never degrade answers. Unevaluated objectives keep `residual_tool_errors_without_review`. `FINAL ANSWER:` always survives; only `task_contract.answer_protocol="final_answer_line"` prompts it. Armed/sticky selection rejects direct array-wrapped controls as malformed; ordinary JSON is unchanged. `completed` can be unaccepted. Reasons persist; owner wording projects on read (§3).

Answers carry `terminal_host_notice` (plan/orphan limits) and the owner's typed `terminal_custody_notice` (nonempty categories). CLI labels host status; Presence omits it. Notices keep answer bytes/hash/verdict, never revive approval; child-result/plan-evidence hashes bind them, changed limits void dispositions. Salvage: `Preserved intermediate output (not a final answer):`, bounded preview, complete `get_task_result`/stop receipts. The reader labels cancelled rows `[CANCELLED_BY]`, others `[OWNER_CONTROL] command=stop_now|wrap_up|unknown` by recorded policy.

A first reply with no selection episode is a plain final. After substantive host continuation, Main selects complete retained bytes with `finish_task(action=finish|stop, answer|answer_sha256)`; compaction withdraws unavailable selectors. Finish checks children, skills/handover, owner sources, material, services, configured review and admission; each hold logs a canonical `completion_held` event. Stop keeps the selected unfinished work without buying criticism or another answer, cancelling descendants or claiming approval; evidence-only changes cannot undo it. Undispositioned direct children hold finish; reminders and custody disclosures never decide it. Presence completes a send only on host-confirmed delivery. A result review binds the exact delivered subject (Result review, Objective authority).

Provider death salvages text but ends `failed`/`infra_failed` with `provider_unavailable` (or `resource_refusal_no_resend`) and an immediate not-completed owner notice. One forced model call runs only while a call can land; wait expiry and `loop_llm_call.provider_no_call_source` forbid another paid window. `terminal_provider_notice` quotes the provider's words beside the result, never recommends blind replay. The finalization sink stamps `model_final`, `host_notice` (host words) or `host_salvage` (model output kept after provider death); a forced reply still requesting tools is incomplete. Finalization controls are typed mailbox entries. Descendant activity is not the task's own progress; an unkillable process stays visibly running: even a zero, final cost cannot settle `delegated_runs_unreconciled` custody.

#### Result review

A task's result is one subject of the one review machinery: `review_change(subject="result")` (`tools/review_result.py`) asks the review pool whether the result, and a method the owner fixed, does what was asked, by the `Result Review Checklist` of `docs/CHECKLISTS.md` (`result_rubric`, fingerprinted like every checklist). The frozen subject has four parts: what was asked (the request fields, the claims it is held to — `effective_acceptance_claims`: an ingress contract's, else the latest plan revision's `done_when` — and its owner's words), the reply (`answer`, else the latest retained reply), what the task produced (registered artifacts and attributed workspace changes by path and hash, plus declared `observed_effect` receipts, failed calls included; a failed capture is a named gap) and the host-attested verification receipts. Expected output, inputs and checkpoints are intent, never production. The exact text is retained once (`result-subject-<sha16>`) and its sha is the wave's identity: the same reply, material and request reuse the settled record at $0.

The wave is `review_change`'s own: composed panel (a Required root widens or needs a reason; else the named rows; omitted = the pool), paid stamp, custody and rejoin, leaving on an addressed message or Pause (a left or unwaited wave settles from recorded seat answers into a notice or late mark, `review_pause`), settlement and the ledger record (`surface="result"`). Seats answer one result part (`PART_RESULT`), reduced without coupling under the adaptive quorum; failed rows are infrastructure evidence, a pre-send refusal `not_dispatched`. Findings are `critical` (fails the ask or misstates the delivery) or `advisory`. Result waves count their own paid cycles per root (`review_result` attempt rows); a child may ask its own (`subject=result`).

Modes (`OUROBOROS_TASK_REVIEW_MODE`, §7). Auto forces nothing. Required adds the floor at a ROOT final delivery with produced material (file, effect, adapter answer line): unless a settled record binds the subject sha, the host collects a running review at $0 or seats the pool (`chosen_by=host`). PASS delivers; else findings show once and delivery holds one turn: Advisory and Cyber Pro deliver on the next decision, Blocking holds until a review passes or the task stops. A spent allowance refuses once at $0; Blocking holds while the ceiling stands. A running review (every mode but Off) is awaited unless a nonblocking install chose `finish_task(pending_review=finish)`. An unchanged answer reviewed against an earlier request shows the new owner words once; redelivery keeps it. Presence speech is never held: the owed review runs with a departed author (`review_pause.departed_binding`) as a late mark. Off refuses `subject=result` before payment.

Objective authority. Every mode but Off binds the settled review of exactly the delivered result into the task's review runs (`authority="host_root"`, `binding_hash` = subject sha); every new delivery candidate (on every rail) supersedes earlier runs, never deleting them. `outcomes._review_axis` reads `source: "result_review"`; `_objective_axis` gives the reviewers' PASS/FAIL, PASS with source `author_acceptance` (reason `author_finish`) for an informed finish, and blocked FAIL (`review_cycles_exhausted`) when blocking enforcement could buy no review. `task_acceptance_review` stays a valid source of older records, whose decisions, panels and rows render read-only. A result PASS never satisfies the commit gate.

Spent allowance and price. When `OUROBOROS_REVIEW_MAX_CYCLES` is spent, Advisory asks the mind whether what was reviewed is enough (finish, or land stating plainly what was not reviewed) and Blocking keeps the owner's ceiling menu (3/5/unlimited). One review's price is measured (`review_price.py`): the median of a row's recent waves on its current model, each seat's attempts summed (`usage_store.review_seat_costs`), with count and range; no history is `cost unknown`, a session row `uses a session seat and time`, a local route `no API cost per review`. `## Review seat activity`, `GET /api/review-pool` (`basis: observed_reviews`), Settings and onboarding print the same words; the table is cached per process for half an hour.

Root admission seal (`delivery_seal.py`, re-exported from `loop`). Sealing closes the root's admission (no new subtask under it) and catches by generation an owner message arriving between "decided" and "delivered". It runs only at an author stop, right before its delivery (`loop_delivery._seal_admission_before_delivery`); a plain finish never opens it, so only the local admission-lock drain catches an owner message routed at the supervisor. Born as the task-acceptance fence, it keeps the persisted names (`acceptance_fences`, the `acceptance_fence` event, `state/acceptance_fence_acks/`, the `_task_acceptance_*fence*` context fields). The supervisor owns the row under Q (`queue_transitions.transition_acceptance_fence`: end compares `owner_message_generation` and seals or releases) and clears it at `task_done`; pooled fences bind attempt/PID (unanswered begins release, ended owners retire at handoff, consumed Resume rebinds park fences). `ok` seals; only owner facts revise, a generation mismatch (also one seen locally) or pending owner mail: `_release_for_owner_followup` pops `task_completion` and ends the fence with `revision` (serving a follow-up after the seal, `_owner_generation_changed`); a begin refused `sealed` is the worker's own lost ack, a pooled attempt refused `stale_attempt` lost its queue ownership and never publishes. Any other refusal, like `unknown`, is a gap, never a refusal of the answer (§10 invariant 25).

Owner-source acknowledgement (the completion protocol of `finish_task`, argument `acceptance_subject`). While delivery control asks Main to select a completion, `loop_messages.prepare_acceptance_observation` appends the `[ACCEPTANCE_SUBJECT_OBSERVATION]` row when the owner-source facts changed (earlier rows stay for prefix caching). `acknowledge_acceptance_observation` advances only consumed ingress, never criteria or a verdict; it refuses with a typed `ACK_*` cause when the named source was unobserved, owner input unread or the owner source or queue generation changed; every outcome is the durable `acceptance_source_ack` row (§10 invariant 21). Raw owner messages stay evidence; their count changes no requirement.

### Own-body candidates

Body authors (queued roots, direct turns, evolution cycles) write a task-owned linked worktree of the serving repository, never the serving checkout, keeping unfinished edits out of serving imports. A candidate commit is version-neutral (every carrier span byte-identical to HEAD, no tag) or a numbered release (VERSION and every carrier in one diff, tagged); the release gate names the form from the diff, a partial carrier move is neither. Retention counts from last use: a candidate with no unique work expires; otherwise its files are captured on `refs/ouroboros/candidates/<id>` and the checkout goes only once capture is complete and the verdict holds (`body_candidate.verdict_holds`); a nested `OUROBOROS_RETAINED.txt` marker keeps the process environment and source checkout.

#### Monetary authority and projections

**Live global limit.** One agent resolver reads saved settings, reparsed on change; a failure falls back to the environment, uncached. Workers refresh the environment at task start, and live file reads keep reservation/wallet `TOTAL_BUDGET` current; planning thresholds stay separate. Absent means the shipped default; non-positive means unbounded, silencing the loop's global axis. A run cap set by a launcher before settings load (`OUROBOROS_REVIEW_RUN_CAP_USD`, the isolated contributor review only) replaces the saved budget for that process tree, whose ledger starts empty; an unreadable cap is a zero allowance.

`pricing.py` uses bounded best-effort exact normalized-route catalog lookup, never manual tables, prefix/fallback prices or admission allowlists. Every limit refuses once known (settled) spend reaches it, at reserve and again at dispatch; holds and unresolved bounds are exposure, never spending, so concurrent or late charges can overshoot. Unknown price: reserve None, settle the reported cost or a later exact price, otherwise None/non-final. `usage_admission.review_wave_admission` admits a skill, plan, task or commit wave while known spend is below every global/root/group limit; the shared estimator's wave total is disclosure, and a managed update only records it (`managed_update_wave_estimate`); unpayable slots bypass without substitution, and unknown prices stay disclosed without disabling priced siblings.

**Whole-work billing group.** `usage_admission.py` separates task/root/parent ids from `billing_group_id`/`billing_group_limit_usd`. One store transaction checks global/root/group for successors and original-root late work too. Continue uses initial `billing_group`, else earliest live ledger authority, else configured cap (`legacy_default`). Review-wave `binding_axis=group`, pacing and strict Resume share it; only the group owner amends its cap. `task_money_snapshot` keeps root/group axes over shared spend. Unestablished authority refuses typed, never as money or a stand-in group/zero; late overruns bar admission without a bill guarantee; standalone UI/marketplace contexts declare a non-task role. Reservations keep applied global limit/unbounded, source and revision through transitions.

For roots, `GET /api/tasks/{id}` derives `cost_breakdown` from the store (own/child/unattributed/delegated costs, subscription sessions, unknowns, finality, authority), never persisted or a third sum; an unreadable or unattributable ledger omits it, never asserting zero. Review emits one `llm_usage` per physical send with wave/slot attribution (`review_records.resolve_review_wave`); a skill wave's seats are the review ledger record's rows; delegated rows report their own, never inferred, route provider and resolved model. `state.json`, task results, `llm_usage`, `/api/state` and `/api/cost-breakdown` are compatibility projections.
