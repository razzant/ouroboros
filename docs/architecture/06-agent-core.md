# 6. Agent Core

Agent lifecycle, tools, context fitting, authority, reviews, delegated custody/activity, planning, reflection, memory, focus, skills and budgets. Pooled tasks and direct turns, including wakes, enter `OuroborosAgent`'s `loop.py`; review/post-task executors settle separately.

### Task lifecycle

Reviewed transports admit queued tasks through the supervisor queue (§5) to `OuroborosAgent`. Each direct-chat turn has its own in-process agent and process-local `DirectActivityRegistry` entry, without `PENDING`/`RUNNING` rows (§3). The root pipeline (`agent_task_pipeline.py`) captures the task contract and immutable context core, runs the loop, preserves a delivery candidate, stores the result (`task_results/<id>.json`, every write stamped `_schema_version: 1`; an unstamped, future, malformed or retired-key row is quarantined by `task_result_schema.py` with its id kept occupied) and artifacts, emits lifecycle and usage evidence, performs the root-only post-task work (`post_task_synthesis.py`, checkpointed by `post_task_checkpoint.py`) and publishes the typed outcome. Queue admission proves durable acceptance only; completion, objective satisfaction, artifact finality, verification and review acceptance remain separate. The loop's tally rides `loop_outcome.usage` while the top-level `total_rounds`/`prompt_tokens`/`completion_tokens` are the ledger's answer (`reconstruct_task_cost`); an internal exception is `failure.kind = "runtime"`, never a fabricated provider failure, and a capture the crash lost is reported unknown, never as zero counters.

`chat.jsonl` stores `message_accepted_at`; `task_received` stores `activity_emitted_at`; request/response manifests and `llm_round` store `first_request_at`/`first_answer_at` (first prepared request/returned model response), never gates.
`finalization_timing.py` carries phases on the live final event; one `task_finalization_timing` row follows the sender's return: last answer, source ack, child calls, admission wait/close/seal, review, cleanup/custody, store, enqueue/send. Durations are monotonic; nested spans overlap. Replay gaps stay unknown; sender return proves no client display.

Review/post-task executors (`review_execution.py`, post-task pipeline) share evidence/context contracts. `supervisor/cognitive_operations.py` tracks in-flight LLM, review, VLM and tool work as typed `cognitive_operation` leases for the idle rail; deadlines, budgets, cancellation and absolute ceilings remain independent.

Within one loop the transcript is append-only: each send extends the previous prefix — because OpenAI-family caches reuse a request only when it is a byte-prefix of the next (inside the leading system unit a byte-prefix is necessary, not sufficient: "Context fitting, retry, and compaction" below), so a replaced tail or a rewritten earlier message discards the whole conversation cache. `transcript_prefix.py` records and never blocks: `unsent_in_previous_send` allows `_append_or_merge_user_content` to merge only a tail absent from the last observed send; an absent slot or missing observation means unknown, so the producer appends a new row, compaction seams stamp `sanction_rewrite`, and a break is the `prompt_prefix_break` checkpoint fact (`kind` = `system_rewritten` | `tail_replaced` | `rewritten` | `shrunk`, plus `sanctioned_by`; a context-fit reprojection after a real overflow is an ordinary break). The observation follows a usable ordinary model response, not every physical send; existing image eviction is unchanged. A `FINAL ANSWER:` line is latched every round as the latest typed candidate, so review, nudge and forced-finalization paths never erase a structured answer; marker prompting is gated on `task_contract.answer_protocol="final_answer_line"` (`answer_protocol_active`) while the latch and extractor stay unconditional, and `outcomes.extract_final_answer` refuses the outcome-tier ledger identifiers as answers — internal enum vocabulary is never a deliverable.

`model_execution` is a compact projection of the last ordinary solve response the loop accepted (text or tool calls), selected from marked `llm_call_refs`; it keeps the initially requested model/local route, the route used and the provider's own label separate, and empty responses, forced finalization, review and post-task calls cannot replace it. Result, terminal frame, history and card share it without changing dispatch or claiming final-answer authorship; the terminal `task_summary` keeps it when the full result ages out, and a current result or live card outranks that fallback. After tool work, host-driven fallback or model-wait model changes record an authoring handover. The successor's first tool-less response gets one recovery round (one prompt per handover, under ordinary stop, deadline and budget limits) with delivery-control JSON held; a second yields `execution=degraded` and `authoring_handover_incomplete`. Ordinary no-tool turns and explicit model changes are exempt. Verification and skill checks still run; later tools clear only this warning, preserving incident and recovery history.

`DeliveryCandidate` is retained before verification or review so a later notice, reviewer failure, deadline or provider outage cannot erase a useful answer. `outcomes.py` combines the execution, objective, review, artifact and child-absorption axes without converting one into another, the terminal custody overlay (`outcomes.custody_debt_axes`) included; verify-before-done receipts and exact artifact references are host-attested evidence; declarations or answer prose are no substitute. Failed tool calls alone do not degrade a delivered answer: unresolved calls retain their typed signal/exit evidence in `execution.unresolved_tool_errors`, cosmetic errors keep their separate bucket, and either kind adds `residual_tool_errors_without_review` when the canonical objective is `not_evaluated`, including after delivery/child-state normalization. Host acceptance or qualified Advisory author completion establishes objective success; unresolved FAIL/DEGRADED verdicts, empty or failed execution, provider failure, deadlines, incomplete delivery, deferred children and failed artifact verification keep their own outcome rules. A forced exit may publish the best current candidate only with its typed rail and evidence-freshness disclosure, and lifecycle may remain `completed` while the objective or review axis records a best-effort or unaccepted result. Custody debt heals from the write side while the stored `reason_code` is never rewritten, so the owner-facing Reason line resolves it at RENDER time — the custody warning only while the row's own `delegated_runs_unreconciled` list is non-empty, else the execution reason, both when both are real; a healed debt is never restored, and the debt warns beside the rail cause, never replacing it — as does every standing limitation of the same answer (deferred child results; a plan review open at delivery, worded by the outcome class on `execution.plan_review` when recorded), which the normal rail types on the result exactly as the forced rails do, so one clause per fact reaches the card, the durable row and Ouroboros's own memory.

Host plan/orphan disclosures ride beside the model answer as `terminal_host_notice`: delivery sends the answer alone and the disclosure stays a result field (an owed pre-upgrade notice row still replays as its untyped System row); the custody audit is its own typed row (`terminal_custody_notice` on the send event → `system_type="custody_notice"`, `card_row="timeline"`, own owed delivery id), so the open-delegation fact is a card row and the unreconciled-runs note never enters the assistant text. CLI gets one host-labelled status (`terminal_host_notice_text`); external Presence speech excludes host notices (chapter 12). Stored answer bytes do not change: the answer keeps its hash and its real PASS or FAIL when only the notice changes, and equal text cannot revive a superseded verdict. Every reader that hands a result on — synthesis, parent handoff, `get_task_result`/`wait_task`/`wait_tasks`, the `task:<id>` plan-evidence reader — carries the notice as a separate field, and the child-result and plan-evidence hashes include it, so a changed child limitation invalidates an old parent disposition or review. A host-salvaged terminal is labelled, not hidden: its durable row carries `Preserved intermediate output (not a final answer):` plus the shared bounded terminal excerpt, `get_task_result` and the stop receipt keep the untruncated copy, and only a row in the chat the stop receipt itself reached (`cancel_receipt.delivered_chat_id`, recorded after a successful send) reduces to its label beside the pointer; the two durable writes are not atomic, and no writer trades its only pointer for the label. One event is disclosed once, at the layer that owns it: the forced orphan note leaves a child to its own terminal row only where that row reached the reader the note addresses, and a rail that ended a routing turn is named by that turn's own row, never inferred from another layer's stamp.

`loop_delivery.py` owns the task-local completion request and retained `DeliveryCandidate`. First replies/direct follow-ups without a selection episode stay plain finals. After a substantive host continuation, Main selects via `finish_task(action="finish"|"stop", answer=...|answer_sha256=...)`: full bytes or an offered retained/whole-held-response hash, regardless of length. Every held no-tool round appends assistant+host rows; interim prose neither replaces the answer nor repeats requests or leaves assistant-prefill tails. Held bytes live in the canonical transcript; compaction withdraws unavailable selectors. Old keep/replace is private historical data, never a command or repair budget.

Owner/tool/material/preparation facts freeze before dispatch; only feedback in a returned request counts as exposed. Finish must observe new sibling reads/errors; successful completion/schema bookkeeping is not work. Non-authorizing stop may accompany completed siblings. Presence send+tool_delivered completes in one batch only with host-confirmed delivery; failed/uncertain sends prove none. presence_finish maps independent action/rationale and delivery outcome to this request: silent/tool_delivered may select empty internal text; omitted message/deferred text reserves one next reply, invalidated by a substantive hold. Non-speaking children gain local completion without altering signed resource ceilings; speakers keep Presence. Legacy review author actions normalize before dispatch; review-only calls remain reviews.

Finish retains child, skill/handover, owner-source, material, service, configured review and admission checks. Stop names unfinished work, buys no critic or replacement answer and retains selected bytes before owner-control drain, required-question parking or prospective budget reservation. Teardown, owner seal, result/outbox and paid custody remain; Stop/Panic, exhausted money, deadline and provider failures keep their causes. Evidence-only changes cannot undo stop; it cancels no descendants. A retained `author_stop` fence cannot cancel queued children after a durably terminal stop and restart. Pre-terminal crashes retain existing shutdown/cancellation semantics. Completion and criticism remain separate; `previous_revision_accepted` keeps distinct reviewed/delivered hashes.

Undispositioned direct children hold finish, showing exact status/hash and inspect/wait/disposition/discard/cancel/defer tools; reminders never terminate, and explicit stop remains available. Child custody debt is visibility, not root-patch authority or verdict (DESIGN §4); undisposed own delegated patches keep their additive warning. All three wait/pause routes share `owner_wait`'s selection/observation/paid-identity serializer. Cold holds drop repair budgets; they and Nano's first hold load the permitted completion schema via the registry, preserving disabled tools and disclosing prefix changes. Forced rails extract one response: the same serialized request, Presence's outward declaration, original-byte duplicate-key checks and unchanged tool envelope; no tool execution or repair call. Live/history (§3) distinguishes completion receipts while counting calls, errors and cognition.

Provider death is the one forced rail that is NOT best-effort completion: it salvages the best text but stamps `infra_failed`, so the task ends `failed` with the typed `provider_unavailable` reason and an immediate "provider outage — NOT completed" owner notification; wait expiry takes a no-resend source: `transport_unavailable_no_resend`, `provider_outcome_unknown_no_resend`, or the chosen primary refusal's `provider_transient_no_resend`/`rate_limit_no_resend`. Its one forced model call runs only while a call can land: a spent same-model retry wall stamps `_llm_retry_wall_exhausted`, a no-call gate beside `context_overflow` and `provider_outcome_unknown`, so no second retry window is paid over a proven-dead provider (disclosed residual: a last-invocation bool on the shared usage dict). Terminal delivery preserves producer authorship: `terminal_provider_notice` is host presentation beside the raw result, quoting only `_last_llm_provider_message`, which `loop_transport.stamp_owner_provider_message` resets per failed call to authored provider text or nothing (a Claudexor engine error authors none: its typed provider fields reset alongside in `_last_llm_provider_fields`; else words for `_last_llm_error_kind`; repr stays in `_last_llm_error`/`llm_api_error`); receipts and secondary System incidents carry wait duration, finalization cause and unknown-outcome warning and never recommend a blind rerun. Every forced rail stamps one closed-vocabulary producer word at the single forced-finalization sink: `model_final` for complete model text (host-authored notices stay separate), `host_notice` for host-written terminal text (an owner System row, never automatic external Presence speech), and `host_salvage` only on the provider-death rail, where managed/direct delivery replaces the text with the enriched outage receipt and the full bytes stay in task details. Missing origin stays unknown; `agent.py` resets it on host text replacement. Presence synthesis seals the recorded adapter body and internal result separately (chapter 12), never a delivery receipt.

Finalization controls are typed owner-mailbox entries, not injected owner prose. The supervisor may request one bounded tool-less answer, salvage the last persisted assistant text, and retain a full canonical copy when a preview would truncate it. A grace episode has one durable control and can be revoked atomically when the task itself resumes; descendant activity does not count as the task's own progress. An unkillable process remains visibly running; custody checks prevent another runtime instance from reaping work it does not own.

Disclosed cancel-lifecycle residuals (deliberate): a cascade over a tree with no resolvable lineage chat whose typed handoff-row append ALSO fails still settles; an empty-intent release can add liveness noise to a foreign claim's forensic trail (bounded by the generation fences); cascade postcondition timing can flake under heavy load (the watchdog re-feeds — one retry, never a lost teardown); and the cost projection of a task whose delegated runs stayed open may read `cost_usd=0`/`cost_final=true` while a run is still live — the disclosure line names the open runs.

#### Task acceptance

Task acceptance grades evidence and advises useful authorized work separately from the P3 commit gate (`triad_review.TIER_CLASSIFICATION_RULES`): partial delivery does not close the goal, and a sufficient result needs no embellishment. `auto`/`required` review observable effects, typed deliverables/criteria and explicit root nominations, including research. Queue membership alone never qualifies; ordinary conversation, exploration or memory updates alone do not qualify in `auto`. No prose/tool-count classifier decides. Child reviews are advisory; `off` suppresses automatic review.

`acceptance_history.py` freezes zero-physical root/retry skips: answer, criteria, owner inputs and retained HOST refs. Copyback follows owned carriers, never agent data/arguments/quotes. No urgent bulk capture/closure; uncaptured bytes stay gaps, never current-file reconstructions.

`task_acceptance_review(late_review=...)` needs a NEW owner chat/quiz/mailbox `owner_source`; Main may target any Project. `amend_cap` (bare-cap default) only sets an absolute original-root cap: no review; Pause/fences/spend stay. `review` runs the full `acceptance_late` triad on frozen terminal roots/retries, even mode-off, after any cap. Original-root/group known spend (successors included; holds disclosed), live global caps apply; finite/unlimited/unknown keep provenance. Caller/target/root Stop, Panic, prohibitions, calendar bounds bind. Hurry/Wrapup block unstarted automatic work, not later explicit authority. Debt-paid identity makes paid/unknown work collect-only.

`events_chat_delivery`/file-ready `task_done` hand off to `review_operation.prepare_historical_operation`. NEW automatic panels need calendar headroom above the acceptance floor, no author reserve; controls recheck after writer drain and before purchase. Supervisor maps prove local ownership; workers read pooled/direct projections and direct postwork checkpoints, conservatively on unknown. The preparation excludes itself. Sources close before freeze; paid/unknown replays stay collection-only. Cold settlement keeps the proven recipient.

`task_acceptance_review` nominates the result (`deferred_to_host_acceptance`, `authoritative=false`). After tool results, the host advances delivery’s operation; feedback seals nothing. Main authors criteria; paid identity binds result bytes/criteria/effects, not status questions.

`acceptance_settlement.announce_acceptance_settlement` mails verdicts at quorum/final settlement. Answer control precedes ready-feedback shortcuts: settled panels/queued wakes skip parking, retaining provenance. Any mail wakes waits; only typed owner/control drain captures sources, acknowledges and seals. System/descendant/independent-task/peer mail grants no owner revision; owner/principal messages, quizzes and controls keep their handling. `awaited_panel_has_settled` admits the next round/control repair; feedback stays on its `review_runs` row.

Pending final deliveries wait unless their mode permits finishing (Blocking waits; Cyber Pro: Main decides; Advisory: `pending_review`). Without re-nomination, a text-only PASS rewrite may reuse approval (`previous_revision_accepted`, disclosed; no commit/plan/skill authority) only if owner source, criteria and material evidence match. Other cases use collected feedback. Before a new panel/capacity refusal, `review_dispatch.reconcile_pending_acceptance_runs` collects at $0 from original requests/rosters. It locks snapshot/apply only; concurrent progress forces recollection so publication keeps settled facts. Stop, missing custody and unfinished outcomes stay visible.

**Already-paid operations.** `review_operation.ReviewOperation`, bound before slot windows by `review_custody.run_custodied_review_slots`, owns drain/workers’ shared wait, union/per-slot quota clocks and controls. Its snapshot retains calendar bounds, money/root lineage and Stop/Panic/settled cancellation; `model_wait.operation_wait_scope` clears author execution deadlines/re-preparation callbacks. Task wait is required; rejoin reuses live custody through worker/drain/publication settlement. Before sends, read-back `review_operations` binds attempt, slot/operation ids, controller `{pid,birth,session}`, immutable request/roster and original-root paid authority. Recovery verifies claimant/binding/paid identity. Legacy sources require canonical same-physical-root proof, exact pointer/source and a matching claim; retry aliases, child/advisory claims and malformed authority refuse. Old bytes stay immutable. `review_operation_scope` serializes `asdict(request)`: sources must already be canonical; failure refuses at $0.

`review_operation.collect_recorded_acceptance_run` restores producer CAS, keeps live workers or observes a proven daemon run after its authenticated non-generative POST handshake. It parses locally: no ensure/start/re-post/cancel/ack/retire/model call. Unparseable narrative stays whole (`parse_unavailable`). Slot facts: `settled|collected|deferred|unavailable|never_dispatched`; the last requires positive proof. The existing off-loop 300-second reconcile collects terminal dead-controller/unpublished operations, retaining unknown-controller/unreadable-source duty. API/native worker death means unknown, no resend; daemon runs remain observable. Cold model/profile/harness and mismatch/unknown facts come from `final_attempt_facts` (§6 Session identity). No new runner, ledger or timer.

`repo_diff_capture.capture_repo_diff` feeds both the `review_evidence_sections.collect_turn_diff` preview and the `artifacts.materialize_repo_diff_evidence` source; a legacy partial preview without its capture stays unavailable. Git writes private spools under a subprocess timeout; memory holds bounded section prefixes. Nonzero exit, timeout, unreadable repository, cuts and undecodable runs are gaps, never a clean tree. Only a root-only lstat proving `.git` and `HEAD` both absent admits a plain root (`applicable=false`, complete, no Git baseline/call); any entry, broken gitfile, missing or unreadable root stays Git-required. Plain preparation hashes bounded file content and symlink targets without traversing links/nested `.git`; special/unreadable/over-bound material is unknown. Git retargeting variables are scrubbed; discovery stops at the root's parent.

Private EXACT bytes go to observability CAS via `retain_private_capture`/`write_blob_stream` (0700/0600); failed retention is disclosed, and neither bytes nor handles are published. Packet, `repo_diff_source_ref` and owner views get REDACTED text, decoded and redacted per whole section before cuts: diff bodies masked, file headers kept, a PEM block in a hunk masked whole. Packet `repo_diff_capture` exposes only applicability, digest, size, gaps and retention state. Readable binary/non-UTF-8/mixed hunks stay beside located gap markers. Stderr, exceptions, failed/timed-out stdout and bound-cut sections are withheld publicly (they may end inside secrets) though privately retainable. Small complete captures are retained at preview collection, larger ones at exact-source consumption or locally without a consumer. Projection/later-section failures release spools; partial construction closes acquired files.

`acceptance_preparation.preparation_source_identity` binds local failures before budgeting/hash/assembly to semantic criteria, canonical receipts, artifact bytes, child results, service-finalization facts and repository/plain-folder inventory. Delivery fingerprint, history/indices, repeated writes/staging, candidate prose, owner-message counts and exception text are excluded. Proven unborn symbolic HEAD uses empty-tree base; other Git failures are unavailable. Unknown material preserves last known identity, failed attempts and spent retries; size/mtime proves no equality. Changed material/criteria reopens preparation. Otherwise one more attempt requires exposed current failure plus explicit source-bound `acceptance_retry` (`material_change|repair_evidence|owner_retry`): host resolves current `owner_source_sha256` or exact receipt content (index only locates); Main judges substance. Rationale/basis grant no identity, spent sources grant nothing again, retry beside a terminal stance refuses. Paid identity stays unchanged.

Feedback exposure binds Main’s responding request, incident and attempt. An informed Advisory finish or Blocking unfinished stop keeps the answer without evidence rebuild, bound to attempt/answer/owner acknowledgement with material rechecked; only root auto/required qualifies, never child/off or outstanding action gates. Reconcile/dispatch/application retain paid/unknown custody; preparation failure grants no resend. `loop_delivery._delivery_evidence_state` / `observed_delivery_evidence` serve retention, nomination, post-tool, controls, publication, forced exits and stance merge. Failed reads yield UNKNOWN while retaining fingerprint/revision: unchanged answers remain one candidate, keep allowed but unverified (`evidence_current=false`, `evidence_status=unavailable_local_preparation`, empty subject hash, unaccepted binding). Unknown rebinding revokes approval; authoritative UNKNOWN cannot qualify for keep. Forced exit or publication hash failure keeps text unaccepted with an unreadable-evidence notice. Only the host acceptance pass accounts the incident.

Local decisions use `origin=local_acceptance_preparation`; reviewer decisions remain intact. §10 publication preserves settlements/newer warnings/resolutions against delayed snapshots. Admission/binding prove no dispatch: handoff/custody processing failure adds `origin=host_acceptance_processing` beside real runs, never invented findings. The existing decision and `review_projection.acceptance_incident` carry incidents with or without panels. `derive_loop_outcome` makes unresolved preparation terminals unfinished/blocked in Blocking, forced rails included; Advisory retains best effort plus stronger rails, unfinished stops and earlier critic failures. Cards/history show warning and detail; completion is the sole notification. Resolution clears warnings but keeps history; repaired first-attempt success resolves the prior incident with its original id/attempt count. Final cause names local failure and terminal rail, never reviewer rework.

Historical plan supplements use the locked result writer and exact producer CAS, settle cost without another cycle and preserve verdict, aggregate, closure, author dispositions and current-wave pointer. Acceptance’s sole publisher, `settle_acceptance_operation`, collects at $0, reads back `late_settlement`, then enqueues one System `card_row="reviews"` through the canonical outbox. Ended-author callbacks require the complete slot roster before marking unpublished duty; delayed quorum callbacks cannot reopen it. Failed publication announces nothing. Historical first-complete runs owe publication without fake pending actors; failed publication/notice custody retains `unpublished` duty across controller exit. Maintenance consumes it only after canonical read-back. Lost traces use the applied source; unreadable publications never become replacement panels. Original answer, decision, status and debt pin stay unchanged.

Late evidence retains settlement time, reviewed identity/hash/length, reviewer outputs and `emitted_answer` (§10): `reviewed_revision=delivered|different|unknown`, `reviewed_is_emitted=true|false|null`. Historical purpose requires its exact delivery triple; supersession, mutable results, disposition hashes and owed sends prove no delivery. Version precedes verdict; owner reviewer lines (DESIGN §4) keep the model mailbox unchanged, and `ChatOutbound.late_evidence` survives live/storage/history for the exact-record link. `late_acceptance_facts` carries that evidence and its exact cross-task source into durable chat/room/Main even with consciousness off. `get_task_result(task_id=<physical author>, review_source_sha256=<digest>, source_start_char=..., source_end_char=...)` verifies canonical HOST acceptance membership or the exact schema/kind/task/attempt/debt/delivery/hash-bound debt source. Forked/empty receivers work; Child/Presence remain refused, with no retry alias, arbitrary digest search or filesystem grant. Settlement grants no continuation; consciousness admission/Stop/Panic still govern further work.

Before review, `supervisor/queue_transitions.py` closes child admission under `_queue_lock` (§10 invariant 25); `task_status.find_child_tasks` proves subtree quiescence. An unanswered/refused fence buys no model round: disclose `admission_fence_available=false`. The canonical `budget_drive_root` packet keeps verbatim owner directives, contract/criteria, deliverable identity, terminal children, verification receipts, artifact refs, touched-skill facts (visibility only) and `omissions_manifest`. Missing required material degrades affected actors. `reviewer_window`/`review_synthesis.quorum_input_token_limit` resolves once per task for identical binding/rebuild. Wave admission prices one API first send per row (sessions unpriced), no rounds multiplier/repricing, as disclosure: only known spend already at a limit is `review_wave_budget_insufficient`. Each send checks the wallet. Packet repair grants no extra retrieving episode/session.

Paid identity (`acceptance_paid_identity`) binds that semantic subject plus substantive nonempty obligation dispositions; forensic source hashes and ingress counters alone buy no panel. A resubmit with the same paid identity replays its recorded verdict free — a clean replay can authorize acceptance, a non-clean one keeps its verdict and `identical_acceptance_refused` — and real criteria or evidence changes need no cosmetic edit.

Configured slots are independent actors under adaptive quorum (`config.adaptive_quorum`: 2-of-N for N≥3, both for N=2, one reviewer as loud `single_reviewer_no_diversity`; too few responses stay a loud infra quorum failure), each with one substantive interaction on its bound route: at most two physical sends per packet row, one bounded episode per native row, one delegated session per session row; retrieving verdicts are equally authoritative. Transport status, parse status, semantic verdict, criterion support, route, quorum contribution and binding hashes stay distinct, so an unavailable or malformed response never masquerades as a negative judgment: a panel refused before any transport projects `not_dispatched` on every row and the panel; a slot released at the dispatch barrier projects `awaiting` transport and parse until it settles, distinct from `success`, `timeout` and `provider_transport_error` and never a failure or verdict. `PASS`/`FAIL`/`DEGRADED` are reviewer verdicts; only `loop_acceptance._set_acceptance_decision` writes the host completion decision (`accepted`, `revision_requested`, `finalized_unaccepted`). A clean quorum supplies critic approval; an Advisory author finish is author authority, never a host tier or stance; neither changes the original verdict. Material FAIL and typed unavailable outcomes reach Main before it responds, even after the last paid panel; a no-quorum outcome keeps real minority findings as partial feedback. A terminal technical failure keeps `reason=review_degraded` when no permitted author completion follows.

### Tool capability and execution

`tool_capabilities.py` is the SSOT for the tool classes (core, meta, cognitive-memory, parallel-safe, stateful-browser, untruncated, capped-result, reviewed-mutative) and the child allowlists, which retain independent mutation and command ceilings. `tool_policy.py` chooses the initial capability set; `ToolRegistry` remains the execution authority; `loop_tool_execution.py` owns timeouts, concurrency, live evidence, result handling and mutative ceilings. Ordinary top-level presets share one built-in name surface: project focus changes the default target, while root policy, runtime mode, task-contract disables, credentials, resources, selected-resource bindings and delegated-child profiles narrow independently — a registered or discoverable tool is not thereby callable for a particular target. Nothing disappears silently: lazy discovery returns an explicit capability omission or `CAPABILITY_UNAVAILABLE`; a policy-filtered REGISTERED tool (a contract-disabled extension/MCP name included) is "hidden by policy: <reason>" (`ToolRegistry.policy_hidden_reason`), never "Not found". A name dispatch cannot run gets one answer (`ToolRegistry._name_miss_result`): its typed reason plus the callable names of the ONE namespace it addresses (`tool_policy.tool_namespace`), or above 12 their count and `list_available_tools(namespace=…)`, never another namespace's or a hidden name. `list_available_tools` (`tools/tool_discovery.py`, bound by the loop) reads `schemas()` in every mode; `loaded` is residency, not availability. A provider's physical ceiling on schemas per request (`provider_models.tool_schema_limit`; direct OpenAI: 128) is held at the Main round seam (`loop_model_call._fit_route_tool_ceiling`): core, meta and actor-loaded schemas stay, the overflow tail is left out under a notice naming it and stays callable through `enable_tools`.

Outcome classification keeps policy refusal separate from execution failure, so an expected authority boundary never becomes the task's headline failure: `user_files_path_blocked`, `cwd_blocked` and `artifact_output_undeclared` are typed non-failure surfaces, while a declared output that cannot be registered is the genuine `artifact_output_error`. The identifier register (`tool_result._EXACT_IDENTIFIER_CODES`) applies the same rule: a typed refusal is recorded as a refusal, never as `ok`. It covers the whole routing family (`STEER_REJECTED`/`STEER_UNCONFIRMED`, `PROMOTE_REJECTED`/`PROMOTE_UNCONFIRMED`, `ROUTE_REJECTED`/`ROUTE_UNCONFIRMED`, `ROUTING_UNCONFIRMED`, `NEEDS_MANUAL_TARGET`), so a promote or route that scheduled nothing is never read as a SUCCESSFUL call; a `_REJECTED` result carries its `(reason: detail)`, and the refusal stays visible to the agent (`is_error`) without degrading the execution axis — the host refused, the agent did not fail. File discovery distinguishes a confinement refusal (an error), a failed listing (a failure) and a path holding nothing — a MISS (`LIST_FILES_NOT_FOUND`, a warning beside `DATA_NOT_YET_CREATED`) that leaves the rest of the outcome uncoloured, because the recovery scan credits only a later success on the same target. The delegate tools (`delegate_start`, `delegate_wait`, `delegate_cancel`, `delegate_answer`) reach the same register from the producer side: `delegate_shared._fail` writes the `ok: false` + `host_code` envelope BESIDE the domain payload (whose `reason` keeps its own vocabulary), so every substrate refusal (daemon, ownership, containment, cancel, subscription window) is RECORDED as a refusal, never counted as a successful call — mapped to `TOOL_REPORTED_FAILURE` (never degrading), a malformed call to `TOOL_ARG_ERROR` (degrades, feeds reflection), never to a timeout or a generic tool error — and a terminal run in state `failed` or `cancelled` is a SUCCESSFUL observation of an unsuccessful leaf.

Tool API v2 exposes the canonical names from `get_tools()`; legacy public names are neither exposed nor translated. `search_code` applies one basename-glob selector (comma brace alternatives included) before ripgrep or the Python fallback reads allowed files; selected-file count and content matches stay separate facts. A missed exact edit (`edit_text`, `edit_batch`, `apply_patch`) answers with one bounded locator (`edit_ops.locate_edit_miss`): the nearest region (line endings, then whitespace-relaxed lines, then the needle's most distinctive line), the first differing line, the `read_file` window to copy from and, for a hunk, whether the region sits before its search cursor; every tier is bounded; only a small file previews whole. `write_file` and `edit_batch` validate item keys before writes through `tools/arg_feedback`: repeated call options and empty extras are disclosed, unsupported requests and non-objects produce one typed refusal. One item declaration supplies validation and the open schema. The file tools share a path-based public ABI; payload-borne paths (`edit_batch` entries, `apply_patch` targets) miss the dispatch seam that rewrites a `path` ARG, so both ends canonicalize through `tool_access.canonical_repo_relative_path` — one normalization keeps a guard from judging `repo/BIBLE.md` while the write lands on `BIBLE.md` — and `_ROOT_ARG_REPO_WRITE_TOOLS` is the single set every repo-write fence keys on. `verify_and_record` (`tools/verify.py`) runs the declared check through the SAME pre-execution guards as the process tools — a post-execution check cannot gate a receipt already written — and appends a host-attested receipt to `<drive_root>/task_results/artifacts/<task_id>/verification_receipts.jsonl` (`expected_match`: substring by default, `exact`, `exact_line`, `json_equals`, `bytes_equal`); it reads only public task info, reports an owner-settings change as a typed note, never auto-reverting it (a revert cannot prove causation), and `delegation_zero_run` writes only `incomplete`/`unknown`, after the custody scan proves no open run.

### Safety and runtime mode

#### Safety Supervisor outcomes

The first line of a Supervisor result is the typed outcome. SAFE passes silently; SUSPICIOUS allows the call with `SAFETY_WARNING`; DANGEROUS, an unrecognised status, a failed check and an answer still unparseable after one repair retry (`safety_parse_retry`, `safety_parse_failed`) block with `SAFETY_VIOLATION`. Outside Cyber that warning/refusal stands; Cyber records a negative or unavailable assessment as advice (`SAFETY_ADVICE`, durable `safety_advisory` event) without manufacturing SAFE. A provider 429 is an infrastructure fact about the Supervisor, not a verdict about the call: after one deadline-capped retry the call is blocked with the typed non-verdict `SAFETY_UNAVAILABLE`, which tells the agent to retry the same call rather than reword it, and a confirmed storm arms a process-local latch (`_SAFETY_STORM_COOLDOWN_SEC`) that answers in-window checks without a provider call, because re-probing from the highest-frequency light-model consumer would amplify the storm it reports; each is a durable `safety_check_rate_limited` event, while a structured insufficient-quota refusal stays PERMANENT and blocks as a verdict. The serialized subject has its own 250,000-character budget (`_SAFETY_SUBJECT_CHAR_BUDGET`, rendered `ensure_ascii=False`): an over-budget subject is refused fail-closed with `SAFETY_SUBJECT_TOO_LARGE_BLOCKED` plus a durable `safety_subject_too_large` event — never truncated, because anything past a cut would run unreviewed. Only the no-backend cases fail open with `SAFETY_WARNING` (no provider key and no local lane; a remote key that does not cover the light model's provider, with no local lane; a local runtime chosen as FALLBACK that fails or is rate-limited), so a misconfigured runtime does not hard-block every unknown tool; an explicitly primary local runtime (`USE_LOCAL_LIGHT`) that fails is a real `SAFETY_VIOLATION`.

Registry dispatch passes its prepared binding into `start_service`; a direct handler consults the same Supervisor only when no prepared registry binding was supplied. Each admitted process effect executes once; post-execution settings/repository observations annotate the original result and never repeat or roll back the operation.

Outside Cyber Pro, read-only shell git is allowed everywhere; mutating shell git only when its resolved target lies outside the Ouroboros system repository and runtime data drives (`git_shell_policy.py`; network-disabled tasks still fence network git). Acting `self_worktree` children remain read-only because patch capture requires an unmoved HEAD. `git init`/`git clone` are judged by destination, relative destinations and path-valued retargeting flags included; `resolve_shell_cwd` supplies the same canonical cwd to target checks and execution, and command text is not an independent runtime-file permission classifier. The generic Tool API VCS family (`vcs_status`, `vcs_diff`, `vcs_pull_ff`, `vcs_restore`, `vcs_revert`) defaults to `root=active_workspace` and accepts explicit `root=system_repo`; protected Ouroboros path names constrain generic restore/revert only on the explicit system target, so a project's own `BIBLE.md` or `contracts/` remains ordinary project content, while `preflight_review`, `commit_reviewed`/`vcs_commit_reviewed`, `vcs_rollback` and promotion remain system-repository lifecycles. `vcs_diff` without refs retains unstaged/staged behavior; `base` compares a resolved local tree to the worktree or index, while `base` plus `head` compares two local trees. The SEND bound `review_native_transcript_bound` is min(owner ceiling `OUROBOROS_REVIEW_NATIVE_MAX_TRANSCRIPT_CHARS`, the reviewer window's density-calibrated capacity in chars) measured as the next send's wire size (serialized messages plus tool schemas, recomputed after every append), enforced before every provider call. Late review completion is retained in the operation-addressed prompt/response CAS (`review_substrate.py`, `review_custody.py`): the response manifest stamps the complete producer outcome with the original task/root, attempt, slot/route, operation, subject, contract and roster/epoch binding, so exact reconciliation verifies that source and runs the existing surface reducer without a second paid attempt; pending, unreadable, mismatched and unknown outcomes keep custody and their full source references. A delegated review seat's custody is the run's, not the worker's. A rejoin after process loss (`review_custody._rejoin_window`) runs for what remains of the run's ORIGINAL window, from saved facts only — the durable START_REQUESTED/STARTED rows (`delegate_custody.invocation_record`, `run_timing`: start instant plus `max_seconds`), else the frozen row's `awaiting_since` plus the slot's logical window — floored at `NESTED_SETTLEMENT_MARGIN_SEC`: a repeated collect never extends it, an expired run gets exactly the margin, never a fresh window, and the $0 collect still returns at its drain window. A `succeeded` first seen by the deadline read is paid evidence: it is accepted (`late_success_accepted` on the actor usage) and its verdict extraction runs on the operation's own wait outside the slot's expired execution deadline, while the calendar `deadline_at`, Stop/Panic and the absolute ceiling remain stop axes; `cancelled`/`failed` terminals are never late-accepted.

Terminal delivery and later inspection derive a bounded host notice from the post-cleanup delegated-custody audit (confirmed terminal cancellations, live runs, unresolved invocation ids and undisposed patches stay distinct) beside unchanged model text and continuation narrative, so a later cancellation never rewrites historical authorship or the answer hash. Contributor slot evidence retains configured-subagent identity while its stored wire uses the mutually exclusive reference-or-route form, preserving native retrieval and its API budget admission.

### Usage ledger substrate vs. accounting policy

The startup seal audit selects its bounded manifest set before reading live attempt rows; missing live ids share one lazily validated archive-id set for the whole audit (an UNKNOWN result included) while forward checks continue independently, and the next audit refreshes that observation through the unchanged archive reader and its integrity/cache checks — no per-manifest archive traversal, no change to monetary authority or archive retention.

`usage_ledger.py` owns the durable append-only physical-attempt ledger (cross-process locking, sequence and transition validation, append+fsync, replay, loud tail quarantine); `usage_accounting.py` is the one-way policy layer above it (pricing, reservations, settlement, scopes, budget fences, imports, projections, admission), and the substrate never imports policy. The boundary means a pricing or budget-policy change cannot redefine valid ledger storage, and a locking or repair change cannot silently change what an attempt costs; compatibility events, state mirrors, task fields and UI projections may carry attempt ids and derived totals but never become a second charge source. `_usage_response.py` is the one NORMALIZER of a provider's usage block for accounting (its importers are `usage_accounting.py` and `loop_llm_call.py`), where a zero-usage body error settles at a confirmed $0 to release the reservation, so a provider storm cannot manufacture phantom budget exhaustion. Not the only READER of that block: every provider adapter reads the raw `usage` dict for its own response envelope, so a "consolidation" there would centralize a read that was never centralized.

#### The live turn slot

Beside assistant-level history the engine keeps ONE live turn per model client session, and its opaque token is transport, not content: it belongs to the caller that is running, not to any stored message. So the caller owns a single mutable slot (`llm_claudexor.ModelTurnState`) that rides the ordinary `LLMClient.chat` parameters to the engine boundary, the only writer — a dispatched durable result replaces the value, a released `invalid_continuation` repair clears it together with message envelopes; other non-dispatched, unknown or legacy-shaped outcomes preserve it. Holding state never licenses another generation, and silence about a turn never ends one. WHY a slot rather than the transcript: the live turn survives compaction that drops the messages and outlives a body that fails after its headers, so the last stored assistant envelope would rebuild the wrong lifetime. One `run_llm_loop` invocation is one turn (rounds, owner steering, acceptance follow-up, forced finalization, quota waits and reprepares continue it; a next loop and a cold restart start empty), and a consciousness wake-up is one such ordinary turn keyed by its own task id. A dispatch that leaves this transport for a direct API or local route ends the turn at the caller and never revives it on return; the engine alone compares route identity. Opting in requires a serving engine at `config.CLAUDEXOR_MODEL_TURN_STATE_MIN_VERSION`, read from the last SUCCESSFUL handshake — a failed probe never un-proves it, so concurrent status polling of that singleton cannot change the shape a running caller sends — and an older or not-yet-observed engine keeps the legacy request shape instead of risking a schema refusal. The token is never usage, an event, a progress note or a task card; mechanism in the `llm_claudexor.py` docstring.

Light mode, capped trees, subagents and the managed-update resolver get none; Cyber Pro may choose `in_place`; a body with no Git tree keeps in-place authoring.

Binding rewrites one fact: `repo_dir`, `system_repo_dir` and `branch_dev` of the tool context name the candidate, so target resolution, mode and protected-path guards, handlers, process cwd, review subject (`review_repo_dirs_for`: the candidate even when the task also carries a workspace root) and `commit_reviewed` share one identity and keep own-body policy — it is never an external workspace. `serving_repo_dir` keeps the running checkout for review governance, the restart marker and rollback. A child of a bound parent receives the candidate as its `self_worktree` source, including an explicitly selected serving root (relative or symlink aliases included), so its patch returns there. File paths inside patch and batch-edit payloads use the same serving-alias normalization as single-file edits. A process whose cwd is inside the candidate or its admitted own-body child copy gets `test_environment.isolated_environment` rooted beside it (`<candidate>.env`): own HOME, data, settings, caches, and the test environment's scrub — no `*_API_KEY`/`*_TOKEN`/`*_SECRET` values, no `GH_*`/`GIT_*` or global Git config, no inherited `OUROBOROS_*`, `OUROBOROS_PYTEST_ACTIVE=1` and `PIP_REQUIRE_VIRTUALENV` — so a push, a provider call or a pip install outside a venv runs from a cwd outside the candidate; local executors replace their inherited environment; Docker commands and services use a cleared environment with backend paths and require a mapping covering both the copy and its sibling `.env` directory. When that environment cannot be prepared the process is refused (`CANDIDATE_ENVIRONMENT_UNAVAILABLE`), never started with the serving environment.

Ownership is the root task. A host-validated continuation inherits its predecessor's candidate and `prepare_self_change(resume=…)` selects one exact retained candidate; either moves ownership only from an owner whose task record is terminal AND whose indexed ledger and executor records for that root, its effective retry chain and their recorded children are settled (`live_lineage_processes`; a corrupt set or an inconclusive matching process record is not quiescent). Nothing is inherited by room, name or date; each independent direct turn owns its candidate, and the Runtime block lists retained candidates. Binding appends the candidate to the lineage's mutation baseline as a late surface (a taken-over candidate names its previous owner as the predecessor whose quiescent changes are adopted), so `commit_reviewed` stages what the task's own baseline attributes to it exactly as on the serving checkout; without a host baseline the explicit/whole-tree contract applies as it does unbound. The commit is never auto-pushed, and each gate-created SHA is recorded on the row. A candidate commit takes P9's version-neutral form (VERSION untouched, every carrier span byte-identical to HEAD, no tag) or a numbered release (VERSION and every carrier in one diff, tagged); the deterministic release gate names the form from the diff and reports a partial carrier move as neither — on the serving checkout the standalone lane still requires the numbered release. Documentation-only changes also preserve every declared carrier span; ordinary prose remains exempt. Retention counts from last use: clean candidates remain until expiry; nested `OUROBOROS_RETAINED.txt` markers retain the process environment and source checkout, including when they appear after the initial GC verdict. Unadopted commits are compared to the serving checkout’s HEAD, even when it is a linked worktree. A candidate with no unique work expires; otherwise its tracked, untracked and ignored files (static env/cache directories and runtime junk excepted — a plain file merely named like one is the author's) are captured on `refs/ouroboros/candidates/<id>`, a version staged but not on disk as its own parent commit, and the checkout is removed only if that capture is complete — an incomplete one keeps the directory. The worktree GC computes that verdict outside the registry lock and applies it under the lock only while the owner remains terminal and quiescent, the row and path set match, and a preserved snapshot's staged index and file bytes are unchanged (`verdict_holds`).

Adoption is deliberate and restart-bound (`body_adoption.py`): `request_restart(adopt_commit=<sha>)`, or an evolution cycle's own restart, authorizes one exact commit that builds on the serving HEAD, came through the commit gate (Cyber Pro records the exception), keeps the entry files and the package-init hook, and meets a clean switch set; a constitutional change needs a numbered release outside Cyber Pro. Authorizing pins the commit, captures the switch helper outside the tree and writes the handoff; the old generation never writes the tree. The restart that carried it re-verifies under the update lock, and its exit tail arms — publishes the Git-dir pointer — only on the stop owners' own evidence: the worker pool's PID census of the kill that just ran (`supervisor.workers.last_worker_exit_census`, every doomed worker confirmed dead; the kill's boolean is about cleanup, never a reader census), `stop_owned_work` completed with no currently registered stop target and no live multiprocessing child; the owner's Restart and Panic never arm and never wait. The same exit tail compares the engine pin the NEXT generation selects — the bound candidate's file when the switch changes it (`bound_candidate_file`) — before stopping the owned daemon. Evolution cleanup abandons only its own task/candidate authorization. Crash recovery retains a reviewed candidate without authorizing adoption: the existing status names `prepare_self_change(resume=…)` and `request_restart(adopt_commit=…)` for deliberate continuation, with no automatic scheduler. The switch and its recovery are §2; `settle_on_boot` records `adopted` only for a generation whose process attested the switched tree before its imports, whose bootstrap (dependency sync and import test) succeeded and whose supervisor is ready, with the native-host readback where one applies, and reports every authorization that was not applied.

### Git and commit review

Missing fingerprints or size-only observations establish no transfer, and adoption grants no review approval or automatic new task. Commit preparation verifies the exact local working-branch ref before an unambiguous checkout: a missing ref refuses without changing the current branch, index or files (remote guessing and implicit branch creation are disabled), detached work retains the `checkout -B <branch> HEAD` recovery, and managed assisted merges retain transaction-owned precommit verification.

A reviewed commit is bound to one staged fingerprint. A cheap LLM-first advisory pass may precede the expensive gates; skipping it never skips independently applicable tests, triad, applicable scope review, aggregation or exact-SHA binding. The hermetic preflight runs the candidate in a disposable worktree and data root; triad and scope inspect the same staged snapshot, aggregation preserves actor evidence and obligations, and any mutation stales the binding. Managed exception: a managed-update resolution commit reviews the declared M0→S subject (`tools/review_subject.py`) and the commit gate binds S to the exact index write-tree the fingerprint pins. External review wrappers report readiness, never commit authority. Durable review state keeps attempts, obligations, readiness debt, raw actor evidence, and the final commit or tag binding; raw advisory output lives in `state/advisory_review.json` (selected by `snapshot_hash`/`ts`), not in `review_status(include_raw=true)`, which exposes raw triad and scope attempt evidence; `commit_gate.py` classifies review blocks, refuses an identical verdict, counts paid cycles against the ceiling and fingerprints the review contract. BIBLE supplies review authority, CHECKLISTS criteria, Development the procedure; snapshot identity, advisory coverage or audited-skip evidence, deterministic results, actor evidence, and final Git identity must all describe the same material.

Material ordinary Advisory commit review returns the complete outcome and exact `review_reference` before commit, tag or push. The author may correct, accept unchanged bytes, request another permitted review or stop. Explicit `commit_reviewed`/`vcs_commit_reviewed` continuation with that reference and `author_disposition` binds the current attributed candidate, reruns independent required preflight/tests and exact Git checks, and dispatches no critic. The author record references the original attempt instead of rewriting its subject or paid facts. Settled handback is `reviewed/review_only`; actual pending custody remains `reviewing/late_wait` and collectible. Clean supported review keeps its one-call path; Blocking gets no author override. Coverage is release metadata only, not syntax, structural size, tests or critic review; size policy stays warning-only locally.

Standalone advisory retains automatic carrier sync and worktree reads. Prepared advisory follows the commit gate's whole-index applicability, regardless of a narrower paths hint, including partial staging and the version-neutral carve; standalone documentation-only scope stays exempt. Governance uses shared tiers (§6 Governance delivery). If commit advisory is unavailable, compensating hermetic preflight runs only for independently applicable tests (tests not explicitly skipped and diff not documentation-only). Readiness accepts only exact repo/hash-matched records, preserving failed status and freshness.

Native preflight uses its executor's end-event and monetary custody, with no separate advisory operation checkpoint or native resume protocol; a returned unknown physical outcome remains failed evidence on the existing refusal and audited-skip paths, and a hard process death has no native exact-rejoin handle. ### Review stack

`review_cycles.py` owns the shared paid-cycle ceiling `OUROBOROS_REVIEW_MAX_CYCLES` (a positive integer or `unlimited`; anything else fails closed to the shipped default). One number, four gate meanings: paid reviewer-panel cycles per task for plan review; paid panel runs per task for acceptance, independently of ordinary author responses; paid triad-plus-scope cycles per ROOT task for the commit gate, counted from the attempt ledger at DISPATCH so the ceiling counts money and only undispatched attempts stay outside it; paid panel dispatches for skill review. Byte-identical material replays each gate's recorded verdict for free under that gate's identity. Physically dispatched technical failures consume capacity; undispatched refusal and collection do not. The last allowed panel still permits author reaction. An explicit task-local `max_improvement_passes=p` retains its p author responses and p+1 paid ceiling; without that override N creates no N−1 response limit. `unlimited` removes only the paid count, not ordinary task rails.

For skill review, reviewer convergence guidance and the author retry note (shared with commits; it owes an outcome, not a procedure, and is not contract identity) use the group's `review_round`, so revising payload bytes does not reset them. `snapshot_attempt` remains the separate ordinal shown in history and headers; free replay keeps its exact material and contract identity. A paid-ceiling refusal names author finish only where the existing enforcement predicate permits it.

#### Physical custody

`review_custody.py` owns physical workers under `review_substrate.py`, with no task scheduler or second timing ledger. Independent operation ids and the live map prevent in-flight work from appearing idle; deadline, budget, cancellation and ceiling still bind. Delegated expiry uses verified cancellation; API/thread calls disclose `in_flight` and collect late answers before retry. Settled terminal API errors remain replayable, so siblings cannot erase them or duplicate dispatch.

Capture state proves custody, never a synthetic id: only `reserved|released` proves pre-dispatch; positive capture outranks conflicting labels; `dispatched|unresolved` without terminal HTTP status remains custody-lost/no-resend (`usage_accounting`). Only explicit `__cause__` or typed transport metadata proves pre-dispatch, not inherited Python `__context__`. Delegated retries require durable invocation tokens matching surface/slot/operation. Explicit material/cycle retry identity excludes mutable prompt/history; changed snapshot, owner intent, route or admitted cycle creates a new identity.

Timeouts narrow to owner deadline/finalization reserve: VLM's 90-second and Anthropic's 120-second provider defaults are not generic review-reasoning limits. Returned responses and typed terminal errors settle even if empty, permitting bounded repair; post-dispatch socket death is `provider_outcome_unknown`, never another paid route. A spent owner window refuses at $0 before fan-out. Blocking triad in-flight rows remain pending; primary deadline expiry uses `deadline_local`, not provider-outage labeling. Reviewed commits have no separate outer tool cutoff: foreground custody lasts to settlement.

#### Paid stamp and owner custody

The `paid` fact behind the cycle ceiling is recorded WRITE-AHEAD at physical dispatch (`review_dispatch.py`): a gate installs one once-only `ReviewPaidStamp` for its wave, and each delivery stamps at its own boundary — a packet api row at the usage ledger's physical-attempt transition, a native episode on each paid send, a session before its replayable `START_REQUESTED` row. Assembly-only refusals exit before that seam, so a $0 attempt stays outside every ceiling, and neither a worker outliving its logical caller nor a crash after dispatch can lose the durable fact. The stamp is idempotent across the concurrent triad and scope callers, so no side's transport starts before the paid fact is durable; commit review and task acceptance treat a failed write as fail-CLOSED, skill review only when resuming a wave, other callers keep fail-open accounting. Task acceptance binds a strict exact-hash tree-wallet claim to that same stamp on every delivery its rows run — one idempotent claim per panel, because the paid identity is material, not route; a wallet or cancellation veto at the claim releases the reservation and no reviewer transport proceeds on any row (the launch floor is evaluated once, at loop admission: §6 Task lifecycle). Disclosed residual: a compatibility transport that raises with positive physical capture without having entered the canonical marker is stamped after the send; if the tree's last paid cycle is consumed concurrently at that late stamp, the wallet refusal replaces the captured exception and the substrate may resend.

Before either parallel surface starts, one locked write records `paid=True` plus both complete slot rosters and operation ids in the commit-attempt row; a delegated slot patches its reserved row with `pending_invocation_id` before the provider POST. Exact resume preserves rows and tokens; a missing or mismatched operation is `custody_lost` under every enforcement mode. The stamp records the process-custody server session and pid owning the reviewer threads (`review_owner_custody.py`): owner-loss is proven by pid death, never elapsed time — a TTL would convert waiting into resend authority, and starting another Agent is not evidence this owner died. Tokenless rows settle as typed infrastructure failure only after a death seam confirms that exact pid gone, and a legacy row without owner identity stays fail-closed. Plan review re-enters a recorded in-flight cycle only through exact live custody or complete operation-addressed CAS for its recorded dispatched rows; a delegated poll that loses transport after a run id exists preserves the exact durable invocation for retry custody rather than cancelling a healthy unknown run.

Per-row delivery is configured only through the structured reviewer-slot SSOT (`reviewer_slot_config.py`); the older per-row route envs are retired and ignored. The one shared session target is `OUROBOROS_REVIEW_SESSION_ROUTE` (`review_execution.REVIEW_SESSION_ROUTE_ENV`), an opaque `harness[=model][:effort]` spec that falls back to `OUROBOROS_SUBAGENT_HARNESS` when unset, so one delegated route is configured once; a set but unparseable value turns review sessions OFF with a warning rather than silently re-routing them onto the subagent route.

#### Surfaces and money admission

The review surfaces:

- Advisory pre-review (`claude_advisory_review.py`) — a cheap, staleness-aware error-finding pass; the audited skip covers only advisory admission, never authoritative review, test policy or snapshot binding.
- Triad diff review (`tools/review.py`) — configured reviewer slots cover the layered Change Review Checklist (the universal core, plus the Ouroboros Body Layer when the subject is the body — `review_helpers.load_checklist_layers`) with JSON findings under `config.adaptive_quorum` (the same SSOT as scope/plan/skill/acceptance review).
- Scope review (`tools/scope_review.py`) — intent/scope/coupling across the whole repository by retrieval on every row, in every context mode; the exact candidate, required-source manifest and diagnostic reading coverage stay distinct from substantive findings and configured enforcement (§6 Scope review by retrieval).
- Parallel orchestration (`tools/parallel_review.py`) — two-phase admission: the triad packet is assembled/fit-checked and every scope brief prepared before any reviewer dispatches, so a deterministic assembly block anywhere dispatches nothing and spends $0 (a lane paid while its sibling was doomed is real money for a half-verdict). Money admission (`tools/review_admission.py`: `commit_gate_paid_seats` / `admit_commit_gate_wave`) admits the wave while KNOWN spend is below the global `TOTAL_BUDGET`, current root and original billing-group fences, scope-first: every PAID seat (blocking scope seats FIRST, then the triad) is priced, as disclosure, with the reservation math `reserve_attempt` will apply (exact first send, native work-order and tool schemas included, plus its own output reservation; later native rounds reserve themselves), under its substrate's usage scope (`review_usage_category` + slot, so a warm split of the caller's transcript never stands in for a seat's cold prefix). Admission uses the reservation's `_merge_scope` resolution, including missing durable group bindings and explicit owner amendments; a raised root cap alone never raises its group — and admitted as ONE wave through `review_wave_budget_gate(surface="commit_gate")`. A refused wave records typed `$0 not_dispatched` on every seat plus one `review_wave_budget_insufficient` event with `binding_axis` (`global`/`root`/`group`) and the remainders; the block names the fence and actual remedy. Admission is a read-only pre-check without a wave-level hold; per-seat reservation and dispatch stay the enforcement, so a fence that known spend reaches mid-wave refuses the remaining seats with truthful custody. A paid seat is any api row (packet or native episode); an agent-session row rides the owner's subscription (ledger row written at settlement, never reserved) and is neither priced nor waited for. Every executor transition toward a seat runs under `contextvars.copy_context()`, so reviewer rows reserve under the admitted usage scope, bound root fence included; a mid-turn settings reload of the per-task limit changes neither side. An admission that raises is fail-open like the gate's own unknowns, but loud and typed (`review_wave_admission_unavailable`; the wave dispatches unadmitted). An admitted wave submits the scope seat first and starts the triad only once that seat's OWN reservation is on the ledger (nothing else releases the hold), bounded by `NESTED_SETTLEMENT_MARGIN_SEC` and by the scope seat itself; a hold ending unobserved emits a typed `review_scope_lead_unobserved` event. Admission touches no transport or logical timeout contract.
- Shared helpers (`review_helpers.py`, `triad_review.py`) — packet/brief building, checklist loading, JSON extraction, usage events, obligations scaffolding and reviewer actor records.

A free refusal never wears the form of a verdict: one that spent nothing is recorded as a typed `not_dispatched` fact plus its reason, never as a DEGRADED panel or a synthetic actor. That is the one shape across every $0 exit — a plan-review locator the evidence policy cannot attach is a named omission row the panel is dispatched with, an acceptance packet that overflows takes the ladder rather than reporting a verdict, a truncated or self-pageable row names its cut, and a request never sent is one seat with `operation_state='not_dispatched'` that stays in the denominator. `task_acceptance_review` refused before dispatch (a child with no selectable row, an invalid roster: `status=not_dispatched`, no run/actor evidence) stays a tool result outside `review_runs`; alone it cannot degrade the review axis. Task acceptance, owned above under Task lifecycle, shares quorum/transports but has no scope actor and stores its verdict separately from the terminal result.

**`## Review`.** The mind sees the lanes its task's settings snapshot serves as one semi-stable block after `## Available subagents`, in the shared and the declared-input context alike (`subagent_runtime.review_facts_block`). It is read by the resolver every review surface uses (`load_reviewer_slot_config`) inside the task's settings scope, so a later save changes the next task's block, never this one, and it never reads `reviewer_slots_last` (a dynamic runtime fact). It states the source — `structured`, the factory `default` with its models, or `error` with the resolver's message beside an empty panel, never an absent one — the enforcement, whether it blocks, the runtime mode and one rule sentence; per seat the catalog handle or route, model, effort and delivery; which lanes each surface runs (task acceptance: a root runs the full triad, a child at most one seat, named by `reviewer_slot_id` when there are several); and the task's five newest review-ledger records (none without the ledger module, `unknown` when it cannot be read). Above four triad/scope seats rows shrink to `{seat_id, model}`; `omitted` counts every row not shown. #### Subject operation

The review wave is parametric in its SUBJECT (`tools/review_subject.py`): a `ReviewSubjectSpec` states what is reviewed — the root (`system_repo` or `active_workspace`), the kind (`index` = the root's staged index, `worktree` = its live tree, `base..head` = a committed proposal whose base must be an ancestor of its head), the surface and the checklist layer — and `freeze_subject` pins it ONCE as a `FrozenSubject`: the prompt diff, the identity of the binary patch between parent and reviewed tree (`diff_sha`), the trees themselves and the name-status rows. Governance is ALWAYS the installed body's (`governance_root`: the SERVING checkout, `review_substrate.review_repo_dirs_for`'s rule — a bound body candidate (`body_candidate.bind`) is the subject that is reviewed and the body fact is read against the serving body, never the candidate's own copy of the rules; the gate's and the scope path's rules, checklist and navigation come from it, never from the reviewed root), while the reading root is the subject's. Exactly ONE subject is read on its live root: the gate's own (`is_gate_subject` — the system repository's `index` against HEAD with no explicit base), which goes through the gate's own capture (`managed_review_subject(surface="gate")` / `capture_staged_diff`) so its api pack, session task, scope brief, seats and gate decision are byte-identical to the gate's. Every other subject — `worktree`, `base..head`, a foreign root's `index`, any `index` against an explicit base — is MATERIALIZED by `isolated_checkout`: a detached worktree at its parent with the frozen binary patch applied to its index, under the install's data root (`state/review_checkouts/<token>/repo`; its `write-tree` must equal the frozen tree). The token is the task's ROUND's (`checkout_token`: a digest of the task id and the custody retry key, identity c below — the subject is frozen first and the path derives from it), so a rerun of the same round on the same task reads the checkout an earlier wave's open custody retained (same tree, read in place, never rebuilt) and its `session_root` is the one the open operation was keyed by; the checkout is removed on exit unless custody stays open. All deliveries read that frozen subject: the api packet and the scope brief carry `FrozenSubject.diff_text` (`ScopeBriefInputs.subject_diff`; never a recapture of a root's index), the `-U0` fit rung is `render_prompt_diff(0)` over the frozen `parent_sha`→`tree_sha` (never a repeated `--cached` of the live root), the required-source manifest is computed against the frozen trees, and the retrieving seats (session and native) are pointed at the checkout, whose staged index IS the frozen patch. `run_parallel_review(subject=…)`, `_prepare_unified_review(subject=…)` and `prepare_scope_review(subject=…)` read the frozen diff, trees and roots; `subject=None` is the gate's path unchanged. A frozen subject that is not the body's own index skips the body's release preflight (version carriers, Architecture book rows): the layer `core` is a foreign root under the body's rules, not the body's release contract.

Three identities derive from the frozen subject, never from the live index of whatever repository the process runs in. (a) The REUSE key (`review_reuse_key` → `review_ledger.reuse_key_digest`): sha256 over surface, subject kind/root/`diff_sha`/`tree_sha`, the rules source digest, the checklist layer, the assigned composition (`seat:part` rows), the enforcement, the review-contract fingerprint and the logical round (b); a SETTLED, DISPATCHED ledger record carrying the same key (`review_ledger.find_reusable`, `reuse_or_none`) is returned instead of a wave — `reused=true`, $0 — unless this task's own operation of the round is still open (it is collected first), while a pending record or a `NOT_DISPATCHED` refusal is never reused. The lookup is staged and disclosed: it reads the bounded hot index first (`INDEX_MAX_BYTES`) and opens archived segments only after a hot miss — every new subject is one — newest first and only until the first match; what it read (`rows_read`, `archive_segments` opened) is handed to the caller (`lookup`) and an archive read is logged with those counts. (b) The LOGICAL round (`review_round_sha` → `review_ledger.round_sha_of`) is what the author asked THIS time of these bytes: the `review_rebuttal` content sha, the author questions, the goal and scope as the semantic brief, and the resolved revisions the record names (`base` = parent, `head`) — so a new rebuttal, a changed brief or two revisions of one tree are each one more paid review of the same subject, while the identical request is the settled record. The identical-diff refusal (`commit_gate.check_identical_verdict_refusal`) lets a NEW rebuttal through exactly once, and the paid-cycle ceiling (`check_review_cycles_ceiling`) counts the round and stays COMMON to the root task per `(repo, tool)`: a second subject under an exhausted root is refused, not reset. (c) The RETRY key (`review_retry_key` = `review:<root_key>:<kind>:<diff_sha>:<surface>[:<round_sha[:16]>]`, the round suffix for every parametric wave; the gate's key has none) is the identity of the PHYSICAL operation the custody layer keys attempts by (`review_custody._attempt_key`), set on the context BEFORE any dispatch: a retry of the SAME round rejoins or replays the same physical review and never pays twice, and a NEW round is a new operation — the custody layer never hands a rebuttal the previous round's settled answers. The rejoin is durable (`tools/review_change_custody.py`): the parametric wave's write-ahead paid row carries its reserved roster and checkpoints each delegated start token onto its exact reserved seat (`review_state_custody.checkpoint_pending_review_invocation`, the gate's own write-ahead), its settled row carries the wave's final roster (a seat still owed stays `late_result_pending` with its operation and token), and a rerun of the round on the same task reads the checkout at the same path — one path per task and round (`checkout_token`), so another task's wave of the round never removes it — and finds that attempt row by the retry key (`pending_round_attempt`) BEFORE any reuse lookup, ceiling check or payment and runs the gate's reconcile-only path (`arm_rejoin` → `prepare_frozen_review_reconciliation`: settled seats replay or recover from their durable producer outcomes, the pending seat is rejoined by its exact invocation, nothing new is sent, no second paid row is written, the SAME ledger record is revised) — in this process or after a restart. A wave that fails before it has settled its own custody keeps a checkout an earlier wave retained. The gate's own key, set by its free-cycle gate, is kept when present. Money accounting at dispatch (`paid`) is unchanged by any of the three. The ledger record of a parametric wave names the frozen subject (`subject`: root kind, root, kind, base = parent, head, tree/diff, checkout) and carries `fingerprints.reuse_key` / `fingerprints.retry_key`; `review_ledger.build_wave_record(facts, surface=…)` builds it for every surface, `build_commit_gate_record` is that call on the gate surface. Same head with a different base is a different subject (§10).

#### Change review on any root

`review_change` (`tools/review_change.py`) is the commit gate's reviewer wave without the landing: one subject, at most one paid wave, one review ledger record (`surface="change"`), nothing committed and no test run (`tests.policy=NOT_RUN`; the author attaches verifiable test results separately). The mind calls it by judgment and nothing starts it. It reviews the active workspace (default), the system repository, or a `workspace_root` admitted by the `schedule_subagent` folder policy; the subject (`index`, `worktree`, or `base..head`) is frozen once by the subject operation (`review_subject.freeze_subject`) and, unless it is the body's own staged index against HEAD, read in an isolated checkout of its frozen tree (`isolated_checkout`), so the wave reviews exactly the bytes its record binds. A deterministic call error — `base..head` without both revisions, an unknown subject, a folder that is not a registered readable git root, an unresolvable revision, an empty change — is a typed `TOOL_ARG_ERROR` before any reviewer is paid. The checklist layer follows the root's `body_fact` (`layer_for`): the body is read against the body layer, every other root against the universal core, and `treat_as_body` raises only a root whose body fact is `unknown` (git cannot place it: no remote, no copy binding) to the body layer — a recognized body and a recognized foreign root are unchanged by it, `how` keeps the fact's original value and `detail` records the raise; the record carries `body_fact`/`how`/`treat_as_body`. Composition follows the same fact: on the body outside Cyber Pro the owner's saved rows stand and `reviewers` only adds seats (a named subset is recorded `reviewers_subset_ignored`); on the body in Cyber Pro and on every other subject `reviewers` is the panel (`panel.composition=composed`; omitted, `full_pool` = every configured seat), `reason` is recorded, and a narrowed panel without one records `reason_missing=true` instead of failing. `coupling_only` critics answer only the coupling question through scope rows, outside the quorum and the recorded verdict; `reviewer_effort` orders this wave's strength; `author_questions` reach the brief and the record verbatim. A composed panel reaches the wave through `reviewer_slot_config.composed_review_panel`, a context-local override (`contextvars.ContextVar`) that `load_reviewer_slot_config` and every slot reader under it see for exactly that wave — the pool threads inherit it through `contextvars.copy_context`, a concurrent wave on another thread keeps the configured panel, and the advisory and deep-review rows stay the configured ones. This is a disclosed deviation from the plan-review rule (DEVELOPMENT 06: an envelope `reviewer_effort` is an argument of `plan_review_slots`, never a contextvar): the commit gate's slot readers have no argument path, and growing `git_review_cycle.py`/`review_execution.py` to thread one is out of this operation's bounds. The same subject, rules, layer, panel, enforcement, review contract and author questions return the settled record at $0 (`reused=true`); a `review_rebuttal` buys a new wave, and an undecided record is never reused — a rerun of a round whose seat is still owed COLLECTS that operation instead (the subject operation's durable rejoin, above: same checkout, same attempt row, the pending record revised to its verdict, nothing paid twice). Paid waves count against the shared cap per root task and (reviewed repository, `review_change`), apart from the commit gate's count, and the paid attempt row records a review, never a commit; exhaustion is the typed `review_cycles_exhausted` with a `NOT_DISPATCHED` record, and it meets only a NEW paid wave — a reached ceiling never strands an open operation's answer. Enforcement is recorded on every root; only the body under Blocking enforcement records `enforcement_blocks=true`, so another root's FAIL is information, never a lock. `commit_reviewed`/`vcs_commit_reviewed` stay the only landing in the system repository: their `root` accepts only `system_repo`, and any other root is a typed `TOOL_ARG_ERROR` pointing at `review_change` and ordinary git.

#### Review ledger record

Every authoritative commit-gate wave leaves ONE durable record (`review_ledger.py`; `state/review_ledger/<record_id>.json`, contract `_schema_version: 1`) that states what was reviewed (`subject`: root kind, tree/diff/parent binding, candidate branch), what the panel was asked (`brief`: goal, scope, the two parts `change` and `coupling`, the author's own questions, the checklist layer and its `body_fact`/`how` pair — `unknown` when the repository kind was not established), who was asked (`panel`: seats, `distinct_models` counted over NORMALIZED observed models so three route selectors that served one model count once and an unobserved seat is `unknown`, never a distinct model; `distinct_engines` from `configured_subagents.engine_handle`; `single_model_panel`; `composition=configured`, `chosen_by=owner` — the owner's saved rows are the panel, there is no full-pool composition), what each seat was asked to run and observed to run (`rows[]`: `requested`/`effective`/`observed_model` kept separate, status, operation state, coverage, capability delta, cost, and `source_refs` to the retained full brief and raw answer), and how the gate read it (`verdict`: aggregate `PASS | FAIL | NOT_PERFORMED | QUORUM_FAILED | NOT_DISPATCHED`, quorum required/responded/assigned, per-row, `per_question.change` = the triad's answer and `per_question.coupling` = scope's, findings, degraded reasons), with `author_decision`, `tests`, `preflight`, `dispatch_refusal`, `cost` and the review-contract/binding fingerprints beside it. `review_wave_id` is `review_records.resolve_review_wave` over the gate's retry key, so the record, the usage ledger and the reviewer actor rows name the same wave.

Honesty rules: a `pending` record (custody still open) carries `NOT_PERFORMED` until the SAME attempt settles, which raises the record's `revision` in place — a stale snapshot at the same or a lower revision never overwrites a newer one (`review_projection._keep_newer_producer_facts` precedent). A free refusal before dispatch (`identical_diff_refused`, `review_cycles_exhausted`, pending custody) and a wave the budget fence declined (`review_wave_budget_insufficient`) are `NOT_DISPATCHED` records naming their cause in `dispatch_refusal`; an explicit author continuation buys no record — it notes the author's disposition on the record of the outcome it answered. The record is written on the CANONICAL data root after `parallel_review.run_parallel_review` returns its typed structured result and `aggregate_review_verdict` reads it; the gate decision itself is computed exactly as before and reads nothing from the ledger. Each seat's full brief and raw answer are retained through `artifacts.store_actor_source_bytes` (`task_results/artifacts/<task>/source_handles/context_checkpoints`) BEFORE the record's row is appended to the hot index `state/review_ledger/index.jsonl`; the index is a bounded projection that strips heavy fields only from rows whose record and sources resolve (`review_state_custody._strip_attempt_heavy_payload` precedent), rotates into sibling segments at 2 MB, and carries unresolvable rows forward unstripped (§10 invariant: hot indexes may rotate only after the source is retained). The record id travels on the attempt row (`CommitAttemptRecord.review_record_id`), in the returned `review_reference`, in the tool result (`review_record_id:` line) and on the reviewer slots' last-execution rows the same wave wrote — bound by each row's own timestamp, so another surface's later run of that seat keeps its own id — (`reviewer_slot_config.bind_reviewer_slot_record_id`); readers use `review_ledger.load_record` / `recent_records`.

#### Prompt size, density and windows

`review_helpers.REVIEW_PROMPT_TOKEN_BUDGET` bounds assembled inputs: triad packets, per-slot plan packets, task-acceptance packets and skill-review chunks with their own headroom. Scope and deep review assemble briefs, not repository packs; native sends use `review_native_transcript_bound` and reach other sources through tools. Every surface scales its output reserve to the route's usable window (`reviewer_window.window_scaled_reserves`); a reserve sized for a much larger window can otherwise consume all input room before a request reaches the provider.

Sizing is density-calibrated, not keyed to model names. `usage_accounting.execute_physical_attempt` records settled `(prompt_chars, prompt_tokens, route_fp)` witnesses in `capability_evidence.json`. Main uses the newest fresh exact-route witness, then exact-model witness, then neutral density; reviews use the densest fresh exact-model witness, which can undercut `COLD_START_TOKEN_DENSITY`. Stale, absent or cross-model evidence keeps the conservative floor. The witness TTL and bounded retention preserve both its densest support and recent observations. `calibrated_input_token_limit` combines the shared cap, measured density and absolute margin per call; triad, plan, acceptance and native transcript sizing consume it rather than freezing an import-time result.

Only the triad packet has a cold-start probe rung: `review_admission.density_probe_before_size_refusal` invokes `capability_evidence.cold_start_density_probe` when an irreducible packet exceeds a cold route's cap. One bounded slice of the actual prompt is sent on that exact model under `physical_attempt_limit(1)`; its witness buys one resize and fit pass. It never probes a warm route, retries the probe or runs when the packet fits. Progress and `review_density_probe` retain the attempt; a paid-ledger refusal is `budget_refused` and leaves the size refusal unchanged. This breaks the loop in which a request rejected before dispatch can never teach its tokenizer density.

`reviewer_window.resolve_reviewer_window` is the route-specific sizing source, with metadata probes serialized per route and limited by evidence TTL. There is no model-window table or window-authority floor. `ReviewerWindow.sizing_window` has a full-window sizing default for an unknown API window; raw subscription routes keep no numeric unknown-window assumption. `scope_window` adds its designated-default or conservative fallback and distinguishes confirmed, asserted, stale-unverifiable, designated-default and unknown provenance. `POST /api/owner/capability-ack` records an asserted window bound to one route fingerprint, invalidated by a route change; it sizes sends and grants no reviewer authority. A failed send supplies no verdict, while a small window alone does not remove a responding reviewer.

#### Governance delivery

`tools/governance_context.py` owns the shared tiers for triad, scope, advisory and deep review, and takes ONE external switch, the checklist `layer` (`review_body_fact.layer_for`; the governance root is always the installed system repository, whose rules execute). In the **body layer** tier 1 inlines BIBLE.md and CHECKLISTS_ARCHIVE.md, plus the executing code's CHECKLISTS sections: the surface's own and `Shared Contract Ownership`; a proposal cannot replace those rules. Tier 2 selects the review-protocol chapter, DESIGN for `web/` changes and DEVELOPMENT chapters naming touched files, within `runtime_limits.REVIEW_GOVERNANCE_INLINE_SHARE` of the usable window. Tier 3 gives physical-source book navigation for ARCHITECTURE; packet triad rows may also inline relevant sections within the same share. A skill payload (skill advisory) stays on the body layer — it is judged under the constitution — but is not this repository's code, so it receives no `Shared Contract Ownership` (`repository_rules=False`). In the **core layer** (the subject is not the body: another repository) tier 1 is the surface's own universal section alone; BIBLE, the archive, the shared section, DEVELOPMENT, DESIGN and ARCHITECTURE are recorded `not_applicable` and never delivered, and the navigation indexes the SUBJECT's own documents (`subject_root`: root Markdown files and `docs/**`, bounded and disclosed) plus its required-source manifest (`scope_required_sources(..., layer="core")`: empty by rule — the protected-path inventory, prompt rule, families and twins name body files). Each non-inlined document has a manifest disposition and navigation pointer. Retrieving rows can follow those pointers; tool-less packet rows receive an index of material not delivered, never an instruction to call unavailable tools. A whole document with the same source identity is credited `delivered_inline` without another read.

**The body predicate.** `ouroboros/review_body_fact.py` answers ONE question for a change review: is this repository root Ouroboros's body? `body_fact(root, system_repo=..., manifest=..., data_dir=..., treat_as_body=...)` returns `BodyFact(body ∈ {true, false, unknown}, how, detail)`; `layer_for` maps `true` to the body layer and everything else to the core. `how` records the git fact that settled it, in recognition order: `dir` (the root is the system repository or inside it), `git_common_dir` (a worktree or nested copy sharing the body's common git dir, `workspace_copies.source_is_system_repo`), `remote_chain` (a local-path remote reaches the body within three hops), `managed_remote` (a fetch URL equals the install manifest's `managed_remote_url` — the configured update source, official repository or fork), `install_fork` (a fetch URL equals the installed repository's own `origin`), `copy_origin` (the task-owned copy registry binds the root to its source), or `unknown`. URLs compare after normalization (scheme, user info, `.git`, trailing slash, host case); the branch never takes part; no directory, branch or remote NAME is matched by pattern (P5). A remote reaching none of these is `false`; no git, no remote and no copy binding, a git failure or timeout are `unknown` — the review then runs the core with the fact recorded, and the mind may raise `unknown` to `true` with `treat_as_body` (recorded in `detail`; nothing lowers a recognized body). The plan-review `constitutional` fact is the same predicate asked of a declared `affected_paths` locator (below). `review_helpers.checklist_fingerprint(layer)` records which rules ran: the sha256 of the layered text and `rules_source` = `docs/CHECKLISTS.md` at the install's blob (D31: the installed body's rules execute).

### Planning, deep review, reflection, memory

Plan review, task acceptance, commit review, and deep self-review answer different questions and never inherit one another's authority: planning judges a proposed approach before implementation, task acceptance the delivered objective, commit review a staged self-change, deep self-review the whole system. Post-task reflection and memory persistence learn from execution but approve none of those boundaries.

#### Plan construction and review

`plan_task` reviews an INTENTION before the work starts — the same organ for code, research, deliverables, and actions (BIBLE P3). The obligation is constitutional and the finalization gate is structural (`owner_hurry.force_plan_decision`); the order in which a task asks, explores and plans is the mind's judgment, and no prompt choreographs it. The envelope carries the goal, the plan prose, and a typed domain-neutral SPEC: `in_scope`, `non_goals`, `acceptance_claims`, `invariants`, `decisions`, `deferred`, `affected_paths` (REQUIRED — the files the work will CHANGE, `[]` when none), `affected_resources` (the same question in words: systems, services, projects, people, never resolved as paths) and `evidence`. Governance documents always come from the system repository; declared targets and evidence resolve against `active_repo_dir_for(ctx)`, and a path escaping the active subject or an unreadable root is a named omission, never a silent gap.

#### Post-task reflection

Typed root post-task triggers decide whether a run warrants Experience Review. `reflection.generate_reflection` sends the Light route one open prompt with the EXACT initial text (never a prefix) and its host-recorded `task_inputs.run_origin` beside it (provenance, never by itself the accepted requirement) plus tool-use, error, review and child projections, a bounded plan-review slice when the task recorded plan-review waves (`plan_review_facts.py`: per element its findings, the author's dispositions and whether it survived in the selected plan, the open author questions, the reviewers that never answered, a source pointer and named omissions — facts, never a score; which advice mattered is the mind's judgement) and the same frozen non-final cost snapshot the facts row carries; it runs outside the tool loop, records its own usage, and its failure never erases the delivered result or changes a review verdict. Its execution trace is the ALL-CALLS listing (`build_trace_summary(all_calls=True)`): every call in order with every argument, identical consecutive calls folded into one `×N` row with their rounds, the first line of a failed or repeated call's result, and one header count of rounds whose every call was non-ok — no positional window and no literal cut, because the consolidation seam fits the call to the Light route whenever that route's window is known (an unknown window sends the prompt unchecked — the accepted residual of enlarging it); the STORED `trace_summary` (task card, parents, children) stays the bounded two-argument preview. The trace row carries the `round_id` of the model round that issued the call (absent when unknown), when the listing really cut an argument value or a failed/repeated call's answer, the redacted per-call record is retained through `retain_memory_source` and named in the prompt as OPTIONAL reading, and its claim states the STORED bounds on both axes, not completeness: an argument already passed `sanitize_tool_args_for_log` (an oversized value carries a marker with its length and sha) and a result is the stored actor-visible cap, a partial one naming its own `FULL_RESULT_SOURCE_JSON` or `FULL_RESULT_SOURCE_UNAVAILABLE`, with a call's recorded manifest named only when it has one. Cut detection reads the ONE shared marker list (`artifacts.SANITIZER_OMISSION_MARKERS`), because a width test over already-sanitized args measured the widest argument in the task as a small one and retained nothing, while a hand-rolled subset missed the `_repr` and `_error` shapes whose arguments survive only in the call blob. Unavailable source retention is disclosed, error details group by full redacted content before display clipping, and post-task synthesis — the reflection and its Pattern Register update — thinks at the owner's Task / Chat effort (`settings_scales.resolve_effort("task")`), never a literal. Admission to the Pattern Register is typed, not a word scan: it opens on a call the loop recorded as errored (its stamped `tool_result_code`, or the recorded status for a legacy row), on a producer fact naming a failure the ok status cannot carry (a preserved commit whose post-commit tests failed publishes `post_commit_tests`), on typed codes already stored with an entry, or on a genuinely FAILED child — a cancelled, soft-landed best-effort or degraded child is not a failure. Those failed-child classes reach the root through the child evidence the synthesis walk already collects and make the run error-bearing for both the trigger and the prompt's error details: children do not reflect, so a short clean root that delegated the work is the only place its child's failure can be learned from. Deliberately not "a reason code exists", which would open the register on every terminal.

A reflection lands where it durably belongs: a non-project root appends the full entry to the canonical `logs/task_reflections.jsonl`, a project-scoped root to its project drive with only a bounded pointer row in the canonical log. #### Skill publication

The passive installed-skill projection never launches Betterleaks and never claims the current bytes are publication-ready (`skill_publish_eligibility.py`). The authoritative flow is:

`passive index (no scan) → selected preflight → explicit confirmation → ordinary managed task → immutable current capture with separate review provenance → payload scan → GitHub read-only planning → derived-output scans → first GitHub mutation → validated same-skill pull-request receipt → ordinary acceptance`

Publication validation and immutable capture share `skill_publish_eligibility.publication_author_acceptance`: fresh publishable critic authority or qualified current Advisory author authority. The host PR checklist states original critic and current author/published hashes, referenced review basis and author rationale, without claiming a second independent review. Recorded findings retain their actual severity, including critical and partial-quorum findings; catalog hashes and PR receipts never become review PASS. Passive and selected preflight use the same authority, with current captured bytes authoritative in selected preflight.

Every outbound byte derives from the capture (`skill_publish_snapshot.py`); the mutable live payload is neither reread nor rehashed to authorize the transaction (no time-of-check/time-of-use drift). Outside Cyber Pro, literal Betterleaks `high` findings (`skill_publish_scanner.py`) block the current outbound call; lower or unknown confidence is a redacted warning. Cyber keeps scanner findings/failures and review status as independent advice; an unavailable scan does not invalidate an observed publication. Packaged installs resolve the bundled `betterleaks-standalone`; source checkouts resolve the managed runtime installed explicitly with `python -m ouroboros.betterleaks_runtime install` — Publish never downloads it. A top-level `skill_publish` task (`tools/skill_publish.py`) is accepted only when pre-truncation metadata holds a validated pull-request receipt for the requested skill and configured Hub repository; the receipt proves the observed publication and never manufactures review PASS. A failed envelope (`skill_publish_result.py`) names its cause beside the stage: `reason_code` (the failed stage — `fork_sync_failed` and siblings), a `repair_hint` chosen from producer evidence, and the transport's sanitized `error_detail` with `github_status`/`github_operation` read only from gh's own error shapes, never inferred from prose. Owner lifecycle actions share `skill_lifecycle_actions.run_skill_action`: grant/toggle run in the lifecycle lane, local delete uses `skill_uninstall_state` (uninstall tombstones and authorized local deletion keep separate retention), and attestation keeps its deterministic floor in `skill_owner_attestation`. ### MCP and browser-facing external tools

`mcp_client.py` owns configured HTTP/SSE and local stdio MCP discovery and invocation (HTTP surface `gateway/mcp.py`; tools are named `mcp_<server>__<tool>`). HTTP/SSE entries accept literal multiple `headers` values alongside the unchanged legacy pair. `mcp_headers.py` validates token names, printable ASCII values without outer whitespace, case-insensitive duplicates and active legacy collisions; collisions fail explicitly, no scheme or value is inferred. Empty values stay configured but are omitted from the wire. Every value is protected in passive GET/status and diagnostic echoes; exact placeholders restore only against one saved server and case-insensitive name, unmatched masks refuse Save/Test without writes. Unchanged malformed stored headers survive unrelated saves; new edits must validate. Selected Show uses the same saved identity and effective loader. `mcp_import.py` translates only the supported `mcpServers` dialect into field patches, preserving absent/unrelated fields and refusing ambiguous identities, malformed input or transport changes; it performs no I/O or writes. URL userinfo is masked through the shared secret projection (`secret_masking.py` owns the exact MCP token placeholder shapes). Load-time placeholder repair runs before environment precedence (a real environment credential is never mistaken for a wire mask), only for recognized top-level Settings secrets — nested MCP values never migrate silently. Stdio entries pass one executable `command` and an exact string `args` list to the MCP SDK without a shell; optional `cwd`, literal `env` and `env_from_settings` (environment name → existing setting key) resolve from the same saved configuration for discovery and calls. Unknown fields are retained with a visible not-applied warning while a valid server stays usable; invalid known fields/references produce `MCP_CONFIG_ERROR`; response-only `auth_configured` never becomes configuration. Discovered tools join the selected initial capability envelope beside enabled, granted extension tools, behind the same `network` resource gate as on a managed task (`schemas()`, `get_schema_by_name` and `execute` agree on that), and a discovery failure is an explicit capability omission through `list_available_tools`, never a silent removal. The catalog lookup (`MCPManager.resolve_tool_name`) precedes the paid safety check: an unlisted name is `UNKNOWN_TOOL`, a disabled server or an unlisted catalog (health unknown) `MCP_UNAVAILABLE`, an allowlisted-out tool `ACCESS_BLOCKED`; none runs safety, transport or a refresh; hits recheck settings before Safety to honor revocation. Hints name only the addressed server's `raw → callable` pairs and an exact naming-rule identity (`mcp_client.naming_rule_matches`); nothing is ranked, aliased or dispatched, and raw names stay out of schema descriptions. Cyber metadata-target and configured `allowed_tools` filters do not veto an existing MCP call; descriptions and results remain untrusted data; every call still crosses registry, resource, safety, timeout and result-handling policy. Web-tool and network prohibition differ: `web=false` alone does not disable configured MCP or extensions; explicit `network=false` and tool disables are enforced at discovery and dispatch.

Browser tools are stateful and thread-sticky because Playwright sessions and greenlets have thread affinity; they cannot be scheduled as ordinary parallel stateless calls. A stateful-tool timeout therefore RETIRES the browser generation: the shared `browser_state` slot is replaced and the close runs on the owning thread once the hung call settles. Retired sessions are bounded in-process at `_RETIRED_GENERATIONS_MAX` per task, after which another session is a typed `BROWSER_BACKLOG_RETIRED_SESSIONS` refusal; generation isolation is best-effort under concurrent replacement (a fully closed class needs a process-isolated browser worker — disclosed future design). Model-driven in-page evaluation runs the supplied expression without substring guesses through `_evaluate_bounded`: Playwright's `evaluate` accepts no timeout, so the expression is raced against an in-page rejection, which bounds the ASYNC class honestly and no further — a synchronous event-loop block cannot be interrupted from inside the page, and the outer tool timeout remains the backstop. The caller's timeout also becomes the session default (`page.set_default_timeout`), floored on the action path so the five-second action default cannot strangle a capture. Chromium is the default; WebKit and device descriptors are targeted tools for a real Safari/iOS risk, not a universal acceptance matrix and not a claim that a narrow Chromium viewport is Safari-equivalent. First-party PR helpers are normal built-ins whose mutating operations stay subject to selected-root policy, runtime mode, delegated-child constraints, credentials and reviewed-publication authority.

Browser target policy is `browser_policy.py`: ordinary owner-control admission uses the actual HTTP request and three-valued service identity — never JavaScript substring guesses, no per-network-request LLM, no second policy engine. Cyber root/acting requests retain target and control reach; explicit read-only assignments keep their restricted contract. A live binding in `state/server_port.bindings.json` proves an endpoint ours; a service's missing snapshot can mean an older installation or failed publication, so its recorded facts still name what is EXPECTED — the integer `state/server_port` (the launcher's `state/server_process.json` can prove main), the Host Service configuration beside an expected main, and the local model's custody row with its live argv — and a matching expected endpoint whose process cannot be verified is refused as unknown, never treated as foreign (`server_process.runtime_service_identity`). Only a live snapshot of the same service supersedes its legacy expectation: main cannot vouch for Host Service. Unmeasurable POSIX identity never counts as proof. Every other port is an ordinary target, an unrelated application reusing an `/api/owner/...` pathname included — the owner-operation request shapes apply only at a proven or unknown Ouroboros endpoint — and a restricted target that DNS cannot classify is a typed `BROWSER_POLICY_UNAVAILABLE` refusal before navigation. Chromium and WebKit follow HTTP redirects natively and Playwright route callbacks see only the first URL of a chain, so `tools/browser.py` re-checks each document's `redirected_from` chain with the same target predicate before any page result: an allowed→blocked→allowed redirect withholds its content and refuses actions on that document, while the forbidden hop's request has already been dispatched — an owner-accepted, disclosed residual, not a pre-request or DNS-rebinding guarantee. Cookies, POST semantics, service workers and native redirects are untouched: no proxy, CDP fork, pre-probe or refetch.

#### Monetary authority and projections

**Live global limit.** One agent resolver: saved settings, reparsed on change; failure (including refused benchmark pins) falls back to environment without caching failure. Workers refresh environment at task start; live file reads keep reservation/wallet `TOTAL_BUDGET` current. Planning thresholds stay separate. Absent means shipped default; non-positive means unbounded, silencing the loop global axis. A run cap set by a launcher before settings load (`OUROBOROS_REVIEW_RUN_CAP_USD`, only the isolated contributor review) replaces the saved budget for that process tree, whose ledger starts empty; an unreadable cap is a zero allowance. Pre-existing gap: supervisor startup/reload parse raw settings and treat absence as unlimited.

`pricing.py` uses bounded best-effort exact normalized-route catalog lookup, never manual tables, prefix/fallback prices or admission allowlists. Every limit refuses once known (settled) spend reaches it, at reserve and again at dispatch; holds and unresolved bounds are exposure, never spending, and concurrent or late charges can overshoot. Unknown price: reserve None, settle reported cost or later exact price, otherwise None/non-final. Only structural pre-generation evidence with zero usage permits confirmed-zero rejection/release (`_usage_response.py` normalizes; adapters retain raw usage). `usage_admission.review_wave_admission`, compatibly exported by `usage_accounting` without eager cycles, admits a skill/plan/task/commit wave while known spend is below every global/root/group limit; the shared estimator's wave total is disclosure, and managed update only records it (`managed_update_wave_estimate`). Unpayable slots bypass without substitution; unknown prices stay disclosed without disabling priced siblings.

**Whole-work billing group.** `usage_admission.py` keeps task/root/parent IDs distinct from `billing_group_id`/`billing_group_limit_usd`. One store transaction checks global/root/group, successors and original-root late work included. Continue carries the initial sourced/revisioned `billing_group`, else the earliest live ledger authority, else the configured cap (`legacy_default`). `BindingIndex` keeps unlimited `None`; imported uncarried block rows bind from their own cap literal (`legacy_live`) when they agree, else the member stays open; the store keeps each binding ([store](../USAGE_STORE.md)). Review-wave `binding_axis=group`, pacing and strict Resume share this authority; late subscriptions retain own root/start custody. Only the group owner amends its cap; successor caps and spend remain independent. `task_money_snapshot` keeps distinct root/group axes over shared spend. Cap-only does not Resume, review or replace pacing. A rootless descendant refuses; unknown prices stay disclosed; late overruns bar admission without a bill guarantee. Standalone UI/marketplace contexts declare a non-task role; inherited managed scope wins. Global and cumulative service-label root caps remain: role repair does not cure lifetime-cap exhaustion.

Reservations retain applied `global_limit_usd`, explicit unbounded state and `global_limit_source`/`global_limit_revision` through transitions. Overrides inherit no foreign revision; legacy unknowns remain unknown. Summaries keep money as decimal text summed with `Decimal` in the writing transaction, because six-decimal display rounding is not monetary equality.
