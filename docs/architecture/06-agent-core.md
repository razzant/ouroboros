# 6. Agent Core

`loop.py` runs tasks, direct turns and wakes; admission, completion, satisfaction, verification, review and artifact finality stay separate facts, never converted into one another.

### Task lifecycle

`OuroborosAgent` runs in workers: pooled tasks and the mind's foci (§5 Conversation lane). `agent_task_pipeline.py` freezes contract/context, runs the loop, stores results/artifacts and root post-work (`post_task_synthesis.py`, `post_task_checkpoint.py`), then publishes. Store rows govern lifecycle (`get_task_result`, `query_data`); result JSON is import/export. `task_result_schema.py` admits rows (§11); usage owns money/tokens. Crash: `failure.kind="runtime"`; lost capture unknown. `finalization_timing.py` times delivery and shares reducer child reads; final evidence reads fresh. `supervisor/cognitive_operations.py` excludes typed operations from idle inference; deadlines/budgets/cancellation stay.

`task_store` reads the stable terminal page plus uncertain rows; the gateway applies effective global top N. `task_status` derives stability per body write; `store_hot_facts` backfills legacy NULLs by CAS. GET keeps envelopes without writes.

The transcript is append-only for OpenAI-family byte-prefix caching (§6 Prompt caching). `transcript_prefix.py` counts scoped breaks by origin (round facts, Health), stamps attempt rows, blocking no send; before preparation/pricing it retires signed reasoning from the first change, or all for system/tools changes or no baseline. `model_execution` separates requested/routed/provider-reported models of the last accepted ordinary solve; empty/forced/review/post-task replies cannot replace it. A host model switch after tool work gives its successor one authorship-recovery round; another tool-less reply degrades as `authoring_handover_incomplete`.

`loop_delivery.py` keeps exact `DeliveryCandidate` bytes before verification/review, even on failure. `outcomes.py` separates execution/objective/review/artifacts/child-absorption/custody. Receipts/exact references prove effects; tool errors alone never degrade answers. Unevaluated objectives keep `residual_tool_errors_without_review`. `FINAL ANSWER:` always survives; only `task_contract.answer_protocol="final_answer_line"` prompts it. Armed/sticky selection rejects direct array-wrapped controls as malformed; ordinary JSON is unchanged. `completed` can be unaccepted. Reasons persist; owner wording projects on read (§3).

Answers carry `terminal_host_notice` (plan/orphan limits), owner's `terminal_custody_notice` (stop receipt apart): nonempty custody only. Notices keep answer bytes/verdict, revive no approval; child (all categories)/plan-evidence hash them, changes void dispositions. CLI labels, Presence omits host status (either form). Salvage: `Preserved intermediate output (not a final answer):`, bounded preview, complete `get_task_result`/stop receipts. The reader labels cancelled rows `[CANCELLED_BY]`, others `[OWNER_CONTROL] command=stop_now|wrap_up|unknown` by recorded policy.

Without a selection episode, a first reply is final unless its typed finish requires recovery. After substantive host continuation, Main selects complete retained bytes via `finish_task(action=finish|stop, answer|answer_sha256)`; compaction withdraws unavailable selectors; conflicting batches hold, live or restored. Finish shows new child results and a pre-delivery notice (unexamined result, running children, open runs), unread reviews, skills/handover, owner sources, material, services, configured review and admission; holds log `completion_held`. Stop preserves selected unfinished work, waits for nothing, buys no criticism/answer, cancels no descendant and grants no approval; evidence-only changes cannot undo it. Presence counts a send only on host-confirmed delivery.

Provider death salvages text but ends `failed`/`infra_failed` with `provider_unavailable` (or `resource_refusal_no_resend`) and an immediate not-completed owner notice. One forced model call runs only while a call can land; wait expiry and `loop_llm_call.provider_no_call_source` forbid another paid window. `terminal_provider_notice` quotes the provider beside the result, never advises blind replay. The finalization sink stamps `model_final`, `host_notice` (host words) or `host_salvage` (salvaged output); a forced reply requesting tools beyond one `finish_task` is incomplete, a whole one survives a disclosed length cut, and its verdict rides `trace_refs`. Finalization controls are typed mailbox entries. Descendant activity is not the task's own progress; an unkillable process stays visibly running; no final cost, even zero, settles `delegated_runs_unreconciled` custody.

#### Result review

`review_change(subject="result")` (`tools/review_result.py`) asks the pool whether the result, and a method the owner fixed, does what was asked (CHECKLISTS `Result Review Checklist`, `result_rubric`). Subject: what was asked (request fields, held claims `effective_acceptance_claims` (§11), owner's words), the reply, what the task produced (`result_material`: registered artifacts (empty too), changes against the admitted folder's baseline and its `attributed_commit` epochs, paths its observed native writes bound (workspace editors skip same-byte writes: `completed_no_effect`), `observed_effect` receipts, failed calls' too; files name exact copies (links: their text) and text excerpts; a failed capture is a gap, not no production) and host-attested verification receipts. Inputs, checkpoints and expected or never-created outputs are intent. Text is retained once (`result-subject-<sha16>`); its sha, the wave's identity, reuses the settled record at $0.

`review_change` owns the wave: panel (`compose_panel`), paid stamp, custody, rejoin and settlement (`surface="result"`). Addressed mail or Pause leaves it with `review_pause`, owing a notice or late mark. Seats answer `PART_RESULT`, without coupling, under adaptive quorum; failed rows are infrastructure evidence, pre-send refusal `not_dispatched`. Children may ask (`subject=result`).

Modes (`OUROBOROS_TASK_REVIEW_MODE`, §7; owner, 8 Nov 2026). Auto forces nothing. Required reviews ROOT deliveries with produced work (observed production, a `review_answer` contract's answer, an adapter answer line): absent a settled subject-bound record, the host collects a running wave at $0 or seats the pool (`chosen_by=host`). An outcome not received whole, PASS included, is handed back once; then PASS delivers and any other outcome delivers on the author's next finish (an acceptance of that subject). After a received review a revision is the author's (`_revised`, Presence's too; its reasoned finish accepts it at once; an earlier PASS stays that version's). The one running review (this or an earlier version) is awaited unless `pending_review=finish` gives a rationale after answers ready since. A spent allowance keeps one $0 refusal per subject/ceiling. A review that missed newer owner words, same or revised answer, shows them and an unread outcome once. Shown facts survive same-ID restore. Presence speech is never held; its review owes late feedback (`review_pause`). `review_decision` says why none ran. Off refuses `subject=result` before payment.

Objective authority. Every mode but Off binds the settled review of exactly the delivered result into the task's review runs (`authority="host_root"`, `binding_hash` = subject sha); a new candidate (any rail) supersedes earlier runs without deleting them; an author acceptance (`informed_finish`) counts only on a current run of its subject. `_objective_axis` gives the reviewers' PASS/FAIL; PASS from `author_acceptance` (`author_finish`, `author_finish_pending`, `previous_revision_accepted`), Done with warnings unless beside a PASS; blocked FAIL (`review_cycles_exhausted`) when Blocking could buy no review. Spent allowance and price. A spent `OUROBOROS_REVIEW_MAX_CYCLES` leaves the author's call on what was reviewed; the ceiling stays the owner's setting. One review's price is measured (`review_price.py`): the median of a row's recent waves on its current model, each seat's attempts summed, with count and range; no history is `cost unknown`, a session row `uses a session seat and time`, a local route `no API cost per review`. `## Review seat activity`, `GET /api/review-pool` (`basis: observed_reviews`), Settings and onboarding print the same words; a measured helper first call uses them too.

Root admission seal (`delivery_seal.py`, re-exported from `loop`). Sealing closes the root's admission (no new subtask under it) and catches by generation an owner message arriving between "decided" and "delivered". It runs only at an author stop, right before its delivery (`loop_delivery._seal_admission_before_delivery`); a plain finish never opens it, so only the local admission-lock drain catches an owner message routed at the supervisor. Born as the task-acceptance fence, it keeps the persisted names (`acceptance_fences`, the `acceptance_fence` event, `state/acceptance_fence_acks/`, the `_task_acceptance_*fence*` context fields). The supervisor owns the row under Q (`queue_transitions.transition_acceptance_fence`: end compares `owner_message_generation` and seals or releases) and clears it at `task_done`; pooled fences bind attempt/PID (unanswered begins release, ended owners retire at handoff, consumed Resume rebinds park fences). `ok` seals; only owner facts revise, a generation mismatch (also one seen locally) or pending owner mail: `_release_for_owner_followup` pops `task_completion` and ends the fence with `revision` (serving a follow-up after the seal, `_owner_generation_changed`); a begin refused `sealed` is the worker's own lost ack, a pooled attempt refused `stale_attempt` lost its queue ownership and never publishes. Any other refusal, like `unknown`, is a gap, never a refusal of the answer (§10 invariant 25).

Owner-source acknowledgement (the completion protocol of `finish_task`, argument `acceptance_subject`). While delivery control asks Main to select a completion, `loop_messages.prepare_acceptance_observation` appends the `[ACCEPTANCE_SUBJECT_OBSERVATION]` row when the owner-source facts changed (earlier rows stay for prefix caching). `acknowledge_acceptance_observation` advances only consumed ingress, never criteria or a verdict; it refuses with a typed `ACK_*` cause when the named source was unobserved, owner input unread or the owner source or queue generation changed; every outcome is the durable `acceptance_source_ack` row (§10 invariant 21).
