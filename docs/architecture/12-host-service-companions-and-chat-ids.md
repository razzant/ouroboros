# 12. Host Service, Companion Processes, and Chat IDs

Place facts and identity:
- Connectors report typed facts; the mind judges. Core matches membership, never text.
- With `presence_identity: 1`, send `identity` on every event and status payload, never in `places.json`.
- Focus voice, owner match, Safety and delivery stamps use the event's identity or none.
- Other Safety targets/own wakes: the first valid identity among 50 newest arrivals.
- Only `kind: user` matches an account-scoped owner confirmation.
- The browser derives owner/can_confirm from status identity/labels; no server path dispatches a route.
- Status `labels` suit any host (older hosts ignore them); a labelled core **manifest** kind needs this release (older hosts drop the place entry).
Silent can wake; Paused admits no new focus. Unverified speech grants no owner authority.

### Host Service boundary

The Host Service (`gateway/host_service.py`, `OUROBOROS_HOST_SERVICE_PORT`) authenticates `x-skill-token` against payload hash, executable review, enablement and grants. Tokens hold no secrets, stale on edits and refuse stringification (`skill_token.py`); routes/permissions: §4. `POST /notify` (`host_notify.py`, `notify_owner` grant, `/identity.notify_version`) writes one sentence ≤`NOTIFY_TEXT_MAX_CHARS` as a `skill_notice` System row signed `Notice · <skill>` in the owner's chat, waking no model; 503 means unconfirmed. Review covers transport identity/attribution, bounded polling, panic cleanup, token confinement and exfiltration. Reviewed owner-bound transports may control Ouroboros; external slash commands use a separate positive-owner slot (`supervisor/state.py`): unidentified transports cannot bind, web identity cannot exclude the remote owner. `wait_for_response` is A2A-only.

Decision/language writers: §4. Review waits reach their live controller after author completion via `pending_action`; a stale revision/identity or absent consumer is 409 (§6 Quota and auth waits). A verdict grants no continuation or skill authority.

`host_service._RateLimiter` is a token bucket for `/ui/ws-message` bursts and sliding windows elsewhere. Refused relays aggregate per burst as a durable `host_service_ws_relay_dropped` event with count in `logs/events.jsonl`; child `send_ws_message` stays best-effort `None`, in-process broadcast unbounded.

`chat_uploads.store_upload` owns Host-confined paths/completed multipart spools, called directly by Host Service and through `gateway.files` for `/api/chat/upload`. The worker copies and closes its spool despite HTTP cancellation; skills keep sources. Neither ingress rejects size; `_INJECT_ATTACHMENT_MAX` and Files-upload policy remain separate. One request-local cleanup stack removes new unaccepted copies on partial copy/refusal/cancellation; replay adopts no duplicates. Accepted bytes survive disconnect/unknown outcomes, which claim no acceptance.

### Operation correlation

Named injection returns `operation_ref=<chat_id>:<client_message_id>` on 202/200/504/disconnect. `message_ingress.accept_local_message` accepts the name and raw `reply_to`; host resolution precedes the canonical row, which must land before enqueue. Same-id/text/skill replay rejoins even before dequeue; changed content/source/Reply yields 409. Content includes ordered attachment `[sha256,name]` (`chat_uploads.same_message`); regenerated storage names do not change identity.

Inline photos (`_INLINE_IMAGE_MAX` before decode; `CREATING_SKILLS.md` `inject_chat`) park once in `data/uploads` and always stage, retaining originals for model pixels. Non-image bytes stage as files, never vision under the transport's label. The queue is in memory: accepted delivery lost on crash reads `lost`, without second-enqueue authority. One same-id retry of a canonical write that raised in this process hands the row over as `queued`.

Routing annotations/outbound task ids only aid discovery. Reads/cancel require the queue/task's complete `origin_message_ref` to match the authenticated canonical skill source; `DirectActivityRegistry` carries that origin. Named waits poll that operation's retry-aware effective result; chat order proves no reply. Cancel enters durable intent/cascade custody (§5) only with matching origin and installation root; otherwise `cancel_unsupported` precedes writes. Unresolved custody never becomes false `cancelled`.

### Focus in places

`review_requested`/`assigned` are observed facts, never inferred words. Source-bound roots contact Main with `send_user_message(destination="main")` or `escalate`, each with a `request_id`. `presence_owner_contact.py` retains source facts for the voice line, preserving authored words. Messages use the outbox, questions `owner_quiz`, deferred events the attached supervisor bus. Identical retries rejoin; changed fields (waiting intent included) refuse. Only source-bound contact deduplicates omitted keys. Authority-only roots keep room questions; children report upward.

Live answers use the author's final-drain admission lock; late answers enter Main with the exact owner words, source snapshot and child reference. Only owner-started roots inherit `presence_binding_authority`, never an automatic external final; the owner stays unrestricted. Silent permits private contact; Paused preserves owed contact without new focus. Service/scheduled notices keep separate gates. Display routing: §3.

`GET /identity` advertises each Presence capability independently (CREATING_SKILLS); missing required support is a setup gap, never fallback through owner ingress.

`POST /presence/turn` (`presence_runner.py`) admits exact provider/account/conversation/thread facts, skill-confined files and an authenticated place. Conversation and active-turn leases span processes; HTTP disconnect releases neither work nor capacity. Live retries join only matching conversation/actor/text under the turn ID; mismatch is `presence_event_identity_conflict` (409), never another room's answer. Refusals: CREATING_SKILLS "Places and focus transport ingress".

Before effects the runner writes/reads its source-bound RUNNING row; ambiguous writes allow receipt retry, not regeneration. Lost stacks, unknown terminals and cancellation return retained refusals (event/receipt kept, FIFO released, original/child observed separately). `/presence/work` stays pending while the attempt can change, then serves selected speech or failed/cancelled silence with unknown-effect facts. The orphan sweep records failed/`presence_attempt_lost`; `presence_recovery.py` keeps `host_task_facts` for room memory/consciousness without forced questions or apologies. Missing evidence proves neither silence nor no effect.

Only `presence_retry_proof` permits regeneration: first-round temporary refusal, every route engine-confirmed `not_started` and ledger-released, no response/tool/handoff, and a dated reset. After reset the conversation gate writes `presence_retry_next`, a new physical ID under the original event; other refusals stay retained. A live turn's shared fallback/continuation (§6) keeps earlier effects, unknown cost, controls and its conversation through recovery or retained refusal, never replaying the event.

`/presence/work` separates queried `work_ref`, producer `task_id`, canonical `output_ref` and actual `child_work_ref`. Original/child/continuation outputs, including selected failed terminals, deduplicate by output identity, never text or queried work. Legacy gaps stay gaps.

`presence_continuation.py` parks only for the author's left review (commit/change/result, `review_pause`) or required private Main question. It grants no generic sleep, detach, owner Pause or budget-pause callback. With tool/process/service custody idle, it records `open_turns` and a source-bound write-once initial envelope on the RUNNING task, reads them back, publishes, then lends conversation and active slot. Otherwise it waits holding custody. Reentry reacquires both in admission order before any model/tool/forced call and appends `[PRESENCE CONVERSATION RESUMED]` facts. Hard stops use the zero-call rail; rounds and wallet persist. Bound question waits resume without inventing consent; durable terminal rows, cancellations included, reconcile questions and waits; unknown attempts stay unconfirmed. Wait-ended events address the question's publication room.

Versions 1–2 take the initial envelope, 0 the terminal; 2 when its prepared loop takes mail, lending nothing, never queueing. Reviews never publish; released selections never resend. Lost authors stay interrupted until an explicit new event starts a new author from retained facts (`CREATING_SKILLS.md` “Presence continuation”).

Reentry keeps exact rows and gaps in immutable `presence_reentry` artifacts, read through existing task scope (`get_task_result` with `presence_reentry_sha256`/`presence_reentry_offset`). It reads only the producer's conversation from `state/dialog.sqlite` within frozen bounds. Legacy cursors use the import ledger; new snapshots bind the end to a retained row identity. Inode/mtime-only snapshots report `legacy_source_identity_unavailable`, keeping their text; import gaps stay explicit (§6). `presence_observations.py` accepts transport-queue snapshots in `event.conversation.transport_queue` or authenticated work POSTs: dated observations, never inbox certainty, admission or delivery proof; absent means unknown.

Entry/receipt identity is `presence_bindings.conversation_key` (empty thread `0`). Durable `first_lent_at` anchors parks/termination; returning authors update their own `open_turns` entry without replacing newer pointers. Outcomes: `message`, `silent`, `tool_delivered`, `deferred` (requires admission; orphans replay silent). `peer_roster.independent_message_target` admits `forward_to_worker` to source-bound RUNNING turns as peer context, never owner authority. Proactive speech uses connector tools.

`places.py` owns atomic revisioned `state/places.json`, serving `ouroboros/gateway/places_api.py` and `configure_presence`. Connect creates Silent, repeat Connect keeps choices; low-level/migration defaults stay Active. Only owner doors/APIs confirm accounts or activate; consciousness may set Silent/Paused. Edits advance document revision; stale edit/disconnect returns current summary or null. Migration copies bindings/instructions/topics/model/folder once, keeping files/routes. Connector updates never replace choices.

`place_projection` owns PlaceSummary: label, icon, readiness, source/settings, facts/labels, revision, rooms, nullable spend and consciousness safety_mode. Status/launch retain brief stored views; display money may be stale, admission strict. Connect sources distinguish absent/nonempty/empty/unavailable; null accounts are not wildcards, broad/narrow places coexist (CLIENT_CONTRACT “Places”).

Contribution `facts` declares core kinds and labelled `signal.<slug>`, `wakes` defaults; `/identity.presence_wake_signals: 1` advertises them. Intake and new signal choices need the live declaration; saved choices stay removable while off. Connectors own signal logic; bot gating/OR semantics unchanged (CREATING_SKILLS).

`ouroboros/gateway/host_service_places.py` captures events/attachments before admission. Paused, Off/Panic and unmatched events settle heard/silent; exhausted or unknown allowance requests retry. `conversation_lease.py` owns process/file locks, lending and reacquisition. An accepting local author holding its conversation lease takes wake and background `place_event` context-only mail under its final-drain lock; closed, ended or remote ones leave ordinary admission eligible. Only an unseen wake earns a round, never owner authority. Stop finds remote lent authors by stack-lifetime locks; reentry checks `supervisor.consciousness_carriers.autonomous_work_enabled` before reacquiring; disabled, it ends on the zero-call rail. Focus keeps consciousness provenance/autonomy and a root cost ceiling; no new capability ceiling; legacy ones stay decodable.

`presence_context.py` appends `prompts/FOCUS.md` after the shared prefix: actor/wake facts, authored notes, existing work, allowance, roots and folder address; full knowledge topics stay context. `actor.authenticated: false` blocks owner confirmation, Safety occasion and root promotion (absent: platform behaviour); wake rows carry `as`. `finish_task` selects speech or silence. `place_reply.py` checks current Place state and Safety (`place_reply`) before automatic speech, including promoted roots (retained destination, no wake stamp). Flags return to the mind; Silent/Paused/disconnected/Advises holds become one System row per subject. Forced finals cannot bypass an unresolved flag. Cached turns/envelopes/polls recheck state without generation or another Safety call; outward silence keeps answer/output identity. Late receipts stay evidence with warnings; transport custody and recovered-output identities persist.

Receipt negotiation: `CREATING_SKILLS.md` “Reporting actual Presence delivery”. `presence_delivery.py` writes authenticated `/presence/delivery` observations: mode 1 records provider-receipted speech, mode 0 unconfirmed authorship. Receipts prove writing, not reading, and never finalize tasks; failures/uncertainty are System facts. Identical readable reports deduplicate; conflicts refuse. Malformed history gives `history_coverage=gapped`; `duplicate=false` then means no readable match. Outboxes own report backoff; report failure neither resends nor blocks delivery. Client-id lookup in `dialog.sqlite` survives restart and refuses unknown import coverage.

### Live meeting peers

`presence_call.py` admits a connector's call by place, as `/presence/turn` does, and opens it only in an Active place whose current choices would start a focus for the event (wake match, consciousness on and not Advises, allowance left; the request is heard in the room first), under the same gate and `PROACTIVE_TURNS` registry with a loaded Live Conversation turn (§13). `/call/open` and `/call/{call_id}/peer` (`gateway/host_call.py`) require `call_peer`; new calls also require the connector's Presence grant. Attachment grants narrow mic/speaker/video directions and bind the token digest. The common peer parser preserves the meeting protocol; `presence_events.py` checks call origin identity. Final external captions remain Presence observations; playback evidence never makes a participant the owner. Meeting skills are unchanged.

### Companion processes

Reviewed manifest descriptors enter host-supervised durable custody, reconcile on lifecycle changes/restart, and stop on disable/unload/panic. `state/extension_generation.json` publishes the server's live set; workers adopt at task start/dispatch miss, so enablement is visible without pool respawn. Workers write durable `state/extension_reconcile/` requests instead of spawning server-owned children; reconcile names the answering process.

Aggregate/Skills health uses the server observation; worker health is only a qualifier, so failed handoff cannot advance `last_known_good`. Restart-budget exhaustion persists until successful start. Companion cwd is the reviewed payload: edits stale review before reload instead of silently changing a live process. Projection: `state/extension_companions.json`.

### Chat-id delivery

Each message has one destination; absence is `None` (§11.1 `chat_id_policy`). `HIDDEN_CHAT_ID=0` serves Skill Review/unbound headless work without a browser reader. `message_bus.notification_chat_route` chooses notices; history query chat 0 coerces to Main and excludes chat-0 rows. Lineage/admitted Project chat routes work to its Project; negative A2A ids never enter human streams.

An exhausted terminal outbox skips chat 0 while retaining incident/message. Only positive same-id/destination evidence suppresses notice (`terminal_delivery`), never bare ids or missing ACKs. Memory/consolidation use the same value/None policy: per-window registry snapshots name Main/Projects by stable ids; missing/ambiguous ids remain explicit, never default Main. Presence labels require transport facts re-deriving the chat id. Labels are read-only attribution, changing neither routing, visibility nor delivery.

`place_intake.py` decides attention; `place_arrivals.py` owns heard facts (imported replays too), deferred sources and room/activity indexes; `presence_history.py` records earlier messages as platform-authored history (never owner/Ouroboros) starting nothing; arrivals keep send time/order (`source_order`; CREATING_SKILLS “Importing earlier history”). `loop_completion_schema.py` selects completion, preserving legacy registries; `tool_effects.py`/`place_guard.py` own effects/targets (§13).

Heard-only events create no task/context blob; the room row keeps identity/reason (`paused`, `off`, `no_wake_match`, current-author handoff). Later On never reconsiders them. Focus/heard settlement share the intake lock and preserve custody. Source rows stay immutable; `dialogue_store` derives deferred pointers from dedup records; `chat_chain.source_row_id` preserves identity.

`places.place_room_index` indexes latest arrivals/nonterminal focus counts, never walking history or loading per-arrival tasks; unknown counts stay null; only the rooms endpoint decodes arrival details. Discovery may miss legacy/outgoing-only rooms; import/gap flags describe the store, not provider completeness. Indexes build once from source rows. `ouroboros/gateway/place_history.py` projects recorded delivery/heard facts, exact-task focus starts, current owner confirmation gated by captured actor authentication, import facts/send times (CLIENT_CONTRACT “Places”). `account_candidates` suggests up to 20 nonbots (not the account itself) of the newest 50 arrivals, confirming no identity, keeping no actor list. Migration imports valid bindings, records failures in `migration.problems` (shown by `/api/places`) and publishes one marker.

For an opaque outbox mutation (empty conversation id), `GET /presence/place` reports any Silent/Paused place owned by that authenticated connector/provider/account, including broad and migrated wildcard accounts. An optional `thread_id` resolves a topic-specific place; omission keeps the room lookup. Declared tool destinations match account, conversation and thread as separate facts, each recipient checked independently. Retained-work GET/POST may omit `binding_id`; authentication checks the retained task's connector, never the ref alone. POST accepts exactly `transport_queue` plus an optional `binding_id`; legacy binding ids remain checked.
