# 11. Frozen Contracts v1 (`ouroboros/contracts/`)

ABI promise: the frozen shapes and helper semantics skills and browser consumers rely on, their extension rules, what stays deliberately unpinned, and the one break window an upgrading install must know. A removed field needs a versioned successor.

`ouroboros/contracts/` freezes shapes with their helper semantics; §11.1 names every owner and its enforcing tests. The additive browser ABI lives in `ouroboros/gateway/contracts.py` and its JSDoc twin `web/modules/api_types.js`, pinned by parity tests; `gateway/schema.py` derives the ingress schema from it, so a contract edit cannot leave a stale schema behind.

### 11.2 What is NOT frozen (intentionally)

The full `ToolContext` dataclass stays mutable implementation detail; the protocol pins only the minimum. Only shape keys are pinned, not raw WebSocket/HTTP values, and only the frontmatter schema, not the free-form SKILL.md body. `state/state.json` and `queue_snapshot.json` carry no `_schema_version` and read as version 0; `task_results/*.json` uses stamped admission owned by `task_result_schema.py` (§11.4).

### 11.3 What to do when extending

Add the field to its active frozen owner (§11.1), keep existing consumers working, and enforce the new surface in the contract/parity tests (CHECKLISTS item 27, `gateway_parity`, owns the review-time criteria). Removing anything from 11.1 is a deliberate ABI break: it requires a versioned successor and a migration note in the release row; 11.4 carries only the upgrade facts of the current window, the release ledger the rest.

### 11.4 Recent ABI Retirements

- **ABI 7.0** is one deliberate window, so the breaks land together, not one per minor. `scripts/rc_audit.py` is the read-only pre-upgrade scan of a third-party install: it names every incompatibility across its six classes, reading the key lists at run time.
- Settings: `RETIRED_SETTING_KEYS` in `settings_defaults.py` is the machine list; `load_settings` strips its members off disk and tells the owner once per retired-key set (a log line per process, one System row; `state.json:retired_settings_notified`). `OUROBOROS_SCOPE_REVIEW_FLOOR`, `OUROBOROS_SOFT_TIMEOUT_SEC`, `OUROBOROS_HARD_TIMEOUT_SEC`, `OUROBOROS_REVIEW_NATIVE_MAX_ROUNDS`, `OUROBOROS_OBSERVABILITY_RETENTION_DAYS` and `OUROBOROS_BG_MAX_ROUNDS` are unsupported (task time is activity-bounded, native review transcript/deadline/wallet-bounded, observability preserved, consciousness on Main's task bounds); `OUROBOROS_EFFORT_EVOLUTION`/`OUROBOROS_EFFORT_CONSCIOUSNESS` are dropped (`OUROBOROS_EFFORT_MAX` decides). The reviewer comma lists and route envs in `RETIRED_COMMA_LIST_SETTING_KEYS` (`OUROBOROS_REVIEW_MODELS`, `OUROBOROS_SCOPE_REVIEW_MODELS`, `OUROBOROS_SCOPE_REVIEW_MODEL`, `OUROBOROS_REVIEW_ROUTES`, `OUROBOROS_SCOPE_REVIEW_ROUTES`, `OUROBOROS_ADVISORY_REVIEW_ROUTE`) are not honored: mark the reviewers in the subagent catalog (Settings → Agents), or an install carrying only comma keys runs the factory reviewer rows (§7 Review pool).
- Review pool: `REVIEW_POOL_MIGRATED_SETTING_KEYS` (inside `RETIRED_SETTING_KEYS`) names the lane key `OUROBOROS_REVIEWER_SLOTS` and the surface keys `OUROBOROS_EFFORT_REVIEW`, `OUROBOROS_EFFORT_SCOPE_REVIEW`, `OUROBOROS_EFFORT_DEEP_SELF_REVIEW`, `OUROBOROS_MODEL_DEEP_SELF_REVIEW`. They are migrated, not dropped: `review_pool_migration.apply_at_read_seam` marks or mints reviewer rows of `OUROBOROS_SUBAGENTS` (`review_eligible: true`, effort and delivery as row properties; factory fallback: §7 Review pool), and a document it cannot convert stays untouched with the error disclosed. The first save writes a snapshot under `state/review_migrations/` and a `state.json:review_pool_migrations` record (`review_pool_receipts.persist_write_receipts`), and the first boot with an owner chat reports it (`server_maintenance._startup_review_pool_notice`). Who reviews is then one list: the reviewer-marked catalog rows (`GET /api/review-pool`). Only the settings document is migrated; the same keys in the process environment are not read, and the boot says so once (`server_maintenance._startup_environment_review_notice`).
- Gateway envelopes: the `api_v1` re-export and the `cost_usd`/`cost_usd_with_children`, `telegram_chat_id`, `project_last_viewed`/`project_hidden` aliases are gone; stored rows are still read tolerantly, and the `UiPreferencesResponse` endpoint answers 400 on an unknown key.
- Plugin ABI: an existing hash-bound PASS keeps loading; manifest negotiation and defaults are in §11.1 (`PluginAPI`).
- Durable task rows: every `task_results/<id>.json` write is stamped `_schema_version: 1` with no converter for older rows; an inadmissible row is quarantined with log-only visibility and keeps its id occupied.
