# 9. Shutdown & Process Cleanup

Close keeps the daemon; Restart stops this generation; Panic never waits. Signals/wait expiry/engine terminals prove no exit. Exit closes collection, retains physical jobs; cold receipts grant no Resume (§6). Switches restore packed handles with stop evidence; boot retries custody.

### Shutdown doors

| Door | Stops | Keeps | Durable mark |
|---|---|---|---|
| Window close with keep-running on (desktop, live indicator) | nothing: the window hides | every task, schedule, companion and the daemon | none |
| Close, quit, SIGTERM, launcher gone (pipe EOF, POSIX too) | this generation's workers, services and owned executor/task processes, unfinished reviews included | the shared daemon and its clients; saved pauses; saved work, held for Resume | `server_shutdown.cause`: `external_signal`, `launcher_quit` or `launcher_gone` |
| Planned restart (self-restart, update, rollback) | the same; the daemon only when the landed checkout pins another engine | saved pauses; saved work and the runnable queue, returned; a same-pin daemon | the restart handoff |
| Manual Restart (owner) | the same plus the installation daemon and every delegated run it serves, other clients' included | saved pauses; saved work and the runnable queue, returned | `owner_restart_no_resume.flag` |
| Panic | all owned work | nothing resumes until the owner acts | `panic_stop.flag` |

**Desktop close, quit and Panic.** `launcher_background.py` reads `OUROBOROS_DESKTOP_KEEP_RUNNING` at close: on with a live indicator hides the window; off or without one quits through teardown; undecided asks once and saves the answer. Quit (indicator, Cmd+Q, sign-out, shutdown) never asks or cancels and sets no Panic flag. Panic exits with its own code and tells the indicator to leave without waiting; indicator and Android notification POST `/api/command /panic` over loopback. A second manual launch shows the running window, even during boot; Linux keeps plain close.

Close releases its PID lock; the daemon serves work beyond one window (outside the Windows launcher Job; spawn custody: §1). `launcher.stop_agent` writes `quit\n` on the server's private stdin (opt-in `OUROBOROS_LAUNCHER_STOP_STDIN`, every platform; else SIGTERM), waits `LAUNCHER_STOP_GRACE_SEC`, then forces group/Job cleanup, keeping handle and record while exit is unconfirmed. Quit, EOF or a signal latches the stop at once; `SERVER_GRACEFUL_SHUTDOWN_TIMEOUT_SEC` bounds the Uvicorn drain, a backstop exits after the launcher's grace, custody completes even when the whole group is signalled. `_exit_signalled` is never cleared, so a settings save mid-teardown cannot revive a supervisor generation; a fresh lifespan clears `_supervisor_stop` (`server.py`).

### Restart and retention

Teardown flags the generation, bounded-joins the supervisor and stops workers before optional waits; the watcher owns handoff. `owned_shutdown.stop_owned_work` shares first-door grace (§10 invariant 6), including event-log lock waits, retains `unconfirmed_since` and retries custody before admission. Daemon pin changes use `server_restart._stop_owned_daemon_for_new_pin`. After stop evidence, `store_switch.switch_at_restart` exports/retires storage and moves the checkout; uncertainty retains intent for boot recovery. Return needs launcher exit 42 or a locked one-shot successor: same-PID exec, custodied POSIX spawn, or Windows original-parent HANDLE exit 42 with measured births. Only that successor returns saved work/queue; undispatched owner-wait/planned carriers keep transaction gates. Failed binding leaves work held and Panic available. Re-upgrade with old unconsumed Windows handle numbers remains unqualified. Listeners close with their server; companions use PID/reserved-port custody (§12), never a port sweep.

Manual Restart (`server_restart._perform_owner_restart`) checks update lock, transaction and `safe_restart` before stopping anything; a refusal (an unwritable no-resume flag too) says "Restart cancelled" and leaves the server intact. It then writes `owner_restart_no_resume.flag` without removing Panic, names returning owner waits, checkpointed work and runnable unstarted queue in one `restart_retention.prepare_restart_returns` transaction, and cancels other live work except saved pauses. Teardown uses `kill_workers(retain_saved_work=True, preserve_pending=True)`, `reconcile_orphaned_runs` with attach-only `read_owned_gateway`, daemon `stop_outcome` and owned stop; never `ensure_owned_gateway` (it could start a dead daemon). Unconfirmed stops retain custody and report `process_stop_unconfirmed`, never veto Restart. No run adoption follows (`owner_restart` is a §6 no-resume cause); owner-gone runs settle from `close_absent_run` or their terminal journal without invented spend.

**Retention.** `restart_retention.py` and `queue_snapshot.py` keep saved pauses through every stop: signal first, retain the marker, emit no terminal, revoke unused grants. Saved work uses the same acknowledged-return transaction; unnamed work stays `owner_restart_hold`, and missing dispatch evidence stays unknown, never proven unstarted. Selectable holds need explicit Resume or model selection under a live root grant. Post-task remainders keep their own checkpoint, without auto-resume. Stop wins. Pausing without a source uses working state or remains interrupted intent (Continue, not exact Resume). Cold body receipts rebind before orphan processing, but neither bypass these holds nor promise external-run survival through a stop door. Panic needs no checkpoint.

### Panic path

Panic latches at ingress; failed thread start executes synchronously. Owned stops (restart successor too) precede bounded I/O and installation census, daemon or not; server, launcher and pid 1 are spared. Only an observed Panic exit permits the launcher to finish broad discovery. Later starts retry only `state/panic_sweep_pending.json`'s saved pid/birth identities; no flag lets old Panic discover new work. Known-only settlement is not full cleanup: the last bounded attempt's misses stay undiscovered; stopping an old controller may affect new work attached to it. Diagnostic faults spare other stop owners; failed writes cannot prevent exit 99. The watcher parks; no successor serves after 99. Worker socket grace, lifeline callbacks and parent Popen kills keep independent bounds. Requests prove no exit; unpublished, inaccessible and backend-only children stay unconfirmed. WS/HTTP uses `LocalChatBridge.panic` without supervisor I/O; Host Service authenticates the skill and pinned owner pair (§12). Boot consumes the flag only after disabled controls persist; failure keeps it and bars reviews of newly admitted owner work until Restart persists them.

### Owned daemon stop and startup failure

`OwnedClaudexorDaemon.stop_outcome` reports `stopped`, `nothing_to_stop` or `unconfirmed`. With an owned marker and authenticated same-home endpoint, `daemon stop --json` needs exit 0 and a terminal receipt, not RPC/lease acknowledgement. Forced signals use only pre-request birth/command identities or the manager's Popen; confirmed death alone retires custody (DEVELOPMENT "Process Custody Rule"). Lock/RPC/exit waits have separate bounds, no promised total. Beyond `CLAUDEXOR_STARTUP_WAIT_SEC`, a live child stays `daemon_starting`; a silent listener is `daemon_not_answering`, an exited child `daemon_spawn_failed`.

**Startup failure.** `claudexor_startup_failure.py` labels the child's `daemon.log` interval `heap_exhausted`, `writer_lease_contended`, `engine_floor` or `unclassified`, carried by `daemon_spawn_failed`, `last_error` and one `claudexor_daemon_start_failed` row. Only `ExitFact.failed_without_control` latches spawning. Live attach or a new manager clears its latch; the server's also clears on the custody sweep (§5), with one zero-wait ensure after release, or owner Refresh (`/api/claudexor/wake`, one spawn per press); workers need attach or respawn. Releases record `claudexor_daemon_start_latch_cleared` and `cleared_by`. Probe `launch.nodeArgs` supplies `--max-old-space-size`; explicit `NODE_OPTIONS` wins; absent or malformed data keeps the plain command (`runtime_launch_invalid`). Residuals: `ExitFact`, `OwnedClaudexorDaemon.clear_start_failure_latch`.

`claudexor_exit_facts.py` reads a bounded `supervisor.jsonl` tail for context (saved exits use observation time, not death time; context never calls the engine). The authenticated `/api/claudexor/status` read adds live `memory`, `loop`, `store`, `servingMode`, effective `capacity` and class `admission` (nulls for absent measurements; finite, unlimited and unknown caps stay distinct); one dated `claudexor_engine_capacity` snapshot per descriptor generation survives beside fresh observations and independent stale facets in Settings → Accounts (§3); no measurement grants lifecycle authority.

Claudexor 4 first-start import can keep an authenticated daemon in `recovery_only` for minutes: `ensure_owned_gateway` waits `CLAUDEXOR_ADMISSION_WAIT_SEC`, then refuses typed `daemon_recovery_only` without killing it; passive status still shows migration progress. Engine storage, forward-only compatibility and logical/physical quarantine: PERSISTENCE.md. External-host CLI/MCP bindings only attach; this manager keeps start/stop ownership; standalone installations keep their own.

### Process custody

Task stdio and pre-ledger marked-container stops: `mcp_task_sessions.py`, [bridge contract](../browser-task-bridge.md). Revocation/detach/exit differ.

`_active_subprocesses`, task-attributed executor records (§1) and ledgered task processes are named by `state/owned_processes.json` (contended registrations land in `owned_processes.pending/`), read by exit and Panic instead of walking `data/state`; a boot thread indexes older records once. Groups and Jobs miss escaped descendants, so signals need measured identity; startup recovery settles no executor backend, retrying only stamped stops. Docker CLI exit proves no backend exit: `backend_completed` persists before marker deletion; a lost reply retains evidence, never signalling a completed CLI PID. `docker_process_observer.py` reads container `/proc`: a zombie leader is exited (return code unknown), stops and writer fences need no live group member, unreadable stat stays unknown custody. Host unwind or exact worker death retires the local invocation only (§6); unknown effects never authorize replay.

**Work scopes** (`process_scope.py`). Plant an installation marker before spawning; daemon, kept services, MCP and extension children/companions keep it, shedding task markers. Invocation identity—not display labels—binds commands, task skills and non-kept services to markers/groups. Only truly-terminal transitions end leftovers by measured birth, never Pause/hold/handoff/placeholders. Retire after recorded settlement (denied signals are final) or `unsupported`; unknown identities stay owed. Panic reads the owned engine's schema-1 `daemon/run-scopes.json`; full settlement needs an absent/valid index. Limits: recycled leaderless groups may pass reuse checks; Linux nondumpable/setuid peers and macOS system binaries may hide markers; shell exit can leave children uncaptured. Command-launched GUI children have no lifetime exemption. Windows/Docker-executor children stay `unsupported`.

**Follow-up controls.** An accepted Stop transfers its control identity to the original task result before the active intent retires, also when natural completion wins, so the completed status and result survive; a failed transfer keeps the intent for recovery. A recorded cancel intent wins over the door's cause; an unreadable store invents none. Manual Restart keeps its control in the schedule document before consuming its marker; Panic needs none (`supervisor/followup_policy.py`).
