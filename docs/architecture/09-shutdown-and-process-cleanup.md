# 9. Shutdown & Process Cleanup

Signals, timeouts and engine terminal facts prove no OS exit; jobs stay until return. Cold receipts grant custody, not Resume or survival (§6). Switching restores stopped handles; boot retries unconfirmed custody.

### Shutdown doors

| Door | Stops | Keeps | Durable mark |
|---|---|---|---|
| Desktop close, keep-running on, live indicator | none: window hides | all tasks, schedules, companions and daemon | none |
| Close, quit, SIGTERM, launcher gone (pipe EOF, POSIX too) | this generation's workers, maintenance child, services, owned executor/task processes and unfinished reviews | shared daemon/clients; saved pauses; saved work held for Resume | `shutdown_entry.json`, then `server_shutdown.cause`: `external_signal`, `launcher_quit` or `launcher_gone` |
| Planned restart (self-restart, update, rollback) | same; off-pin daemon unless newer | saved pauses; saved work/cut owner turns/runnable queue, returned; same-pin or newer daemon | restart handoff, then `shutdown_entry.json` |
| Manual Restart (owner) | same; its own delegated runs end | as Planned restart (§3) | restart transaction `door=owner_restart`, `shutdown_entry.json` |
| Panic | all owned work | sleeping work: owner Resume; working: saved for Resume after launch; pauses unchanged | `panic_stop.flag` (`panic`), then `panic_ingress_receipt` |
| Fault (`bus_lost`, `loop_failed`; §5) | as Close; kept work's delegated runs end | as Close; unsaved rows `cancelled` | as Close, cause named; a `supervisor_failure` row, then the startup notice and one recovery turn per died generation (`state/core_loss_recovery.json`); exit 1 under a launcher, else census and re-exec (`server_process.fault_exit`); Panic owns exit; never 42/99 |

**Desktop.** `launcher_background.py` hides keep-running close only behind a live indicator; unset choice asks/saves once. Quit asks nothing, never cancels, never sets or overtakes Panic; both latch startup/handoff shut. Early Quit closes setup windows, stops captured/bootstrap children and identity-proven servers, sparing stale companions. Tray/window Panic stops captured/bootstrap children; non-daemon `execute_panic_stop` persists/exits. Windows owns Popen until transfer; Panic never waits. New source checks inherited parent exit; old source/failed inheritance leaves late spawn unproved. POSIX captures descendants before orphaning; timeouts give no total bound. Windows keeps Job-error fallback. No HTTP/callback/replay; failures disclosed. Android loopback uses `/api/command /panic`; second launch opens during boot; Linux closes normally.

Close frees the PID lock; the daemon outlives windows outside the Windows launcher Job (§1). `launcher.stop_agent` sends private-stdin `quit\n` (`OUROBOROS_LAUNCHER_STOP_STDIN`, all platforms; else SIGTERM), waits `LAUNCHER_STOP_GRACE_SEC`, then forces group/Job cleanup, retaining handle/record until confirmed exit. Quit/EOF/signals latch stop at once; group signals still complete custody. `SERVER_GRACEFUL_SHUTDOWN_TIMEOUT_SEC` bounds Uvicorn drain; backstops fire after the launcher grace (a stop exits 1; a fault, its door). `_exit_signalled` stays set against settings-save revival; new lifespans clear `_supervisor_stop`.

Commands enter `executable_main()`: signals latch stop for the serving loop, preserving cleanup joins. Final exit bypasses capture joins; signals return `128+signal`, Panic owns exit.

### Restart and retention

Teardown marks its generation, bounded-joins the supervisor and stops workers before optional waits; the watcher owns handoff. `owned_shutdown.stop_owned_work` shares first-door grace, event-log locks included (§10 invariant 6); unconfirmed custody retains `unconfirmed_since` for retry before admission. Pin rule: `server_restart._stop_owned_daemon_for_new_pin`. After stop evidence, `store_switch.switch_at_restart` exports/retires storage and moves the checkout; boot recovers uncertain intent. Returns need launcher exit 42 or a locked one-shot successor: same-PID exec, custodied POSIX spawn, Windows original-parent HANDLE exit 42 with measured births. Only that successor returns work/queue; undispatched wait/planned carriers keep transaction gates; failed binding holds work with Panic available; unconsumed Windows handles leave re-upgrade unqualified. Listeners end with the server; companions use PID/reserved-port custody (§12), never port sweeps.

Manual Restart (`server_restart._perform_owner_restart`) refuses conflicts/unwritable transactions before teardown. Its `door=owner_restart`, `status=prepared`, generation/PID stop same-generation starts without Panic. `prepare_restart_returns` names returns; boot consumes only prior-generation doors after holds/`record_restart`, setting `door_applied_at` independently of ACK. Legacy flags/bytes translate once to this boot's door. Teardown retains saves, reads attach-only custody (never ensuring a daemon) and keeps unconfirmed cleanup visible, without veto. A 404 proves absence, not output/spend; store-bound runs need the same store.

**Retention.** `restart_retention.py` keeps pauses, revokes unused grants and yields spent carriers to newer continuation custody. Warm owner Pause converts to cold; acknowledged planned/update sleep returns, manual Restart holds it. Doors replace only `saved_sleep_recovery` and `continuation_writer_unsettled`; stronger prior stops survive, even Panic. Panic gives sleeping work `panic_hold`/owner, working work `saved_work_hold{door:panic}`/resume; stored release never changes retrospectively. Source/money/time/Stop still govern; unknown dispatch is not unstarted. Resume removes the stop; history stays in the journal. Rollback loses Q9 checks; old launchers may need the removed Restart flag (PERSISTENCE).

Schema-2 delegated handoffs (§6) keep each holder, cursor and wake independent; migration is effect-free; live v2 forbids downgrade.

### Panic path

Panic latches at ingress; a failed thread start runs it synchronously. Owned stops (restart successor too) precede bounded persistence and installation census, daemon or not; the executing process, parent and pid 1 are spared. Census follows observed Panic exit or local tray/window Panic; the indicator leaves without waiting. Boot retries only saved pid/birth pairs in `state/panic_sweep_pending.json`; a flag grants no new discovery, so undiscovered work is missed; stopping old controllers may affect new attachments. Diagnostic faults spare other stop owners; failed writes cannot prevent exit 99, which authorizes no successor. Worker socket grace, lifelines and parent kills have separate bounds; lane carriers die by measured identity like any worker, an inline executor's pid-less slot by a cooperative stop only. Requests prove no exit; inaccessible/unpublished/backend-only children stay unconfirmed. WS/HTTP uses `LocalChatBridge.panic` without supervisor I/O; Host Service authenticates skill and pinned owner (§12). Only installation gates read `installation_stop.py`: Panic bytes and file identity. Boot persists work stops and disabled controls, then `state.json.panic_ingress_receipt`, then unlinks. Failed unlink repeats only deletion; new identity reapplies Panic; failed controls keep it closed.

Browser Panic sends once on its captured open socket with no buffered output; `panic_accepted` means latch, not exit. No confirmation, upload/save wait, replay or clock check; sent bytes may arrive late. `panic_source.py` journals causal ids and guards newer snapshots from late enrichment. Unknown PIDs stay unknown; diagnostics neither authorize nor veto.

Local tray/window Panic bypasses the observed-99 `kill_runtime_orphans` finalizer, which signals saved companion PIDs/ports without fresh identity proof. Escaped companions with unreadable/absent scope markers remain unconfirmed by captured trees and census (§12).

### Owned daemon stop and startup failure

`OwnedClaudexorDaemon.stop_outcome` reports `stopped`, `nothing_to_stop` or `unconfirmed`. With an owned marker and authenticated same-home endpoint, `daemon stop --json` needs exit 0 and a terminal receipt, not RPC/lease acknowledgement. Forced signals use only pre-request birth/command identities or the manager's Popen; confirmed death alone retires custody (DEVELOPMENT "Process Custody Rule"). Lock/RPC/exit waits have separate bounds, no promised total. Beyond `CLAUDEXOR_STARTUP_WAIT_SEC`, a live child stays `daemon_starting`; a silent listener is `daemon_not_answering`, an exited child `daemon_spawn_failed`.

**Startup failure.** `claudexor_startup_failure.py` labels the child's `daemon.log` interval `heap_exhausted`, `writer_lease_contended`, `engine_floor` or `unclassified`, carried by `daemon_spawn_failed`, `last_error` and one `claudexor_daemon_start_failed` row. Only `ExitFact.failed_without_control` latches spawning. Live attach or a new manager clears its latch; the server's also clears on the custody sweep (§5), with one zero-wait ensure after release, owner Refresh (`/api/claudexor/wake`, one spawn per press) or Restart Claudexor (§3); workers need attach or respawn. Releases record `claudexor_daemon_start_latch_cleared` and `cleared_by`. Probe `launch.nodeArgs` supplies `--max-old-space-size`; explicit `NODE_OPTIONS` wins; absent or malformed data keeps the plain command (`runtime_launch_invalid`).

`claudexor_exit_facts.py` reads a bounded `supervisor.jsonl` tail for context (saved exits use observation time, not death time; context never calls the engine). The authenticated `/api/claudexor/status` read adds live `memory`, `loop`, `store`, `servingMode`, effective `capacity` and class `admission` (nulls for absent measurements; finite, unlimited and unknown caps stay distinct); one dated `claudexor_engine_capacity` snapshot per descriptor generation survives beside fresh observations and stale facets in Settings → Accounts (§3); no measurement grants lifecycle authority. The custody sweep (§5) attaches read-only to an engine whose catalog lists the route (`gateways/claudexor_route_health.py`) and records its per-route failure shares (harness × access, seven-day window of created runs, failed/runs, top causes, or no runs) only when changed: one `claudexor_route_health` row and the file the vitals and deep self-review read (`record_route_health`; PERSISTENCE.md).

Claudexor 4 first-start import can keep an authenticated daemon in `recovery_only` for minutes: `ensure_owned_gateway` waits `CLAUDEXOR_ADMISSION_WAIT_SEC`, then refuses typed `daemon_recovery_only` without killing it; passive status still shows migration progress. Engine storage, forward-only compatibility and logical/physical quarantine: PERSISTENCE.md. External-host CLI/MCP bindings only attach; this manager keeps start/stop ownership; standalone installations keep their own.

### Process custody

`state/owned_processes.json` indexes task-attributed executor records (§1) and ledgered task processes; contended writes use `owned_processes.pending/`. Exit/Panic avoid a `data/state` walk; boot indexes old records once. Groups/Jobs miss escaped descendants: signals need measured identity. A service stop (`end_owned_processes`) reaches chain descendants and launch-marker carriers, never a task marker or daemon root (unknown roots: held). Before any signal or native kill it persists what could outlive it (no write, no signal) and discharges only what it measured; one reconciled end holds the name through log/outputs. Consumers read launches via `launch_custody.py`: ledger plus copies, unreadable unknown. Startup retries stamped stops, never settles executor backends. Docker CLI exit proves no backend exit: persist `backend_completed` before deleting markers; lost replies keep evidence, never signal completed CLI PIDs. `docker_process_observer.py` reads container `/proc`: zombie leaders exited (return code unknown); stops/writer fences need no live group member; unreadable stat keeps unknown custody. Host unwind or exact worker death retires only the local invocation (§6).

Only a measured birth/command mismatch retires other owned custody, journalled first as `process_not_ours` with both fingerprints; a foreign leader's EPERM, a reused non-leader, unreadable identity or a failed signal proves nothing and keeps the stop.

**Work scopes** (`process_scope.py`). Plant an installation marker before spawning; daemon, kept services, MCP and extension children/companions keep it, shedding task markers (task-session MCP servers keep theirs). Invocation identity—not display labels—binds commands, task skills and non-kept services to markers/groups. Only terminal transitions end leftovers by measured birth, never Pause/hold/handoff/placeholders. Retire after recorded settlement (denied signals are final) or `unsupported`; unknown identities stay owed. Panic reads the owned engine's schema-1 `daemon/run-scopes.json`; full settlement needs an absent/valid index. Markers/captured births remain independent. Limits: recycled leaderless groups may pass reuse checks, Linux nondumpable/setuid peers and macOS system binaries can hide markers; command-launched GUI children have no lifetime exemption; Windows/Docker-executor children stay `unsupported`.

**Follow-up controls** (§5). Recorded cancel intent wins over the door's cause (`followup_policy`); failed Stop transfer retains it; unreadable stores invent no control; Panic needs no schedule control.

### Test runs

Lanes and `safe_test` commands run in a `ProcessContainer` with scrubbed temporary roots (`test_environment.py`). A passed test's `tmp_path` goes once its processes are gone; a marker keeps its folder; a private copy's test records join its task (PERSISTENCE).
