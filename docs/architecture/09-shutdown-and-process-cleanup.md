# 9. Shutdown & Process Cleanup

Signals, timeouts and engine terminal facts prove no OS exit; jobs stay until return. Cold receipts grant custody, not Resume or survival (§6). Switching restores stopped handles; boot retries unconfirmed custody.

Server startup raises descriptor capacity for per-run transports (`server_process.raise_open_file_limit`; platform rules and failures: its docstring).

### Shutdown doors

| Door | Stops | Keeps | Durable mark |
|---|---|---|---|
| Desktop close, keep-running on, live indicator | none: window hides, on macOS only after full screen's DidExit | all tasks, schedules, companions and daemon | none |
| Close, quit, SIGTERM, launcher gone (pipe EOF, POSIX too) | this generation's workers, maintenance child, services, owned executor/task processes and unfinished reviews | shared daemon/clients; saved pauses; saved work held for Resume | `shutdown_entry.json`, then `server_shutdown.cause`: `external_signal`, `launcher_quit` or `launcher_gone` |
| Planned restart (self-restart, update) | same; off-pin daemon unless newer | saved pauses; saved work/cut owner turns/runnable queue, returned; same-pin or newer daemon | restart handoff, then `shutdown_entry.json` |
| Manual Restart (owner) | same; its own delegated runs end | as Planned restart (§3) | restart transaction `door=owner_restart`, `shutdown_entry.json` |
| Panic | all owned work | sleeping work: owner Resume; working: saved for Resume after launch; pauses unchanged | `panic_stop.flag` (`panic`), then `panic_ingress_receipt` |
| Fault (`bus_lost`, `loop_failed`; §5) | as Close; kept work's delegated runs end | as Close; unsaved rows `cancelled` | as Close, cause named; a `supervisor_failure` row, then the startup notice and one recovery turn per died generation (`state/core_loss_recovery.json`); exit 1 under a launcher, else census and re-exec (`server_process.fault_exit`); Panic owns exit; never 42/99 |

**Desktop.** `launcher_background.py`: unset choice asks/saves once. Quit asks nothing, never cancels, never sets or overtakes Panic; both latch startup/handoff shut. Early Quit closes setup windows, stops captured/bootstrap children and identity-proven servers, sparing stale companions. Tray/window Panic stops captured/bootstrap children; non-daemon `execute_panic_stop` persists/exits. Windows owns Popen until transfer; Panic never waits. New source checks inherited parent exit; old source/failed inheritance leaves late spawn unproved. POSIX captures descendants before orphaning; timeouts give no total bound. Windows keeps Job-error fallback. No HTTP/callback/replay; failures disclosed. Android loopback uses `/api/command /panic`; second launch opens during boot; Linux closes normally.

Close frees the PID lock; the daemon outlives windows outside the Windows launcher Job (§1). `launcher.stop_agent` sends private-stdin `quit\n` (`OUROBOROS_LAUNCHER_STOP_STDIN`, all platforms; else SIGTERM), waits `LAUNCHER_STOP_GRACE_SEC`, then forces group/Job cleanup, retaining handle/record until confirmed exit. Quit/EOF/signals latch stop at once; group signals still complete custody. `SERVER_GRACEFUL_SHUTDOWN_TIMEOUT_SEC` bounds Uvicorn drain; backstops fire after the launcher grace (a stop exits 1; a fault, its door). `_exit_signalled` stays set against settings-save revival; new lifespans clear `_supervisor_stop`.

Commands enter `executable_main()`: signals latch stop for the serving loop, preserving cleanup joins. Final exit bypasses capture joins; signals return `128+signal`, Panic owns exit.

### Restart and retention

Teardown marks its generation, bounded-joins the supervisor and stops workers before optional waits; the watcher owns handoff. `owned_shutdown.stop_owned_work` shares first-door grace, event-log locks included (§10 invariant 6); unconfirmed custody retains `unconfirmed_since` for retry before admission. Pin rule: `server_restart._stop_owned_daemon_for_new_pin`. After stop evidence, `store_switch.switch_at_restart` exports/retires storage and moves the checkout; boot recovers uncertain intent. Returns need launcher exit 42 or a locked one-shot successor: same-PID exec, custodied POSIX spawn, Windows original-parent HANDLE exit 42 with measured births. Only that successor returns work/queue; undispatched wait/planned carriers keep transaction gates; failed binding holds work with Panic available; unconsumed Windows handles leave re-upgrade unqualified. Listeners end with the server; companions use PID/reserved-port custody (§12), never port sweeps.

Manual Restart (`server_restart._perform_owner_restart`) refuses conflicts/unwritable transactions before teardown. Its `door=owner_restart`, `status=prepared`, generation/PID stop same-generation starts without Panic. `prepare_restart_returns` names returns; boot consumes only prior-generation doors after holds/`record_restart`, setting `door_applied_at` independently of ACK. Legacy flags/bytes translate once to this boot's door. Teardown retains saves, reads attach-only custody (never ensuring a daemon) and keeps unconfirmed cleanup visible, without veto.

**Retention.** `restart_retention.py` keeps pauses, revokes unused grants and yields spent carriers to newer continuation custody. Warm owner Pause converts to cold; acknowledged planned/update sleep returns, manual Restart holds it. Doors replace only `saved_sleep_recovery` and `continuation_writer_unsettled`; stronger prior stops survive, even Panic. Panic gives sleeping work `panic_hold`/owner, working work `saved_work_hold{door:panic}`/resume; stored release never changes retrospectively. Source/money/time/Stop still govern; unknown dispatch is not unstarted. Rollback loses Q9 checks; old launchers may need the removed Restart flag (PERSISTENCE).

### Panic path

Panic latches at ingress; a failed thread start runs it synchronously. Owned stops (restart successor too) precede bounded persistence and installation census, daemon or not; the executing process, parent and pid 1 are spared. Census follows observed Panic exit or local tray/window Panic; the indicator leaves without waiting. Boot retries only saved pid/birth pairs in `state/panic_sweep_pending.json`; a flag grants no new discovery, so undiscovered work is missed; stopping old controllers may affect new attachments. Diagnostic faults spare other stop owners; failed writes cannot prevent exit 99, which authorizes no successor. Worker socket grace, lifelines and parent kills have separate bounds; lane carriers die by measured identity like any worker, an inline executor's pid-less slot by a cooperative stop only. Requests prove no exit; inaccessible/unpublished/backend-only children stay unconfirmed. WS/HTTP uses `LocalChatBridge.panic` without supervisor I/O; Host Service authenticates skill and pinned owner (§12). Only installation gates read `installation_stop.py` (Panic bytes and file identity; boot order, receipt, failures and repeats: its docstring).

Browser Panic sends once on its captured open socket with no buffered output; `panic_accepted` means latch, not exit. No confirmation, upload/save wait, replay or clock check; sent bytes may arrive late. `panic_source.py` keeps its causal evidence (docstring). Unknown PIDs stay unknown; diagnostics neither authorize nor veto.

Local tray/window Panic bypasses the observed-99 `kill_runtime_orphans` finalizer, which signals saved companion PIDs/ports without fresh identity proof. Escaped companions with unreadable/absent scope markers remain unconfirmed by captured trees and census (§12).

### Process custody

`state/owned_processes.json`: task executor (§1) and process ledger index; contention queues in `owned_processes.pending/`. Boot indexes legacy once; Exit/Panic skip `data/state` walks. Groups/Jobs miss escapees. `end_owned_processes` follows descendants/launch markers, never task markers/daemon roots (unknown roots held): persist survivors before signals, require measured identity/exit, hold the name through capture. `launch_custody.py` reads ledger+copies across workers (unreadable→unknown); session-scope kept services: one launch-ID/reason Stop via the exit routine and fresh read. Owner: Activity; root: `stop_service(service_id=)` after proven producer completion. A kept start's `kept_outputs/<task>/<launch>.kept.json` (no-output: by its log) records outputs/capture context; outside Stop saves to the producer's store, not the stopper's. Logs wait for all task writers; sources wait for capture (transient retirement holds, Activity Save outputs retry). Startup retries stamped stops, not executor settlement. Docker: persist `backend_completed` before marker deletion; CLI exit proves no backend exit; lost replies retain evidence, never signal completed CLI PIDs. `docker_process_observer.py` reads `/proc`: zombies exited, return code unknown; stop/writer fences need no live group member; unreadable stat: unknown. Host unwind/exact worker death retires only its local invocation (§6).

Only a measured birth/command mismatch retires other owned custody, journalled first as `process_not_ours` with both fingerprints; a foreign leader's EPERM, a reused non-leader, unreadable identity or a failed signal proves nothing and keeps the stop.

**Work scopes** (`process_scope.py`): pre-spawn installation marker survives in daemon, kept services, MCP and extension children/companions; task markers do not, except task-session MCP. Invocation identity, never labels, binds commands/task skills/non-kept services to markers/groups. Terminal transitions alone end leftovers by measured birth, not Pause/hold/handoff/placeholders. Retire on recorded settlement (signal denial final) or `unsupported`; unknown identity remains owed. Panic's schema-1 `daemon/run-scopes.json` needs absent/valid index for full settlement; markers/births stay independent. Limits: leaderless recycled groups may pass reuse checks; Linux nondumpable/setuid peers and macOS system binaries hide markers; GUI children have no exemption; Windows/Docker-executor children stay `unsupported`.

**Follow-up controls** (§5): `followup_policy` puts recorded cancel intent above door cause; failed transfer retains it; unreadable stores invent no control; Panic needs no schedule control.
