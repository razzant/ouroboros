# 9. Shutdown & Process Cleanup

Close keeps daemon. Restart: cleanup then launcher/POSIX exec/Windows spawn. Panic stops. Exit needs proof.

**Close, quit, Panic (desktop).** `launcher_background.py` decides a desktop window close from `OUROBOROS_DESKTOP_KEEP_RUNNING`, read at close time. On (Windows, macOS) it hides the window while an indicator is live; tasks, schedules, consciousness, Telegram and Presence companions and the shared daemon keep running. Off, or with no live indicator, it quits via the window-close teardown below. Undecided, it keeps this close, asks once from a worker thread (pywebview's Cocoa confirmation deadlocks inside `closing`), stores the answer and quits on dismissal. A quit (the indicator's Quit, Cmd+Q, Dock Quit, sign-out, shutdown) is never asked or cancelled: Windows decides in the form's FormClosing, the only place carrying CloseReason; macOS marks `applicationShouldTerminate:` before pywebview runs its shared `closing` event. Quit sets no Panic flag and leaves sign-in startup alone. Panic's path: the server exits with the Panic code; the lifecycle thread asks the indicator to go, without waiting, before orphan cleanup and `os._exit`; the indicator's Panic item posts `/api/command /panic` over loopback HTTP, as Android's notification does. A hidden window returns when its indicator dies; the launcher exits when the window cannot be shown. A manual second launch shows the running window (Windows: a named auto-reset kernel event from the PID-lock path, not a durable file; POSIX: SIGURG to the PID in the lock file, which an older launcher ignores; a lock loser leaves that file intact), also during that copy's boot: it listens once it takes the lock, and a request before pywebview shows the window waits for it and cancels a quiet start; an automatic second launch only logs. Linux keeps the plain close.

Close stops this generation's workers/services and releases its PID lock, retaining the shared daemon and clients. Windows keeps the daemon outside the launcher Job. POSIX tree cleanup takes one PID/PPID snapshot for target and retained subtrees; an unavailable snapshot falls back to pgrep.

`launcher.stop_agent`: POSIX SIGTERM targets only the server (Manager/pool owner). Windows sends `quit\n` on owned stdin (`OUROBOROS_LAUNCHER_STOP_STDIN=1`). Before children, `_SignalStopServer.watch_launcher_stop` consumes the flag, keeps a non-inheritable raw reader and sets CRT/OS stdin to null, so children cannot wait for the Quit pipe's EOF. Quit sets stop/exit latches and ends Uvicorn; EOF is not Quit. Direct-server stdin is unchanged. Both keep `LAUNCHER_STOP_GRACE_SEC` and forced group/Job cleanup; old Windows launchers force `terminate()`. Group SIGTERM can kill Manager early; `handle_exit` sets `_supervisor_stop` immediately, avoiding false BrokenPipe crash alerts. `SERVER_GRACEFUL_SHUTDOWN_TIMEOUT_SEC` bounds Uvicorn drain for custody; embedded Host Service uses `capture_signals=nullcontext` for one signal owner. `_exit_signalled` prevents revival by settings/admitted generations; `_supervisor_stop` is revivable (§5). Tests: `tests/test_shutdown_signal_1142.py` (open HTTP/WS, group signal, pipe). `server_shutdown.cause`: `external_signal` or `launcher_quit`.

Planned restart retains same-pin daemons. After worker custody, before optional cleanup, graceful and final paths call `_stop_owned_daemon_for_new_pin`: `load_runtime_pin` versus attach-only `read_owned_gateway`. Unpublished/unreadable pins and unreachable/foreign/stopped daemons leave handoff unchanged; unconfirmed stop retains custody/diagnostics for reconciliation without invented spend.

Teardown sets the stop flag, joins the supervisor within its bound and terminalizes `kill_workers` before optional waits/sweeps. SIGKILL may lose writes/late frames; snapshot restore recovers missed writes. Queue init hands over `state/direct_roots.json` before clearing it, fencing listed roots like surviving RUNNING rows as Cancelled, not infra-failed. The restart watcher owns final worker/executor/service/companion cleanup and transfer; main joins after Uvicorn returns. Launcher exit 42 or POSIX direct re-exec preserves planned-handoff environment. Windows direct restart spawns a custodied successor in its console group; the prepared transaction binds both process births and the child PID; the child acknowledges only after its inherited parent HANDLE signals exit 42. Missing or foreign evidence leaves it prepared. Venv launches run the base interpreter with the venv selector, so the spawned PID is the interpreter's. Cleanup may delay exit: no absolute bound. Unexpected cleanup/transfer errors log unconfirmed custody and exit 1. Restart skips port sweeps: exit/exec closes its listeners; a port is no ownership proof. Ordinary close closes Host Service; launcher/recovery/Panic sweeps remain separate, prove no PID identity and may stop unrelated listeners.

Manual Restart uses `server_restart._perform_owner_restart`, re-exported by `server`, with transport notices. HTTP/WS buttons use this owner until supervisor/bridge readiness. Typed WS chat retains its canonical row/echo; Host Service retains correlation and checks the known owner pair. Ready dispatch keeps its envelope; Panic keeps its early bypass. Before stopping anything, `_safe_restart_serialized` locks updates, checks the managed-update transaction and runs `safe_restart` checkout/dependency/import/stable fallback. Refusal, including an unwritable no-resume flag, reports "Restart cancelled" and leaves the server intact.

Restart proceeds despite unconfirmed cleanup: persist followup holds and `owner_restart_no_resume.flag`, preserving an existing Panic flag (otherwise write the compatibility `panic_stop.flag`); `_stop_owned_work` requests `owner_restart` cancellation for RUNNING/direct/post-task work except SAVED pauses; run `kill_workers(hold_never_started=True)`, `reconcile_orphaned_runs(running_task_ids=set())` via attach-only `read_owned_gateway`, then the attested daemon `stop_outcome()` used by Panic. No `ensure_owned_gateway` may wake a stopped daemon. Worker failure logs critically; daemon uncertainty emits `process_stop_unconfirmed`. Both retain custody and permit restart. This stops installation-wide daemon runs, including other clients, unlike window close.

Boot `delegate_recovery.NO_RESUME_CAUSES` includes `owner_restart`: no adoption. Reconcile owner-gone runs: absent → `close_absent_run` without invented spend; journal terminal → settle; pending invocation → original key. Model `dispatched`/`unresolved` retains its monetary bound. Unconfirmed stop attaches to the surviving daemon; provisioned homes retain background `warm_owned_daemon()`. Planned restart, update and Panic remain separate.

**Retention.** `restart_retention.py`/`queue_snapshot.py` retain/restore loop pauses; `worker_chat_lane.auto_resume_after_restart` consumes markers. Every stop keeps saved live-attempt pauses, including pre-park workers/direct actors: signal first, park the marker, never terminalize or emit `task_done`. Unused grants return to Pause. Saved post-task remainders stay in `root_phase_checkpoint`, without auto-resume (§6). Warm-sleep conversion, even failed markerless retention, carries the actual Restart/Panic hold; kill/restore upgrades generic recovery holds for accurate Restart counts. Explicit Stop wins; sourceless `pausing` is interrupted intent: Continue only, not exact Resume.

Manual Restart retains `admitted_dispatch=none` rows, including interrupted parents' children, under `_budget_pause_hold`/`reason_code=owner_restart_hold`. Historical `paused_before_dispatch` keeps its exact pause, never becomes "never started." Missing dispatch evidence keeps the same row under `dispatch_outcome_unknown`; ordinary Resume refuses it and no `none` is invented. Known `possible` follows interruption policy; unknown handoffs stay held. Zero model rounds and terminality prove no dispatch outcome. Ordinary schedule replay also requires its matching never-dispatched receipt; exact same-ID Resume uses separate single-use authority. Canonical `_owner_hold` and `_consciousness_continuation` survive stale snapshots; Resume cannot clear unrelated holds. Teardown/restore retains holds at any age. Only explicit owner Resume or model selection under a live root grant releases selectable holds; Stop cancels. No policy is inferred for other doors, and Panic gets no prerequisite: retention reads follow signalling. The Restart notice reports the held count.

Panic requests owned stops before I/O or cleanup. The worker socket gives local owners 250 ms; its lifeline bounds the callback at 500 ms. The parent retains native Popen and requests worker kill after 750 ms, even on Darwin without a responsive lifeline, before settlement and server exit. Published separate-session children retain local ownership during that window; unpublished spawns, inaccessible owners and escaped/backend-only children remain unconfirmed. Delivery, signal request and proven death stay distinct. Attached Linux targets use their pidfd; Darwin watches cannot signal or authorize numeric PID/group guesses. Ordinary EOF/parent loss skips Panic callbacks. Settlement includes the port sweeps; bounded flag/control writes follow. Queue/custody reconcile at boot. Live local WS/HTTP Panic reaches the emergency owner through `LocalChatBridge.panic` without waiting for supervisor intake or state/chat I/O. External Host Service ingress authenticates the skill, then matches a positively pinned immutable owner pair without a new state read; unknown or foreign identities never gain a binding there, and Reset invalidates the bridge generation before deletion. Boot/ticks/wakes respect the flag; boot consumes it only after disabled controls persist. OPEN: if that persistence fails, the retained flag also aborts reviews of owner work explicitly admitted later; its legacy bytes carry no generation and an old immutable launcher compares them exactly to `panic`, so they are neither ignored nor rewritten. After storage recovers, another explicit Restart consumes the flag once controls persist but revives no stopped review; no compatible typed generation fact exists yet.

`stop_outcome` returns `stopped`, `nothing_to_stop` or disclosed `unconfirmed`. With a valid owned marker and an authenticated same-home endpoint it first invokes the installed managed CLI `daemon stop --json` (read-only `resolve_cli_command(require_npm=False)`; why: DEVELOPMENT's Process Custody Rule); it never ensures a runtime, wakes a daemon or probes accounts. Exit 0 plus the typed terminal CLI receipt is required: an RPC acknowledgement or a clean lease release does not prove the captured OS processes exited, and a surviving authenticated endpoint is disclosed without chasing a successor. The pre-request custody snapshot limits forced fallback to those original rows; forced signalling still requires both measured birth and command identity or the manager's own Popen; legacy Windows empty-birth rows cannot authorize signals, though a healthy attached daemon can still stop cooperatively via the CLI. Token refusal, invalid discovery, malformed responses and a matching error-code string alone give no stop authority. Only confirmed death permits signal-stop custody removal; concurrent rows survive.

The short manager lock retires the local startup generation before waits and never spans runtime preparation, network or process-exit work. CLI RPC, termination confirmation and startup slack use `config.CLAUDEXOR_OPERATOR_STOP_TIMEOUT_SEC`; captured-process observation uses `config.CLAUDEXOR_STOP_EXIT_WAIT_SEC` (both from `runtime_limits`); no absolute total stop duration is promised. A live startup outlives its caller's window (20 s by default, independently narrowable): `daemon_starting` invites joining the same work, while `daemon_spawn_failed` identifies the exited child/build/log interval.

**Startup failure.** `claudexor_startup_failure.py` classifies an owned child's exit without a control endpoint from its identity-checked `daemon.log` interval into `heap_exhausted` (V8's fatal heap-limit banner), `writer_lease_contended` (the engine's single-writer refusal), `engine_floor` (the root-authority version-floor refusal) or `unclassified`. Classification is diagnostic, never behavioral: typed `daemon_spawn_failed`, `last_error` and one durable `claudexor_daemon_start_failed` row retain pin, exit code/signal, descriptor presence, classification, log interval, `latched` and `ts`. The latch uses only the typed exit: signal/non-zero and no descriptor from that spawn. Clean exits or crashes after control publication record `latched=false`; vanished joined peer startups write no row. While latched, every ordinary caller (delegation, model calls, review, warmup) gets the same immediate `daemon_spawn_failed` refusal before runtime preparation and without a new spawn, unless a live startup exists, which it joins: refusing there would hide a daemon that may come up. Releases (three rowed as `claudexor_daemon_start_latch_cleared`, the fourth not): attaching to a live authenticated daemon (`cleared_by=live_daemon_attached`); the ~600 s periodic supervisor sweep (`cleared_by=supervisor_sweep`), off the loop thread and attach-only once a stop is in flight, which, only when it released a latch, makes one zero-wait ensure on a short-lived background thread, so a healthy install never spawns or waits in the sweep and a persistently crashing engine costs one spawn per period; the owner's Refresh (`/api/claudexor/wake`, `cleared_by=owner_wake`), one spawn per press; and the owner's Restart or Panic, which release it without a row by building a new manager. The latch is per-manager state and the manager a process global: the sweep and the Refresh release the server process's latch; a task worker holds its own, released only by a live-daemon attach or the worker's respawn. No backoff, counter, cooldown, heap policy or new timing constant exists: the host neither derives the engine's heap from host RAM (V8's default old space is 4096 MiB from 8 GiB up: a guess only moves the crash; the engine's bounded replay removes the need) nor touches the writer lease. `NODE_OPTIONS` on the server process reaches the spawned daemon unchanged: the operator's documented escape hatch (e.g. `NODE_OPTIONS=--max-old-space-size=8192`), not a product mechanism. The registration pass of the same sweep (`retire_settled_registrations`) reaches the daemon only for a registration every sharer has settled. Its typed `PROJECT_RETIRED`/`PROJECT_RETIRE_FAILED` discharge, the harvest cadence, the two disclosed residuals and the native-evidence rule are stated once, in DEVELOPMENT's Process Custody Rule.

Tool custody: `_active_subprocesses` and task-attributed executor records (§1). `os.walk` scans arbitrary nested roots and matching directory symlinks, not parent symlinks; separate foreground/service scans catch late service records. Startup OS/delegated recovery does not settle executor backends. Host unwind/exact worker death retires local invocation only (§6); unknown effects never authorize replay. Groups/Jobs miss escaped descendants. Docker CLI exit proves no backend exit: persist `backend_completed` before marker deletion; lost replies retain evidence, never signal completed CLI PIDs. Panic never waits on nonessential cleanup.

**Future work controls.** The full stated cancellation reason is retained. Recorded cancel intent wins; a proven absent intent uses the shutdown door's cause, while an unreadable store must not invent one. An accepted explicit Stop also transfers its exact future-work control identity to the original task result before active intent retirement, even when natural completion wins, preserving the completed status, result and custody. A failed transfer keeps the active intent for recovery. Manual Restart retains a schedule control in the schedule document before consuming its marker; Panic gains no prerequisite. These schedule control identities leave the legacy global flag carriers generation-unaware; generation-aware markers remain separate.
