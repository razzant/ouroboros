# 8. Git Branching, CI, and Build

Publication rules: three update feeds, CI/trust boundaries, keyless system E2E, builds, dependency locks and proof for seven required desktop assets plus an optional verified Android pair.

`ouroboros` is the local working branch. The runtime-selected official feed is independent: Stable = newest plain release tag reachable from both `main`/`ouroboros-stable`; QA = `ouroboros-stable` tip; Development = `ouroboros` tip (`update_channels.py`). Owner-controlled promotion/rollback move exact SHAs. Restart keeps the local tip; explicit update owns fetch, validation, rescue, apply and rollback. `managed` reads/updates officially; optional `origin` persists personal work. Desktop/Colab targets need regular nonempty `BIBLE.md`. External PRs target `ouroboros`, leave versions alone; maintainers allocate collision-free versions on landing (CONTRIBUTING.md).

Candidates use `candidate/<task>` and private pins (§6), published explicitly. Auto-push sends the branch and its operation-created annotated tag; selected adoption withholds both (DEVELOPMENT "The tiered commit and CI gates"). Adoption retains that creation fact; interrupted recording leaves the tag local. Neutral commits and legacy receipts backfill none. Tag failure is disclosed, not retried.

Local `ouroboros-stable` is also the fallback advanced by `promote_to_stable`: safe restart checks it out after a working-branch import failure (`supervisor/git_ops_reset.py`); this role selects no QA feed. Launcher metadata is bootstrap provenance only. Status, preflight, Colab bootstrap and apply resolve channel and fetched SHA themselves; older launchers cannot redirect updates. Stable also requires the shared plain release tag; QA/Development admit without version comparison.

### CI topology

`ci.yml` runs only on dispatch or `v*` tags; local tests and review stay strict. After merges to `ouroboros` the secret-free `post-merge.yml` runs the affected tests (coalesced, one retry) and `ruff --select F`, bisects a red to its merge and reports it to that PR and a `post-merge-red` issue, blocking nothing. UI/provider wrappers are manual; Claudexor and non-test publishing keep their triggers; Hub validation is separate.

Quick/full `size_ratchet` checks exact manifests and shrink-only transitions against `OURO_SIZE_RATCHET_BASE_REF` (local warnings). Unresolvable bases use the tree-verified parent; missing manifests fail without borrowing debt. Only book checks skip without an event base. `scripts/book_growth_mode.py` derives `OURO_BOOK_GROWTH_MODE` (`block|warn|approved`) from PR metadata (`pull-requests: read`; DEVELOPMENT "Documentation contract"). Both run full Node (`preflight_node.py`). Skill smoke (`tests/skill_smoke_author.py`): dependency-only Python, one author, review/rebuttal, immutable payload, persisted gate. Reap key-bearing tree before enable. Review precedes downloaded imports; payload code never shares credentials. Missing keys fail. CI uploads only redacted judgments.

Shared UI and keyless wait/repair browser fixtures run the dirty Git candidate in an independent checkout (`tests/candidate_checkout.py`) and prove through `/api/health` and static sentinels that the served assets and imported Python came from that copy (recipe: DEVELOPMENT "Safe local verification and dirty browser candidates"). `ouroboros/test_environment.py` gives pytest, preflight and server children scrubbed temporary roots before imports.

Tool-schema compatibility has two layers. Local and manual/tag tests build the complete shipped catalog without MCP or extensions, validate every schema as JSON Schema plus the cross-provider subset, and require every provider projection to preserve the complete tool-name set. Trusted `integration-test` sends that full registry, fitted to the route's schema ceiling as Main does, in one bounded, unexecuted `delegate_start` canary per route and requires positive usage, exact provider/model identity and a schema-valid call carrying exactly the requested arguments; quota, 429, 5xx and timeout outcomes stay typed inconclusive, while contract, auth, model, tool and reasoning 4xx are red (DEVELOPMENT "Provider Independence").

Informational test reports, safe artifacts, step ceilings and partial UI checks: DEVELOPMENT "Reading CI failure evidence".

Each manual/tag `CI` run and re-run has its own concurrency group, so no qualification cancels another.

`claudexor-platform-gate.yml` retains path-filtered branch/PR triggers, tags and dispatch. It proves the managed Claudexor runtime on three OSes: a fixture lane (fake harness, offline, $0) and a toolchain lane (`scripts/claudexor_toolchain_smoke.py`: production `ensure_cli_command()` installs the pinned Node/npm with no ambient toolchain) always, a Windows consumer lane where `install_missing_harness_cli` really installs the engine-pinned Codex (resolves directly, by bare name and in doctor; no login or task), and a live lane only on explicit API keys. Subscription auth stays out of CI: an interactive machine-bound token never enters CI secrets. Fixture triggers also run the credential-free `scripts/claudexor_lifecycle_smoke.py` on all three OSes: a real pinned engine under production custody proves that cancel, daemon-kill respawn, completion and retirement settle and continue, not vendor sessions or child-process containment. `dependency-graph.yml` submits the `ouroboros/claudexor_runtime_pin.json` runtime relationship to GitHub's dependency graph (`contents: write` only) without presenting Claudexor as a Python or Node package. `.github/workflows/scorecard.yml` runs on `main` pushes and weekly, pins every action by commit SHA, defaults permissions to read-only and adds only `security-events: write` + `id-token: write`. `CODE_OF_CONDUCT.md` owns community rules, `CITATION.cff` the software and technical-report citations, `site/paper/index.html` the paper landing page, `docs/benchmarks/evidence.json` the release-bound public benchmark projection; README stays the claim SSOT.

`scripts/` is operator and release tooling, each script documented by its own docstring: `safe_test.py` (stdlib verification boundary), `book_growth_mode.py` (official contribution growth mode), `browser_ci_scope.py` (documentation-only browser selection), `run_tests.py` (test battery), `ci_retry.py`, `post_merge_check.py`, `run_external_review.py` (the runtime's own review flow over the staged index or, with `--contributor`, over a committed `base..head` proposal under the installed body's review flow and rules; `READY_FOR_INTEGRATION` is evidence, never merge authority), `contributor_review_evidence.py`, `run_plan_review.py` (the `plan_task` engine; review-exempt), `validate_scope_receipt.py`, `claudexor_platform_smoke.py`, `claudexor_toolchain_smoke.py`, `fetch_claudexor_runtime.py` (pin SSOT: `claudexor_runtime_pin.json`), `cleanup_test_pollution.py` (dry-run first). `site/` is the Vite source of the public pages (`site/scripts/sync-assets.mjs`); `skills/` holds the bundled skills (`skills/builtin.json`); `packaging/cli/`, `packaging/appimage/` and `packaging/systemd/` hold the CLI wrappers and installers, the AppRun dispatch and the opt-in user unit (§1 Runtime topology).

### System E2E suite (`tests/system_e2e/`)

The deep-integration suite drives a real isolated `server.py` per scenario (`KeylessIsolatedServer`, whose child environment can never carry a provider credential) and asserts durable artifacts through `ArtifactOracle` readers (the task store, `logs/*.jsonl`, `state/*`), never an HTTP 200 or a harness exit code. Synchronization is durable-event polling, never bare sleeps; a scenario that must act mid-round holds the loopback model on an event-gated `ModelGate`. Two loopback models share one HTTP base: `ScriptedStubModel`, an ordered per-scenario tool script whose review-organ calls are classified by prompt markers, and `ReplayModel`, deterministic keyed fixtures where a miss or an unconsumed row is red. A default-lane pin greps the prompt markers back out of their source files verbatim, so drift is a named failure, not a silently mute stub. Reviewer routing is pinned through an `OUROBOROS_SUBAGENTS` catalog (`keyless_review_catalog`), because a never-configured catalog reads the factory reviewers, live routes that block keyless runs. `FakeClaudexorDaemon` imitates the exact `gateways/claudexor.py` client contract and records every wire request.

The scenario inventory (`SCENARIOS` in `harness.py`) binds the package's `test_*.py` modules both ways; missing rows or tests fail. S41 checks the skill-smoke author. Scenario tests carry `integration` (shared-resource cases also `serial`) and their `OUROBOROS_E2E_DEEP` lane gate, so neither the default local run nor either CI pytest pass executes them: keyless `mock` is `OUROBOROS_E2E_DEEP=mock pytest tests/system_e2e/ -o addopts=""`, in CI `system-e2e-mock`; S39's operator-run `container` lane needs one named Docker daemon (`test_managed_container.py` docstring). The paid owner-shaped stand against a real provider is operator tooling: `devtools/e2e_live/README.md`.

### Build scripts

Release owners: `build.sh` (.dmg), `build_linux.sh` (.AppImage/.tar.gz), `scripts/build_appimage.sh`, `scripts/build_linux_packages.sh` (.deb/.rpm/.red80.rpm), `scripts/smoke_linux_packages.sh`, `build_windows.ps1` (.zip), `scripts/pack_windows_archive.ps1` (preserves hidden files), `scripts/sign_windows_release.ps1` (eSigner), `scripts/verify_windows_signature.ps1` (signer/timestamp), and `scripts/build_repo_bundle.py` (writes `repo.bundle` + `repo_bundle_manifest.json`, validated by `launcher.py`). It requires annotated `v$(cat VERSION)` at `HEAD`.

Native Linux: Ubuntu 22.04 x86_64, portable Python; other builders keep the host backend (`OUROBOROS_BUNDLE_LINUX_GTK=auto|0|1`; release requires `1`). `scripts/bundle_linux_gtk.py` stages GTK3/WebKitGTK 4.1, typelibs, helpers and resources in `_internal/linux-gtk`. `Ouroboros` saves caller state, then starts `Ouroboros.bin` with GUI loader paths. `desktop_media.prepare_linux_bundle` restores GI paths/cwd after frozen hooks; `host_environment` restores copies for server/host children. Source handoff keeps GUI state; both interpreters carry GI. `scripts/capture_linux_sources.py` retains exact Debian sources, edits and hashes in production/diagnostics; recipient access remains a release obligation. Digest-pinned AppImage/packages share payload/entry; packages use `/opt/ouroboros` and an inactive opt-in user unit. Gating package smokes install via `apt`/`dnf` on Ubuntu 22.04/Fedora 42. Astra Linux/RED OS vendor smokes are informational: registry availability cannot block publication.

Betterleaks: packages stage the pinned binary/license in `betterleaks-standalone`; source checkouts explicitly install the managed runtime. Publish never downloads it (§6 Skill publication).

`pyproject.toml` owns requirements/groups; `uv.lock` resolves them with `tool.uv.required-version`. Source/CI use `--locked` and reject export drift. Embedded Python/managed updates use `requirements-runtime.lock` (pip); `requirements.txt` redirects older updaters. Both interpreters need desktop extras: source cannot import frozen PYZ. Archive smokes probe plain Python with `-I -B`; DMG also probes its app entry. AppImage bundles GTK; missing display/backend keeps browser fallback. [Native qualification](../../packaging/appimage/README.md) is separate from headless smoke.

Unchecked-hash Python bytecode and external runtime caches preserve the bundle signature. macOS `build.sh` compiles `packaging/macos/ouroboros_shell.c` before pruning headers, linking the matching `Frameworks/python-standalone/lib` libpython. The Contents/MacOS entry preserves source Python's app identity. Deep signing precedes its explicit app identifier, then outer sealing/verification. Signing is not launch proof: builds drop `*.dSYM`/pyobjc tests (unticketed debug companions fail Gatekeeper); proof checks the stapled, copied-out app.

The release proof begins with the final DMG/AppImage/tarball/ZIP, never its staging directory: a validated staging tree does not prove the published bytes contain or execute the same payload (`scripts/release_proof.py`). Each platform shard checks the embedded repository bundle, the packaged CLI and the managed Claudexor seed + Node by starting the owned daemon, completing a fixture task and verifying an identity-bound stop; the proven Linux tarball payload is wrapped into the three native packages, each with its own digest-bound package-manager smoke receipt and provenance attestation. The release job requires seven desktop assets, admits a verified optional Android pair, recalculates digests, records actual job conclusions in the checksum/evidence capsule and rechecks the remote annotated tag before publication. Signing credentials stay step-scoped and absent from SBOM/attestation steps.

Configured platform signing is mandatory and recorded: Windows Authenticode (`ESIGNER_CERT_SHA1`; a fresh runner bound to the `windows-release-signing` Environment, tag pushes and their reruns only) and macOS notarization (required once signing is; app, then DMG) stop the release on failure, and each receipt carries the observed state the notes disclose. Unconfigured repositories publish explicitly unsigned or unnotarized assets; macOS prereleases build unsigned, Windows signing covers every tag. Mechanics and setup: DEVELOPMENT "Build & CI".

Public installer naming and links ride the same projection: `ouroboros/tools/release_sync.py::RELEASE_ASSET_TEMPLATES` is the filename SSOT shared by the proof builder, README and the install pages. A version bump rewrites only named download references and `data-release-download` anchors to immutable `/releases/download/v{VERSION}/...` URLs; the `/releases/latest/download/...` shape is forbidden because GitHub excludes prereleases from `latest`. Generated release notes link only proof-accepted assets: seven required desktop installers plus an optional Android pair and its USB setup guide; the APK alone is not the runtime. The default README and GitHub Pages deployment use the stable `main` boundary (`main:/docs` for Pages); stable promotion advances `main` only after the release publishes all seven proof-bound desktop installers, so an unreleased development VERSION never exposes dead installer links and an omitted promotion leaves the previous working release public.

`scripts/build_android_release.py` binds a source archive, a common Git seed and a publisher-signed reference APK to the tag SHA, package/version/certificate and smoke/SBOM/attestation proof. Android is nonblocking: a failed, cancelled or skipped build, a partial pair or a failed digest/smoke/SBOM/attestation check excludes both Android artifacts, while required desktop failures stay fatal. Compilation certifies no physical root, boot, hardware or runtime behavior.

### Docker

Docker runs the web and server runtime without PyWebView, bound to `0.0.0.0` (exposure, passwords and both modes: DEPLOYMENT); `--target managed` hosts the common launcher over a released seed, body and `--runtime-venv` on volumes (§2 Packaged seed).

The root `.dockerignore` keeps secrets, host environments, caches and runtime/review/operator state out of `COPY . .` layers; `.git`, `tests/` and sources stay: CI runs pytest inside the image.

The image is one self-contained `Dockerfile`: Debian trixie with the pinned python-build-standalone 20261009 build (CPython 3.10.22, SQLite 3.53.1; the assets of `scripts/download_python_standalone.sh`), the pinned `uv`, git, Playwright's native libraries and the Chromium/WebKit of the `uv.lock` Playwright in `/ms-playwright` (the `PLAYWRIGHT_BROWSERS_PATH` the runtime honors as-is), then `uv sync --locked` into `/app/.venv` on that interpreter, then the sources; browsers and apt packages sit above the lock copy that every release rewrites. Compose's healthcheck is `GET /api/health` with `boot.phase` ≠ `failed`, no start deadline (DEPLOYMENT). No runtime `UV_PROJECT_ENVIRONMENT` is baked, or an agent's `uv sync` in a task workspace would rewrite the runtime venv; the tag-only `docker-ui-smoke` and `docker-portable-test` lanes exercise the shipped browsers without a download. No trust anchor is baked in (`OUROBOROS_EXTRA_CA_BUNDLE`: DEPLOYMENT).
