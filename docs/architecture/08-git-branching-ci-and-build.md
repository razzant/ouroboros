# 8. Git Branching, CI, and Build

Branches/feeds, CI trust boundaries, keyless E2E, builds, dependency locks and release proof: seven required desktop assets and an optional Android pair. Guarantees govern published claims.

`ouroboros` is the local working branch; `managed` tracks official updates and optional `origin` holds personal work. Official feeds (`update_channels.py`): Stable = newest plain release tag reachable from `main` and `ouroboros-stable`; QA = `ouroboros-stable` tip; Development = `ouroboros` tip (QA/Development skip version comparison). Promotion and Restore bind exact SHAs (Restore keeps rescue/keep refs, never pushes), explicit update owns fetch/validation/rescue/apply/rollback, Desktop/Colab targets need nonempty `BIBLE.md`, and external PRs target `ouroboros` leaving versions untouched (CONTRIBUTING.md).

Candidates use `candidate/<task>` and private pins (§6). Auto-push sends branch + operation-created annotated tag; selected adoption withholds both while recording creation (interrupted recording leaves the tag local; DEVELOPMENT "The tiered commit and CI gates"); neutral commits/legacy receipts backfill none, and tag failures disclose without retry. Local `ouroboros-stable` is also the recovery fallback (not the remote QA feed), advanced by Save recovery point, `promote_to_stable` (also pushing it), and every ready managed boot of a clean managed development checkout to its smoke-proven commit on any update channel (`server.py`, `supervisor/git_ops_reset.py`). Status, preflight, Colab bootstrap and apply resolve the selected channel and fetched SHA directly so frozen launchers (bootstrap provenance only) cannot redirect updates.

### CI topology

Keyless `post-merge.yml` coalesces `ouroboros` pushes without blocking merges. Linux/WAL and Windows/PERSIST select each first-parent change and retry reds once; Linux adds ruff F, size vs base and cost (8min k=30; k=100 opt-in). RED separates comparable blame (omitting old fixtures), cost/stage gaps and cost xfails; per-OS `post-merge-red` issues notify PRs until pass (size: same base) or removal (non-size). Base advances only when one attempt measures both legs, hands off reds and has no cost failure; dispatch seeds bootstrap/recovery. Interface windows start pilot `post-merge-browser.yml` (own run, `post-merge-red` issues; one-merge culprit PR comment if base passed; no group/verdict/base).

### System E2E suite (`tests/system_e2e/`)

Runs a real isolated `server.py` per scenario (`KeylessIsolatedServer`, child env credential-free), polling durable events (never bare sleeps; mid-round actions hold an event-gated `ModelGate`) and asserting `ArtifactOracle` state (task store, `logs/*.jsonl`, `state/*`), never HTTP 200 or exit codes. Loopback models share one base: `ScriptedStubModel` (review-organ prompt markers grepped verbatim from source by a default-lane pin so drift fails named) and `ReplayModel` (keyed fixtures; miss/unconsumed red). `keyless_review_catalog` pins the `OUROBOROS_SUBAGENTS` review pool onto the loopback stub, because a never-configured catalog reads the factory reviewers, live routes that block keyless runs; `FakeClaudexorDaemon` implements the exact `gateways/claudexor.py` contract, logging wire requests.

`SCENARIOS` (`harness.py`) binds `test_*.py` two-way (S41 skill-smoke author; S43 load stand `test_stand_server.py`, `OUROBOROS_E2E_DEEP=stand_full`). `integration` (`serial` where shared) and `OUROBOROS_E2E_DEEP` exclude scenarios from default local and both CI pytest passes: keyless mock is `OUROBOROS_E2E_DEEP=mock pytest tests/system_e2e/ -o addopts=""` (`system-e2e-mock`), S39 `container` requires a named Docker daemon (`test_managed_container.py`), and the paid live stand is operator tooling (`devtools/e2e_live/README.md`).

### Build scripts

Owners: `build.sh` (.dmg), `build_linux.sh` (.AppImage/.tar.gz), `scripts/build_appimage.sh`, `scripts/build_linux_packages.sh` (.deb/.rpm/.red80.rpm), `scripts/smoke_linux_packages.sh` (RED OS via `scripts/ci_redos_image.py` + `scripts/redos-ubi8.pin`, registry-only TLS trust), `build_windows.ps1` (.zip), `scripts/pack_windows_archive.ps1`, `scripts/sign_windows_release.ps1` (`windows_signing_catalog.json`), `scripts/verify_windows_signature.ps1`, and `scripts/build_repo_bundle.py` (`repo.bundle` + `repo_bundle_manifest.json`, validated by `launcher.py`, requiring annotated `v$(cat VERSION)` at `HEAD`).

Native Linux (`OUROBOROS_BUNDLE_LINUX_GTK=auto|0|1`, release `1`): `scripts/bundle_linux_gtk.py`, `Ouroboros`/`Ouroboros.bin`, `desktop_media` restore and `scripts/capture_linux_sources.py` follow `packaging/appimage/README.md`; digest-pinned AppImage and `/opt/ouroboros` `.deb`/`.rpm` packages (inactive opt-in user unit, CycloneDX SBOMs, gating Ubuntu 22.04/Fedora 42 `apt`/`dnf` smokes, informational Astra/RED OS vendor smokes) follow `README.md` (Packaged Linux) and DEVELOPMENT §14. Pre-signing builds swap `playwright/driver/node` for pinned Node + `LICENSE.node` (macOS Resources mirror; Android venv) and stage `betterleaks-standalone` (source checkouts install the managed runtime; publish never downloads, §6). Desktops also bundle ripgrep; DMG/AppImage/tarball/ZIP stage fallback `git-standalone/` (`dugite-native`: `darwin-{arm64,x64}`, `linux-{arm64,x64}`; Schannel `MinGit`: `win32-x64`; `.deb`/`.rpm`/Android omit). Embedded Python and managed updates share `requirements-runtime.lock` (`requirements.txt` redirects older updaters; both interpreters carry desktop extras since source cannot import frozen PYZ). Archive smokes probe plain Python with `-I -B` (DMG also probes its app entry), and the desktop launcher keeps browser fallback when a display or GUI backend is missing (DEVELOPMENT "Release proof capsule").

Unchecked-hash bytecode and external caches preserve bundle signatures. macOS `build.sh` compiles `packaging/macos/ouroboros_shell.c` before pruning headers, linking `Frameworks/python-standalone/lib` (keeping `Contents/MacOS` app identity for source Python), strips `*.dSYM`/pyobjc tests for Gatekeeper, and signs in order: `--deep` first, then restores the explicit app identifier (`--identifier com.ouroboros.agent`) on `Contents/MacOS/ouroboros-shell` (`--deep` overwrites helper identifiers), then applies the outer seal and strict verification (macOS prereleases unsigned; Windows `windows-release-signing` Environment on tags/reruns only; DEVELOPMENT "Apple signing & notarization (macOS Build job)" and "Windows Authenticode release signing (SSL.com eSigner)"). Signing is not launch proof: `scripts/release_proof.py` checks the stapled copied-out app and final DMG/AppImage/tarball/ZIP bytes (bundle, CLI, Claudexor seed + Node start, fixture task, identity-bound stop; staging proves nothing). The proven Linux tarball's payload supplies the three native distro packages (`.deb`, `.rpm`, `.red80.rpm`; each has a digest-bound package-manager smoke receipt and provenance attestation); `build_linux.sh` builds the AppImage beside the tarball from `dist/Ouroboros/`. `release` requires seven desktop assets and pinned bundled-Git source archives (`README.md`), admits a verified optional Android pair, recalculates digests, records job conclusions and rechecks the remote tag while keeping signing secrets step-scoped and out of SBOM/attestation.

`ouroboros/tools/release_sync.py::RELEASE_ASSET_TEMPLATES` owns filenames across proof, README and install pages. Version bumps rewrite only named download refs and `data-release-download` anchors to `/releases/download/v{VERSION}/...` (`/releases/latest/download/...` forbidden since `latest` skips prereleases); development markers (BIBLE P9) rewrite none and take no tag, build or row, and release notes link only proof-accepted assets (APK alone ≠ runtime). Default README, Pages (`main:/docs`) and Homebrew tap sit on stable `main`: `scripts/promote_stable.py` runs after desktop publication (omitted promotion keeps the prior release public, avoiding dead links), refuses until `ouroboros` carries the tag and links under a greater marker, and atomically fast-forwards `ouroboros-stable` while appending the tag tree + `Casks/ouroboros.rb` to `main` (merging the tag unless present) so the Stable resolver and mirrors trace the tag.

`scripts/build_android_release.py` binds source archive, Git seed and publisher-signed APK to tag SHA, package/version/certificate and smoke/SBOM/attestation proof. Android is nonblocking: failed, cancelled or skipped builds, partial pairs or failed digest/smoke/SBOM/attestation checks exclude both Android assets while desktop failures stay fatal; compilation certifies no physical root, boot, hardware or runtime behavior.

### Docker

Docker serves web/server without PyWebView on `0.0.0.0` (DEPLOYMENT); `--target managed` runs the launcher over released seed, body and `--runtime-venv` volumes (§2). `.dockerignore` keeps secrets/local state out of `COPY . .` while retaining `.git`, `tests/` and sources for CI pytest. `Dockerfile` owns layout and `/ms-playwright` (`PLAYWRIGHT_BROWSERS_PATH`), omits `UV_PROJECT_ENVIRONMENT` so workspace `uv sync` cannot rewrite the runtime venv, and tag-only `docker-ui-smoke`/`docker-portable-test` verify shipped browsers offline (interpreter, healthcheck, root Chromium refusal, trust anchors—none baked: DEPLOYMENT).
