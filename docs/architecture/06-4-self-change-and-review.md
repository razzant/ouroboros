# 6.4 Agent Core — Self-Modification & Review Stack

How I modify my own body safely: isolated candidates (`prepare_self_change`, `body_candidate.py`), staged Git/commit discipline, `diff_pulse`, and my multi-model immune system (`review_change` for commits/preflight/skills/system, result review, and council waves). Self-edits use an isolated candidate by default (Cyber Pro allows an explicit `in_place=True` exception); review scores one frozen subject under installed governance, paid cycles share `OUROBOROS_REVIEW_MAX_CYCLES`, and read coverage is diagnostic, never a veto.

#### Late completion and typed refusals

Released custody stays unresolved; later notices or cancellation never rewrite model text, authorship or hash.

An empty pool (`pool_empty`) reviews on Main alone as one native seat `main` (`review_pool_slots`; §7 Review pool: malformed catalogs refuse Save and review; naming an off/unknown row refuses, never rerouted). Technical failure and commit permission are separate facts: producers keep a failure's origin beside the original status and findings, and what Access permits is the protocol's rule (DEVELOPMENT "Review & Commit Protocol"); neither changes quorum.

### Own-body candidates

Body authors (queued roots, owner turns, evolution cycles) write a task-owned worktree `candidate/<task>` of serving HEAD in the isolated worktree root, so unfinished edits never enter serving imports; a `kind=body_candidate` row rebinds it across retry, Resume or new worker. `prepare_self_change` provisions it; body writes, `git_pr.BODY_WORKTREE_TOOLS` and acting `self_worktree` children enter `body_candidate.authoring_seam`; earlier reads stay on serving. Light mode, capped trees, subagents and the managed-update resolver get none; Cyber Pro may pick `in_place`; Git-confirmed non-Git bodies edit in place; Git bodies off a worktree root and failed probes (Git's reason or error class) refuse `CANDIDATE_UNAVAILABLE`. First binds and explicit receipts list open neighbours' changed paths.

Binding points `repo_dir`, `system_repo_dir` and `branch_dev` at the candidate as one body identity, never an external workspace; explicit workspace/room folders stay the planning base, and `serving_repo_dir` owns governance, restart markers and rollback. Candidate and admitted body-child processes run in `<candidate>.env` (`test_environment.isolated_environment`: private HOME/data, venv pip, no credentials or global Git config; push/provider calls need another cwd); setup failure refuses `CANDIDATE_ENVIRONMENT_UNAVAILABLE` rather than borrowing the serving environment.

The root owns the candidate; validated continuation or `prepare_self_change(resume=…)` transfers it only from a terminal owner with settled ledgered processes, never by room, name or date. Attribution uses original/prior basis or creation `base_sha`, not today's files: proven late capture is superseded with history intact, other observations keep uncertain dirt. `commit_reviewed` retries missing attachment, never auto-pushes, and writes neutral (carriers unchanged, no tag), numbered (all synced, tagged) or development-marker (all but links and history, no tag) commits, never a partial bump. Copies without unique work expire by last use; unique work pins to `refs/ouroboros/candidates/<id>` before removal under `body_candidate.verdict_holds`, and a nested `OUROBOROS_RETAINED.txt` keeps checkout and environment.

Adoption is deliberate and restart-bound (`body_adoption.py`; re-verification and arming: its docstring): `request_restart(adopt_commit=<sha>)` (caller's claimed reason) or an evolution restart authorizes one exact reviewed commit on serving HEAD (`authorize_row`; Cyber Pro logs a gate exception; constitutional changes require a numbered release outside Cyber Pro). The old generation never writes the tree, the candidate's engine pin decides the owned daemon first (§9), and owner Restart/Panic never arm or wait so stuck stops never hold the owner hostage. Switch and recovery live in §2; `settle_on_boot` marks `adopted` only for a bootstrapped, supervisor-ready generation that attested the switched tree before its imports, attaching outcomes (`body_adoptions`, card row, `official_relation`, and running commits landed over review FAIL/no verdict via `review_overrides.py`) to the authorizing task.

### Git and commit review

`mutation_attribution.py` records root baselines (`capture_root_baseline`) and adopted predecessor changes (DEVELOPMENT "Mutation Attribution Rule"). A stale/ambiguous baseline blocks automatic staging for review to weigh; in a candidate an explicit selection may name uncertain paths or pass an overlapping moved base (never re-anchored), its facts reaching brief, handback and next epoch. `commit_reviewed` stages only attributed paths (explicit subset, `GIT_NO_ATTRIBUTED_CHANGES` if empty, reviewed paths if omitted in continuation), while managed updates keep whole-tree authority. Terminal dirty-only counts (including `attribution_uncertain`) ride execution facts to live/history cards with paths/HEAD in Details; failed scans stay unknown, clean commits stay silent, and outcomes stay apart from adoption.

Commit prep preserves native merge state (the current branch is never checked out again, no switch runs during a pending merge or after a failed state read, and path-only unstaging keeps `MERGE_HEAD/MODE/MSG`). One staged fingerprint binds tree, ordered parents, VERSION, expected/existing tag and binary diff and is rechecked after commit before success or push; release tags are never silently accepted or retargeted. Seats inspect that snapshot and mutation stales its binding; the early look changes neither tests nor binding. Managed resolution reviews M0→S (`tools/review_subject.py`) while binding S to the index; `release_sync.sync_release_metadata` projects carriers (`VERSION_CARRIER_SPANS` / `substitute_carrier_spans`). BIBLE owns authority, CHECKLISTS criteria, DEVELOPMENT procedure; GitHub child commands append existing `platform_layer.common_tool_directories` to PATH, and process bootstrap prepends them once without shadowing selected Git.

Outcomes return whole with `review_reference` before Git; `shown_outcomes` names what was rendered, and an unshown later outcome refuses continuation until collected free (Cyber Pro states gaps). Author continuation (`author_disposition`, own or recorded-Continue) binds current candidate, discloses drift and reruns preflight/tests/Git checks without critics (`reviewed/review_only`, pending `reviewing/late_wait`; evicted free rows read settled records); evolution receipts keep actual `triad_scope_status`, never an inferred PASS.

`owner_pause.run_operation` guards commit, tag, post-commit tests and push: Pause after review refuses an unsubmitted commit, while a handed-off commit succeeds with later steps marked not started; after Resume they are the author's explicit work, never a new commit. Managed merges keep `postcommit_resume` so `commit_reviewed` rechecks HEAD/clean tree and finishes tests/smoke under the receipt's review without a new commit or rollback (`git_managed_postcommit.py`).

`pr_merge(number, expected_head_sha, method)` sends one synchronous REST merge under the selected gh identity against the PR read back. `merge_receipts.py` writes intent before effect, separating reviewed/current/merged heads: `review_record_id` binds via `base..head`, or for index/worktree via an exact-merged-SHA `commit_landings` row; `checks` records runs/failures/omissions (missing checks stay unknown); merge/squash messages carry `update_qualification`; declarations never prove PASS and reviews never veto. Unknown/queued readbacks only observe until `NO_EFFECT`, a merged readback or Resume naming a settled unknown frees custody (`continue_receipt_id` gates one new request; links survive trimming); shell/web merges lack receipts.

`github_read` runs read-bound (read-only children too) GET/query paging with disclosed cuts, needs no checkout for `repo` reads except `{branch}`, and keeps logs/artifacts unextracted with bytes, size and sha256. `github_write` records actor/readback receipts (Hub shares `github_pr_identity.py`): PR methods need expect.head_sha (base_sha to `create_pr` or retarget); `update(kind="pr",target=N)` edits title/body/base by one REST PATCH at the read PR's URL (no read:org) or toggles draft separately. Nonatomic precheck → one send → readback; unanswered sends are looked up, never resent; failed/lost sends stay unknown, but a PATCH 4xx with every sent field read back unchanged is not applied.

### Review stack

`review_cycles.py` owns the shared paid-cycle cap `OUROBOROS_REVIEW_MAX_CYCLES` (a positive integer or `unlimited`; anything else fails closed to the shipped default, §7) across three pools: per root task, paid `review_result` waves, counted independently of the mind's responses, plus free rewording reminders, and paid skill waves (manual lane: per content version); and paid code-review waves (`paid_review_pool`: `review_change` and the commit gate share one allowance per tree and repository, Continue included), counted from attempt rows at dispatch so the cap counts money. What consumes capacity is DEVELOPMENT §5's. The last wave permits author reaction, and `unlimited` lifts only the count, not ordinary task rails (§10 invariant 17).

Review waiting has six independent axes:

| axis | bound |
|---|---|
| transport | dead-socket read bound |
| operation | typed active-operation lease |
| logical | slot/task deadline |
| policy | budget / cancellation |
| absolute | task ceiling |
| aftermath | late-result custody |

#### Physical custody

`review_custody` owns workers and operation IDs across all axes; permits belong to physical workers until durable settlement, never drains or free rejoins, and `review_wave` shares the first detach so consumed mail strands no sibling. Pause fences unsent starts even after Resume, wait-only exits never (`review_pause.left_wait_only`). Outer failures persist before readiness; progress says "answered" only for parsed answers; seats publish execution at settlement.

Capture state proves custody: `dispatched|unresolved` without terminal HTTP status is custody-lost and never resent; only explicit `__cause__` or typed metadata proves pre-dispatch. Answers and terminal errors settle even when empty; socket death stays `provider_outcome_unknown`, never another paid route. Transport defaults never cap reasoning; windows narrow to the owner deadline minus finalization reserve (spent windows refuse at $0; commits have no outer cutoff), `review_live_join` keeps remaining window and Pause/Stop controls.

#### Paid stamp and owner custody

`review_dispatch.py` stamps `paid` write-ahead at each delivery's physical dispatch via one once-only, idempotent `ReviewPaidStamp` per wave (packet row, native paid send or replayable session `START_REQUESTED`); assembly, pre-send refusals, replays and rejoins skip that seam, so $0 attempts never spend cycles, and neither a worker outliving its caller nor a crash after dispatch loses the fact. Concurrent seats await the write; commit review and `review_change` (result and skill waves too) fail closed on write error while others stay fail-open.

Before the wave, one locked write records the reserved roster and operation IDs in the attempt row, bound to server session and pid (`review_owner_custody.py`); the first send sets `paid=True`. Delegated seats patch `pending_invocation_id` before POST; missing/mismatched operations on resume are `custody_lost` on every install. Owner loss is proven by pid death, never elapsed time, because a TTL would turn waiting into resend authority.

Delivery is a catalog-row property (`reviewer_slot_config.review_pool_slots`, §7). `OUROBOROS_REVIEW_SESSION_ROUTE` (`review_execution.REVIEW_SESSION_ROUTE_ENV`) sets one shared `harness[=model][:effort]` session target (defaulting to `OUROBOROS_SUBAGENT_HARNESS` when unset, so one delegated route is configured once); unparseable values disable review sessions with a warning instead of re-routing.

#### The coupling question (Part 2 of the brief)

The commit gate runs one wave, one seat role and one quorum over ASSIGNED seats (`tools/parallel_review.py`), assigning briefs by `parts`: packet seats `[change]` (contract A, `triad_review.REVIEW_JSON_ARRAY_CONTRACT`), retrieving seats (native API or session in every mode) `[change, coupling]` (contract B, `REVIEW_TWO_PART_OBJECT_CONTRACT`: `{change, change_clean, coupling}`), and `review_change` `coupling_only` critics `[coupling]` outside quorum. Part 2, the coupling question (`tools/review_brief_coupling.py`), asks every retrieving seat of the wave repo-wide intent, scope and coupling, with no separate scope role; Part 1 (line errors) and Part 2 (cross-module contracts) run on one seat over one snapshot (managed updates: M0→S), so neither answer hides the other. `config.adaptive_quorum` counts responding seats once, and `review_ledger.reduce_verdict` (also `ParsedTriadReview.quorum_met`) forbids `PASS` if coupling is unperformed. Native API seats keep configured route/account/effort while the surface picks inspection delivery.

`review_admission.build_two_part_brief` renders Part 1 (intent, rebuttal, history, checklist, task evidence, staged change) and Part 2 (coupling questions, governance tiers, repo index, required-source manifest), placing stable governance first for cache reuse. Diffs inline up to `native_first_send_chars` (`SESSION_INLINE_DIFF_CEILING_CHARS` for sessions) and otherwise page from the artifact store (`.review-drive` for sessions; skill payloads page hash-bound copies). Native size never refuses a brief; prep faults emit `review_brief_preparation_failed` and block as `infra_failure` at $0.

`scope_required_sources.py` defines the change-relative reading minimum: touched protected runtime, prompts, frozen contracts, their families (`GIT_OPS_FAMILY_PATHS`, tool-dispatch leaves) and declared value twins (browser limits and release carrier, §11.1). Other files are reachable beyond the complete diff. Rows pin `source_revision` and `complete_sha256`/`complete_chars`; `required_sources_ref` and `SCOPE_REQUIRED_SOURCES_POLICY` enter `commit_gate.commit_review_contract_fingerprint` so replay never survives a contract change.

Observed coverage (`complete`, `incomplete`, `declared_empty`, `unobserved`; a changed source is a `source_gap`; plan seats pair `room_delivery` with `room_read_coverage`) is purely diagnostic: inline delivery never proves understanding, `review_context_atlas.repository_index` only orients (no bodies, no spend, no limit on what a reviewer opens), and gaps never alter quorum, block commits or buy extra reviews; the author judges whether a gap needs more reading. Critical findings return to the author; a defective `coupling` block leaves that question unanswered (its FAIL rows discarded, and with no seat answering it the review is `NOT_PERFORMED`) while the seat's `change` answer still counts; oversize, route and binding faults never become `PASS`. If a change cannot fit a reviewer, split the change instead of weakening the reviewer.

#### Governance delivery

`tools/governance_context.py` supplies CODE/coupling briefs, preflight and deep review. Installed governance judges proposals. Native inspection binds `system_repo` to the installation, `active_workspace`/default to the candidate, even outside HOME. Tier 1 inlines BIBLE, CHECKLISTS_ARCHIVE and executing CHECKLISTS surface/`Shared Contract Ownership` sections. Tier 2 budgets review protocol, DESIGN and DEVELOPMENT chapters naming touched files; tier 3 adds ARCHITECTURE maps/relevant packet sections within `runtime_limits.REVIEW_GOVERNANCE_INLINE_SHARE`. DESIGN's map names the excerpt actually inlined or its absence; a missing source stays explicit. Core review gets its universal checklist, body books `not_applicable`, `subject_root` navigation and no body-required sources. Retrieving seats can read sources; packets disclose undelivered text.
`review_words.py` adds bounded word changes before change diffs and to Result Review.

**The body predicate.** `review_body_fact.body_fact` returns `BodyFact(body ∈ {true, false, unknown}, how, detail)` from Git/manifest facts only — never branch, directory or remote-name patterns (P5) — and `layer_for` selects body iff true. `treat_as_body` raises only unknown (recorded in `detail`) and never lowers a recognized body; plans qualify by declared `affected_paths`, copies included. `review_checklist.checklist_fingerprint(layer)` pins layered sha256 and `rules_source`.

#### Guaranteed-fit ladder

`review_admission.fit_triad_prompt` runs a one-pass fit ladder for packets (optional cold-density probe, evidence projection, touched-path note, `-U0`) keeping every file/hunk identity and changed line. Briefs and packets share span-only release-carrier cuts, packets omit duplicate inline governance (managed subjects keep full text), omissions are named, and irreducible packets refuse typed; retrieving seats page exact subjects instead, and plan asks size attachments per participant while keeping the body constitutional pack.
