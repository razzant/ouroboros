# 2. Startup / Onboarding Flow

Startup orders launcher checks, gateway onboarding and an atomic save of settings, next-boot mode and install-time presets. Boot normalization never creates `settings.json`: fresh-install latches need its absence. Sufficient provider configuration starts the optional supervisor. Automatic intent (`--launch-intent automatic`; direct server: `OUROBOROS_LAUNCH_INTENT=automatic`) passes `launcher_bootstrap.automatic_launch_allowed`: after Panic it exits 0 before startup, marker intact. Launcher intent overrides the child's inherited intent; owner/default intent starts normally. Containers: [DEPLOYMENT](../DEPLOYMENT.md#containers).

### Boot order

**Launcher.** UI prep (Linux: browser), PID lock and automatic-intent check precede tray/activation and Git/venv/seed bootstrap: `git_selection.py` (stdlib-only) sets `OUROBOROS_GIT` (`launcher.check_git`: server PATH order, keeping Finder Homebrew Python/OpenSSL; `packaged_cli`: inherited PATH first; working system Git first, bundled fallback). Missing Git gets an install hint, not an installer; `GitUnverified` gets a retry hint (no path in the window). `launcher_bootstrap.py` reaps commands on exit or Quit/Panic (Windows Jobs, source POSIX lifelines, frozen POSIX group/token custody without an abrupt-death guardian). The lifecycle thread (exit 42, crash fuse: §1) probes `/api/health` while its child lives (`launcher_readiness.py`); pre-serve exit fails startup. Readiness opens onboarding, then shell/browser. `launcher_onboarding.py` shows the wizard without writing settings; subscription login uses live `/api/*`, neither boot reader takes settings mirrors, and boot-pin changes recycle the server without counting a crash.

**Lifespan & provider gate.** Pre-serve, lifespan admits the data root, applies the settings/UI/runtime-mode baseline, starts the WS heartbeat and opens `store_switch.start` import. Data-, extension- and child-dependent steps run in `server_liveness.start_boot_coordinator` (`server_boot.py`; `server_boot.mcp_startup` makes the server sole MCP lister, pruning then listing in background, §6), ending with store and supervisor publication. Once serving, `/api/health` answers 200 from memory with `boot` (`gateway/health_contracts.py`: `phase` starting → serving → ready | failed, `dialogue_ready`, `tasks_ready`, steps, jobs as `/api/state` read them): fail-soft steps (failed extension) report failed and continue, while an unpublished store or failed supervisor init fails `phase`. `store_switch.when_ready` opens dialogue before repairs: provider-ready `server._open_dialogue` publishes bridge/bus so owner turns persist before `tasks_ready` (supervisor recovery and pooled admission, `supervisor_ready`); before the bridge, `initialization_notice` refuses a frame without saving it, and history reads separately (§3). Workers require `has_startup_ready_provider()`, the store and `_extensions_ready` (after bus subscriptions so tick 1 sees Telegram). `has_startup_ready_provider()` (`server_runtime.py`) accepts nonempty recognized remote config or active task-capable local routing without probing network, credentials, entitlement, model or process (`LOCAL_MODEL_SOURCE` alone fails; `USE_LOCAL_HEAVY` is migration input only); false finishes workerless with the blocking onboarding overlay until a passing settings save hot-starts the supervisor. Without a provider, the ordinary slot drains owed dialogue, rechecks registry recovery and retries contention; clean roots import nothing. Colab and `--start` wait on `boot.dialogue_ready` while the server lives, ending on `phase: failed`, never a clock.

**Store switch & reconcile.** `store_switch.start` resumes pending switches (restarting if switched), else runs `prepare_startup_state(initialize_journal=True)`: on a clean, published store, one read transaction plus child journal headers with no history reads ([USAGE_STORE](../USAGE_STORE.md) §1, `store_switch.py`). NULL flags (`store_import._flags_need_derivation`, reading affected tasks to write derived columns), missing or old schema, or changed mounts trigger preparation, `job:current_store_import` resumes children, stamped absence is `StoreLost`, child writes import while reads never do, and `body_sha` grants no journal authority. Fresh stores commit schema, headers and seeds once before rename (`store.connect` keeps FULL/journal policy); until publication, writes and task/history return 503 `migrating` (700 ms retries) while readiness/recovery wait, and failures keep import open. After owner binding, `startup_notice` reports switches once (`switch_progress.json.reported`); timings log to `supervisor.jsonl`, and seal audits/packing share `finish_maintenance_job`. Absent both state copies, `state_initialization.supervisor_evidence` counts `state/dialog.sqlite` chat rows (pre-cutover: nonempty legacy chat file by stat) as history (unknown mints nothing and creates no store/import). Before `_bootstrap_supervisor_repo` overwrites `state/state.json.current_sha`, `_run_supervisor` waits in `require_published`; boot compares that SHA with `meta.last_store_body.sha`, and a changed, missing or unreadable one queues `legacy_reconcile` once per newly observed stamp (an unchanging one reconciles once) (`store_import.run_legacy_reconcile`, maintenance-only; [PERSISTENCE](../PERSISTENCE.md)). Cancel/question work is generation-gated: only unique stable publication evidence binds a question (ask-time routing proves nothing; others stay `question:` unknowns), unstable history gets one maintenance retry then explicit rebuild, and maintenance also classifies old-body asks.

### Install-time agent presets

### Provider defaulting

Absent Main, Light or Fallbacks slots (unsaved and unset in env, excluding our echo: §7) propose per read (`server_runtime.provider_slot_proposals`): sole direct provider's ids (§7 Direct-provider routes), blank Light/Fallbacks when local-only or multi-direct without OpenRouter/compatible (unless that lane alone runs local), else shipped defaults; unset Main under multi-direct/compatible without OpenRouter keeps the shipped id (wizard proposes blanks). Saved values (former default, blank, unreachable route) beat env: Main/Light/Fallbacks may respell onto a sole built-in key; Vision/Consciousness stay exact; blank Main runs via `model_slots._main_model`. Only Settings edits, wizard and Colab author absent slots or automatic catalogs (`unedited_unauthored_slots`, `repropose_unedited_catalog`); wait cards author only their slot.

### Packaged seed and managed checkout

The immutable seed (§8) is never rebuilt or relabelled. Android and container hosts keep `VERSION`, bundle and manifest; validation (`launcher_bootstrap.py`) checks manifest fields (`schema_version`, `source_sha`, `bundle_sha256`, `managed_remote_branch`, `app_version` against the launcher version, and `release_tag` against `v<app_version>` when non-empty) and hashes the bundle file against `manifest["bundle_sha256"]`, while Git proves source and HEAD. `ensure_managed_repo()` clones temporarily, verifies SHA, sets branches/remotes and moves to `repo/`, preserving tips/owner edits (changed manifests refresh metadata/`managed` only). Restart fetches nothing; unmanaged, it keeps the checkout or refuses before stop. `supervisor/git_ops.checkout_and_reset` applies approved official SHAs.

`launcher_bootstrap.exec_source_launcher` adopts changed helpers at cold start, exit 42 or `/app`: probes imports first (`MACOS_SOURCE_ENTRY_PROTOCOL`, signed macOS entry keeping identity/profile/venv, warm desktop exec on main thread when no window is full-screen via `launcher_window_chrome`), uses plain Python for body/venv/probes (other successors drop `--runtime-venv`), fences teardown/exec/spawn under Stop (icon removed before unlock; refusal keeps shell, retaking lock unless stopping; a released lock is never re-released; no post-spawn fallback), and runs working files selected by commits. Plain-Python Windows/Linux window identity is unqualified, and cold adoption needs a corrected archive (Update cannot patch old executables or add macOS entries). Pre-import Windows repair respawns legacy GUI handoffs hidden (matching PyInstaller archive/GUI PE, seed, sole visible classic console, one-use entry marker; Windows Terminal/ConPTY unqualified; old CRT quoting can fail on spaced paths before repair, needing the corrected archive).

Bootstrap creates an absent world profile and `verify_system_state` refreshes its measured block (§6). Built-ins (`skill_builtin.py`): fresh installs get selected platform-eligible starters (computer use, `ui_design`); upgrades offer each default-on built-in once, respecting Off and removal. Startup re-seeds unmodified marker-owned copies on manifest-version changes (bundled changes bump that version), keeping enablement; grants carry only from a proven prior built-in release with unchanged requests, while edited copies await owner choice. Dropped unchanged copies uninstall after clean re-seed (grants kept) and edited ones become the owner's; an enabled Unix copy without an `os` limit keeps `legacy_remote_platform=win32` remote eligibility (not recorded launcher auto-ON; §13). Off-boot, receipt or not, the server (never the frozen launcher) readies admitted skills on or requested on, packageless ones too (extensions reload only; failures retry next boot). `state/native_seed.json` records the reconciled committed `skills` tree (clean match: 1 receipt read + 2 Git queries; changed/unknown invalidates before reconcile, successful source phases restore it; package/turn-on work never holds it). Post-exit-42 launchers refresh metadata/deps: a failed install gets one visible retry (`launcher.py`), then logs under the crash fuse so pip errors cannot hide behind ImportError; offline checkouts holding requirements still restart.

### Rescue and dependency sync

Bootstrap rescue (`supervisor.git_ops`, §10 invariant 9, `git_ops_rescue.py`) writes a merge-aware directory before reset/clean: porcelain status, raw-byte `changes.diff` keeping merge resolutions a stash cannot capture, a stash-created rescue ref when possible, copied `untracked/` files, unpushed-commit evidence, and `rescue_meta.json` recording the untracked copy's completeness; an incomplete snapshot blocks `rescue_and_reset`, never licensing loss of what it missed, and normal managed bootstrap cleans to the local branch's own HEAD, not `managed/<branch>`.

All destructive update rollbacks use `rollback_managed_update`; it and boot re-materialization rescue afresh first because the pre-update copy lacks the resolver's work (failed rescue disclosed, never blocking; unreadable status = dirty; `rollback_rescue` avoids duplicate snapshots on retry; rescue stays outside Evolution; re-materialization re-creates a dirty tree without rescued edits). Verified-present rollback targets skip destructive Git; only stash restore awaits a held lock. A proved pre-tree Replace refusal abandons only its matching transaction on the pinned checkout (local files, rescue and keep refs stay); later effects keep recovery. Restore's first reset refused at the index lock returns unrestarted; others stay fenced. Only store switch moves to a store-less target. Managed bootstrap reports failures/fallbacks (`server_restart._noticed_bootstrap`), passing the store-switch owner and never booting an incompatible recovery point. A landed update keeps its identity/smoke authority despite a failed redundant checkout; adoption needs a successful bootstrap.

Active Evolution/managed merges use `rescue_and_block` (keeping tree, pausing Evolution); else startup uses `rescue_and_reset`. Dependency sync runs pip only on requirements/interpreter/target-fingerprint changes; clean import smoke writes `state/git_bootstrap.json` (`git_ops_reset._bootstrap_snapshot`) so exact matches skip checkout/reset and smoke (invalidated by dirt, unknown state, tx markers, body adoption, Evolution or checkout/rollback writers). Source/local-dev skips reset while sharing sync and receipt (`OUROBOROS_PYTEST_ACTIVE=1` suppresses sync only; deployment policy skips checkout, reset and fallback: DEPLOYMENT). `ensure_repo_present` repairs detached HEAD only on clean non-managed source entry on a known remote dev line; Git/adoption/Evolution transitions and unknown checks refuse it (one prepared `update-ref --stdin` transaction with `symref-update` creates the branch and attaches HEAD, its native ref locks protecting a final detached-form check because an oid condition alone accepts another named HEAD at the same commit; else manual non-forcing `git switch`; files/index untouched, success logged, never triggers fallback/rollback). Destructive bootstrap needs the launcher marker plus matching `OUROBOROS_MANAGED_REPO_DIR` or managed metadata (else local-dev); `runtime_environ`, `ProcessContainer.spawn` and server re-exec scrub both variables.

### Interpreters

`server.py` sets `OUROBOROS_AGENT_PYTHON` on entry before workers or reviews start; hermetic preflight uses it (then `sys.executable`, `python3`) so tests run with Ouroboros's dependencies. User process tools use `ouroboros/process_interpreters.py` (rule: DEVELOPMENT "Mutation Attribution Rule"): unversioned `python`/`python3` resolves once before deterministic guards (so guard and handler see one argv), bare `node` after dispatch gates (because its health probe executes the candidate). Nothing installs. Only Python pre-blocks; if no usable Node is found, the original argv runs.

### Body switch at entry

Every entry runs the stdlib hook atop `ouroboros/__init__.py` (one failed `open` without a Git-dir pointer). Armed adoption (authorization, arming: §6 Own-body candidates) runs `state/body_adoption/` (`body_switch.py`: atomic file replacement → index → branch CAS; interrupted switches resume by content) and relaunches (exit 42 under a launcher, else exec after dep sync). Bytes matching neither side are never overwritten (aborts onto coherent old tree); moved HEAD or unusable helpers exit 3 (never importing a mixed tree); under a deployment policy none runs: an armed adoption is abandoned untouched (`managed_by_deployment`, pointer removed) and an interrupted or unreadable one exits 3; failed dep sync returns files while packages may stay changed. The managed boot after a switch, or a returned or still-open transition of this checkout (`holds_checkout`), skips reset/clean; handoff obeys the seed contract; macOS Frameworks symlinks mean helpers count by named or resolved repo path; `--seed-bundle` carries the bundle into reconciliation.
