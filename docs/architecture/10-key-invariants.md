# 10. Key Invariants

Numbered rules identify cross-cutting owners; the continuity map separates exact sources, working views and authority.

1. **Constitution and identity persist.** `BIBLE.md` is never deleted; `identity.md` stays a physical file while its content evolves.
2. **Release metadata has one projection.** `VERSION` is canonical; `ouroboros/tools/release_sync.py::version_carrier_desyncs()` and `sync_release_metadata()` project it into every carrier the Release Invariant names (BIBLE) plus both root entries of `web/package-lock.json`; changelog prose stays deliberate. A pull request into `ouroboros` leaves the carriers byte-identical to its target; integration assigns the release version.
3. **Configuration and messaging have single owners.** `ouroboros/config.py` is the one import surface for paths and settings; the vocabularies live in its leaves `settings_defaults` (keys, shipped defaults, the dropped-key lists), `settings_scales` (clamps), `model_slots` (slot resolution), `review_model_routes` (reviewer lists), `runtime_limits` (numeric knobs) and `settings_integrity` (the verified read), so a new key belongs to a leaf, never to the facade (§7). Messages go through `supervisor/message_bus.py`; concurrent state transitions use the owning file lock.
4. **The usage store is the record of spend.** `state/usage.sqlite` owns current attempts and their summaries; state, task, event and UI amounts are projections carrying attempt identity. Owner: `ouroboros/usage_store.py`.
5. **Packaged bootstrap is manifest-bound.** A packaged install verifies `repo.bundle` and its manifest once, then runs the managed checkout; Restart preserves the local tip, and only an explicit update applies an approved exact SHA.
6. **Shutdown stops what it owns, once, within the grace** (§9). A close or restart stops the executor and task-started processes in the ownership set (`state/owned_processes.json`) and spares the installation daemon, whose lifecycle owner ends it only for manual Restart, a new engine pin or Panic, by confirmed ledger identity; the first door starts the grace and stamps every pending stop, a signal needs a measured identity, and the next start retries the recorded rest before admitting work. No agent code may delay Panic. Owner: `ouroboros/owned_shutdown.py`.
7. **This book is the present-tense map.** A structural change updates the owning chapter in the same commit as the code; release chronology lives in git and README (DEVELOPMENT "Documentation contract").
8. **Skill gates do not collapse.** Discovery, deterministic preflight, content-hash-bound critic or qualified Advisory author authority, owner grants, dependency readiness, enablement and execution stay separate: a PASS installs no dependencies, and `enabled=true` proves no executable readiness.
9. **Startup rescue has one mutation owner.** Supervisor recovery writes rescue evidence before a reset, or blocks while preserving the tree; worker and agent construction stay warning-only and never stage or commit inherited dirt.
10. **Current facts are stored, not re-derived.** Money (admission, sends, displays), the terminal-maintenance duty, boot recovery and the exit stop read addressed current facts and outstanding obligations written by the owning transitions, never a fold over unrelated completed history; the remaining history-walking paths are tracked (issue #1528) and new code adds none. Retained evidence serves cognition, audits and repair, not bookkeeping. A current fact in doubt is recomputed by an explicit rebuild job outside the dialogue's process; only its dependents wait, and a display reports it as unavailable. Owners: `ouroboros/usage_store.py`, `ouroboros/obligations.py`, `ouroboros/owned_shutdown.py`.
11. **UI resources carry a disposer.** Every subscription, listener, observer, timer, stream and live page instance has explicit teardown; navigation leaves no hidden instance mutating visible or durable state.
12. **Frozen contracts extend explicitly.** `ouroboros/contracts/` is a versioned, backward-compatible ABI of typed shapes with their parsing, normalization and policy helpers (§11); new capability extends the frozen shape or ships a versioned successor, and existing consumers keep working.
13. **Provider wire adaptation stays exact-route and success-confirmed.** Canonical history stays provider-neutral; a typed physical projection may change values, fields or a registered dialect on one provider/endpoint/API/model only. Failed candidates teach nothing durable, task-local degradation never becomes dispatch authority, and the physical-attempt ledger stays distinct from terminal request-wire history.
14. **Cancellation is intent-then-custody.** Intent never rides the canonical task status, and no teardown begins before the durable, watchdog-replayable intent row exists; the settle owner takes an exclusive claim before any custody mutation; a settled result does not prove a dead worker, so live ownership gates a settled-target cancel; natural completion wins a late cancel and the stored terminal row survives byte-identical, because the kill is about the process, never the result; the deliverable is registered as owed before the intent settles; a cascade acts on lineage roots. Flow: §5. Owners: `supervisor/task_lifecycle.py`, `ouroboros/cancel_intents.py`, `supervisor/cancel_publication.py`, `supervisor/terminal_delivery.py`.
15. **Cancellation registry corruption stays visible.** In `state/cancel_intents.json` and `state/terminal_deliveries.json` an absent file reads as empty; a malformed file or row is disclosed and its bytes kept, and no mutation rebuilds an existing malformed store from a `{}` collapse.
16. **Verification receipts reconcile by one typed identity key.** Sameness is equality of the single (kind, value) key, never a match across kinds, so reconciliation fails safe toward fewer reconciliations; disclosed parts are never the comparison (`_outcome_receipts.py`).
17. **Review spend has one ceiling.** Every paid review gate shares `OUROBOROS_REVIEW_MAX_CYCLES` (SSOT `review_cycles.py`; per-gate meanings: §6 Review stack). The ceiling never removes the last author reaction; a blocking correction or stop grants no approval.
18. **A typed permanent engine refusal discharges a custody duty once.** Durably, under the engine's own code, never retried on a timer and never recorded as a deletion. A non-review registration stays while its owner line is live or reserved or its root offers Continue; unknown authority keeps it, and settlement alone grants no retirement. Owners: `delegate_custody._retire_project_locked`, `delegate_continuation.still_continuable`.
19. **An interrupted parent leaves no orphan.** A child whose parent was interrupted is cancelled with the parent's cause through any door, pooled or direct: `kill_workers(preserve_pending=True)` on the planned path, `pending_parent_interrupted` at snapshot restore. Owners: `supervisor/workers.py`, `supervisor/queue_snapshot.py`.
20. **A stalled loop says where it went silent.** `supervisor_loop_stall` names the tick phase and the lag facts, `supervisor_loop_stall_end` closes every alerted stall with stack samples, and `host_duty_stall` is its off-loop twin. The loop publishes, the watchdog only reads, and the owner's chat stays silent: the journal is the record.
21. **Source acknowledgement is a pre-check over known facts.** The queue's compare-and-seal stays the single fail-closed authority; an unknown queue state is disclosed, never read as a change, and every refusal carries its typed cause in the durable row `acceptance_source_ack` (owner `ouroboros/loop_messages.py`).
22. **A host-owed round never parks.** A turn parks behind a review panel only when the panel is the sole thing it waits for; a turn in which the host has just spoken to the model never parks (`loop._finalize_loop_candidate`).
23. **Every call has a bound, and a recorder speaks only for what it collected.** A reviewer's tool call runs under the loop's per-tool timeout narrowed by the inherited dispatch deadline; a call that outlives it is abandoned and its late value sources no receipt; a deadline recorder reconciles the turn's own panel at $0 before writing a terminal reason. Owners: `review_native_episode.py`, `loop_tool_execution.py`, `acceptance_settlement.py`.
24. **The thread that answers workers runs only queue-bounded work.** Work that scales with history, the daemon or the network runs off-thread, reads candidates before liveness, stops mutating when its loop generation ends and is attach-only to the daemon once a stop is in flight; the terminal-maintenance duty selects from the open sets (open attempts, dirty owners, obligations, live owners) and re-proves no unrelated completed history. Owner: `ouroboros/server_maintenance.py`.
25. **An answer that has not arrived is a gap, never a refusal, a failure, a verdict or an owner message.** A direct turn fences in-process, admission lock before `_queue_lock`, never the reverse; a pooled request is acknowledged per request. A fence that did not answer buys no model round: the panel advises on `admission_fence_available=false`, delivery seals again, and a blocking install accepts a reviewer-approved answer with the typed note `admission_close_unconfirmed`; only `sealed` is a seal, an absent row is not one (§6 Task lifecycle). Owners: `ouroboros/agent.py`, `supervisor/queue_transitions.py`, `ouroboros/loop_delivery.py`.
27. **The predecessor list is a hint; the door is a predicate on the result.** Any actor holding a routing verb continues any settled, readable result, whichever project or helper it came from (a live root is `steer_task`, not a second root; a pending promote is not a result); the predecessor's origin is disclosed in the receipt, never an admission condition; the successor's ceiling, origin and contract come from its caller and admission; only a root stamps the pointer and only roots are offered. An emitted promote is durably `promotion_admission{status:"emitted"}`: pending, granting no schedule, owning no id, never `unknown`. Owners: `tools/control_routing.py`, `tools/control_events.py`.
28. **A display never waits on money, and paid admission never waits on history.** Paid dispatch compares known spend with the applicable limits and discloses in-flight, late overshoot and estimates separately; unknown cost is shown as unknown, never zero, and never by itself refuses work; displays read the same addressed records, never run the history import, and report unavailable data as unavailable. Owners: `ouroboros/usage_accounting.py`, `ouroboros/usage_store.py`.
29. **English at the source, translation at render.** Every owner-visible string is authored in English; no language is enumerated in code and no dictionary ships in the repository. A non-English install paints from its own translation memory (`state/i18n/<tag>.json`, generated by the light model or imported) at the surface, while durable rows keep the English and their typed codes; model text and owner-supplied names are never translated, and a string the memory lacks stays English (`i18n_memory.py`, `ui_translation.py`).
30. **A review subject is frozen once, read everywhere, and governed by the installed body.** What a wave reviews is a `FrozenSubject`, never the live index of whatever repository the process runs in; rules, checklist and navigation come from the system repository, reviewers read the subject's own root or its isolated checkout, and every identity derives from the frozen subject, so the same head with a different base is a different subject (§6 Subject operation, `tools/review_subject.py`).
31. **Saved work continues; it never repeats, outlives a Stop or orphans a child.** One rolling working state per attempt has one writer and recovery freezes its exact bytes; a call without a recorded result stays UNKNOWN and is never re-executed, and an owed or delivered answer is never answered again. Only a fresh acknowledged restart transaction returns work by itself; Quit, a crash and Panic hold it for Resume, and Stop, earlier holds and invariant 19 stand. Under owner Pause only an attempt armed at its actual handoff may finish, and a local owner is ended only on positive proof, never `ps lstart` (`working_checkpoint.py`, `restart_retention.py`, `local_custody_repair.py`).

### 10.1 Continuity data-flow map

A bounded view is an interface projection, never a new authority: the actor that decides must be able to resolve the named source through an existing reader, or the view is partial and the consumer stays non-final or abstains.

| Surface | Canonical source and owner | Bounded projection | Actor-readable source/ref | Decision and retention rule |
|---|---|---|---|---|
| Owner authority and biography | canonical chat/archives and `memory/chronicle/records.jsonl` | room views and selected common accounts | `memory_read` exact record/revision; chat/archive readers | accounts retain non-exclusive source versions; selection seals nothing, local detail survives, later changes stay explicit; no retelling replaces governing words |
| Shared understanding and knowledge summaries | the `overview` knowledge note (`memory/knowledge/overview.md`) and each note's authored YAML `summary` | the resident `## Shared understanding` section and each active note’s authored summary in the knowledge index | `knowledge_read(topic=..., scope='global')`, `knowledge_list` | a missing overview renders as a visible gap line; active summaries stay resident either way; archived sources remain addressable and explicitly listable (§6 Durable memory and project focus); a body-only rewrite keeps the summary |
| Execution evidence | task results, observability call manifests and blobs, service logs, process-custody records | status cards, terminal rows, bounded tails, compact child summaries | exact artifact, blob and service-log refs carried by the task result or canonical promotion | a projection cannot certify a missing child or source; referenced sources and every task-owned physical call survive child-drive GC |
| Terminal task/project memory | the root terminal result plus the task and project summary producers | Main terminal summaries and the two Project-root lifecycle rows | task-result id, project binding, summary and source refs | a summary is a biography projection, not evidence; summary and reflection consume the same frozen origin, owner and verification inputs; failed, cancelled and degraded outcomes stay retained through their result owner |
| Plan/review authority | exact wave/answer artifacts, predecessor links and immutable author selections (§6 Review ledger record) | whole operative spec and current statuses/obligations; individual notes or grouped historical accounts | observed source versions, membership, lineage and task-source readers | all surviving local accounts cross cold/new packets/Continue; unchanged indexes stay in place; notes change no verdict or paid replay; invalid transfers keep their own bodies |
| Task acceptance (three deliveries) | the full host packet (`review_evidence.build_task_acceptance_evidence`, with its `__provenance__` table), the applied host run retained through task source handles, and the paid-identity wallet ledger | the per-delivery work order (`acceptance_retrieving.acceptance_retrieving_work_order`): api pack, full packet with pointers, or packet without its degradable tail plus a scoped read root | exact `evidence_refs` from the packet's exhibit vocabulary; absolute pointers to the workspace and immutable snapshots; `review_projection.panels[].applied_source_ref` | refs resolve against the full packet only, never the rendered projection; native reads are `host_observed`; one strict wallet claim per panel whatever the deliveries |
| Canonical versus execution roots | the canonical data root owns identity, authority, biography, results and promoted observability; execution drives own tools, workspace, transient trajectory and per-call manifests while a task runs | project, fork and task lenses and status projections | canonical-root resolver, task-result pointers, source handles | a fork is an execution lens, not a second mind; adoption precedes background retention; GC requires referenced sources and all task-owned calls; its inventory recheck cannot prove quiescence of untracked late tool futures; missing bytes stay gaps |

Four rules the map relies on. Acceptance identity is fixed before history-dependent packet budgeting, and changed sources still invalidate it; `tool_trajectory:<corpus-sha>[<source-index>]` addresses original records, not moving-tail positions. Applied reviews and checkpoints are retained write-once (`source_handles/context_checkpoints`) before the compact `write_task_result` projection; `review_projection.publish_acceptance_checkpoint` orders panels under the result lock, and a retention failure is `applied_source_status="unavailable"`. `review_projection.late_notice_receipts` hands the late-notice duty to the existing outbox: custody, not delivery. `terminal_delivery.register_delivery` keeps the first retained receipt, and `basis="send_handler_returned"` proves that the send seam returned, not that a human read the text; Ouroboros judges late evidence on an admissible turn (§6 Task acceptance).
