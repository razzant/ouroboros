# 10. Key Invariants

Numbered rules identify cross-cutting owners; the continuity map separates exact sources, working views and authority.

1. **Constitution and identity persist.** `BIBLE.md` is never deleted; `identity.md` stays a physical file as its content evolves.
2. **Release metadata has one projection.** `VERSION` is canonical. `ouroboros/tools/release_sync.py::VERSION_CARRIER_SPANS` lists its carriers: `pyproject.toml` `[project].version` and `uv.lock` root version (PEP 440), `web/package.json` and both `web/package-lock.json` roots, `web/modules/api_types.js` `GATEWAY_CONTRACT_VERSION`, README badge/latest history row/named downloads, `docs/install` and `site/install` pages, and the ARCHITECTURE header. `version_carrier_desyncs()` checks; `sync_release_metadata()` projects; changelog prose stays deliberate. PRs into `ouroboros` keep carriers byte-identical to target; integration assigns the version.
3. **Configuration and messaging have single owners.** `ouroboros/config.py` is the one import surface for paths and settings; the vocabularies live in its leaves `settings_defaults` (keys, shipped defaults, dropped-key lists), `settings_scales` (clamps), `model_slots` (slot resolution), `review_model_routes` (reviewer lists), `runtime_limits` (numeric knobs) and `settings_integrity` (the verified read), so a new key belongs to a leaf, never to the facade (§7). Messages go through `supervisor/message_bus.py`; task-fact transitions are store transactions (`ouroboros/store.py`; `store_switch.py` owns the boot import and restart exit); other transitions use the owning file lock.
4. **The usage store is the record of spend.** `state/usage.sqlite` owns current attempts and their summaries; state, task, event and UI amounts are projections carrying attempt identity (`ouroboros/usage_store.py`).
5. **Packaged bootstrap is manifest-bound.** A packaged install verifies `repo.bundle` and its manifest once, then runs the managed checkout; Restart preserves the local tip; only an explicit update applies an approved exact SHA.
6. **Shutdown stops what it owns, once, within the grace** (§9). Close/restart stops executors and task-started processes in `state/owned_processes.json`, sparing the installation daemon; its lifecycle owner ends it only for manual Restart, a new pin not below it, or Panic, by confirmed ledger identity. The first door starts grace and stamps pending stops; signals need measured identity; next boot retries recorded obligations before admission. No agent delays Panic; clients never queue or replay it. Owner: `ouroboros/owned_shutdown.py`.
7. **This book is the present-tense map.** A structural change updates the owning chapter in the same commit as the code; release chronology lives in git and README (DEVELOPMENT "Documentation contract").
8. **Skill gates do not collapse.** Discovery, deterministic preflight, content-hash-bound critic or qualified Advisory author authority, owner grants, dependency readiness, enablement and execution stay separate: neither a verdict nor `enabled=true` proves executable readiness.
9. **Startup rescue has one mutation owner.** Supervisor recovery writes rescue evidence before a reset, or blocks while preserving the tree; worker and agent construction only warn, never staging or committing inherited dirt. No `index.lock` is aged out: a refused checkout fails its operation.
10. **Current facts are stored, not re-derived.** Owning transitions publish addressed facts/obligations; history serves cognition/audits/explicit repair, never ordinary authority. Capture coherent reads, then materialize off transaction. One current stop per scope; `current_stop` reads installation → tree → member. Release removes its record; `_resume_selection` retains choice identities, not a cause. Technical refusal, execution evidence and permission stay separate; uncertainty holds only dependent effects, visible even on terminals. Observations stay open only while a live producer can change them; outbox history follows commit. Owners: `store.py`, `usage_store.py`, `store_switch.py`, `obligations.py`, `work_stop.py`, `owned_shutdown.py`.
11. **UI resources carry a disposer.** Every subscription, listener, observer, timer, stream and live page instance has explicit teardown; navigation leaves no hidden instance mutating visible or durable state.
12. **Frozen contracts extend explicitly.** `ouroboros/contracts/` is a versioned, backward-compatible ABI of typed shapes with their parsing, normalization and policy helpers (§11); new capability extends the frozen shape or ships a versioned successor; existing consumers keep working.
13. **Provider wire adaptation stays exact-route and success-confirmed.** Canonical history stays provider-neutral; a typed physical projection may change values, fields or a registered dialect on one provider/endpoint/API/model only. Failed candidates teach nothing durable, task-local degradation never becomes dispatch authority, the physical-attempt ledger stays distinct from terminal request-wire history.
14. **Cancellation is intent-then-custody.** Intent is not canonical status. Custody mutation needs durable watchdog-replayable intent and exclusive claim. Settled results prove no dead worker; live ownership gates their cancel. Natural completion wins late cancel: custody targets the process, never the result; its stored row stays byte-identical. Owe delivery before settling intent; cascades follow lineage roots. Finals show task-addressed open runs, closing receipts and pending non-review invocations; live enqueue precedes annotation, resource release stays synchronous (§5); owners: `supervisor/task_lifecycle.py`, `ouroboros/cancel_intents.py`, `supervisor/cancel_publication.py`, `supervisor/terminal_delivery.py`, `ouroboros/delegate_terminal.py`.
15. **Cancellation registry corruption stays visible.** In `state/cancel_intents.json` and `state/terminal_deliveries.json` an absent file reads as empty; a malformed file or row is disclosed, its bytes kept; no mutation rebuilds an existing malformed store from a `{}` collapse.
16. **Verification receipts reconcile by one typed identity key.** Sameness is equality of the single (kind, value) key, never a match across kinds, so reconciliation fails safe toward fewer reconciliations; disclosed parts never compare (`_outcome_receipts.py`).
17. **Review spend has one ceiling.** Every paid review gate shares `OUROBOROS_REVIEW_MAX_CYCLES` (SSOT `review_cycles.py`; per-gate meanings: §6 Review stack); plan asks stand outside it. The ceiling never removes the last author reaction; a blocking correction or stop grants no approval.
18. **A typed permanent engine refusal discharges a custody duty once.** Durably, under the engine's own code, never retried on a timer and never recorded as a deletion. A non-review registration stays while its owner line is live or reserved or its root offers Continue; unknown authority keeps it; settlement alone grants no retirement. Owners: `delegate_custody._retire_project_locked`, `delegate_continuation.still_continuable`.
19. **An interrupted parent leaves no orphan.** Admitted children follow the parent's cancellation cause through pooled/direct teardown and snapshot restore (`kill_workers`, `pending_parent_interrupted`). Preparation-only requests have their own durable token/phase and typed never-admitted recovery (§5, `recover_interrupted_preparations`); snapshot absence alone proves no non-dispatch. Owners: `supervisor/workers.py`, `supervisor/queue_snapshot.py`, `supervisor/task_admission.py`.
20. **A stalled loop says where it went silent.** `supervisor_loop_stall` names the tick phase and the lag facts, `supervisor_loop_stall_end` closes every alerted stall with stack samples, and `host_duty_stall` is its off-loop twin. The loop publishes, the watchdog only reads, the owner's chat stays silent: the journal is the record.
21. **Source acknowledgement is a pre-check over known facts.** A completion's owner-source acknowledgement (`acceptance_subject.owner_source_sha256`) advances only consumed ingress, never a verdict; the root admission seal's compare-and-seal stays the single fail-closed authority; an unknown queue state is disclosed, never read as a change; every refusal carries its typed cause in `acceptance_source_ack` (owners `loop_messages.py`, `delivery_seal.py`).
22. **A host-owed round never parks.** A turn parks behind a review panel only when the panel is the sole thing it waits for; a turn where the host just spoke to the model never parks (`loop._finalize_loop_candidate`).
23. **Every call has a bound, and a recorder speaks only for what it collected.** A reviewer's tool call runs under the loop's per-tool timeout narrowed by the inherited dispatch deadline; a call that outlives it is abandoned and its late value sources no receipt; a wave whose author no longer waits settles later from its seats' recorded answers at $0, never a re-send. Owners: `review_native_episode.py`, `loop_tool_execution.py`, `review_pause.py`.
24. **The thread that answers workers runs only queue-bounded work.** Network, workspace preparation and history upkeep run off-thread with generation ownership; no durable admission fact is written under `_queue_lock` (the admission lane writes it); closing admission never pretends physical jobs ended. Independent cancel/delivery/notice/usage duties preserve domain claims and receipts; observers do not queue behind heavy collection. Current selection re-proves no unrelated completed history. Stop-time engine access is attach-only. Owners: `server_maintenance.py`, `delegate_collection.py`, `sleep_custody.py`; preparation: §5.
25. **An answer that has not arrived is a gap, never a refusal, a failure, a verdict or an owner message.** The queue's own process fences in-process, admission lock before `_queue_lock`; a pooled attempt is acked per request, proves itself, never publishes once superseded. At the seal only owner mail revises; silence or another refusal buys no round: the seal runs once, at an author stop; an unanswered one delivers with `admission_released=False` and a durable `supervisor_ack_unavailable` row; only `sealed` seals, an absent row never (§6 Result review); Presence frees its row. Owners: `ouroboros/agent.py`, `supervisor/queue_transitions.py`, `ouroboros/loop_delivery.py`.
27. **One request keeps one work identity.** `move_to_project` places the current work; `start_task` creates separate work without predecessor or origin-sibling selection. The complete new-work intent is durable before emission. Boot never replays it: proven unadmitted becomes `not_started` with explicit retry, unknown admission stays held. Technical Continue keeps its own eligibility and custody contract. Owners: `project_placement.py`, `promotion_intent.py`, `tools/control_routing.py`.
28. **A display never waits on money, and paid admission never waits on history.** Paid dispatch compares known spend with the applicable limits and discloses in-flight, late overshoot and estimates separately; unknown cost is shown as unknown, never zero, and never by itself refuses work; displays read the same addressed records, never run the history import, and report unavailable data as such. Owners: `ouroboros/usage_accounting.py`, `ouroboros/usage_store.py`.
29. **English at the source, translation at render.** Every owner-visible string is authored in English; code enumerates no language and the repository ships no dictionary. A non-English install paints from its own translation memory (`state/i18n/<tag>.json`, light-model generated or imported) at the surface, while durable rows keep English and their typed codes; model text and owner-supplied names are never translated; a string the memory lacks stays English (`i18n_memory.py`, `ui_translation.py`).
30. **A review subject is frozen once, read everywhere, and governed by the installed body.** What a wave reviews is a `FrozenSubject`, never the live index of whatever repository the process runs in; rules, checklist and navigation come from the system repository, reviewers read the subject's own root or its isolated checkout, and every identity derives from the frozen subject: the same head with a different base is a different subject (§6 Subject operation, `tools/review_subject.py`).
31. **Saved work continues; it never repeats, outlives Stop or orphans a child.** One writer saves each attempt; recovery freezes bytes. UNKNOWN calls never re-execute; owed/delivered answers are never answered again. Acknowledged Restart returns named work; other application stops require Resume. A crash after consumed Resume with newer working state retries that state, never its old grant. Release removes the stop, not independent stops or Q9 child selection. Under Pause only already-sent reviews finish. Ended local custody needs positive proof, never `ps lstart`. Owners: `working_checkpoint.py`, `restart_retention.py`, `local_custody_repair.py` (invariant 19).

Task control and phase facts (`store_hot_facts.py`) commit with their body, so Stop and the live-activity census read addressed columns, never bodies. Card display facts (`store_task_cards.py`) are one row per task, merged row-only in one acquisition slice, no body or signature write; the census takes the card from the hot row each poll. The census reads one short transaction per store, released before display consumers; its snapshot authorizes no mutation, an unknown read stays unknown, question details keep their body reader.

### 10.1 Continuity data-flow map

A bounded view is an interface projection, never a new authority: the deciding actor must be able to resolve the named source through an existing reader, or the view is partial and the consumer stays non-final or abstains.

| Surface | Canonical source and owner | Bounded projection | Actor-readable source/ref | Decision and retention rule |
|---|---|---|---|---|
| Owner authority and biography | canonical chat/archives and `memory/chronicle/records.jsonl` | room views and selected common accounts | `memory_read` exact record/revision; chat/archive readers | accounts retain non-exclusive source versions; selection seals nothing, local detail survives, later changes stay explicit; no retelling replaces governing words |
| Shared understanding and knowledge summaries | the `overview` knowledge note (`memory/knowledge/overview.md`) and each note's authored YAML `summary` | the resident `## Shared understanding` section and the whole index’s active summaries (outline: every active address/title and people’s summaries) | `knowledge_read(topic=..., scope='global')`, `knowledge_list` | a missing overview renders as a visible gap line; only physical window pressure selects the outline; archives stay addressable/listable (§6 Durable memory and project focus); body-only edits keep summaries |
| Execution evidence | task results, delegated message frames, observability call manifests and blobs, service logs, process-custody records | status cards, terminal rows, bounded tails, compact child summaries | exact artifact, blob and service-log refs carried by the task result or canonical promotion | a projection cannot certify a missing child or source; referenced sources and task-owned physical calls outlive child-drive GC |
| Terminal task/project memory | the root terminal result plus the task and project summary producers | Main terminal summaries and the two Project-root lifecycle rows | task-result id, project binding, summary and source refs | a summary is a biography projection, not evidence; the result review reads the frozen origin, owner words and verification receipts; failed, cancelled and degraded outcomes stay with their result owner |
| Plan/review authority | exact wave/answer artifacts, predecessor links and immutable author selections (§6 Review ledger record) | whole operative spec and current statuses/obligations; individual notes or grouped historical accounts | observed source versions, membership, lineage and task-source readers | surviving local accounts cross cold/new packets/Continue; unchanged indexes stay; notes change no verdict or paid replay; invalid transfers keep their bodies |
| Result review | the retained subject text (`result-subject-<sha16>` in the task's artifact store: the ask, the reply, produced files by path and content hash, verification receipts) and the wave's ledger record (`surface="result"`) | the record's compact projection on the task card and in `## Review records`; the findings shown to the mind before delivery | the retained subject and the produced files at their absolute paths, read in place by retrieving seats and inline by packet seats; the record's `source_ref` | the subject is frozen at the call: bytes not matching a named hash record a gap; the same subject sha reuses the settled record at $0; a changed answer or material supersedes the binding |
| Canonical versus execution roots | canonical root: identity, authority, biography, results, promoted observability; execution drives: tools, workspace, trajectory, call manifests | project/fork/task lenses | `install_identity`, task pointers, source handles | stored paths never authorize another install; copies mint an identity, foreign tasks await explicit move; forks remain execution lenses; adoption precedes retention, which verifies `task_source` without rewriting carriers; GC cannot prove untracked late futures quiescent; missing bytes stay gaps |

Four rules the map relies on. A review subject's identity is fixed before any budgeting of what a seat reads; changed sources invalidate it; `tool_trajectory:<corpus-sha>[<source-index>]` addresses original records, never moving-tail positions. Review records and checkpoints are retained write-once (`state/review_ledger`, `source_handles/context_checkpoints`) before the compact `write_task_result` projection; a task-acceptance checkpoint stored before the result review keeps `applied_source_status`. `review_projection.late_notice_receipts` hands a late-notice duty to the existing outbox: custody, not delivery. `terminal_delivery.register_delivery` keeps the first retained receipt; `basis="send_handler_returned"` proves the send seam returned, not a human read; late evidence is judged on an admissible turn (§6 Review stack).
