# 5. Supervisor Loop

`server.py::_run_supervisor()` alone schedules pooled work. Only `state.init_state` creates state on first-boot proof before bridge publication (PERSISTENCE.md); unavailable controls/binding do not block independent work/chat/diagnosis. Each tick publishes liveness, rotates logs, checks workers, drains FIFO worker/direct events, accepts bridge input, flushes a dirty budget projection, checks deadlines/schedules, reconciles/evolution-admits, assigns, snapshots, then ticks the threadless consciousness alarm (sole wake starter). Drain uses `SUPERVISOR_EVENT_BATCH_MAX_EVENTS` and inter-handler `SUPERVISOR_EVENT_BATCH_MAX_SEC` (slow handlers may overrun). Backlog skips idle sleep; bridge input precedes slow work. Three consecutive failures clear readiness, stop the watchdog generation, notify the owner. Shutdown errors are not crashes: `_SignalStopServer.handle_exit` sets the local stop on SIGTERM/SIGINT, repeated first in teardown, so old launchers cannot kill the event Manager early (§9).

The compatibility `state.json` budget projection validates the ledger before `STATE_LOCK`. Provenance `(compaction_epoch, seq)` combines the lock-free leading baseline epoch and validated high-water sequence; compaction increments epoch and renumbers rows, so totals/timestamps cannot order writes. Under the lock, lower epoch or same-epoch lower sequence is stale; equal/higher may write. Older-ledger restores, malformed saved markers or quarantine (`integrity_degraded`) freeze projection until explicit repair. Unavailable provenance retains the prior projection. Lock timeout, unreadable primary or uninitialized state skips the write (never unlocked). Failure leaves it dirty, retried at most every `BUDGET_PROJECTION_RETRY_SEC`. This is display, not admission (invariant 28): only totals persist; per-root money comes from `usage_projection`. After bridge intake, `usage_writer_snapshot` renders totals, marker and OpenRouter comparison once per dirty tick. Startup and 50-call crossings schedule one asynchronous OpenRouter diagnostic; no key starts none. Captured request key, paired ledger/baseline and supervisor generation bind publication; missing baselines stay unknown. Busy crossings are skipped under the diagnostic owner, never changing monetary admission. `/api/state` and the budget line share slim shapes.

`supervisor.queue._queue_lock` (Q) guards live lifecycle authority `PENDING`/`RUNNING`. Before Pause/Hurry, `ensure_control_task_result` create-only seeds an absent pooled result from exact admitted lineage/budget/source, phase and `task_attempt`. Existing/concurrent terminal rows win; bare IDs, blocked admissions, direct actors and billing cannot seed it. Admission reserves identity before project/workspace/attachment/routing effects; refuses disabled pools, duplicates, project deletion, accepted/sealed roots, exhausted root budget or unusable/unprovisionable workspaces (typed repair in `detail`); attaches the contract and preserves stable priority. Assignment skips reaping, budget pauses, closed projects, conflicting writers and exhausted root child capacity/depth. Only evolution has runtime-mode fences (`supervisor/evolution_lifecycle.py`): Light refuses campaign entry; `enqueue_evolution_task_if_needed()` pauses/disables carried campaigns; assignment drops leftovers while `evolution_block_reason()` is set. Generic `enqueue_task()` has no mode predicate. Capacity = assignable idle workers after custody/reaping/admission fences, not configured count.

Headless addressing is fixed at admission (`log_addressing.ingress_chat_id`). A registered Project's explicit `chat_id` must match its thread; another address, including hidden, is refused with a typed 400 rather than honoured, avoiding a Main card detached from its Project work. Without a Project, ordinary API tasks default to `HIDDEN_CHAT_ID` (0). Confirmed browser Publish carries `source="web"` and `WEB_UI_CHAT_ID` to request Main: caller-declared addressing, not authentication. Other non-Project conversation addresses are refused. Work for an active registered Project is admitted into that project's thread. Main gets one host-stamped completion only for work addressed or BOUND there. Registration alone does not qualify: other work stays in the hidden partition, silent in every chat, readable through the terminal, `--result-json-out`, Logs and `GET /api/tasks/<id>`. Reserved inactive Projects keep their chat valid so the queue gives its typed lifecycle refusal.

The run is also NAMED at admission and chat promotion, without a new model call. Authored `title` (`ouroboros run --title` or top-level contract) fills `title`/`suggested_name`; `metadata.title` is refused with a 400, as is `metadata.project_id`. Otherwise the first request line fills only `suggested_name` and never outranks a real name coined later. Admission broadcasts `task_named`, never using status as title.

`queue_snapshot.json` atomically projects pending/running rows, acceptance/root-budget fences, worker counts/capacity, pool-disabled reason and bounded root focus. Restore recent snapshots into empty PENDING; RUNNING survivors get `server_shutdown` cancel intents (`terminalized_running`) for custody settlement and quiz/wait closure. Boot `kill_workers` settles their children as `pending_parent_interrupted`. Acknowledged planned handoffs, exact pauses, owner-Restart holds and accepted Project rows ignore snapshot age (revalidation: §6 Project registry and lease). Restore persists Restart holds before `auto_resume_after_restart` consumes the marker; failure retains it. Scratchpad resumption needs `pending_restart_verify.json`, never log-tail inference.

Fresh admission sets `admitted_dispatch=none`, retry/resume `possible`; restore backfills neither; verified unscoped admission stamps `_project_scope_none`. Under the launch fences (below), `_claim_worker_launch` marks PENDING `possible`, persists `worker_launch_claimed`, reads back monotonic Project/unscoped result `possible` (`task_admission.record_project_dispatch_possible`), writes schedule receipt/row `dispatch=possible` and the RUNNING mirror, then puts; refusal sends nothing, keeps custody and lets the worker try another row. Snapshots never replay a `possible` row; live retries and exact continuations still run.

`_continuation_prepared` rows await publication repair; unresolved restores stay held. Loop pauses restore `_budget_pause`/checkpoint and `_is_direct_chat`; unknown/invalid sources/fences keep `_budget_pause_hold`. Stop/restore: `restart_retention.py` (§9). Restart/lost affordability revoke unused `_budget_pause_resume`. `root_phase_checkpoint` keeps post-task Pause for explicit same-task Resume. Assignment keeps `started_at`/`budget_paused_sec`; children need the current root grant/fence. Before assignment, `sleep_wake.py` observes off-lock, granting via `grant_exact_sleep_resume` unless holds/owner Pause/paused root veto; throttled observation settles requested Pauses. Clocks/grants/custody: [§6](06-agent-core.md#exact-budget-pause-and-resume).

Terminal rows stay terminal; custody cancels accepted/sealed roots' descendants except exact pauses; malformed fences stay closed. Orphan healers read stored status, so a failed RUNNING mirror can escape snapshot-less cleanup; root settlement closes quiz/wait. Focus merges under Q; `direct_roots.json` carries gap/freshness. `task_status` separates lifecycle from `execution_observation`: `execution_owner` binds kind/root/task/attempt on result/mirror, rebound at pooled Resume. Local actors and fresh queue/direct fragments prove activity; gaps stay unknown. Only pooled work admits worker-boot orphan inference (reads and writes); lost Presence stays unknown, never replayed.

`supervisor/queue_schedules.py` alone writes `state/scheduled_tasks.json`. All mutations (tick, skill resync, gateway, followup cap/write, `manage_schedules`) enter `schedule_transaction`: Q then sidecar lock, reentrant per resolved table path. Strict `load_schedule_store` treats only absence as empty; non-regular files, invalid JSON or non-object rows raise `ScheduleStoreUnreadable`. Unreadable tables refuse mutation and read as unknown.

`schedule_occurrence.py` admits one root per due occurrence: claim, typed `hold` (no failed root/counter/message), off-lock preparation via `workers.REPO_DIR`, recheck, enqueue, frozen receipt, snapshot. Under the Q/table transaction a claimed row with absent result and no dispatch mark re-prepares the SAME token/id after restart; enqueue alone cannot execute, restore/dispatch need the receipt. No refusal witnesses. Unreadable/foreign results or receipt-less admissions stay unknown. Edits/disable govern unstarted work. Exact-root receipt reads let deletion drop unaccepted work; owed or unknown work returns `delete_deferred`. Accepted bytes stay frozen. Cron keeps one overdue occurrence then advances; Runtime shows original `due_at`/`claimed_at`. Older admissions never consume later firing points; same-instant text edits cannot re-arm once. Custody same-ID retries survive row retirement/successors; snapshot replay stays fenced. A `kind:"notify"` row is a note, never an occurrence or task: the tick consumes it in its one table write (cron skips past any gap), then `schedule_notes.py` shows the mind's words as one signed `reminder` System row; an unconfirmed show is recorded as the row's `last_error` (Activity and `manage_schedules` show it), never retried.

`followup_policy.py` binds explicit related/independent relationships. Unrecorded rows keep published launch and own-root money (relation unknown; source-less owner rows: independent) until an origin Stop/manual Restart. Host origin and `continuation_of` provenance/cap exemption establish neither relationship nor billing authority. Creation resolves money via `usage_admission` and origin results off-lock; normalized templates cannot forge host facts. Live/frozen/canonical related work keeps original group cap/source/revision and deadline. The ledger checks root/group/global; root cap changes widen neither group nor permission. Own-root initial billing publishes atomically with the receipt.

Stop's `followup_stop` transfers from cancel intent to the original result even when completion wins. `stop_action_id` identifies the ingress action apart from custody `request_id`; exact retry preserves CURRENT control even after another Stop. New actions create controls; altered arguments under one ID refuse. Existing carriers hold receipts; omitted IDs claim no replay. Browser uncertainty reuses the page ID; ACK/reload starts another.

Restart persists restrictions before consuming its marker. Pause gives WAIT; Resume releases neither Stop nor enabled state. Launch fences: final enqueue and worker put take queue → schedule → cancel projection → origin launch locks, then the task's own, with no preparation/provider wait inside. Cancel retirement never takes the schedule lock; Pause releases its launch lock before queue mutation; guards are reentrant per root. Ordinary replay needs a matching never-dispatched receipt; single-use Resume is separate authority.

Restore compares `expected_hold_id` with locked current controls; newer Stop/Restart refuses stale release, discovery persists `hold_not_observed`. Exact Restore stays release-only after the hold disappears: never generic enable or reversal of Disable/Delete. It preserves enabled, consumed receipt, pending ID and unrelated task holds. A resolved already-fired relation binds the SAME task/token through the occurrence owner only on positive never-dispatch authority. Partial persistence stays held; no one-shot rearm or budget reset.

Activity/tools/context/Continue disclose relationship, money/deadline and holds (unpersisted too). Related/unknown work keeps its control/binding row until settlement (unknown retains); deleted rows stay `delete_pending`, without firing, then disappear. Independent Delete is unchanged. Generic Restore cancels deletion; exact hold release does not. Occurrence “settled” may mean possible dispatch. Missing fired binding waits as `pending_binding_unavailable`.

`schedule_mutation` INTENT/OUTCOME share `operation_id`, excluding templates. Intent failure refuses; outcome failure reports `changed_audit_incomplete`, no unaudited rollback. `manage_schedules` and `POST /api/schedules/{id}/action` share this seam: explicit action/reason, no text inference. Restore stays owner/root authority despite Observe argument narrowing. Activity surfaces release refusal as error even when bookkeeping changed; applied/audit-incomplete stays applied.

Lifecycle controls govern FUTURE work and report `running_or_queued`; workers read the durable snapshot, and absent, unreadable or >300 s (even idle) snapshots mean unknown, held in flight by the tick. Skill deletion retains suppression by schedule ID across manifest edits/resync. Restore rechecks presence, declaration, `supervised_task` permission and readiness: blocked means `restored_not_ready`; absent skill/entry means `manifest_absent`, `changed=false`, keeping suppression. Enabled edits contradicting readiness refuse in favour of lifecycle controls. A consumed one-shot needs fresh `run_at` to rearm; timezone edits preserve its instant/receipt. GC ages out receipts; continuations await task settlement.

At execution start, `agent._persist_running_record` mirrors a split root's or subagent's start time, attempt and execution-drive address into its canonical result via the terminal-preserving writer.

Pooled completion separates a finished file-save attempt from publishable terminal truth: the worker prepares its terminal task files (`headless.prepare_terminal_task_files`) before its buffered `task_done`, and `events_task_done` publishes only when `headless.terminal_task_files_ready` confirms CURRENT — on a split drive the child-bound copyback, with no workspace artifact finalization pending. Legacy or faulted completions go through `enqueue_terminal_file_recovery` (`worker_health` prepares and recovers, `task_reaper` runs the queues): unreadable or missing CURRENT keeps RUNNING ownership and retries on the health cadence (never a false Done, never replayed model work), and only CONFIRMED absence of a terminal source reaches the lifecycle-fault owner, which marks execution `infra_failed` while an early sticky completed status, the authored answer, review and cost survive.

A required owner wait keeps the task RUNNING, its worker and browser after a completed-tool checkpoint. Capacity is lent; a capped grant resumes the same attempt/start without replay, consuming continuation authority before dispatch. A new owner-bound wait stamps its own `parked_at` beside, never instead of, the task start; the whole wait row rides every later write, so a planned restart keeps it. Any mail wakes, only an owner answer answers; Stop, deadline and ceiling still bind. A settled Project result is no longer steerable even if post-work holds RUNNING: fast mail and typed steer refuse it and a quiz answer takes the late-answer path (one actor-drive settlement predicate, `owner_mailbox.mailbox_drain_ended`), so cleanup cannot eat unread input. Ordinary Main/Project waits stay in-process (`owner_wait.direct_owner_wait`), lend no pooled slot and resume the live stack/browser on addressed text or quiz; a saved source grants no cold restart.

A crash or automatic timeout retry keeps the current-attempt checkpoint as evidence, never blindly replaying; cold continuation exists only for a confirmed planned restart, which cannot preserve an OS browser session. An owner-requested MANAGED UPDATE is such a restart: its writer fence prepares the handoff before stopping the pool and passes the parked ids as `preserve_running_task_ids`, so a wait is requeued instead of interrupted, and preparation failure blocks the update rather than terminalizing the wait; the re-exec seam arms the transaction only in the phases `_safe_restart_serialized` allows (launcher mode observes exit code 42), no-resume flags suppress it, and an aborted update's leftover record never authorizes a later manual Restart or rollback. A manual ROLLBACK (to an older runtime) deliberately parks nothing. Cold continuation resumes saved economics (the CostCeiling under its re-read authority, `task_pacing.restore_cost_ceiling`: an explicit profile's saved point, a producer allowance at its actual value, a removed default dropped, an unreadable root's number kept as `legacy_policy_unverified`; hard clocks, saved-model ContextFit, TaskModelWait choices, the saved round's pending budget decision); calendar deadlines and owner-wait time stay unchanged.

Cancellation is intent-then-custody; intent and outcome are separate fields, because one field carrying both wedges a task forever. The skeleton:

1. **Intent.** Every cancel ingress (the agent `cancel_task` tool, HTTP single/cascade endpoints, evolution stop, project deletion, cascade-sweep per-descendant mints, boot migration of legacy `cancel_requested` files) writes one durable row via `ouroboros/cancel_intents.request_cancel` into locked `state/cancel_intents.json` (active intents only; every transition also appends a forensic `cancel_intent` supervisor-ledger row). Every ingress fails closed (tool `CANCEL_INTENT_WRITE_FAILED`, HTTP 503, `CANCEL_INTENT_PROJECTION_CORRUPT` for a corrupt projection), so no teardown runs without a durable, watchdog-replayable fence; evolution stop keeps any task whose intent write failed and reports the stop INCOMPLETE with typed per-task outcomes; the campaign stays OPEN under the durable `evolution_owner_stopped` flag, which only an OWNER start ingress clears (the agent's `toggle_evolution` is refused: the owner's stop is sticky).
2. **Scope.** A cascade ingress mints `scope: cascade`; recorded scope is widen-only (single→cascade, never narrowed, so Stop-now cannot shrink a cascade). A cascade over an already-settled root with live descendants still mints the coordination intent (`allow_settled_target`), the watchdog's replay trigger for the subtree. Timeout reaping is deliberately NOT a cancel ingress: the reaper keeps its own custody over the `reaping` slot marker, because cancellation is reserved for explicit intent.
3. **Claim.** `supervisor.task_lifecycle.cancel_task_custody` is the ONE settle owner: it claims the intent (owner + generation) before any custody mutation; a refused claim exits untouched, so racing custodies never double-settle; the pre-assignment pending drop holds the same fence, and a budget-exhausted queued task PAUSES, so there is no batch terminalizer beside custody. A LIVE direct-chat turn is stopped through the same custody (`supervisor/worker_chat_lane.py`): the chat lane writes a typed `finalize_now` control into the owner mailbox once per turn, and the loop ends at its next round boundary with zero further model calls, paid post-task synthesis included. A Stop-now landing after the loop returned, during that synthesis, stays addressable: in-flight synthesis counts as live ownership, custody keeps the immediate intent open, and the synthesis worker checks it before each paid stage, disclosing the skipped ones as `post_task_stop_reason` `owner_stopped:skipped=<stages>` on a `degraded` checkpoint. Custody waits `OUROBOROS_DIRECT_TURN_STOP_WAIT_SEC`; the typed outcome is `gone`/`ended`/`live`, and `live` releases the claim for the sweep never publishing a fabricated `cancelled` row over a running turn.
4. **Kill and re-check.** Custody confirms process death, then re-reads the child's real settled result. Natural completion WINS: a child that finished before the kill keeps its result, artifacts and cost, and the cancel settles as already-settled.
5. **Reconcile and capture.** The task's open delegated runs are reconciled from durable custody rows and always re-audited and disclosed. Workspace artifacts are captured from the real tree; a failed or owed-but-unrunnable capture is `failed`, never `missing`, and a shared-tree capture carries `attribution: shared_unproven`.
6. **Settle.** The settled result carries reconstructed-or-honestly-unknown cost, never a fabricated final `$0`; `parent_decision` is stamped only at this outcome. `cancel_publication._intent_outcome_fields` preserves recorded cancellation provenance as `cancel_origin`: source, scope, reason, `request_id`/`requested_at`, `requested_by` when present, and the typed observation `request_origin`. These facts survive removal of the active intent and travel through the terminal event, task detail, history and result-tool reads, including conditional reads with an unchanged answer body. HTTP proves transport, never a personal owner; absent actor evidence remains absent. `requested_by` still conditions parent-decision semantics.
7. **Owe, then publish.** The owner's terminal answer is registered as OWED in the durable outbox (or a typed no-chat handoff row) BEFORE the intent settles and before `task_done` publishes, so a crash between settle and send replays, not loses, the answer. A cascade delivers one root message with a children digest under the deterministic delivery id `cascade:<root_tid>:<request_id>`, each child's line rebuilt from its current durable status.
8. **Watchdog.** The supervisor tick runs the cancel/delivery/usage sweep off drain (`server_maintenance._run_cancel_delivery_ref_sweep`, ~20 s cadence); `sweep_cancel_intents` re-feeds unclaimed or abandoned-claim intents into custody (a cascade replayed as a cascade), so a lost control event or a custody attempt that died mid-teardown cannot wedge a cancellation. Only the physical no-live check settles a cascade's coordination intent, after the tree's summary is registered as owed.

Readers see typed `cancel_state: "pending"` (with `cancel_reason`) on effective results until settlement; the UI shows "Cancelling…" and restores Cancel only when fetched live non-pending detail proves the intent gone. Steering writes (`steer_task`, mailbox follow-ups, `forward_to_worker`) are refused typed while a cancel is pending (this fence makes the owner-stop single-turn rail safe); queue restore/pre-assignment read the projection under Q, so a cancelled pending task never starts. `task_done` asserts a SETTLED outcome, validated against the DURABLE result per event: a non-settled event status, or a settled/blank status over a non-settled or absent durable row, is a lifecycle fault, left to custody while a cancellation is pending, else published with a typed infrastructure-failure axis preserving an existing sticky terminal status.

`supervisor/terminal_delivery.py` owns terminal sends: bounded pending outbox in `state/terminal_deliveries.json`, owed before enqueue and replayed on boot/tick, with restart-surviving `delivery_id` dedupe shared by natural completion. Eviction/exhaustion emits `terminal_delivery_exhausted`; the notice says send unconfirmed and saved copy of THIS message. Only a cancel receipt proving the same id reached the same chat suppresses the notice; the event remains. Cancel/non-retry reap sends lineage-routed UNREVIEWED salvage with bounded preview, exact omitted count and full-copy receipt; cascades send once per root, retryable reap sends nothing. Settled/miss paths retain the kill path's delegated-run audit. Agent cancellation adds no narration beyond terminal rows/tool result, except failed settlement's `cancellation_fault` incident. §10 owns custody, completion-wins, owed-before-published and emitted-byte receipt invariants.

Stop POLICY is an axis on the same durable intent, independent of cascade scope. Omitted/empty-body cancellation is synchronous IMMEDIATE teardown, keeping programmatic callers' bounded budgets. `stop_policy=finalize_then_cancel` answers 202 with the intent OPEN and runs one bounded owner-stop finalization episode (`supervisor/owner_stop.py`): live descendants settle first and feed a bounded child-result projection into the root's final turn; the root gets a `finalize_now` control whose typed first line (`owner_requested_finalization`) routes to its own loop rail: zero or one tool-less model turn, terminalizing completed/best-effort under the honest owner reason, not a false deadline. Grace starts at durable `control_drained_at` (first drain wins, so a task inside a long tool call still gets its final turn when hard bounds allow) under the request-anchored `OWNER_STOP_OUTER_CAP_SEC` cap; a held task bypasses only generic idle/finalization-grace rails (explicit deadline and absolute ceiling stay independent, never widened), and expiry, a hard-bound hit, a pending root or an already-settled root feeds ordinary custody. Transitions are monotonic: immediate HARDENS a pending graceful intent (keeping cascade scope); graceful never softens accepted immediate. A successful graceful root suppresses the redundant cascade summary; Panic bypasses both. The UI projects the soft stop via `cancel_state`+`stop_policy` ("Finalizing…").

Beside stopping sits the owner "hurry" control: a typed task-local `kind=hurry` owner-mailbox control (`ouroboros/owner_hurry.py`, `gateway/task_hurry.py`) that skips the next otherwise-eligible acceptance panel with a typed reason, zeroes remaining improvement passes, and makes force-plan projection task-locally advisory (never a chat message, settings mutation or P3/commit/review-gate weakening). Its effect is attempt-scoped (`task["_attempt"]`): a shared `retry_reset` strips it on every same-id requeue. These invariants hold for every install configuration class.

The event bus is process-lifetime, not worker-generation-lifetime: respawns reuse one manager-backed queue shared by workers and direct chat, since a force-killed producer can corrupt a raw multiprocessing feeder frame and a queue rebuilt on pool rotation strands surviving producers on the old endpoint. Live-frame publication of persisted rows is exactly-once and process-symmetric: `ouroboros/utils.py::append_jsonl` streams only runtime `logs/*.jsonl` rows into the process log sink (never `chat.jsonl` or state/memory/receipt stores), and each process suppresses the types whose live delivery has a dedicated owner (`WORKER_LOG_SINK_SUPPRESSED_TYPES`, the server superset `SERVER_LOG_SINK_SUPPRESSED_TYPES`). One persisted event yields exactly one live frame (`tests/test_log_forwarding.py`); an LLM call failure is one durable `llm_api_error` row only.

Heartbeat and progress differ: a heartbeat proves a process/loop alive; owner-visible progress and model-usage events prove the task advanced. Progress keeps an orchestrator alive, but deadline, Stop and budget stay hard. The absolute ceiling ends solve/owner-stop finalization, not settled post-work; Stop, deadline, money and per-call bounds still apply (§6). After the typed finalization episode, timeout handling freezes its decision under Q, marks the worker `reaping`, and hands kill, join, salvage, retry and respawn to the single off-loop reaper; an orchestrator with live descendants is never blindly retried (a retry would replay its plan, spawning a competing tree). No retry or assignment may occupy a timed-out slot until the original process is provably dead: if kill and join cannot establish death, the reaper keeps a low-rank RUNNING result and the `reaping` slot, emits a visible `task_reaper_wedged` receipt and restart hint, and writes no terminal, `task_done`, retry or respawn: one slot is sacrificed rather than letting a live process race a replacement; the next supervisor generation reconciles the record after old-generation custody. Typed timeout codes (`queue_timeouts.TIMEOUT_TERMINAL_REASONS`) keep their `task_incident` identity; owner-facing grace/kill/salvage text uses `project_dialogue.TASK_CAUSE_PHRASES`, unknown codes raw.

Slots stay unassignable until their child’s PID-bound `worker_ready` (`supervisor/worker_pool_lifecycle.py`). `worker_sha_verify.ok` is equality; ancestry is diagnostic. Descendants stay in Logs; non-descendants/unavailable applicable checks warn Main; no baseline stays skipped. Neither attests loaded code or review. A live child’s `worker_starting` before extensions/agent construction permits one extension from `WORKER_READY_WINDOW_SEC` to `WORKER_READY_CEILING_SEC` (300 s from birth; `runtime_limits.py`), logged as `worker_ready_window_extended`. Foreign/pre-spawn rows cannot extend it; silence keeps its window. Logging failure cannot block startup. After `WORKER_READY_MAX_ATTEMPTS`, `Worker.readiness_exhausted` is final per slot: late events and new tasks cannot clear it. Total exhaustion, distinct from busy/booting/reaping capacity and live owner-wait stacks, closes pooled ingress (owner `/review` included), not direct chat/control or boot/update recovery. After RUNNING custody settles, `disable_exhausted_worker_pool` fails unstarted PENDING with a Restart hint. Readiness is not liveness or task idle time. Watcher errors release only booting, non-exhausted slots to crash detection (`worker_ready_released`). Linux uses forkserver; macOS/Windows use spawn.

`worker_health.recover_confirmed_dead_worker` reserves exact custody under Q, then enqueues reaper `confirmed_dead_worker`. Saved terminal bytes win even after signal death; unknown/incomplete publication retains `TerminalFileRecoveryPending`. Only confirmed absence reaches crash policy: signal means infrastructure failure; eligible non-signal crashes retry within `QUEUE_MAX_RETRIES`, preserving cost and owner-wait restrictions. Budget continuation forbids ordinary retry; unconsumed grants re-park, consumed grants remain terminal, and failed revocation retains source/grant with honest persistence status (§6).

Crash storms suppress respawn while terminal sources settle, then fence pooled admission; direct chat remains. Startup recovers addressed `pending_drives`, `nonterminal` and `synthesis` obligations after process custody, on provider, no-provider and init-failure doors. Live/unknown ownership preserves sources. File recovery adopts saved answers before orphan healing; pending ref retention remains off-loop. The legacy scheduled-child rebind requires a positive child start and existing orphan proof. Ordinary startup enumerates neither completed results nor drives. Bulk prunes leave readiness. Addressed recovery links exclude protected trees; unreadable members/coarse gaps keep pruning owed. Mailbox/service cleanup retries gaps, independent of running tasks.

Startup and throttled maintenance reconcile three residue classes; the ~600 s custody and ~300 s reconcile passes each run off the loop thread on their own latch (§10). Process custody checks strict PID, start-time, command, owner-task, session and generation evidence before reaping. Delegated-run reconciliation applies the same owner-gone reasoning to harness rows (§6 Delegated subagents). Task, review and project reconciliation repair producer-less records; task reconciliation decides and persists on a status-only read, fenced by the row's attempt basis and queue ownership, settles quiz/owner-wait only for the row it heals, then the drive-custody pass (child-ref retry, then bounded drive settlements under the queue interlock; startup copies no child store); the pass stamps its cadence when it ends; the generation fences each item, commit and write (`task_custody.publication_fence`). None are command-line-class kill sweeps; one instance never reaps another. The dedicated watchdog, started at startup, separately observes phase-stamped loop liveness (a stall row carries the loop thread's bounded stack) and every native actor; a wedged chat turn alerts with a `/restart` hint, a loop stall only journals; neither kills a thread. Other owner conversations run on independent native actors without a second scheduler.

Cooperative project checkpointing has two equivalent quiescence triggers: a host-minted genesis or cooperative tree is checked when its root settles with no live descendants, and again when the last child settles beneath an already-terminal root — a root-scope budget stop terminalizes the root before its children, so a root-only trigger would see a live tree once and never return. The bounded git chain runs on a daemon thread, revalidates quiescence under Q immediately before mutation, and replays a trigger that arrives during an in-flight check. Only host-minted project roots are eligible: owner-attached folders are never auto-committed, credential-shaped files stay excluded and disclosed, and every material success, skip or error receives a durable receipt.

Bridge intake is batched: `LocalChatBridge.get_updates` blocks only for the first item, then drains a bounded ready snapshot. Each update keeps a monotonic id and own reply transport (`activate_update_transport`); malformed items are logged and skipped singly.
