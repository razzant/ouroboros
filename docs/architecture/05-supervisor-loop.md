# 5. Supervisor Loop

`server.py::_run_supervisor()` owns the pooled scheduling tick and lifecycle lock. Cancellation intent precedes teardown. Its admission, waits, controls and maintenance keep intent, outcome and money separate; unknown is not zero or absence.

### Tick and locks

`state.init_state` alone creates state on first-boot proof, before bridge publication (PERSISTENCE.md). Each tick publishes liveness, rotates logs, checks workers, drains bounded control before telemetry, which never delays an answer (`runtime_limits.py`; `event_taxonomy.EventDisposition.lane`), takes bridge input (a backlog skips its wait and idle sleep, not intake), projects money, enforces deadlines, runs maintenance, admits/assigns, snapshots, publishes direct roots, ticks consciousness and writes a busy minute's `supervisor_load` row (`publish_supervisor_load`, `supervisor/loop_load.py`). Three consecutive tick crashes clear readiness and notify the owner, shutdown excepted (`_SignalStopServer`, §9).

`supervisor/event_observation.py` indexes pending idle inputs across both lanes and holds outstanding-delivery membership (`put_unless_outstanding`); `event_taxonomy.py` names the reducers changing idle inputs. Pending inputs defer idle observations, granting no progress or lease; heartbeats, telemetry and host narration cannot suppress attention indefinitely; dequeue does not certify a failed handler's effects.

`state.json` money is display, not admission (§10.28): totals persist, `usage_projection` owns per-root values, `usage_writer_snapshot` renders once per dirty tick after intake. Ledger `(compaction_epoch, seq)` ordering rejects stale renders. Quarantine (`integrity_degraded`) freezes display until explicit repair; failed writes stay dirty until `BUDGET_PROJECTION_RETRY_SEC`. The async OpenRouter comparison never changes admission.

`supervisor.queue._queue_lock` (Q) owns queue transitions; `task_admission` reserves identity before effects (§1). Admission persists nothing under Q: child receipts, launch marks and warm Resumes reserve memory there, persist on the generation's admission lane (`PreparationGeneration.wait_store`: a slice per attempt, controls re-read between, never behind a copy), re-take Q, compare memory, then put; a later refusal settles the row typed; an uncertain write is inspected, never re-sent. Closed, it starts nothing; paused, no launch, yet committed marks reach a worker: process-ending stops pause it and wait before reading the queue or writing restrictions (`pause_admission`); a longer stall, a refusal or error after its marks, or Panic leaves one possibly dispatched. Assignment skips registered inline ids, reaping, holds, claimed launches, closed projects, competing writers and exhausted root capacity. Cold external holders keep their project lane (§6); capacity counts idle assignable workers. Remaining outer-lock probes use `store.acquisition_budget(0)`: confirmed contention defers unsent work off locks, unknown grants nothing. Only Evolution has mode fences. `execution_owner.kind` governs carrier policy and pooled completion notifications; `_is_direct_chat` is historical. First `detached_at`/`detached_by` survive queue/result metadata.

### Admission and addressing

Headless addressing is fixed at admission (`log_addressing.ingress_chat_id`). A registered Project's explicit `chat_id` must match its thread; any other address, hidden included, gets a typed 400, so a Main card never detaches from its Project work. Without a Project, API tasks default to `HIDDEN_CHAT_ID` (0). Confirmed browser Publish requests Main with `source="web"`/`WEB_UI_CHAT_ID` (caller-declared addressing, not authentication); other non-Project addresses are refused. Main gets one host-stamped completion only for work addressed or bound there; other work stays in the hidden partition, silent in chats, readable via terminal, `--result-json-out`, Logs and `GET /api/tasks/<id>`. Reserved inactive Projects keep their chat valid for the queue's typed lifecycle refusal.

Admission names runs without model calls; `task_named` never uses status as a title. Authored `title` (`ouroboros run --title`/top-level contract, a schedule's name) fills `title`/`suggested_name`; `metadata.title`/`metadata.project_id` get 400. First-line fallback (owner/API/queued events) fills only `suggested_name`, keeping later names. Model `start_task` needs a root title for separate new work; historical routing cards resolve.

`queue_snapshot.py` publishes Q-locked snapshot/dispatch/direct-root generations; `queue_observation.py` dates reads by matching `queue.alive`. Empty processes/concurrent restore keep unread work; Continue waits (`queue_not_restored`). Boot normalizes legacy stops before retention (`work_stop_migration.py`, `work_stop_format`): selected holds become cause-free choices; stale copied causes yield to current pauses; prose goes to the journal; missing paused queue locators return held, never running. Stop/terminals still win. Interrupted RUNNING/direct roots without saved work are fenced, with their pending children (§6). Spent grants yield to current continuation custody; confirmed absence fences, unknown stays a point refusal. Rollback: PERSISTENCE.md. Restart verification needs `pending_restart_verify.json`.

`_claim_worker_launch` reserves the row and the slot under Q; the lane reads the schedule control, then puts only after the dispatch marks commit in one write, before anything says `possible` (`_commit_launch`); snapshots never replay a put. Contention is demand, not refusal: the lane retries the same row, attempt and marks; a refusal frees the slot, the row stays demand. Dispatch, hold release and deadline expiry read the loop's `governing_continuation`; saved successors need the frozen source and prior `admitted_dispatch_attempt` (§6). Proven no-put callers bind source/attempt/claim to terminalization, rechecked by the reaper; terminal rows stay terminal; accepted/sealed roots' descendants stay fenced except exact pauses. `task_status.execution_observation` keeps fresh activity apart from lifecycle; only pooled work admits worker-boot orphan inference.

`workspace_preparation` owns child admission off the event thread. Memory claims precede lane work: copies run on the copy lane with preparation-time bytes; readonly children and receipt-then-put admissions use the admission lane. Requests are never re-put. Neither direct-child-count pre-check (worker `schedule_subagent`, supervisor early check) refuses an unknown count; the interlocked re-check decides (`control_delegation.schedule_delegation_refusal`). At startup and reconciliation, `recover_interrupted_preparations` settles proven preparation loss as never admitted and keeps uncertain admissions (§10.19). `forward_to_worker` also reaches a requested child's mailbox. Entry: `events_schedule_task`, `task_admission`.

### Schedules and follow-ups

`supervisor/queue_schedules.py` alone writes `state/scheduled_tasks.json`, every mutation inside `schedule_transaction` (Q, then the sidecar lock). `load_schedule_store` reads only absence as empty; an unreadable table raises `ScheduleStoreUnreadable`: no mutation, unknown reads.

`schedule_occurrence.py` admits one root per occurrence with a frozen receipt; `hold` waits without failing the root. Restart keeps token/task identity: restore holds positive `possible`, replays proven-unsent work and keeps missing/foreign/unreadable receipts unknown. Edits govern unaccepted work; accepted tasks survive deletion (`withdrawn`, restorable: PERSISTENCE). Cron keeps one overdue occurrence. A `kind:"notify"` note is consumed once; `schedule_notes.py` shows its words as a signed `reminder` System row; unconfirmed display sets `last_error`, never retries.

`followup_policy.py` needs explicit related/independent relationships; provenance grants neither relationship nor billing authority. Related work keeps origin cap/source/deadline. Missing or stale queue evidence holds. Restart records an episode, never holding healthy schedules; the finite scan admits legacy Restart holds (even disabled settled rows) to audited refresh: remove only Restart, keep history/owed occurrences, recompute mixed identities. GET only projects. Stop writes `followup_stop` on the original result even if completion wins. `stop_action_id` names ingress apart from custody `request_id`: exact retries rejoin, changed arguments refuse. Restore's `expected_hold_id` releases only that identity; generic Restore may re-enable/cancel deletion. `schedule_mutation` intent/outcome share `operation_id`; failed outcome reports `changed_audit_incomplete`, never unaudited rollback. Tools and `/api/schedules/{id}/action` share action/reason (`schedule_lifecycle.py`). Scans adopt legacy skill rows and cache settled last runs for the next run (`last_outcome`: notice, else the sentence, else the answer's end; `previous_run_open`); other disabled idle rows skip admission. Observations run off Q; publication compares row/Restart generation. Reconciliation, binding repair and GC use signed receipts (`task_ownership.py`), rechecking versions under Q; changed/busy defers, unknown stays unknown. Admission verifies its committed write. Writes and final control checks still hold Q.

### Completion, owner waits and restarts

Workers prepare files before `task_done`; its stamp never replaces CURRENT readiness (`headless.terminal_task_files_ready`). Capture needs `ready`, `ready_with_changes`, `ready_no_changes`, `failed` or `missing`; blank/unknown stays owed, failed/missing grants no PASS. Readers and preparation share `task_requires_workspace_capture`: no workspace, readonly subagents and actual inline Presence/direct owners are exempt after terminal-source verification and split adoption; cancellation wins. `CustodyBusy` keeps RUNNING and `pending_drives` for health/startup recovery, even without a fork. Recovery neither replays the model nor scans history.

Answer first: `agent_task_pipeline.emit_task_results` owes and live-enqueues the root final BEFORE cost reconstruction, review evidence/input capture and `_store_task_result`; `task_done` follows that store. Carrier ordering and `task_finalization_timing` (`basis: post_answer_store`): `finalization_timing.emit_post_answer_timing` docstrings. Timeout/dead-worker recovery adopts owed, exhausted, delivered or unreadable registrations; direct boot-fence custody needs a readable registration (`working_checkpoint.adopt_registered_answer`). Adoption keeps the answer with `failed`/`infra_failed`/`finalization_incomplete` and a host notice, never replays the prompt.

`worker_owner_wait` keeps task, worker and browser RUNNING; durable parking lends capacity; a Resume grant persists on the admission lane under its claim, rolled back if the stack changed before put. Contention retries the same row under Stop/deadline/ceiling. Pre-ACK sleep and the native-restart interval fold once. Resume keeps the attempt, never replays. Main/Project waits survive planned restart with unread input; mail wakes, only owner answers answer. Settled Project post-work rejects steering (`owner_mailbox.mailbox_drain_ended`). Direct waits (`owner_wait.direct_owner_wait`) lend no slot; settled ones block no update/restart drain, wake on writer admission, ride the owner-wait handoff.

Crashes, timeouts, restart and update-abort use §6 Saved working state. A live retained wait dominates rolling work (`working_checkpoint.live_park`); refused returns emit `restart_return_refused`. Updates save handoffs before stopping (failure blocks update); Rollback saves none. Cold continuation keeps economics, deadlines/wait time and same-requester/attempt Restart intent; cost authority is reread (`task_pacing.restore_cost_ceiling`).

### Cancellation

Cancellation is intent-then-custody (§10 invariants 14-15), intent and outcome separate fields:

1. **Intent.** Every cancel ingress (`cancel_task`, HTTP single/cascade, evolution stop, project deletion, cascade sweep, boot recovery of `cancel_requested` files) writes one durable row (`cancel_intents.request_cancel`, locked `state/cancel_intents.json`); a failed write stops nothing (`CANCEL_INTENT_WRITE_FAILED`, HTTP 503).
2. **Scope.** Recorded scope only widens (single to cascade; Stop-now cannot shrink a cascade). Reaping is no cancel ingress: its custody survives health hand-back until replay settles. Stop needs explicit intent; a replay in flight keeps it pending.
3. **Claim.** `task_lifecycle.cancel_task_custody`, the one settle owner, takes the exclusive claim (§10 invariant 14): racing custodies never double-settle; the `cancel_task` event only wakes it. A live direct-chat turn stops through the same custody (`worker_chat_lane.py` writes one typed `finalize_now`; its loop ends at the next round boundary, no further model call); an inline Presence turn's runner (§12) reads the intent at each call or answer and records `cancelled`. Stop during post-task synthesis discloses skipped paid stages as `post_task_stop_reason`. A still-live turn releases the claim for the sweep, never publishing a fabricated `cancelled` row.
4. **Kill and re-check.** Custody confirms process death, then rereads the settled result; natural completion wins (§10).
5. **Reconcile, capture, settle.** Open delegated runs are re-audited from durable custody rows; workspace artifacts come from the real tree (a failed or unrunnable capture is `failed`, never `missing`); the result carries reconstructed-or-unknown cost, never a fabricated `$0`; only here is `parent_decision` stamped; `cancel_publication` keeps `cancel_origin`; restore-fence receipts name its cause. HTTP proves transport, not owner intent.
6. **Owe, then publish.** After claim re-check, owe the terminal answer before the terminal row, settled intent and `task_done`; pending-deadline expiry owes inside its lock too. Winning completion withdraws salvage; crash after settlement replays debt. Cascades send one root digest (`cascade:<root_tid>:<request_id>`). `terminal_projection.py` holds Done until no `final:`, `cancel:<tid>:<request_id>` or `cascade:` debt stays; unknown/exhausted delivery stays visible (`_delivery_disposition`, `events_chat_delivery._handoff_delivered_review`).
7. **Watchdog.** The tick's off-drain sweep (`server_maintenance.py`, `sweep_cancel_intents`) re-feeds unclaimed/abandoned intents to custody (cascades as cascades): a lost control event or custody dead mid-teardown cannot wedge cancellation.

Effective results show typed `cancel_state: "pending"` with `cancel_reason` until settlement (UI: §3 Stop and cancel controls). Steering writes (`tell_task`, mailbox follow-ups, `forward_to_worker`) are refused typed while pending; restore and pre-assignment read the projection under Q, so a cancelled pending task never starts. `task_done` asserts a settled outcome validated against the durable result (`events_task_done`); a mismatch is a lifecycle fault, left to custody while cancellation is pending.

`terminal_delivery.py` owns the outbox: exact-id debt before enqueue, boot/tick replay; refusal keeps debt (PERSISTENCE.md). Producers use the injected bus; queued/in-flight originals neither duplicate nor spend retries (`put_unless_outstanding`, process claims). Exhausted rows keep payload and kept copy until receipt. A delivered Stop receipt supersedes its task's older `host_notice` final in that chat, never resent, whatever prior sends did. Card dedupe probes task/summary id/readiness token in `dialog.sqlite`; importing misses stay owed. Main's frozen event/clock survives eviction until strict receipt (§3). Cancel sends lineage-routed unreviewed salvage; a reap does so only without a held answer. Receipt proves neither display nor reading (§10).

Best-effort dialogue tries zero wait, publishing live at the same timestamp; `dialogue_retry` bounds rows/bytes, counts eviction (progress first) and exit loss, so crash or sustained contention can lose rows (PERSISTENCE.md). The delivery duty and workers drain it (before an append, at task end, exit or an idle probe; retiring it counts leftovers lost); content-address dedup covers an uncertain COMMIT without a second frame. Required rows and named inbound acceptances never use it; inbound failure stays loud.

Named sends keep timestamp/id; unnamed notices keep their producer. The duty continues writes/sends/receipts off-consumer; `emitted` facts/id cache repair receipts without resend (earlier crash: at-least-once). Only non-Main replays count durable dispatch entries (`message_bus`, after required writes, unknown outcomes too); queueing only dates backoff. Handlers use a 0.25 s slice (unnamed progress: zero); other writers keep caller waits. Readiness stays indexed.

### Stop policy and hurry

Stop policy is a durable-intent axis, scope-independent; omission is immediate (CLIENT_CONTRACT §8). `finalize_then_cancel` answers 202, intent open: descendants settle first, no final turn; then root `finalize_now` allows one tool-less turn under the honest owner reason (`supervisor/owner_stop.py`). `owner_stop_receipt.py` keeps child/run material and readers in the custody envelope: the turn's counted view, one card row per Stop, Files' on-read copy of all rows/texts, on any exit; model bytes untouched; no session transfer. `OWNER_STOP_OUTER_CAP_SEC`, deadline, ceiling bound grace. Immediate only hardens graceful; Panic bypasses both.

Owner "hurry" is a typed task-local `kind=hurry` owner-mailbox control (`ouroboros/owner_hurry.py`; `gateway/task_hurry.py`): it makes that task's plan gate advisory; never a chat message, settings mutation or weakening of the P3 commit/review gates; attempt-scoped (`retry_reset` strips it on each same-id requeue).

### Event bus, timeouts and worker readiness

One server-owned, process-lifetime manager bus serves worker generations/direct actors/non-task review usage (§Tick and locks). Respawn never rotates it; lookup cannot create it, producer exit cannot close it, and a killed producer cannot corrupt another feeder frame. `log_addressing.task_event_queue` stamps chat/lineage by value so late telemetry stays addressed. Workers attempt checkpoint storage before one live frame (`loop_messages._emit_checkpoint_event`); the nested handler persists only `task_start_settings_reload_failed`. `utils.append_jsonl` streams `logs/*.jsonl` except dedicated-sender types (worker/server) and `live=False` copies: one live frame/event; `llm_api_error` in drive and canonical log.

Heartbeat proves liveness only. `silence_attention` mails the source and one waiting ancestor (late warm/cold/in-slot waits too). Otherwise `workspace_preparation` admits one readonly diagnostic even with background off, under source restrictions/money; unreadable authority defers. It targets only its source (child Pause: `not_a_root_task`); request/effect recheck the episode. Source change revokes it by single-scope `silence_resolved` (launch: no-put proof), proving no writer death. Worker/root-child capacity may delay it indefinitely; recorded refusal consumes its diagnostic. It owes no disposition, grants no source progress, is never diagnosed.

Deadlines and finite execution bounds freeze under Q, mark `reaping` and enter `task_reaper`; queued deadlines expire undispatched. Kill/join precede salvage and settlement. Unconfirmed death keeps custody without terminalization, retry or replacement; `task_reaper_wedged` suggests Restart. A result file proves no process exit. Typed incidents keep `TIMEOUT_TERMINAL_REASONS` identity.

One Python worker starts; more come on demand and quiet surplus retires, with no idle timer (owner choice: idle memory beats burst startup); explicit counts and MAX stay. Startup verification runs once per server generation and code version (`state/startup_verification.json`; `worker_boot` stays per process); a worker caches bytecode in a prefix inside its data dir (`worker_process.write_bytecode_to_prefix_only`). `worker_assignment` forecasts residual demand with dispatch's chooser, claiming nothing; `worker_pool_lifecycle` grows only that deficit and keeps one ready spare at quiescence; `booting` slots forecast capacity, unresolved reservations stay charged.

Assignment/free counts need live current PID/birth-bound `worker_ready`: births are compared only when both sides measured one, else the pid (`_births_agree`, `_record_worker_processes`). SHA equality proves neither loaded code nor review. `worker_starting` grants one bounded extension (`runtime_limits.py`); watcher errors use bounded replace/park. Per-slot exhaustion leaves unused MAX headroom. All-spent capacity closes pooled ingress (`/review` too); `disable_exhausted_worker_pool` fails unstarted rows with a Restart hint, sparing chat, control, boot and update recovery.

Surplus retirement and cap-full warm Resume share a quiescence token probe; a worker answers once its local reviews, tool futures with late callbacks, abandoned senders and owed custody writes settle (`worker_process.local_work_settled`; `review_operation._LIVE` counts `wait.close` and final pointer publication; unknown defers; no history scans). Retirement reserves the slot, kills with kept services through the off-loop `task_reaper` and frees capacity and its claims only on confirmed death; the lifecycle serializer guards membership, never a kill or join (`request_worker_quiescence`, `retire_quiescent_worker`, `reap_idle_worker` docstrings). No rotation or setting; intentional retirement is not a crash.

`worker_health.recover_confirmed_dead_worker` reserves `confirmed_dead_worker` custody under Q. Saved terminals (`task_exception` included) beat signal death; exact pauses re-park (§6); unknown/incomplete publication stays `TerminalFileRecoveryPending`. Only confirmed absence reaches `infra_failed`, keeping answer/review/cost. Eligible crashes retry within `QUEUE_MAX_RETRIES` from newer working state, never spent Resume grants (storms: docstring). After process custody, startup recovers addressed `pending_drives`, nonterminal/synthesis obligations and saved answers before orphan healing.

### Maintenance and custody

`server_maintenance.HOST_DUTIES` names every pass the tick starts off-loop (name, latch, runner), measured by `tests/test_cost_contract.py` B7. Domain claims and receipts arbitrate writer checks. `bind_body_lifespan` observes after store publication; readiness enables collection. Startup/Stop/Restart keep terminal sources and money without joining bulk work. Body collection uses input-bound custody outcomes; reviewer markers enable first-ready native capture. Cold holders enter orphan-exclusion before recovery (§6). Stop admits nothing; pause proves no exit (§10.24). `invalid_source` wakes on watched files/rows/release (`source_retention._unavailable_basis`); busy cost reads stay unknown. Reviews stay panel-owned. Reaping proves PID/birth/command/task/generation. Watchdogs record stalls and suggest Restart without killing threads.

Bulk work uses one child (`python -m ouroboros.maintenance`: low priority, Panic/exit census); `job:<name>` facts govern dispatch; a throw adds `last_error`. Jobs and order: `maintenance.JOBS`. Recovery gaps keep task sources. Plan changes queue signatures; missed wakes replay at dispatch, boot rechecks indexed plans. Non-contended examinations rest, keeping seat debt. Retirement wakes on age eligibility, nonblocking publication or a removed source tree; compression on terminal writes or an unfinished pass; startup/repair discover missed bytes; nothing else wakes them. Queue recovery, drive settlement and runtime custody stay in the server; Storage Free (§3) is explicit. Absent usage owners keep debt and rest; money-only passes select newer dirty revisions, arrivals recheck absence.

Cooperative project checkpointing (`supervisor/events_coop_checkpoint.py`) runs on two equivalent quiescence triggers: a root settling without live descendants, or the last child settling under a terminal root (a root-scope budget stop terminalizes the root before its children). The bounded git chain revalidates quiescence under Q before mutation. Only host-minted project roots qualify: owner-attached folders are never auto-committed, credential-shaped files stay excluded and disclosed; each material success, skip or error gets a durable receipt.

### Bridge intake and commands

Bridge intake keeps identity, transport and durable acceptance; failed handlers requeue only their unprocessed memory tail, never accepted rows. Room input goes to its sole live reader, a warm question wait included, queued/held work not. Tell and answers owe mail to living work until its saved read, never resuming it: the asker, then proven admitted successors under each admission lock; else named ingress at the saved publication address for the asker's earliest live late-input head or a fresh head. Panic has emergency ingress.

The bridge recognizes `/panic`, `/restart`, `/review`, `/evolve [on|off]`, `/bg [start|stop|status]` and `/status`; other text enters ordinary routing. External transports invoke them only with positive owner identity and a current transport-specific owner-chat binding; unknown refuses and registers nobody; Panic keeps its observed immutable binding until owner Reset closes it (`PanicIngress`). Commands reuse runtime-mode, queue, cancellation and typed-result authority. Archive readers keep rotated runtime logs' timelines (§1).

Confirmed budget/owner pauses register `pause_notices` with the confirming result update (`pause_notices.py`): one obligation set, a saved System chat row as the receipt, a failed append still owed, older episodes retained by Resume and newer pauses. Consciousness reports paused/pausing or unknown, never guessing settlement.
