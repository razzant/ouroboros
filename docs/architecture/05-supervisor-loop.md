# 5. Supervisor Loop

`server.py::_run_supervisor()` owns the pooled scheduling tick and lifecycle lock. Cancellation intent precedes teardown; intent, outcome and money stay separate.

### Tick and locks

Each tick publishes liveness, rotates logs, checks workers, drains one bounded batch in one round trip (`ObservedEventQueue.drain`), control before telemetry, so no answer waits (`event_taxonomy.EventDisposition.lane`), takes bridge input (a backlog skips wait and idle sleep), projects money, enforces due deadlines (`enforce_due_task_timeouts`), runs maintenance, admits/assigns, feeds the queue publisher (`start_queue_writer`), ticks consciousness and writes a busy minute's `supervisor_load` row (`loop_load.py`; Q per site). A lost bus (`EventBusLost`, read first; `bus_lost`) or three straight failures on a live bus, publication included (`loop_failed`), end a ready generation (`server_process.end_generation_on_fault`; §9 Fault door); shutdown excepted (`_SignalStopServer`).

`supervisor/event_observation.py` indexes pending idle inputs across both lanes and holds outstanding-delivery membership (`put_unless_outstanding`); `event_taxonomy.py` names the reducers changing idle inputs. Pending inputs defer idle observations without granting progress or a lease; heartbeats, telemetry and host narration cannot suppress attention indefinitely; dequeue certifies no failed handler's effects.

`state.json` money is display, not admission (§10.28): totals persist, `usage_projection` owns per-root values, `usage_writer_snapshot` renders once per dirty tick after intake. Ledger `(compaction_epoch, seq)` ordering rejects stale renders. Quarantine (`integrity_degraded`) freezes display until explicit repair; failed writes stay dirty until `BUDGET_PROJECTION_RETRY_SEC`. The async OpenRouter comparison never changes admission.

`supervisor.queue._queue_lock` (Q) owns queue transitions; `task_admission` reserves identity before effects (§1). Admission persists nothing under Q: child receipts, launch marks and warm Resumes reserve memory there, persist on the generation's admission lane (`PreparationGeneration.wait_store`: a slice per attempt, controls re-read between, never behind a copy), re-take Q, compare memory, then put; a later refusal settles the row typed; an uncertain write is inspected, not re-sent. Closed, it starts nothing; paused, no launch, yet committed marks reach a worker: process-ending stops pause it and wait before reading the queue or writing restrictions (`pause_admission`); a longer stall, a refusal or error after its marks, or Panic leaves one possibly dispatched. Assignment fills project slots, skipping registered inline ids, reaping, holds, claimed launches, closed projects, competing writers and exhausted root capacity; cold external holders keep their project lane (§6); capacity counts idle assignable workers. Other outer-lock probes use `store.acquisition_budget(0)`: confirmed contention defers unsent work off locks, unknown grants nothing. Only Evolution has mode fences. `execution_owner.kind` is the origin, its `lane`/`executor` the carrier and carrier policy; `_is_direct_chat` is historical. First `detached_at`/`detached_by` survive queue/result metadata.

### Admission and addressing

Headless addressing is fixed at admission (`log_addressing.ingress_chat_id`). A registered Project's explicit `chat_id` must match its thread; any other address, hidden included, gets a typed 400, so a Main card never detaches from its Project work. Without a Project, API tasks default to `HIDDEN_CHAT_ID` (0). Confirmed browser Publish requests Main with `source="web"`/`WEB_UI_CHAT_ID` (caller-declared addressing, not authentication); other non-Project addresses are refused. Main gets one host-stamped completion only for work addressed or bound there; other work stays hidden: silent in chats, readable via terminal, `--result-json-out`, Logs and `GET /api/tasks/<id>`. Reserved inactive Projects keep their chat valid for the queue's typed lifecycle refusal.

Admission names use no model; `task_named` never titles by status. Authored `title` (`ouroboros run --title`/top-level contract/schedule name) fills `title`/`suggested_name`; `metadata.title`/`metadata.project_id` get 400. First-line fallback (owner/API/queued events, or what a late-input head answers) fills only `suggested_name`, keeping later names. `start_task` needs a root title for separate new work; old routing cards resolve.

Transitions only mark the queue under Q (`persist_queue_snapshot`); the tick publishes outside Q when the revision moved (`queue_publication.py`), and an effect needing the documents first calls the barrier `publish_queue_snapshot` outside Q (§10.24). `queue_snapshot.py` restores; `queue_observation.py` reads (`load_queue_document`), dated by `queue.alive` (PERSISTENCE.md). Empty processes/concurrent restore keep unread work; Continue waits (`queue_not_restored`). Boot normalizes legacy stops before retention (`work_stop_migration.py`); Stop/terminals still win. Interrupted RUNNING/direct roots neither returned nor held (§9) are fenced, with their pending children (§6). Spent grants yield to current continuation custody; confirmed absence fences, unknown stays a point refusal. Restart verification: `pending_restart_verify.json` (PERSISTENCE.md).

`_claim_worker_launch` reserves the row and the slot under Q; the lane reads the schedule control, then puts only after the dispatch marks commit in one write, before anything says `possible` (`_commit_launch`); snapshots never replay a put. Contention is demand, not refusal: the lane retries the same row, attempt and marks; a refusal frees the slot, the row stays demand. Dispatch, hold release and deadline expiry read the loop's `governing_continuation`; saved successors need the frozen source and prior `admitted_dispatch_attempt` (§6). Proven no-put callers bind source/attempt/claim to terminalization, rechecked by the reaper; terminal rows stay terminal; accepted/sealed roots' descendants stay fenced except exact pauses. `task_status.execution_observation` keeps fresh activity apart from lifecycle; only pooled work admits worker-boot orphan inference.

`workspace_preparation` owns child admission off the event thread. Memory claims precede lane work: copies run on the copy lane with preparation-time bytes; readonly children and receipt-then-put admissions use the admission lane. Requests are never re-put. Neither direct-child-count pre-check (worker `schedule_subagent`, supervisor early check) refuses an unknown count; the interlocked re-check decides (`control_delegation.schedule_delegation_refusal`). At startup and reconciliation, `recover_interrupted_preparations` settles proven preparation loss as never admitted and keeps uncertain admissions (§10.19). `forward_to_worker` also reaches a requested child's mailbox. Entry: `events_schedule_task`, `task_admission`.

### Schedules and follow-ups

`supervisor/queue_schedules.py` alone writes `state/scheduled_tasks.json`, every mutation inside `schedule_transaction` (Q, then the sidecar lock; its pass: PERSISTENCE.md). `load_schedule_store` reads only absence as empty; an unreadable table raises `ScheduleStoreUnreadable`: no mutation, unknown reads.

`schedule_occurrence.py` admits one root per occurrence with a frozen receipt; `hold` waits without failing the root. Restart keeps token/task identity: restore holds positive `possible`, replays proven-unsent work and keeps missing/foreign/unreadable receipts unknown. Edits govern unaccepted work; accepted tasks survive deletion (`withdrawn`, restorable: PERSISTENCE). Cron keeps one overdue occurrence. A `kind:"notify"` note is consumed once; `schedule_notes.py` shows its words as a signed `reminder` System row; unconfirmed display sets `last_error`, never retries.

`followup_policy.py` needs explicit related/independent relationships; provenance grants no relationship or billing authority; the owner's words ride by value. Related work keeps origin cap/source/deadline. Missing or stale queue evidence holds. Restart records an episode, never holding healthy schedules; the finite scan admits legacy Restart holds (disabled settled rows too) to audited refresh: remove only Restart, keep history/owed occurrences, recompute mixed identities. GET only projects. Stop writes `followup_stop` on the original result even if completion wins. `stop_action_id` names ingress apart from custody `request_id` (retries: CLIENT_CONTRACT §8). Restore's `expected_hold_id` releases only that identity; generic Restore may re-enable/cancel deletion. `schedule_mutation` intent/outcome share `operation_id`; a failed outcome reports `changed_audit_incomplete`, never an unaudited rollback. Tools and `/api/schedules/{id}/action` share action/reason (`schedule_lifecycle.py`). Scans adopt legacy skill rows and cache settled last runs (`last_outcome`, `previous_run_open`: PERSISTENCE.md); other disabled idle rows skip admission. Observations run off Q; publication compares row/Restart generation. Reconciliation, binding repair and GC use signed receipts (`task_ownership.py`), rechecking versions under Q; changed/busy defers, unknown stays unknown. Admission verifies its committed write; writes and final control checks still hold Q.

### Completion, owner waits and restarts

Workers prepare files before `task_done`; its stamp never replaces CURRENT readiness (`headless.terminal_task_files_ready`). Capture needs `ready`, `ready_with_changes`, `ready_no_changes`, `failed` or `missing`; blank/unknown stays owed, failed/missing grants no PASS. Readers and preparation share `task_requires_workspace_capture`: no workspace, readonly subagents and inline executors are exempt after terminal-source verification and split adoption; cancellation wins. `CustodyBusy` keeps RUNNING and `pending_drives` for health/startup recovery, fork or not. Recovery neither replays the model nor scans history.

Answer first: `agent_task_pipeline.emit_task_results` owes and live-enqueues the root final BEFORE cost reconstruction, review evidence/input capture and `_store_task_result`; `task_done` follows that store. Carrier ordering and `task_finalization_timing` (`basis: post_answer_store`): `finalization_timing.emit_post_answer_timing`. Timeout/dead-worker recovery adopts owed, exhausted, delivered or unreadable registrations; direct boot-fence custody needs a readable registration (`working_checkpoint.adopt_registered_answer`). Adoption keeps the answer with `failed`/`infra_failed`/`finalization_incomplete` and a host notice, never replays the prompt.

`worker_owner_wait` keeps task, worker and browser RUNNING; durable parking lends capacity; a Resume grant persists on the admission lane under its claim, rolled back if the stack changed before put. Contention retries the same row under Stop/deadline/ceiling. Pre-ACK sleep and the native-restart interval fold once. Resume keeps the attempt, never replays. Main/Project waits survive planned restart with unread input; mail wakes, only owner answers answer. Settled Project post-work rejects steering (`owner_mailbox.mailbox_drain_ended`). Lane carriers wait here too, their Resume outside `MAX_WORKERS`; only inline executors use `owner_wait.direct_owner_wait`.

Crashes, timeouts, restart and update-abort use §6 Saved working state. A live retained wait dominates rolling work (`working_checkpoint.live_park`); refused returns emit `restart_return_refused`. Updates save handoffs before stopping (failure blocks update); Rollback saves none. Cold continuation keeps economics, deadlines/wait time and same-requester/attempt Restart intent; cost authority is reread (`task_pacing.restore_cost_ceiling`).

### Cancellation

Cancellation is intent-then-custody (§10 invariants 14-15), intent and outcome separate fields:

1. **Intent.** Every cancel ingress (`cancel_task`, HTTP single/cascade, evolution stop, project deletion, cascade sweep, boot recovery of `cancel_requested` files) writes one durable row (`cancel_intents.request_cancel`, locked `state/cancel_intents.json`); a failed write stops nothing (`CANCEL_INTENT_WRITE_FAILED`, HTTP 503).
2. **Scope.** Recorded scope only widens (single to cascade; Stop-now cannot shrink a cascade). Reaping is no cancel ingress: its custody survives health hand-back until replay settles. Stop needs explicit intent; a replay in flight keeps it pending.
3. **Claim.** `task_lifecycle.cancel_task_custody`, the one settle owner, takes the exclusive claim (§10 invariant 14): racing custodies never double-settle; the `cancel_task` event only wakes it. A lane turn stops like any worker; an inline executor's actor gets one typed `finalize_now` (`inline_carrier.stop_direct_chat_turn`), ending at its next round boundary without another model call. Stop during post-task synthesis discloses skipped paid stages as `post_task_stop_reason`. A still-live turn releases the claim for the sweep, never publishing a fabricated `cancelled` row.
4. **Kill and re-check.** Custody confirms process death, then rereads the settled result; natural completion wins (§10).
5. **Reconcile, capture, settle.** Open delegated runs are re-audited from durable custody rows; workspace artifacts come from the real tree (a failed or unrunnable capture is `failed`, never `missing`); the result carries reconstructed-or-unknown cost, never a fabricated `$0`; only here is `parent_decision` stamped; `cancel_publication` keeps `cancel_origin`; restore-fence receipts name its cause. HTTP proves transport, not owner intent.
6. **Owe, then publish.** After claim re-check, owe the terminal answer before the terminal row, settled intent and `task_done`; pending-deadline expiry owes inside its lock too. Winning completion withdraws salvage; crash after settlement replays debt. Cascades send one root digest (`cascade:<root_tid>:<request_id>`). `terminal_projection.py` holds Done until no `final:`, `cancel:<tid>:<request_id>` or `cascade:` debt stays; unknown/exhausted delivery stays visible (`_delivery_disposition`, `events_chat_delivery._handoff_delivered_review`).
7. **Watchdog.** The tick's off-drain sweep (`server_maintenance.py`, `sweep_cancel_intents`) re-feeds unclaimed/abandoned intents to custody (cascades as cascades): a lost control event or custody dead mid-teardown cannot wedge cancellation.

Effective results show typed `cancel_state: "pending"` with `cancel_reason` until settlement (§3). Steering writes (`tell_task`, mailbox follow-ups, `forward_to_worker`) are refused typed while pending; restore and pre-assignment read the projection under Q, so a cancelled pending task never starts. `task_done` asserts a settled outcome validated against the durable result (`events_task_done`); a mismatch is a lifecycle fault, left to custody while cancellation is pending.

`terminal_delivery.py` owns the outbox: exact-id debt before enqueue, boot/tick replay; refusal keeps debt (PERSISTENCE.md). Producers use the injected bus; queued/in-flight originals neither duplicate nor spend retries (`put_unless_outstanding`, process claims). Exhausted rows keep payload and copy until receipt. A delivered Stop receipt supersedes its task's older `host_notice` final in that chat, never resent, whatever prior sends did. Card dedupe probes task/summary id/readiness token in `dialog.sqlite`; importing misses stay owed. Main's frozen event/clock survives eviction until strict receipt (§3). Cancel sends lineage-routed unreviewed salvage; a reap only without a held answer. Receipt proves neither display nor reading (§10).

Best-effort dialogue tries zero wait, publishing live at the same timestamp; a contended row waits in `dialogue_retry`, which crash or sustained contention can lose (bounds, drains, dedup: PERSISTENCE.md). Required rows and named inbound acceptances never use it; inbound failure stays loud.

Named sends keep timestamp/id; unnamed notices keep their producer; `emitted` facts/id cache repair receipts without resend (earlier crash: at-least-once). Only non-Main replays count durable dispatch entries (`message_bus`, after required writes, unknown outcomes too); queueing only dates backoff.

### Stop policy and hurry

Stop policy is a durable-intent axis, scope-independent; omission is immediate (CLIENT_CONTRACT §8). `finalize_then_cancel` answers 202, intent open: descendants settle first, no final turn; then root `finalize_now` allows one tool-less turn under the honest owner reason (`supervisor/owner_stop.py`). `owner_stop_receipt.py` keeps child/run material and readers in the custody envelope: the turn's counted view, one card row per Stop, Files' on-read copy of all rows/texts, on any exit; model bytes untouched; no session transfer. `OWNER_STOP_OUTER_CAP_SEC`, deadline, ceiling bound grace. Immediate only hardens graceful; Panic bypasses both.

Owner "hurry" is a typed task-local `kind=hurry` owner-mailbox control (`ouroboros/owner_hurry.py`; `gateway/task_hurry.py`): it makes that task's plan gate advisory; never a chat message, settings mutation or weakening of the P3 commit/review gates; attempt-scoped (`retry_reset` strips it on each same-id requeue).

### Event bus, timeouts and worker readiness

One server-owned, process-lifetime manager bus serves worker generations/inline actors/non-task review usage. Respawn never rotates it; lookup cannot create it, producer exit cannot close it, a killed producer cannot corrupt another feeder frame. Its `spawn` manager ignores SIGINT/SIGTERM; each `get_event_q` reads its exit code, raising `EventBusLost`. `log_addressing.task_event_queue` stamps chat/lineage by value so late telemetry stays addressed. Workers attempt checkpoint storage before one live frame (`loop_messages._emit_checkpoint_event`); the nested handler persists only `task_start_settings_reload_failed`. `utils.append_jsonl` streams `logs/*.jsonl` except dedicated-sender types (worker/server) and `live=False` copies: one live frame/event; `llm_api_error` in drive and canonical log.

Heartbeat proves liveness only, dated by its own source time (never before its attempt), reading no store (`_handle_task_heartbeat`). `silence_attention` mails the source and one waiting ancestor (late warm/cold/in-slot waits too); otherwise `workspace_preparation` admits one readonly diagnostic even with background off, under source restrictions/money (unreadable authority defers), aimed only at its source (child Pause: `not_a_root_task`), request and effect rechecking the episode. A source change revokes it by single-scope `silence_resolved` (launch: no-put proof), proving no writer death; worker/root-child capacity may delay it indefinitely; a recorded refusal consumes it; it owes no disposition, grants no source progress, is never diagnosed.

Deadlines and finite execution bounds freeze under Q, mark `reaping` and enter `task_reaper`; queued deadlines expire undispatched; kill/join precede salvage and settlement. Unconfirmed death keeps custody without terminalization, retry or replacement; `task_reaper_wedged` suggests Restart. A result file proves no process exit; typed incidents keep `TIMEOUT_TERMINAL_REASONS` identity.

The lane spare starts first; project workers grow on demand to MAX; surplus retires, no idle timer (idle memory over burst startup). Startup verification runs once per generation/version (`state/startup_verification.json`; `worker_boot` per process); workers cache bytecode in a data prefix (`worker_process.write_bytecode_to_prefix_only`). `worker_assignment` forecasts residual demand with its chooser, claiming nothing; `worker_pool_lifecycle` grows only that deficit and publishes it (`project_demand`: PERSISTENCE.md); `booting` slots forecast capacity, unresolved reservations stay charged.

Assignment/free counts need live current PID/birth-bound `worker_ready`: births compared only when both sides measured one, else the pid (`_births_agree`, `_record_worker_processes`). SHA equality proves neither loaded code nor review. `worker_starting` grants one bounded extension (`runtime_limits.py`); watcher errors use bounded replace/park. Per-slot exhaustion leaves unused MAX headroom. All-spent capacity closes pooled ingress (`/review` too); `disable_exhausted_worker_pool` fails unstarted rows with a Restart hint, sparing chat, control, boot and update recovery.

Surplus retirement and cap-full warm Resume share a quiescence token probe: a worker answers once its local work settles (`worker_process.local_work_settled`; unknown defers; no history scans). Retirement reserves the slot, kills with kept services via the off-loop `task_reaper` and frees capacity and its claims only on confirmed death, the serializer guarding membership only (`request_worker_quiescence`, `retire_quiescent_worker`, `reap_idle_worker` docstrings). No rotation or setting; intentional retirement is not a crash.

`worker_health.recover_confirmed_dead_worker` reserves `confirmed_dead_worker` custody under Q; a refused respawn is logged when it starts, changes cause and ends. Saved terminals (`task_exception` included) beat a death; exact pauses re-park (§6); unknown/incomplete publication stays `TerminalFileRecoveryPending`. Only confirmed absence reaches `infra_failed`, keeping answer/review/cost. Only a recorded stop terminalizes; an unrecorded death, signals included, retries once (`QUEUE_MAX_RETRIES`) from newer working state, never spent Resume grants, then `worker_crash_retry_exhausted`; a signal death reserves no delegated handoff and ends that attempt's running delegated runs. After process custody, startup recovers addressed `pending_drives`, nonterminal/synthesis obligations and saved answers before orphan healing.

### Conversation lane

Startup and auto-resume notices name still-paused places (legacy too) without changing them. Owner Main/room turns, wakes, Presence bodies and auto-resume run in `WORKERS` slots with `lane="conversation"` (`conversation_lane.py`), admitted by routing with their RUNNING row published first, never PENDING; outside `MAX_WORKERS`, project leases and `disable_exhausted_worker_pool`. The pool's one ready spare is the owner's (a wake waits for its own carrier), replenished at once; a closed repo-writer gate stops spawns, never a dispatch; spawn success is the only bound. `inline_carrier.py` runs the same body on a server thread, disclosed (`inline_executors` in `/api/health` and the vitals): `inline_call` for a live voice call; `inline_degraded`, with an owner notice, only on a physical fact (spawn refused, carrier parked, marker window, no queue of its own; §12).

### Maintenance and custody

`server_maintenance.HOST_DUTIES` lists off-loop tick passes (name, latch, runner), flat as history/live sets grow (`tests/test_cost_contract.py` B7; §10.24). A pass reads what it can act on, once: reconcile skips queue rows, batches the rest; preparation and held custody rows re-read only when stamps move (`task_store.owing_documents`, `delegate_custody_current.held_runs`); the receipt refresh and a settled Owner-Pause tree rest while inputs stand; an unsettled tree's pass stops ended members' runs (`owner_pause_control`). Domain claims and receipts arbitrate writer checks. `bind_body_lifespan` observes after store publication; readiness enables collection. Startup/Stop/Restart keep terminal sources and money, joining no bulk work; body collection uses input-bound custody outcomes; reviewer markers enable first-ready native capture. Cold holders enter orphan-exclusion before recovery (§6). Stop admits nothing; pause proves no exit (§10.24). `invalid_source` wakes on watched files/rows/release (`source_retention._unavailable_basis`); busy cost reads stay unknown. Reaping proves PID/birth/command/task/generation. Watchdogs record stalls and suggest Restart; they kill no thread.

Bulk work uses one child (`python -m ouroboros.maintenance`: low priority, Panic/exit census); `job:<name>` facts govern dispatch; a throw adds `last_error`. Jobs and order: `maintenance.JOBS`. Recovery gaps keep task sources. Plan changes queue signatures; missed wakes replay at dispatch, boot rechecks indexed plans. Non-contended examinations rest, keeping seat debt. Retirement wakes on age eligibility, nonblocking publication or a removed source tree; compression on terminal writes or an unfinished pass; startup/repair discover missed bytes; nothing else wakes them. Queue recovery, drive settlement and runtime custody stay in the server (holds: §10.32); Storage Free (§3) is explicit. Absent usage owners keep debt and rest; money-only passes select newer dirty revisions, arrivals recheck absence.

Cooperative project checkpointing (`supervisor/events_coop_checkpoint.py`) runs on two equivalent quiescence triggers: a root settling without live descendants, or the last child settling under a terminal root (a root-scope budget stop terminalizes the root first). The bounded git chain revalidates quiescence under Q before mutation. Only host-minted project roots qualify: owner-attached folders are never auto-committed, credential-shaped files stay excluded and disclosed; each material success, skip or error gets a durable receipt.

### Bridge intake and commands

Bridge intake keeps identity, transport and durable acceptance; failed handlers requeue only their unprocessed memory tail, never accepted rows. Room input goes to its sole live reader, a warm question wait included, queued/held work not; the room's other live roots receive the row as carried context. Tell and answers owe mail to living work until its saved read, never resuming it: the asker, then proven admitted successors under each admission lock; else named ingress at the saved publication address for the asker's earliest live late-input head or a fresh head. Panic has emergency ingress.

The bridge recognizes `/panic`, `/restart`, `/review`, `/evolve [on|off]`, `/bg [start|stop|status]` and `/status`; other text is ordinary routing. External transports invoke them only with positive owner identity and a current transport-specific owner-chat binding; unknown refuses and registers nobody; Panic keeps its observed immutable binding until owner Reset closes it (`PanicIngress`). Commands reuse runtime-mode, queue, cancellation and typed-result authority.

Confirmed budget/owner pauses register `pause_notices` with the confirming result update: a saved System chat row is the receipt, a failed append stays owed (`pause_notices.py`). Consciousness reports paused/pausing or unknown, never guessing settlement.
