# 5. Supervisor Loop

`server.py::_run_supervisor()` owns the pooled scheduling tick and lifecycle lock. Intent precedes teardown; intent, outcome and money stay separate.

### Tick and locks

Each tick publishes liveness, rotates logs, checks workers, drains one bounded batch in one round trip (`ObservedEventQueue.drain`), control before telemetry, so no answer waits (`event_taxonomy.EventDisposition.lane`), takes bridge input (backlog skips wait/idle sleep), projects money, enforces due deadlines (`enforce_due_task_timeouts`), runs maintenance, admits/assigns, feeds the queue publisher (`start_queue_writer`), ticks consciousness and writes a busy minute's `supervisor_load` row (`loop_load.py`; Q per site). A lost bus (`EventBusLost`, read first; `bus_lost`) or three straight failures on a live bus, publication included (`loop_failed`), end a ready generation (`server_process.end_generation_on_fault`; §9 Fault door); shutdown excepted (`_SignalStopServer`).

`supervisor/event_observation.py` indexes pending idle inputs and tracks outstanding deliveries (`put_unless_outstanding`); `event_taxonomy.py` names idle-input reducers. Heartbeats, telemetry and host narration cannot suppress attention indefinitely; dequeue certifies no failed handler's effects.

`state.json` money is display, not admission (§10.28): totals persist, `usage_projection` owns per-root values, `usage_writer_snapshot` renders once per dirty tick after intake. Ledger `(compaction_epoch, seq)` ordering rejects stale renders. Quarantine (`integrity_degraded`) freezes display until explicit repair; failed writes stay dirty until `BUDGET_PROJECTION_RETRY_SEC`; the async OpenRouter comparison never changes admission.

`supervisor.queue._queue_lock` (Q) owns queue transitions while `task_admission` reserves identity before effects (§1). Admission persists nothing under Q (Q's I/O sites: §10.24) and waits outside it: child receipts, launch marks and warm Resumes reserve memory under Q, persist on the generation's admission lane (`PreparationGeneration.wait_store`: a slice per attempt, controls re-read between, never behind a copy; `task_admission.py`, `workspace_preparation.py`), re-take Q, compare memory and put; late refusals settle typed, uncertain writes are inspected (never re-sent). A closed admission starts nothing; a paused one launches nothing, yet committed marks still reach workers: process-ending stops pause the current generation's admission, never Q (`pause_admission`), and wait for its lane before reading the queue or writing restrictions; longer stalls, post-mark errors or Panic leave one possibly dispatched; cold roots keep lanes (§6). Outer-lock probes use `store.acquisition_budget(0)` (contention defers unsent work; unknown grants nothing). Only Evolution has mode fences. `execution_owner.kind` is origin and `lane`/`executor` carrier policy (`_is_direct_chat` is historical); first `detached_at`/`detached_by` survive metadata.

`dispatch_choice.py` picks only work reusable/admissible capacity can carry via launch gates (order, costs, identity reuse, repair, residuals).

### Admission and addressing

Headless addressing fixes at admission (`log_addressing.ingress_chat_id`). A registered Project's explicit `chat_id` must match its thread (else typed 400 so Main cards never detach); Project-less API tasks default to `HIDDEN_CHAT_ID` (0). Confirmed browser Publish requests Main via `source="web"`/`WEB_UI_CHAT_ID` (caller-declared, not auth); other non-Project addresses refuse. Main gets host-stamped completion only for work addressed/bound there; other work stays hidden (silent in chat; readable via the terminal, `--result-json-out`, Logs, `GET /api/tasks/<id>`). Inactive reserved Projects keep their chat for lifecycle refusal.

Admission names use no model; `task_named` never titles by status. Authored `title` (`ouroboros run --title`/contract/schedule) sets `title`/`suggested_name` (`metadata.title`/`metadata.project_id` get 400); first-line fallback sets `suggested_name` only. `start_task` requires a root title for separate new work.

`queue_publication.py` writes and `queue_observation.py` reads outside Q (§10.24): atomic replacement certifies fences (tightening anytime; relaxation after durable snapshot; parks/grants publish after Q release and re-compare). Boot `work_stop_migration.py` converts legacy stops, and `queue_snapshot.py` recovers interrupted direct parks from indexed pauses and saved envelopes: empty processes and concurrent restores keep unread work, Continue waits for custody, Stop and terminals govern retained rows, other caught roots stay fenced with their pending children (§6, §9), and spent grants yield to current custody.

`_claim_worker_launch` reserves row and slot under Q; the lane reads schedule control and puts only after dispatch marks commit in one write, before anything says `possible` (`_commit_launch`; snapshots never replay puts). Contention is demand (lane retries the same row/attempt/marks; refusal frees the slot, row stays demand). Dispatch, hold release and expiry read `governing_continuation`; saved successors need the frozen source and prior `admitted_dispatch_attempt` (§6). Proven no-put callers bind source/attempt/claim to terminalization (rechecked by reaper); terminal rows stay terminal, and accepted/sealed descendants stay fenced except exact pauses. `task_status.execution_observation` separates fresh activity from lifecycle; orphan inference is pooled-only.

`workspace_preparation` admits children off-loop (lanes, no re-put); store contention retries only the refusal receipt. Neither child-count pre-check (worker `schedule_subagent`, early supervisor) refuses an unknown count; `control_delegation.schedule_delegation_refusal` decides. `recover_interrupted_preparations` settles proven loss as never admitted and keeps uncertain admissions (§10.19). `forward_to_worker` reaches requested children (`events_schedule_task`, `task_admission`).

### Schedules and follow-ups

`queue_schedules.py` alone writes `state/scheduled_tasks.json` under `schedule_transaction` (Q then sidecar; PERSISTENCE). `load_schedule_store`: only absence is empty (`ScheduleStoreUnreadable` forbids mutation, reads unknown). `schedule_lifecycle._stamp_text_authors` stamps changed-field suppliers (`/api/schedules` ignores client copies via `ignored_fields`).

`schedule_occurrence.py` freezes one root/receipt per occurrence (`hold` waits; Restart preserves token/task identity: positive `possible` holds, proven-unsent replays, missing/foreign/unreadable stays unknown; cron keeps one overdue occurrence). Edits affect unaccepted work; accepted tasks survive restorable withdrawal. `schedule_notes.py` consumes `kind:"notify"` once as a signed `reminder` System row (`last_error` on unconfirmed display, no retry). Frozen objective/context ride `owner_words.SCHEDULE_TEXT` across inputs, Continue, helpers, review and Safety as assignment/conditions, never personal owner words or permission.

`followup_policy.py` requires explicit related/independent relationship (never inferred; related keeps origin cap/source/deadline; missing/stale queue holds; Restart never holds healthy schedules); its finite audited refresh accepts legacy Restart holds (disabled settled too), removing only Restart while keeping history/owed occurrences. Scans adopt legacy skill rows and cache `last_outcome`/`previous_run_open` (PERSISTENCE); other disabled idle rows skip admission. Stop writes `followup_stop` on the original result (`stop_action_id` is ingress, not custody `request_id`: CLIENT_CONTRACT §8); `expected_hold_id` releases only that hold (generic Restore may re-enable or cancel deletion); `schedule_mutation` shares `operation_id` (`changed_audit_incomplete` on failure, never unaudited rollback); tools/API share `schedule_lifecycle`. Observe off Q; publish checks row/Restart generation. Reconciliation/GC recheck signed `task_ownership` versions under Q (changed/busy defers, unknown stays unknown); admission verifies committed writes, and writes/final controls hold Q.

### Completion, owner waits and restarts

Workers prepare files before `task_done`, whose stamp never replaces CURRENT readiness (`headless.terminal_task_files_ready`). Capture needs `ARTIFACT_TERMINAL_STATUSES` (blank/unknown stays owed; failed/missing grants no PASS); readers and prep share `task_requires_workspace_capture` (no workspace, readonly subagents and inline executors exempt after terminal-source check and split adoption; cancellation wins). `CustodyBusy` keeps RUNNING and `pending_drives` for health/startup recovery without prompt replay or history scans.

Answer first: `agent_task_pipeline.emit_task_results` owes and live-enqueues the root final BEFORE cost reconstruction, review capture and `_store_task_result` (`task_done` follows store; `task_finalization_timing`, `basis: post_answer_store`: `finalization_timing.emit_post_answer_timing`). Timeout/dead-worker recovery adopts owed, exhausted, delivered or unreadable registrations (direct boot fence needs readable registration: `working_checkpoint.adopt_registered_answer`), keeping the answer with `failed`/`infra_failed`/`finalization_incomplete` and a host notice without prompt replay.

`worker_owner_wait` keeps task, worker and browser RUNNING (parked tasks do not act); `grant_warm_returns` returns it on its own worker without a capacity grant, even above cap, never holding, silencing or killing another process. Main/Project waits survive planned restart with unread input; mail wakes, only owner answers answer (`owner_mailbox.mailbox_drain_ended` rejects post-work steering); lane carriers wait here too, while inline executors use `owner_wait.direct_owner_wait`. Crashes, timeouts, restart and update-abort follow §6 Saved working state.

### Cancellation

Intent precedes custody; intent and outcome stay separate (§10.14–15):

1. **Intent.** Ingresses (`cancel_task`, HTTP single/cascade, evolution stop, project deletion, cascade sweep, ended work's parked-helper closure, expired-park Close, boot recovery of `cancel_requested` files) use `cancel_intents.request_cancel` to write one durable locked row in `state/cancel_intents.json`. Failed writes stop nothing (`CANCEL_INTENT_WRITE_FAILED`, HTTP 503).
2. **Scope.** Widens only (single→cascade; Stop-now cannot shrink a cascade); reaping is no cancel ingress (custody survives until replay settles). Stop needs explicit intent; in-flight replays keep it pending.
3. **Claim.** `task_lifecycle.cancel_task_custody` claims exclusively so racing custodies never double-settle (§10.14; `cancel_task` only wakes it; obsolete helper closures withdraw uncancelled). Lane turns stop like workers; inline actors get typed `finalize_now` (`inline_carrier.stop_direct_chat_turn`), ending next round without a model call; stop during post-task synthesis records `post_task_stop_reason`; live turns release claims for sweeps without publishing `cancelled`.
4. **Kill and re-check.** Confirm process death, then reread settled result; natural completion wins (§10).
5. **Reconcile, capture, settle.** Re-audit open delegated runs from durable custody and capture real workspace artifacts (failed or unrunnable: `failed`, not `missing`); record reconstructed, known (`$0` included) or unknown cost, never a fabricated `$0`. Only settlement stamps `parent_decision`; `cancel_publication` keeps `cancel_origin` (restore-fence receipts name cause; `supervisor_cancel` dates observed cancellation, not death; HTTP proves transport only).
6. **Owe, then publish.** Recheck claim; owe the answer before terminal row, settled intent and `task_done` (pending deadlines under lock). Winning completion withdraws salvage; crashes replay debt; cascades send one `cascade:<root_tid>:<request_id>` digest. Any owed final/cancel/cascade holds Done; Project/Main bind failures and copies to answer/chat while unbound/unreadable receipts stay visible (`terminal_projection.py`, `events_chat_delivery._handoff_delivered_review`).
7. **Watchdog.** Off-drain tick sweep (`server_maintenance.py`, `sweep_cancel_intents`) re-feeds unclaimed/abandoned intents (cascades as cascades) so lost events or mid-teardown crashes cannot wedge cancellation.

Effective results show `cancel_state: "pending"` and `cancel_reason` until settlement (§3). Steering (`tell_task`, mailbox follow-ups, `forward_to_worker`) refuses typed while pending; restore and pre-assignment read the projection under Q so pending cancels never start. `task_done` asserts a settled outcome matching the durable result (`events_task_done`); a mismatch is a lifecycle fault, left to custody while cancellation is pending.

`terminal_delivery.py` owns the outbox (PERSISTENCE.md): exact-id debt before enqueue, boot/tick replay, `put_unless_outstanding` dedupe; refusal, retry exhaustion and the pending cap never discharge debt (exhausted rows keep payload and copy until receipt), and a delivered Stop receipt supersedes its task's older `host_notice` final in that chat, never resent. Card dedupe probes `dialog.sqlite`; Main's frozen event/clock survives eviction until strict receipt (§3); Cancel sends lineage-routed unreviewed salvage, a reap only without a held answer; receipt proves neither display nor reading (§10).

Best-effort dialogue tries zero wait first, publishing live at the same timestamp; only a contended row then waits in `dialogue_retry`, which crash or sustained contention can lose (PERSISTENCE.md). Required rows and named inbound acceptances never use it; inbound failure stays loud. Named sends keep timestamp/id, unnamed notices keep producer, `emitted` facts repair receipts without resend, and only non-Main replays count durable dispatch entries (`message_bus`).

### Stop policy and hurry

Stop policy is a durable-intent axis, scope-independent (omission = immediate; CLIENT_CONTRACT §8). `finalize_then_cancel` (`supervisor/owner_stop.py`) answers 202, settles descendants first without a final turn, then gives a running root at most one tool-less `finalize_now` turn within the remaining grace (a pending task gets none), under the honest owner reason while `owner_stop_receipt.py` preserves child/run material and readers on any exit (no session transfer). `OWNER_STOP_OUTER_CAP_SEC`, deadline and ceiling bound grace; immediate hardens graceful and Panic bypasses both.

Owner "hurry" is a typed task-local `kind=hurry` mailbox control (`ouroboros/owner_hurry.py`, `gateway/task_hurry.py`): wakes a waiting task, lets delivery skip just-arrived review answers and gives one line asking to finish sooner; attempt-scoped (`retry_reset` strips it on requeue), never a chat message, settings change or P3-gate weakening.

### Event bus, timeouts and worker readiness

One server-owned, process-lifetime manager bus serves worker generations, inline actors and non-task review usage; respawn never rotates it, lookup cannot create it, producer exit cannot close it, and a killed producer cannot corrupt another feeder frame. Its `spawn` manager ignores SIGINT/SIGTERM; `get_event_q` raises `EventBusLost` on exit. `log_addressing.task_event_queue` value-stamps chat/lineage/attempt; workers attempt checkpoint storage before live frames (`loop_messages._emit_checkpoint_event`; nested handler persists only `task_start_settings_reload_failed`), and `utils.append_jsonl` streams `logs/*.jsonl` except dedicated-sender types and `live=False` copies (`llm_api_error` in drive and canonical log).

Heartbeat proves liveness only, source-dated and store-free (`_handle_task_heartbeat`). `silence_attention` dates episodes on row and task doc, mailing source plus one waiting ancestor (ends only on source progress, no host role minted; projection leads with `No recorded progress since …`, reason `no_progress`; without a mail-reading waiting ancestor no mind is told).

Q freezes deadline/run limits: `reaping`→`task_reaper`. Queued expiry skips dispatch, a kept park awaits Close (`expired_park_close.py`, `parked_deadline.py`); kill/join before salvage/settlement. Unknown exit keeps custody, no terminalization/retry/replacement; `task_reaper_wedged`: Restart hint; a result proves no exit; incidents keep `TIMEOUT_TERMINAL_REASONS`.

`worker_pool_lifecycle.pool_slot_counts` separates acting tasks from idle/booting/sleeping processes (cold sleepers hold none, §6; cap, §7). `pool_admission.py` holds new project processes—floor included—on confirmed critical memory pressure while running work continues. The conversation spare starts first; project workers have no spare and grow only for rows the pass chose and no idle worker took (`booting` slots charge capacity, unresolved reservations stay charged; `worker_boot` stays per process). Surplus retires only after local-work quiescence and confirmed death, with no idle timer (idle memory is preferred to burst startup), keeping services; unknown defers; with no healthy slot pooled ingress closes (`/review` too); lifecycle lives in `worker_pool_lifecycle.py` and PERSISTENCE.md (`request_worker_quiescence`, `retire_quiescent_worker`, `reap_idle_worker`; `disable_exhausted_worker_pool` fails unstarted rows with a Restart hint while sparing chat, control, boot and update recovery; unchanged skills reuse catalogs/digests §13).

`worker_health.recover_confirmed_dead_worker` reserves `confirmed_dead_worker` custody under Q: saved terminals (`task_exception` included) beat death, exact pauses re-park (§6), registered answers adopt without replay, and incomplete or unreadable publication stays `TerminalFileRecoveryPending`. Only confirmed absence of both a saved terminal and a registered answer enters crash policy (`_recover_crashed_task_without_terminal`, keeping reconstructed cost and review). First, a replay-unsafe crash (warm owner-wait checkpoint, or unfrozen, incomplete or unreadable budget pause) or exhausted retries settle as `infra_failed` (`worker_crash_owner_wait`, `worker_crash_budget_pausing`, `worker_crash_retry_exhausted`). Otherwise, a replay-safe attempt still within `QUEUE_MAX_RETRIES` cancels if it is stopped Evolution (`evolution_stopped_no_retry`), or else retries once from newer working state without reusing spent Resume grants (signals included; a signal death reserves no delegated handoff and ends that attempt's running delegated runs). Startup recovers `pending_drives`, nonterminal/synthesis obligations and saved answers before orphan healing.

### Conversation lane

Startup and auto-resume notices name still-paused places unchanged. Owner Main/room turns, wakes, Presence bodies and auto-resume run in `WORKERS` slots with `lane="conversation"` (`conversation_lane.py`) outside cap, memory admission, project leases and `disable_exhausted_worker_pool`: admitted RUNNING and published first (returned owner turns wait via `resumes_on_lane`). The pool's one ready spare is the owner's, replenished at once; a closed repo-writer gate stops spawns, never dispatch; spawn success is the only bound. `inline_carrier.py` runs the same body on a server thread (`inline_executors` in `/api/health` and vitals): `inline_call` for live calls, `inline_degraded` with an owner notice only on physical `refused_carrier_reason` (§12). Its Presence slot is negative and non-pool; only the boot stop (`startup`) spares it and awaiting Presence rows.

### Maintenance and custody

`delegate_collection.BodyRuntime` observes held runs independently (§6; `delegate_feed.py` outside acting cap). `server_maintenance.HOST_DUTIES` runs off-loop tick passes, flat as history/live sets grow (`tests/test_cost_contract.py` B7; §10.24), reading actionable state once via `task_store.owing_documents` and `delegate_custody_current.held_runs`, gating refreshes on input/stamp moves. `owner_pause_control` (`tasks_owner_pause`) stops ended members on Pause and catches late fence writers; `bind_body_lifespan` observes after store publication; readiness enables collection, reviewer markers first-ready native capture (§6); `invalid_source` wakes on watched files/rows/release (`source_retention._unavailable_basis`); reaping verifies PID/birth/command/task/generation; watchdogs log stalls and suggest Restart without killing threads.

Bulk jobs use low-priority `python -m ouroboros.maintenance` children (`job:<name>`, `maintenance.JOBS`; providerless dialogue: §2). Recovery gaps keep task sources. Plan changes queue signatures, missed wakes replay at dispatch (boot rechecks indexed plans), and non-contended examinations rest while keeping seat debt. Retirement wakes on age eligibility, nonblocking publication or a removed source tree; record compression wakes on terminal writes, a new server generation or an unfinished pass; startup or explicit repair discover legacy or missed bytes. Nothing else wakes those two jobs. Queue recovery, drive settlement and runtime custody stay in the server (§10.32; Storage Free §3 is explicit). Separately, the server's off-loop `abandoned_usage_reconciliation` duty (`server_maintenance.py`, `terminal_cost_reconciliation.py`) rests absent usage owners with debt: money-only passes select newer dirty revisions plus still-present owners, while result arrivals (such as late child-result copyback), a ledger epoch change or restart reselect absent owners without a new receipt and apply the projection when eligible.

Cooperative project checkpointing (`supervisor/events_coop_checkpoint.py`) fires on two quiescence triggers (settled root without live descendants, or last child settling under a terminal root), revalidates quiescence under Q before bounded git mutation, and acts only on host-minted project roots while excluding credential-shaped files and recording durable receipts.

### Bridge intake and commands

Bridge intake keeps accepted rows, identity and transport; only its unprocessed memory tail requeues. A named App Reply goes only to its reading root (queued/unheld cold sleep too, never Resume); else its source room answers (`work_reply.py`). On `unconfirmed`, no repeat write or room answer; other readers get passive `delivery_unconfirmed` context, never Resume. Room input without `new_work` reaches its sole live reader (warm question waits too; not queued/held/restricted returns); other Project roots: context only. Main owner/program-note turn (`_route_main_followup`): signed notes get a final-drain round, no owner authority. Tell/answers owe mail until saved read, never Resume: asker, successor proved under admission locks, else named ingress at saved publication address for earliest live late-input or fresh head. Panic has emergency ingress. Continue carries read quiz replies only; `deliver_answer` uses live ACKs/pre-cleanup receipts.

Commands (`/panic`, `/restart`, `/review`, `/evolve [on|off]`, `/bg [start|stop|status]`, `/status`; other text is ordinary routing) reuse runtime-mode, queue, cancellation and typed-result authority (Telegram panels say the window's works, `said_works`; unread: unknown); external transports need positive owner identity and a current transport-specific owner-chat binding (unknown refuses without registering; Panic uses `PanicIngress`). Confirmed money/owner pauses owe one System notice per episode, and technical waits one per task naming the cause in the reader's language (`pause_notices.py`).
