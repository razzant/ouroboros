# 13. External Skills Layer

This chapter owns the skill plane outside the runtime package: where native and marketplace payloads live, the independent gates between installation and execution, and how archive installs, declared dependencies, extension staging and the bundled Telegram transport are admitted. It exists so discovery, review, grants, dependency readiness and enablement stay separate facts, because collapsing any two of them turns a UI toggle into execution authority.

Native and external payloads live in separate data-plane buckets (`data/skills/{native,clawhub,ouroboroshub,external}`), with review, grants, enablement, dependencies, tokens and health under `data/state/skills/<name>/` (§1 Data layout). Discovery and manifest parsing establish identity, source, hash, provenance and conflicts — never trust; a conflict declared by either enabled peer is enforced symmetrically without deleting either payload.

The executable sequence is install → deterministic preflight → hash-bound multi-model review → grants → dependency readiness → enablement → execution, and the gates stay independent: a review PASS installs no dependencies, `enabled=true` does not prove readiness, and an extension additionally needs host registration (§10 invariant 8). Mutating lifecycle work flows through one deduplicated queue (`skill_lifecycle_queue.py`); review jobs keep task/source/hash/attempt/actor/terminal evidence in the private full record, with the compact UI history as a projection that shows a `running` job with a dead process or stale heartbeat as `interrupted` without writing (its owners persist it); the Skills list read heals and syncs nothing. Review ordinals are allocated only after a job starts under the lifecycle lock, so retry history stays explainable across hash changes without a UI counter becoming review authority: a started failure, cancel or timeout consumes its number with one idempotent terminal row, pre-start dedupe consumes none. Accepted rebuttals reduce reviewer thrash; a new payload hash needs its own critic or qualified current-author binding.

Execution resolves one selected canonical directory through the full loader on every request. Payload walks prune cache directories before descent but still add confined manifest entries explicitly. Conflict checks use a fresh immutable peer projection (`skill_peer_inventory.py`) containing only canonical location, enablement, manifest conflicts and malformed/collision facts; peer payloads are not hashed and no partial executable object is synthesized. The verdict itself is one duck-typed projection (`skill_conflicts.py`, re-exported by `skill_loader.py`), so the full loaded skill and the cheap peer descriptor cannot reach different answers. The selected payload and peer projection are refreshed again after slow lifecycle reconciliation before dispatch, so a cross-process disable, revoke or same-size restored-mtime edit takes effect on the next request. Collision and malformed-manifest semantics remain the canonical inventory's disabled/broken outcomes, and a valid manifest keeps its declared conflicts even when its payload is unreadable.

Skill review combines deterministic preflight with independent multi-model feedback; an optional advisory cannot replace that feedback. Official catalog payloads get their reduced-noise profile only when sidecar, catalog/local file sets and every SHA-256 match exactly against a fresh catalog read; the listing's and manifest's `official_hub_verified` hint runs the same match against the display-plane memo (`marketplace/ouroboroshub.py` §7.1a) and is never authority. A deterministic preflight failure persists as PENDING, not advisory-overridable BLOCKERS. Ordinary Advisory explicit author finish may accept current bytes after prior substantive feedback or an exact returned terminal job/hash reference with partial feedback or disclosed review unavailability. Each newly written finish runs current deterministic preflight; its proof and actual source stay inside `author_disposition.review_reference`, and old pending Cyber metadata without that proof cannot authorize ordinary execution. A running or unresolved physical critic without feedback is not unavailable; real partial feedback may support finish while a sibling continues, with custody retained. `SkillReviewState.gate_for` supplies the same current authority to readiness, grants, extension and Host Service consumers; original critic hash/status/findings remain unchanged. Blocking always needs fresh critic approval, while Cyber retains its P0/P3 judgment. Enablement, owner disable, requested grants, dependency readiness and token hash remain independent. Hub publication uses this same review authority plus its capture/scanner/consent contract in §6.

`skills/telegram/` bundles an in-process bridge (binding, polling, injection, settings) and supervised companion (sidecar, tunnel, menu rollback, heartbeat, singleton); text works without the Mini App/tunnel. This native hash-bound seed stays disabled until grants, not a marketplace install. Colab requires fresh native discovery/seed authority, grants only missing grantable items under owner auto-grant policy, then enables. State under `data/state/skills/telegram/` separates binding, companion, menu rollback, delivery cursors and tunnel cache. Files (10 MiB) ride `/chat/inject` from confined skill state to host `data/uploads`; captions and file-only inputs become one owner message. Quiz answers use `/chat/decision` and `task_decision.answer_decision`, like web cards. Deferred network validation reports `degraded`/`telegram_startup_deferred`; task-done text/icon follows `outcome_phase`. The bridge speaks the install's interface language (`OUROBOROS_UI_LANGUAGE`, §7): its own lines are English tables registered with the translation generator under `code:tg.<table>.<key>` and read through the memory (`lib/telegram_i18n.py`), a host-composed sentence the bridge only relays (a task's reason line, a question's host facts) is sent in English as the host wrote it — it carries ids, times, the English task-control words and sometimes the author's rationale, and transports have no typed clauses yet — `/language` lists the memories on disk and sends any other wording to the Host Service `/ui/language`, and the retired bridge-private `TELEGRAM_LANGUAGE` is migrated once at the poller's start. Skill-local `TELEGRAM_PROXY` covers all Telegram API polling, sends, downloads, notifications and companion menus via HTTP(S)/SOCKS. Its masked form omits credentials, keeps the saved value on blank input and clears explicitly; disable/re-enable applies changes. Without it, bridge egress stays unchanged and companion calls stay direct. Host, Mini App and tunnel routes are unaffected. This in-process seed needs `httpx[socks]` in the core lock; invalid proxy errors omit credentials.

The model-facing `list_skills` tool projects the unchanged lifecycle summary through `skill_catalogue.py`. Without a name it returns name-sorted pages of whole compact records under the ordinary result cap: state (enablement, review, readiness, script executability or extension liveness, load error) plus purpose, trigger, Model Experience and tool-name previews that count what they omit. Disabled, unreviewed, broken and colliding skills stay listed. The returned `snapshot` refuses a page after skills were added or removed (restart at 0); state and payload edits never refuse one, and no page claims an atomic snapshot. A name returns that skill's full summary row and `manifest.read`, the `read_file(root="skill_payload")` call for the `SKILL.md` or `skill.json` the loader parsed in its physical bucket; instruction text is read there, never copied. A readable manifest stays addressed when another payload file is unreadable; an unparsed manifest or a name collision fails without naming a document; an unknown name completes with `found: false`. A detail beyond the cap uses the loop's generic result source. Optional `model_experience` prose also reaches the bounded installed-skills context; parse refusals teach the repair through each `SkillManifestError`'s `fix_hint`.

Marketplace installs are bounded archives staged privately and landed atomically with per-file hash checks. Inert resource bytes, PDF/PPTX included, need no suffix allowlist; archive validity, extraction paths, checksum and actual loader support remain separate facts, and Cyber policy findings are warnings. Install metadata drives isolated dependencies (`marketplace/install_specs.py`); manual instructions remain guidance, not execution. Fresh review and hash-covered declarations authorize literal build/check argv; verified resources and package caches survive under `state/skills/<name>/dependency_cache`, and `deps.json` records resolved package metadata, bytes, outputs and diagnostics. Delivery is distinct from a declared executable check: absent checks remain unknown, and declared-output drift invalidates installed readiness. Large resources stay outside the payload and the Git patch. Marketplace update and adopt rollback (`install.PayloadRollbackSnapshot`, verified `rolled_back`): §6 Skills and extensions; script runtimes and their Go/Deno specifics: `tools/skill_exec.py`, `docs/CREATING_SKILLS.md`.

Tool results retain two views when the host adds route or safety notes. `tools/tool_result.py` captures `producer_text` before composition and keeps `host_annotations` outside the bounded metadata map; the existing `text` projection and typed status remain authoritative for model/review behavior. Builtin, extension and MCP dispatch use this same composer. `loop_tool_execution.py` records both views in observability and stores producer bytes separately through the existing write-once task source store. `PRODUCER_RESULT_SOURCE_JSON` is the parser-readable source, distinct from the complete annotated `FULL_RESULT_SOURCE_JSON` used for review. Notes remain visible after truncation; a failed source write is disclosed rather than presented as a usable file. Unannotated results and historical retained files keep their existing representation.

Extensions import through staged trees (`_stage_extension_import_tree` under `__extension_imports/`), so concurrent workers cannot remove a peer's live import and stale trees stay reclaimable. Per-call child processes may proxy tools/routes/WS/UI/settings/companion descriptors, while persistent subscriptions and supervised tasks require in-process or companion lifecycle — reported through the generic capability matrix, never inferred from a platform name. Isolated children run the same staged loader in a private base with a scrubbed env, so native crashes cannot kill `server.py`. In-process extensions are more powerful, which is why namespacing, declared permissions, per-skill tracking and atomic unload are an executable contract rather than convention. Skill repair enqueues an ordinary managed task with an exact selected resource and revision admission (`skill_repair_admission.py`); a legacy `skill_repair` selector remains readable but selects no reduced profile. Shell, browser and delegation remain normal task capabilities; an installed payload needs no mandatory Git copy, and review never forces unload merely because the caller is repairing it.
