# PERSISTENCE.md — durable data-plane inventory

`DATA_DIR` entities: schema, retention and stopped-server deletion effects. The constructor scan in `tests/test_persistence_inventory.py` pins paths against these rows in both directions.

## Shared idioms (the vocabulary the rows use)

- **Stamp** — opt-in `_schema_version` (`ouroboros/contracts/schema_versions.py`,
  ABI-2): missing/invalid = legacy 0; no retrofit. Pre-ABI-2 own spellings
  (`schema_version`, `schema`, `state_version`) are noted per row;
  new stamps use the shared key.
- **GC retention** — `ouroboros/retention.py`: one owner knob
  `OUROBOROS_GC_RETENTION_DAYS` (default 7, clamped 1–365; legacy per-subsystem
  keys migrate). The maintenance child retires task trees, service logs, delegate
  recovery/supervision, code_intel, failed markers and agent media on changed source/recovery
  facts or restart; age alone never wakes it. Server custody retains headless/task drives,
  subagent worktrees and unmarked review materialization leftovers, unused views and
  unmarked isolated checkouts; marked uncaptured review copies/bases do not age out; consumed schedule receipts and settled withdrawals age out on the scheduler tick,
  confirmed capability probes at their write seam.
  Memory journals keep full new rows regardless of this knob.
- **Lifetime** — every row's Retention cell starts with its class: `[record]` (kept as
  history or authority), `[bounded]` (cannot grow with work: overwritten, capped or rotated)
  or `[disposable: <module.function>]` (a copy, cache or scratch, and the production function
  that retires it; `none` while nothing does). `tests/test_persistence_lifetimes.py` resolves
  every retirer and lists the planes without one; that list only shrinks.
- **Rotation** — `supervisor/state.py::rotate_jsonl_log_if_needed`: ≥800,000 bytes →
  atomic rename to `archive/<prefix>_<ts>.jsonl` under the append lock, with
  collision suffixes and an empty new live file. The supervisor tick rotates
  `events.jsonl`, `tools.jsonl`, `supervisor.jsonl` and `task_reflections.jsonl`;
  benchmark-sentinel roots skip rotation. This optional maintenance contains
  escaped `OSError` across checks, locking, rename and live-file creation
  (`finally` still unlocks) and logs one ERROR per path per 30 s (completion
  resets the throttle; lock-helper/busy warnings are separate, unthrottled);
  the next tick retries without added delay. Before rename, live bytes stay put;
  after it, a failed touch leaves history archived and the next append recreates
  live. Persistent failures can grow live logs past the threshold;
  `agent_startup_checks.hot_store_growth_notes` warns above 8 MB. Other exceptions,
  and mandatory `utils.replace_atomic` and `dialogue_import.rotate_final` failures,
  propagate. The dialogue cutover rotates chat/progress once; frozen segments feed
  `dialogue_import`, their readers query `state/dialog.sqlite`. File-log readers
  walk archives chronologically; `utils.jsonl_chain_handles` opens live first and
  deduplicates inodes against rotation races; whole-chain custody reads hold one
  archive beside live (`sequential`).
- **`archive/` is durable history, never GC'd** (BIBLE P1): readers backfill
  from rotated segments; no retention sweep touches `archive/` and none may be
  added.
- **Atomic writes** — `utils.atomic_write_json`: compact JSON (`settings.json`: indent 2),
  tmp+rename; orphan temps wait for `temp_sweep`. `json_update_lock` owns the sidecar shared by
  `update_json_locked` and stores with custom load/save. `append_jsonl`: O_APPEND plus sidecar lock unless noted.
- **Evidence pack** — `ouroboros/evidence_packs.py`: a task is PACKABLE once its row is
  terminal and no review of it is open (`task_packable`: the row's `review_collection_pending`
  fact, 1 for an open review operation of any surface or an uncollected acceptance, whose
  agent-session reader holds a retained handle's absolute path; a NULL row predates the
  selector and has no such reader); no
  duty, money or delivery fact is consulted, and nothing written for it later is lost: it
  becomes the task's next generation. A blob a live or reviewed task's manifests reference
  stays loose until that task's own pass; a folder with no store row is neither packed nor
  kept, only counted. The maintenance child (`ouroboros/maintenance.py`, job
  `evidence_packing`, passes in `ouroboros/evidence_packer.py`; never at boot) writes per-task
  xz streams, checkpoints first. The inventory row owns
  publication, revalidation, retention and recovery. Loose placements go; bytes
  stay forever. Readers distinguish missing from `evidence_corrupt`; a referenced record that
  is neither loose nor packed is reported (`missing`), never invented.

Claudexor 4.2.0 migrates the engine store from schema 1 to 2 for `account_last_service`, and 4.8.1 from 2 to 5 in one transaction (task-group indexes, `deferred_message`, `turn_plan_answer`, whose first start scans existing rows); reverting Ouroboros code or its engine pin does not downgrade these data. Ouroboros takes no automatic engine-data backup. Returning to an older release (4.1.x after 4.2.0, 4.7.x after 4.8.1) requires a complete pre-upgrade backup of `DATA_DIR/claudexor/` and `~/.cache/claudexor/`, taken with Ouroboros and its owned daemon stopped, restored at the same absolute paths with private modes and ownership preserved, without hard links. This discards later engine state; restored credentials may need reauthentication. The engine also refuses releases below the last one that served the root, even on the same schema (4.3.0 after 4.3.1). A planned restart onto a lower pin, automatic boot-smoke rollback included, keeps a still-serving newer engine (ARCHITECTURE §9), though a body predating that rule stops it at its own next planned restart. While serving off-pin, Connect cannot automatically install a missing vendor CLI (its response matcher requires the exact pin), and gateway calls still probe the pinned runtime, installing it if missing or probe-failed. Once it stops (manual Restart, Panic, exit), the older engine refuses the store and Claudexor-backed routes stay unavailable until a body pins that release or newer, or that backup is restored.

Logical global quarantine changes generation visibility while retaining the independent upload scope (`pid=0`). Explicit physical `engine-state` quarantine instead closes storage and archives the database/WAL/SHM **and the whole `resource-store/`** in one `daemon/journal-quarantine/` artifact before creating fresh SQL. The fresh resource directory inherits no old upload replay authority; accounts, runs and `journal-legacy/` stay in place. Recovery intent and its receipt stay under `daemon/recovery-operations/engine-state/` so an interrupted operation resumes without importing old state. A raw physical export is diagnostic evidence, not a complete restorable backup. These are engine operations, not Ouroboros's own data migration.

Downgrade: old builds keep holds but lose `_resume_selection`; with a released latch children can dispatch without root-generation checks: **not Q9-equivalent**, no reverse export. Old bodies miss the Restart door and restore as after Quit. Old launchers can block auto-start after failed Panic unlink; explicit Start works. Gateway `stop`, `refusal`, `members.states` and model/external tails are optional observations, not authority.
