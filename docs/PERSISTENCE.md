# PERSISTENCE.md — durable data-plane inventory

Durable entities under `DATA_DIR` (default `~/Ouroboros/data/`): schema,
migration, retention and reset consequences (deletion with the server stopped).
Entity-local contracts; no generic persistence framework.

`tests/test_persistence_inventory.py` scans constructors in `ouroboros/`,
`supervisor/`, `server.py` and `launcher.py`: every data-relative path needs a
row here, count-anchored both ways.

## Shared idioms (the vocabulary the rows use)

- **Stamp** — opt-in `_schema_version` (`ouroboros/contracts/schema_versions.py`,
  ABI-2): missing/invalid = legacy 0; no retrofit. Pre-ABI-2 own spellings
  (`schema_version`, `schema`, `state_version`) are noted per row;
  new stamps use the shared key.
- **GC retention** — `ouroboros/retention.py`: one owner knob
  `OUROBOROS_GC_RETENTION_DAYS` (default 7, clamped 1–365; legacy per-subsystem
  keys migrate). Governs subagent worktrees, headless/task drives, task trees,
  service logs, consumed schedule receipts,
  confirmed capability probes, delegate recovery/supervision sweeps, code_intel
  reconcile-failed prunes and agent media. Memory journals keep full new rows regardless of this knob.
- **Rotation** — `supervisor/state.py::rotate_jsonl_log_if_needed`: >800 KB →
  atomic rename to `archive/<prefix>_<ts>.jsonl` under the append lock. The
  supervisor tick rotates `chat.jsonl`, `progress.jsonl`, `events.jsonl`,
  `tools.jsonl`, `supervisor.jsonl` and `task_reflections.jsonl`. Readers walk
  `archive/<stem>_*.jsonl` in chronological name order;
  `utils.jsonl_chain_handles` prevents rotation races by opening live first
  and deduplicating inodes.
- **`archive/` is durable history, never GC'd** (BIBLE P1): readers backfill
  from rotated segments; no retention sweep touches `archive/` and none may be
  added.
- **Atomic writes** — `utils.atomic_write_json`: compact JSON (`settings.json`: indent 2),
  tmp+rename; `update_json_locked`: sidecar lock; `append_jsonl`: O_APPEND
  plus sidecar lock unless noted.
- **Evidence pack** — `ouroboros/evidence_packs.py`: SETTLED means terminal,
  result/owner duties clear, reviews/debt/late receipts closed, money known and
  resolved; no timer. Every obligation set is owed, an undeclared one too,
  except the declared records (`obligations.RECORD_SETS`: notice receipts,
  custody marks, refusals). The maintenance child (`ouroboros/evidence_packer.py`, never
  at boot) writes per-task xz streams, checkpoints first. The inventory row owns
  publication, revalidation, retention and recovery. Loose placements go; bytes
  stay forever. Readers distinguish missing from `evidence_corrupt`.

Claudexor 4 stores current authority in `claudexor/daemon/engine.sqlite` with its WAL and `resource-store/` bodies/uploads. Ordinary first-start import publishes one verified SQL store, preserving `journal/` as `journal-legacy/`; an existing database wins on restart. Historical `resource-store/idempotency/` keys stay in place for addressed lazy replay: removing them can change an old upload key's result. The engine reader floor makes migration forward-fix only; retained journals are evidence, not automatic downgrade or restore authority.

Logical global quarantine changes generation visibility while retaining the independent upload scope (`pid=0`). Explicit physical `engine-state` quarantine instead closes storage and archives the database/WAL/SHM **and the whole `resource-store/`** in one `daemon/journal-quarantine/` artifact before creating fresh SQL. The fresh resource directory inherits no old upload replay authority; accounts, runs and `journal-legacy/` stay in place. Recovery intent and its receipt stay under `daemon/recovery-operations/engine-state/` so an interrupted operation resumes without importing old state. A raw physical export is diagnostic evidence, not a complete restorable backup. These are engine operations, not Ouroboros's own data migration.
