`python devtools/context_fit_report.py --data ROOT --room ID --window TOKENS --reserve TOKENS` measures the ordinary fresh-task projection at density 1.0: block/host/memory/tool costs, profile, room work levels, window record, ladder and physical margin. A start-work-room refusal is named separately from physical session capacity; its minimum estimate is not a sent candidate. `--session-provider gemini_live|grok_realtime|openai_realtime` additionally runs the real conversation host's tool selection and session-candidate seam with the bundled default model/options and cached output limit, including call tools, driver instructions and provider wire, without connecting. Output names missing inputs (saved feature settings/languages, opening turn, live mailbox, account observations); a supplied retained host can be measured through `devtools._context_fit_session.measure_session`. Other options: `--mode max|low|nano`, `--json`. SQLite uses `mode=ro&immutable=1`; ROOT writes are forbidden, while content-addressed diagnostic blobs go to scratch so the measured context keeps the server's pointers. Live PID/lock or WAL requires `--snapshot` (private clonefile/copy, WAL recovery there). Changing inputs, stale indexes and external local skill sources are refused. Live process scanning is unavailable and adds no diagnostic text to the measured input; this estimates a fit, not provider acceptance.
