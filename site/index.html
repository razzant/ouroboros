Your rules.
It keeps them.

Write standing rules in your own words, for everything or for one chat. Ouroboros reads them every time, and a second reader, the Safety Supervisor, reads them before actions. An action it flags is sent back before it has any effect; by default, one it judges dangerous waits for your answer.

Rules for one chat live with that place, and a team's administrator can add organization rules on top. Work that is already running keeps the rules it started with. The Supervisor does not read every kind of action, and you choose how much it checks.

It remembers.
In its own words.

Open conversations stay verbatim; closed matters become pages it wrote, with the quotations checked. Knowledge sits on shelves, notes link to each other, and one memory spans every room and channel.

It thinks between
your messages.

Advises, acts or evolves: you set the level. Once you turn it on, it wakes on its own schedule, day or night, reads what arrived, prepares, and tells you only what matters.

Make it
a skill.

“Make me a Doom-style shooter I can play right here.” Done, playable in the chat card. A chart becomes a widget, a 43-paper research becomes a table, an image gets drawn. Whatever it makes, one click keeps it.

It rewrites
its own code.

Evolution campaigns change its implementation: code, prompts, tools, memory. Every change is reviewed by other models, checked, and kept in Git history. The constitution it wrote for itself sets the limits.

Don't like a part?
Swap it.

Plugin-first: the core stays small, and the rest plugs in. Skills, widgets, connectors, voice engines, chat controls and MCP tools are plugins. You decide which sources to trust: by default the maintainer's official skills install as they are, and community skills are reviewed before they run. Install one from OuroborosHub, write your own, or ask Ouroboros to write it for itself. What you install or write stays through every update.

  • SkillsTools, workflows and instructions it learns to use.
  • WidgetsLiving cards on its board, from a chart to a game.
  • ConnectorsSlack, Telegram, email, GitHub: the places where it is a colleague.
  • Voice enginesLive calls, speech-to-text and read-aloud, on the engine you pick.
  • Chat controlsButtons and chips a skill adds to the composer and to messages.
  • MCP toolsAny server, loaded when a task needs it.
